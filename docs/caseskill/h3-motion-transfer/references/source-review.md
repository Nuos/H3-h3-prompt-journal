## 2. 多维简评

**方法论。** 输入分权、应用顺序和失败条件较完整，能够形成可审计流程。但“先建人物再建世界”目前是自然语言要求，并不是JSON中独立运行的多个生成阶段；没有证明模型内部严格按该顺序计算。[S2：245—276行；S3节点138]

**输入输出。** 三参考具有清楚角色，文本可用于多种动作与场景；JSON还保留机器本地素材名称、加载器版本及若干非核心节点。部分节点具有 `cnr_id` 或提交号，部分没有，尚缺完整安装清单和资产替换表。保存的工作流文件是工程基础，不等于已交付即用环境。[S3]

**时序与验证。** 音频优先原则和动作连续性清楚，但未附可机读的BPM、重拍表或动作到节拍的映射。FINAL VALIDATION要求“生成前”核查每帧身份，实际上需要拆为提交前规范检查与生成后逐帧检查；现有清单没有证明这些检查已执行。[S2：416—537行]

**泛化边界。** 从原场景迁移到新场景时，脚下支撑、可用空间和运镜通路可能不同，仍需动作可行性检查。作者报告9.4秒成片，本评估只确认该文字记录；媒体按任务要求未查看。

## 3. Skill 化判断与最小落地步骤

建议先固定可运行工作流版本，建立输入角色表与资源校验，再抽取动作／机位表，读取目标音频网格，输出带时间码的完整提示词与有效参数摘要。将八项文字核查分为生成前后两道检查，保存运行配置、种子、素材哈希、失败类型和重试结果。其可独立作为动作迁移主流程，也可由更大的分镜编排流程调用。

## 4. 主要缺口与优先级

1. **P0：修正有效参数。** 文档写“Duration=9s／124帧@24fps”；JSON的时长9经节点131表达式产生**226帧，约9.417秒**，124是已接线输入旁的保存值，且124÷24约5.167秒。宽高也由节点115的**16:9、0.4MP**选择器连入，不能用旁边的1344×768旧值代表有效输出；内置参考表对应864×480。[S1：42—50行；S3节点115、131、132、136、140]
2. **P0：核对音频接入。** LoadAudio节点155存为 `mode=4`，视频加载节点154的音频输出未接线；首段连到 `ref_video_audios`，续段连到 `ref_audios`。应验证启用状态与两种端口语义是否满足独立Audio1的时序职责，不能只凭提示词认为音频已生效。[S3节点136、155、191]
3. **P0：统一续接裁剪。** 说明要求裁掉22帧；JSON节点213起点为26帧，音频节点212起点为1秒。在24fps下26帧约1.083秒，与22帧和1秒均不同；需说明偏移依据并核查声画同步。[S1：49行；S3节点194、211—213]
4. **P1：补运行与稳定性证据。** 模型／编码器的元数据下载名与实际选用文件名不同，需锁定准确依赖和权重；为时长、量化、采样模式建立实验记录，再界定8—9秒经验适用的配置范围。[S3节点128、170；S1：40—48行]
