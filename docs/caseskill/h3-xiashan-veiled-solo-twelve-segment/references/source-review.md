## 2. 多维简评

**方法论。**案例记录“场景引入背景人物”“面纱被当作道具摘掉”“规则未进入单段”等失败与修订，因而可以抽取问题—原因—修复—检查的闭环。袖/面纱的语义消歧尤其适合发展成资产状态保护规则。全文自包含解决提交时约束缺失，但重复文本仍需要统一来源来维护。[S1：13–40]

**动作与时间。**链记法明确进出态，持续呼吸层为等待和停顿提供连接；歌词只作为时序及情绪参考。不过“拍数”和时间块未始终一致：SEG01 的 C1 标为 4 拍，所在 0.889–4.471 秒窗口长 3.582 秒，按 0.4478 秒/拍约为 8 拍。若剩余时间用于保持或过渡，正文也应写出，不能同时宣称精确拍数与精确时间已完全对齐。[S2：45–59]

**镜头与约束。**稳定与延迟观察的对比有明确用途，适合成为可选择模式；但开头限定醉酒模式只用于 S03/S10/S11，S05 又使用 E8 过冲修正，S09 又要求 E8 延迟环绕，且同一行最终写 `no orbit`。首尾静止与“持续层在 stillness 中永不停”也需定义为主体宏观静止或微运动，避免绝对词互斥。[S2：7–8、309、425、553]

**复现与泛化。**作者称歌词 40/40、段长 12/12 已核对；本目录没有对应 SRT/manifest，无法独立复算。README 提交流程的切点串最终到 181.956 秒，而摘要及十二段正文到 141.845 秒，属于可确认的文档版本不一致。面纱、单人、特定场景、旋转次数是本案例设置，不是通用 H3 限制。[S1：3、56–68]

## 3. skill 化判断与最小落地步骤

建议构建“多图职责＋不可变资产状态＋多段舞蹈”主流程原型：

1. 建立统一配置：图像职责、可变/不可变对象、音频源、全局段界、局部首拍、动作链编号及入出态。
2. 从配置编译每段自包含正文，避免十二份锚块分别手工维护；歌词锚、环境与背景人物许可逐项审核。
3. 检查拍数与时间窗、段间部位/方向、镜头模式许可和互斥要求，再生成试跑顺序。
4. 按 S05 的面纱/背景测试思路增加双段接缝、旋转段和地面段回归，记录模型与输入版本。
