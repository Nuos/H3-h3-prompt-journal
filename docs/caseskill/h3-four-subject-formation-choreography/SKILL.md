# H3 四主体身份锚与队形状态接力

将固定视觉锚、队形节点和动力状态接力组合为可审计的多人编排子流程，解决角色随站位改名、穿越许可冲突、段首回到参考姿势及为了看全队形而退成远景的问题。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **主体与场景资产表**：提供参考图及四个主体的唯一ID、图中初始定位、稳定外观/服饰标记和场景权限。图中位置只用于首次识别，不能在换位后重分配ID；资产缺失标missing。
- **段落和音乐时间域**：提供目标总时长、分段区间、已测beat/onset表及local/global映射；93.75 BPM与源k标签只用于复现本源材料，不能套给新曲。
- **场地、队形及通道**：提供地面坐标约定、可用空间、禁入区、队形节点、交叉/层交换需求和可通过间隙；无空间证据时把避碰判断保留为规划待核验。
- **动作与接缝状态**：提供每人动作风格、承重脚、躯干朝向、手臂运动和段末方向；后续段必须有前段outgoing状态，缺失时先建立接缝设计。

## 执行流程

1. **建立并冻结视觉锚版本**：从实际参考识别主体，形成ID—参考初始位置—外观标记—场景职责表；保留该任务所需的简洁服饰锚，但不凭空重述未见内容。冻结anchor版本并在所有片段复用同一文本，局部角色变化需显式改版本。
2. **核对工程范围与节奏证据**：若复现案例，说明目录仅有SEG10完整正文和14段总览，cuts_manifest.json缺失。可转录内嵌22拍节点并标source_inline/unverified，不能声称重建原manifest或其他13段正文；新曲从用户提供的数据生成自己的时间表。
3. **为四人分配动作性格**：分别设置紧凑果断、外向弹性、精细低幅、轻快侧切等可观察动作差异，用错拍、镜像、幅度和头部朝向区分主体，只在写明的共同重音齐做动作。特写中其余人仍保留可读的承重和恢复。
4. **把队形变化展开为逐人舞步路径**：对每个队形节点列出每人起点、目标点、支撑脚、转向、身体先后传导和时间窗；让支撑脚与重心先行，膝胯躯干再跟随，避免把换位写成散步。保留保护弧、层交换、旋转接力和四线展开的功能，按新场地重新布局。
5. **发放局部穿越许可并检查遮挡**：默认维持各自通道；中心穿越、前景经过、前后层交换只在显式许可表内发生，写明参与主体、通道、进入/退出时间和让行关系。不得同时注入全局禁过中线和局部穿越。若同时间占用同空间，错开时间、改外侧通道或减小动作幅度。
6. **接力身体状态与观看机位**：逐字段传递每人的位置、承重脚、躯干扭转、手臂余势和运动方向，OUTGOING与下一段INCOMING保持一致。镜头通过预置机位或明确切点揭示队形；允许为维持距离而跟随后退，禁止仅为揭示新队形把主体拉成难读大全景。
7. **组装段落并核验**：输出固定锚、音频/时间域、入态、动作风格、人物差异、摄影机、队形图、逐拍/逐段动作、约束和音频职责。检查ID不随位置漂移、每人动作全程有去处、穿越许可无自相矛盾、接缝状态一致；未做连续生成回归前只报告文本通过。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **FSC01**：同一任务的视觉锚逐段复用相同版本，主体ID不随站位与镜头前后变化重新编号。
- **FSC02**：参考图负责已声明的身份/场景，后续段的起始动作来自INCOMING而非重新摆参考姿势。
- **FSC03**：队形换位必须有支撑脚—承重—膝胯—肩臂—恢复的动作链，不能只有目的地或普通步行。
- **FSC04**：主体动作性格和错拍关系保持可区分，共同重音之外不把四人写成同步复制。
- **FSC05**：把中心交叉和层交换编码成局部许可；不同时保留全局不穿越和正文交叉动作。
- **FSC06**：区分同距跟随后退与拉远揭示队形：前者可依动作使用，后者受本案例近景观看策略限制。
- **FSC07**：每段OUTGOING与下一段INCOMING逐主体传承位置、承重、旋转、手臂路径和行进方向。
- **FSC08**：歌词只塑造情绪/力度，不把歌词名词自动生成道具、特效或字幕；音频是否原样保留按任务职责显式声明。
- **FSC09**：原14段总览、93.75 BPM和近零漂移自述不得当成完整工程与通用性能证据。

## 输出与检查

- **身份锚与参考职责表**：稳定Subject ID、参考定位、身份/服装/场景作用域、anchor版本和缺失资产。
- **逐人队形与穿越许可表**：每个时间窗的起终位置、支撑脚、动作链、通道、参与交叉者、让行顺序、遮挡/避碰待核验项。
- **段落接缝表**：每人OUTGOING/INCOMING对照，含位置、承重、躯干、手臂余势、方向和未解决差异。
- **完整片段提示词**：固定锚和本段动态编排完整组装；可单独阅读，不依赖未提供的其他13段文本。
- **时序与证据核对表**：local/global、beat来源、实际/计划状态，说明哪些结论仅来自案例文字及哪些未做连续生成验证。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
