## 2. 多维简评

**方法论系统性强。** “作品意图→音乐→编舞→动力学→衔接→音乐对齐→摄影机→分段→自检”已明确；动作密度只是初步参考，身份图权限与剪辑模式须按项目选择。这些边界适合转成决策流程，而非全局禁令。[S2]

**输入输出明确，资料复现链不完整。** README 给出十三段文件名与连续源窗口；prompt 各段可以独立复制。`cuts_manifest(2).json` 仅被引用，案例中没有实体；原图、音频及成片也注明不随公开仓库分发，因此本次只能核查文本内部一致性，无法确认网格来自何种分析及实际误差。[S1][S3]

**动作、音乐、镜头的职责划分较清楚。** 准备、发起、扩张、重音完成、回收形成动作链，镜头服务身体信息；段内硬切与“全片连续物理镜头”没有被误写成同一模式。不过 README 强调段尾 hand-off，实际 prompt 主要规定“以活动状态结束”，下一段常另起局部构图，尚未逐对说明支撑脚、朝向和手臂出入态如何匹配。[S1][S3]

**验证是文字自检，效果仍是待验证项。** Implementation notes 已承认精确运动可能变化。正文的时间戳与约束应作为编排意图和检查目标，不能直接当作模型精确执行的证据。[S3]

## 3. skill 化判断与最小落地步骤

建议建立“输入权限表→音乐事件表→母题与动作链→分段镜头计划→提示词输出→自检”的主流程。将参考权限、是否持械、蒙太奇/连续模式、动作密度和末段收束设成参数；为每段记录源窗口、local 时间、起止状态和音频文件标识。随后增加时间越界、人声事件引用、武器状态及跨段配对检查，再使用不同曲速、无武器/有武器输入做回归。[S2][S3] 这些属于建议实现，当前目录尚无可执行 skill 包。

## 4. 主要缺口与优先级

1. **P0｜统一时间事件来源。** Segment 05 的 6.044、9.000 秒动作块分别称在“下一/最后人声句”开始时动作，人声表对应起点却为 6.950、9.633 秒。应区分按强拍提前动作与按人声起点动作，由同一事件表生成标注，先核对原音频再修订。[S3，185–200 行]
2. **P1｜补全可核对的跨段契约。** 将“活动状态结束”细化为相邻段起止状态表，并明确哪些边界允许蒙太奇跳接；不要把音频首尾相连等同于身体状态自然连续。[S1，42–49 行；S3]
3. **P1｜补齐来源与执行记录。** 提供脱敏 manifest、节拍分析口径、模型/工作流版本及按检查项记录的成功和失败样本；其中 0.663 秒的拍点标签命名也需统一解释。[S1][S3]
