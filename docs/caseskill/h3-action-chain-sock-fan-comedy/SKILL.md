# 道具脱离、触镜与局部扇风的连续动作链

把动作名清单改成“起态→动作→结果→下一态”的有条件动作表，保持实体身份与所有权，区分永久身份和阶段性姿态，补足音乐事件、时长预算及错误动作主体。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **参考图和初始身体状态**：确认人物身份、服装、机位及左右脚起态。以人物解剖学左右为准记录哪脚支撑、哪脚抬起、布料物穿在哪；参考图不满足起态时重写起态或请求相符素材，不能假装符合。
- **实体与两手角色**：给人物、左右手、左右脚、布料物稳定ID。明确哪只解剖学手在双手协作后持物并投掷/扇风，另一只手何时转为捂嘴；不是只写“同一只手”而不绑定左右。
- **动作链与不可省前提**：确认检查、闻、投掷、触镜、反弹、下落、落脚和扇风中哪些必须保留；写出接触点、所有权变化、释放时点及阻止并发的条件。
- **音轨、时长及节奏要求**：读取已提供音轨的实际音头时刻或用户给定标记；记录总故事长度、每态可辨认的预算和结束保持。只有图片或抽象ACCENT标签时标记audio/onsets为missing。

## 执行流程

1. **检查起态并固定解剖学实体**：建立LEFT_FOOT、RIGHT_FOOT、LEFT_HAND、RIGHT_HAND及PROP表，不随屏幕方向互换。将图像可见身份与初始支撑/穿戴状态分开。原案右脚抬起穿袜、左脚赤脚支撑可按新图整体重映射，但重映射必须贯穿所有状态。明确袜子无鞋不等于已赤脚。
2. **指定道具归属及手部角色交接**：双手共同移除布料物，动作完成后道具归明确的一只手，另一只手空出后再捂嘴。持物手依次承担检查、靠鼻、投掷、随挥和扇风；捂嘴手在后续保持下半脸位置，鼻梁和眼睛可见。归属变化仅发生在明确转交或释放事件，不允许镜头遮挡后换手。
3. **把25态整理成有边界的状态表**：使用案例25态作为参考，将每态写为前置条件、活动部位、保持部位、动作、道具位置/归属、结束条件及下一态。检查看物、靠鼻、短闻一次、眼神反应、捂嘴和投掷准备的顺序；修正STATE 8为“人物再次看道具”，不复用“持物的手看道具”的错误主语。无需机械保留25个编号，但不得合并掉可辨认因果。
4. **锁定释放、接触、反弹和落脚门槛**：把道具路径写成手持→肩臂带动→手指释放→前景飞行→轻触镜头→小幅反弹→开始下落。释放后保留自然随挥，不能让道具先飞。抬起脚的下降以“已触镜且已开始下落”为门槛，落地时交代髋膝踝和骨盆从单腿支撑到双腿承重；镜头接触只由道具靠近产生，不重置视角。
5. **按阶段设置运动不变量**：移除至道具下落前，支撑脚保持在地，另一脚保持抬起；双脚落稳后允许后续tap与换重，永久不变的是解剖身份和脱下后裸足状态。投掷结束后，肩、上臂、肘、前臂维持总体前伸结构，腕掌负责横向扇风；局部稳定不等于全身冻结，后续下身舞步仍可执行。
6. **把重音标签转成时间预算**：将ACCENT 1–8、释放、触镜、落脚、扇风、乐句、最终大扇和freeze映射到真实音头及允许误差。缺音头时只输出带missing的暂定动作时间表。先给移除、飞行接触、反弹、落脚和收尾足够可辨认时间，再加入重复扇风与加速步法；25态塞不进目标时长时压缩重复段或增加故事长度。超过15秒的故事按4–15秒生成片段规划，优先在双脚落稳处交接完整状态。
7. **构建H3正文与接续记录**：按 references/h3-official.md 选择适用结构，声明图像负责视觉和起态、真实音频负责时序。跨片交接记录道具是否已落下、双脚穿戴/支撑、哪手捂嘴、哪臂前伸、镜头与音频偏移。脚本 scripts/audit_plan.py 只检查计划结构，不冒充动作检测。
8. **逐态验收和定向修订**：列出实际可见的移除完成、归属不变、释放、触镜、反弹、下落、落脚和腕掌运动检查点；记录缺失、颠倒、错误并发、换手换脚、道具消失和大臂乱甩。失败时修订相邻状态边界与活动关节，不靠增加互相矛盾的“全程不动”。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **S1**：身份标签永久，支撑、穿戴和位置是随阶段变化的状态；左右采用人物解剖学坐标。
- **S2**：上一态结束必须满足下一态前置条件；道具从穿戴、手持到飞行的归属变化必须可追踪。
- **S3**：将两手角色绑定到具体解剖学手，持物→投掷→扇风是同一只手，另一只手保持捂嘴职责。
- **S4**：释放先于飞行，触镜先于反弹，下落开始后才允许抬起脚下降；不能用同时发生省略因果。
- **S5**：扇风阶段保持近端肩臂肘前臂总体稳定，只让腕掌产生主要横摆；允许后来下身有独立节奏。
- **S6**：支撑脚不移动只适用于单腿支撑阶段，不能与后续该脚tap同时写成全程禁令。
- **S7**：STATE 8 的看物主体必须是人物与眼睛，不是持物的手。
- **S8**：抽象重音标签必须有实际时刻、持续预算和容差才构成可验收音乐计划；无音轨不得虚构。
- **S9**：25个自然语言状态和作者成功自述不等于已通过物理、同步或稳定性验证。

## 输出与检查

- **实体和阶段不变量表**：解剖学左右、手部职责、道具归属、支撑状态、穿戴状态及各规则生效区间。
- **动作状态表**：每态前提、活动/保持部位、动作、结果、下一态接口和不允许并发的动作。
- **音频事件与片段计划**：实际或missing的音头、动作时间预算、容差、重复段降级、生成切片和跨片末态。
- **正式正文及验收记录**：可用H3结构的正文和逐态人工审片清单，明确计划检查与未完成的媒体验证。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
