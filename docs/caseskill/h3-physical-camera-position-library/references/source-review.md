## 2. 多维简评

**标准化价值明确，分类尚需工程化。** “25 类”实际上是 A1–A25 的条目数，另有 A0；其中 A22–A25 是响应、校验、结构与原则，并非二十五个互斥的机位。A17/A18 已包含运动行为，也说明本库与动态运镜系统存在交叉职责。[S1][S2]

**输入输出适合模块化。** 输入可抽象为主体、拍摄意图及空间条件；输出为镜头的物理定义块。A24 明确位置、高度、距离、光轴、空间关系、物理结果、运动响应与锁定规则，适合转成结构化字段。当前各模板对距离、可见范围等字段的详略仍不一致。[S2]

**镜头语义清楚，但不能直接整段叠加。** A19 荷兰角模板固定“自然人类高度”，A5 则是离地 5–15 厘米；若要贴地滚转，必须把高度与滚转解耦。A11 默认不移动，A17 要持续跟随，组合前也需判断是否属于同一镜头的冲突要求。[S2]

**缺乏完整制作与验收闭环。** 本案没有角色/音频路由、动作时序、分段生成、失败重写流程，也没有逐模板对应的输入、参数和结果记录。README 指向 System B 的时间同步规则，但这里没有独立的镜头时间表。[S1][S2]

## 3. skill 化判断与最小落地步骤

优先作为 `references` 层使用，由主流程根据拍摄目的选取少量条目。下一步可实现专项“机位描述生成与检查”子技能：将高度、方位、距离、光轴、滚转、移动模式和可见部位拆成字段，先检查可兼容性，再生成八要素文字；未给出的字段应请求补充或明确假设。选择典型低机位、正上方、侧面、荷兰角分别做参数记录与失败对照，才有依据提升为 S2/S3。当前 S1 表示素材就绪，不否定其较高复用价值。

## 4. 主要缺口与优先级

1. **P1｜解决条目兼容与字段耦合。** 不要将二十五块全部拼入一个镜头；拆开“位置”和“滚转/倾斜/运动”，给出允许组合及排斥条件。[S2，159–195、361–385、517–603、719–751 行]
2. **P1｜标注跨库规则适用范围。** A9 使用约 90 度，A12/A14 使用 30–45 度；若调用项目同时启用 NO DEGREE 纪律，应按项目政策转换为相对空间语言，不能声称本库本身已全部取消数值角度。[S2，291–326、389–454 行]
3. **P1｜把效果保证改为可检验目标。** “无法被平均掉”应通过同输入、不同表述的对照与错误率记录检验；现阶段只确认其提供更具体的描述，不能证明模型必然执行。[S1，11、27 行；S2，793–795 行]
