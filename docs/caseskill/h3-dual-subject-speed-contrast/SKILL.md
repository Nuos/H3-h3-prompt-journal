# 双人异速：动作完成数、观察延迟与可见性

把“快者连续做、慢者观察后再做”变成有身份、起止、计数窗口和可见判据的双主体关系，使异速效果可以被计划和复核。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **角色参考与稳定身份**：指出每张图中各角色的可识别特征及初始位置，分别绑定主体；一张图片可定义两个主体，摄影机绕行后仍按身份而非屏幕左右编号。
- **可计数动作单元**：给出动作开始/完成姿态、是否允许不同单元、连续衔接方式。计数脚步需脚部可见；近景可选膝、髋或手臂的完整循环作为判据。
- **时间关系**：给定总时长、动作完成数比例、统计窗口、容差及观察延迟；原案未给总时长或BPM，不把它们补成历史事实。
- **摄影与声音**：记录近景、环绕路径、最低入画部位、能否放宽景别，以及器乐/人声要求和实际音频是否已提供。

## 执行流程

1. **建立两个稳定主体**：从真实图片中分别定义快者和慢者，绑定脸、发型、服装；初始左右只是定位信息。把场景构图参考与身份参考分开，未提供素材时先交付带缺项标记的计划。
2. **把动作单元写成可完成事件**：每个单元写进入姿态、关键路径、完成姿态与编号。若需要比较重复次数，优先选择相同可观察循环；使用不同动作时分别定义完成边界，避免幅度或难度差异被误称速度比。
3. **分开三种时间变量**：分别记录观察/响应延迟δ、快慢单元的执行时长d_fast/d_slow、累计完成数N_fast/N_slow。延后开始不自动意味着执行较慢；瞬时关节速度也不等于完成数比例。
4. **给出窗口和配对事件表**：选定统计起止、是否计入观察前导与容差。对每个窗口按完成时刻计数，在共同边界完成的事件只记入前一窗口一次；核对3∶1或其他目标。不要要求尚无首次完成事件的每一帧都具有非零精确比值。
5. **保持看过再模仿及持续落后**：为慢者每次模仿标出此前实际看见的快者动作；快者完成后直接进入下一单元。慢者按独立较长执行时长完成，不为重新对齐而追赶，不把自然局部加减速全部禁止。
6. **让景别支持计数**：核对环绕期间两主体及完成判据是否可见。若脚步被裁掉，用任务允许的膝髋/手臂事件计数；若用户要求完整足部证明且不允许扩大景别，明确两约束不能同时验收，给可选修订而不暗改镜头。
7. **编写H3模式正文**：有身份参考时使用Ref2VA，定义两Subject可同源Picture，沿用官方六字段与有效引用；图片仅供身份时不强制作为首帧。连续环绕用一个Shot，绕到侧面不自动产生切镜。无实际参考且不需既有人物身份时可改用T2VA。
8. **核对声音与实际证据**：纯器乐明确无对白、演唱、哼唱或旁白；有音乐时不能把整个声场误写成完全静音。计划表通过只证明文字调度一致，生成后仍需逐事件计数、可见性和滞后复核。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **DS-01**：两个角色保持独立稳定身份；一张输入图不等于一个Subject，绕行后不按当前屏幕左右重新分配快慢角色。
- **DS-02**：完成数比例必须附动作单元起止、统计窗口和容差；比例只在定义的窗口验收，不能替代逐事件计数。
- **DS-03**：响应延迟、执行时长、累计落后分别建模；3∶1完成数不等于所有身体部位瞬时速度恒为三倍。
- **DS-04**：慢者仅模仿此前看见的动作，不预知下一动作；快者持续衔接，慢者不突然追赶恢复同步。
- **DS-05**：计数判据必须在当前景别中可见；腰至头顶或膝上构图不能声称验证了被裁掉的完整脚步。
- **DS-06**：近距离环绕可连续通过不同视角，不等于横摇、画面滚转或新增切镜；两人身份与动作相位贯穿镜头。
- **DS-07**：沿用原案纯器乐时排除各种人声，但音乐仍是有效声音；若用户改声音策略，以当前明确任务为准。
- **DS-08**：作者“约三倍”是结果报告；没有真实媒体计数时，不声称本次已达到比例或能保证模型稳定异速。

## 输出与检查

- **主体与事件定义**：快慢Subject映射、动作单元进入/完成姿态、判据可见部位及参考权限。
- **双人配对事件表**：观察前导、δ、两人各事件起止、完成时刻、窗口归属、目标/计划完成数和比例容差。
- **摄影及声音组件或完整提示词**：按任务提供连续环绕组件，或正确模式的英文H3正文；中文时序与待核验项在正文之外。
- **逐项验收记录**：区分计划计数与生成后实测计数，记录遮挡、同步化、追赶和身份串位等失败。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
