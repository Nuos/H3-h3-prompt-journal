# 舞蹈动链检索、时间容量与状态衔接编排

从庞大知识库提取本任务真正需要的动作链，在时间容量、身体与道具状态、音乐、摄影和参考权限之间建立可审查的连接；让正文说明动作如何开始、达到主结果、制动并接入下一链，而非罗列动作名。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **片型与生成模式**：声明continuous_dance、posed_portrait、partner_support、edit_swap或fantasy_vfx；根据官方H3规则确定T2VA/I2VA/Ref2VA等实际模式。Picture1作首帧锚定时继承当前身体中间态；仅作身份世界参考时另选支持该角色的模式，不能在I2VA初帧无过渡改姿势。
- **舞种、人物与资产**：给出舞种／密度、实际人数与SubjectID、服装材料、现有道具、可用支撑面和空间。若图片、视频、音频或需要的扇／袖／墙／伙伴缺失，登记missing；不把K章源演员外观、场景、字幕、道具自动写入新任务。
- **音乐与时间规格**：给实际音轨及已核验起音表，或声明创作计划的BPM／拍号／起拍偏移；自由散板可直接用秒窗而不虚构BPM。记录总片长、标准24FPS、各次生成4–15秒与最终编辑时长，长范本须分段、短片须生成余量后裁窗。
- **候选链与状态**：优先提供稳定ID如A18、A19、C27、K7及来源版本。逐条读取完整条目而非只抄H3一句话，登记标题拍数、分解拍数、入态、出态、支撑／重心、方向、手位、道具、动力、峰值、回收、材料和证据标签。
- **摄影、剪辑与旋转预算**：选camera_response=static_observe/sync_follow/anticipate_hit/delayed_observer，选edit_policy=continuous/phrase_end_cut/phase_match_cut/pose_jump_cut；两轴独立。旋转同时记录episode数、每段周数及方向；明确预算单位，不能把多周连续链误判成多个独立旋转事件或反过来。
- **保留与变化范围**：明确首帧继承、持续律动是否可在指定hold停下、服装／身份是否跨镜保持、是否允许场景硬切、是否需要原声回贴、是否允许概念VFX。只启用与当前片型和资产一致的局部规则。

## 执行流程

1. **锁定版本并按片型检索**：使用Rev.1.4固定快照；先读0章规则和本任务相关章，不将全文灌入提示词。A适合宅舞、B抖舞、C古风、D多人、K跨类型扩展；E为摄影响应、I为物理机位、G为Hero、F为同曲变体、H/J为案例范本。写真微动作不默认加入膝弹或胯八字，剪辑换装也不默认连续舞蹈。
2. **为选中链建立证据与字段卡**：逐条读取入出态、逐拍分解、H3句和来源时间码，分清观察、作者推测、单图重构与工程补齐。标题／分解／英文不一致先标conflict：C19和C25标题7拍但分解8拍；C35五圈／4–5圈／Four不一致；D8中文灯起与英文聚散不同。缺入出态的B早期短句补显式状态，但注明是新设计，不伪称库已完整。
3. **先分配时窗，再选择动作容量**：以目标beat_seconds=60/BPM或实际onset建立绝对时间窗，扣除入态准备、峰值后制动和接续所需时间。0章0.3–0.6／0.6–1.2／1.2–2.5秒表只作初始容量启发；按具体身体／难度裁决。选中链实际拍数优先于全库2–8拍概括，C27确有19拍。超载先删旁支、延长链或跨相邻窗连成完整Hero；不能靠高级／流畅形容词或循环摇晃填空。
4. **缝合连续状态与三层动作**：建立每窗OUT→下窗IN比较：支撑面与脚、重心、朝向、位移、手位、道具握持、动量和衣料状态。不同状态需分配桥接动作，不能瞬移站好。持续层按舞种与当前支撑适用，遇到明确hold、平衡或离地要让位给主链；微表情不能破坏承重。每链写动力从哪里来、如何传到主结果、回收顺序和明确完成时刻。
5. **分配Hero与多人配合**：需要Hero才选G的AIR/TURN/FLIP/LINE/ACCENT技术族，补预载、峰值、落地或退出、吸收、保持与释放；A/B/C/S只保留作者经验评级。旋转episode与总周数双计数，先解决C35等不一致再给终止方向。多人按实际人数固定ID及几何槽位，接触列接触点、承重者、动作者与保持者；D的四人、2×2、末尾solo、无镜像等是局部方案，不能压到D21六人或K双人、五人场景。
6. **选定摄影时序与切镜语法**：所有轨道共享绝对时间，但按响应模式分别允许零延迟、提前到位或有限滞后。sync_follow才要求启动／峰值／回收对应；E1提前跑位与E8迟半拍不同时施加。按I章写实际位置、高度、距离、光轴、几何结果与设备不入镜；每窗一个主要摄影行为或明确静止。连续镜头需可达路径；phrase_end_cut在动作完成处切，phase_match_cut在同向同速同相位切，pose_jump_cut允许新姿势首帧已就位并不谎称物理连续。
7. **隔离参考资产、音频与旧范本**：迁移动链时只保留与动力有关的材料功能，把K/H/J源服装、发色、房间、道具映射到当前参考，未知项留空。音频选择生成重建、原声后期回贴或场内演奏；原案N/A、响度数值和推测节拍不当本次检查结果。H01的15.1秒、H07的28.1秒及J6/J7/J8超15秒需分段或裁定改编，J9的2.7秒作为编辑目标用≥4秒生成加裁窗，不复制为标准单次参数。
8. **编写自包含段落与变更记录**：输出每段必要公共资产规则、完整动作因果、时间、摄影响应、边界IN/OUT与音频方式；仅加载相关链的工程卡和E/I/G片段。保留源ID、固定版本、原拍数与目标重定时。J7实际只有SHOT1–8，默认以已写表形成8镜7硬切并标修正；若用户坚持9镜，要求明确新增镜头方案，不能虚构源第9镜。
9. **按逐窗结果验收返修**：生成前检查容量、完整性、动力因果、唯一主结果、Hero预算、音乐证据、摄影模式、转场入口、重复和生成后可判定性。问题定向修复：摇晃无完成点则减负并固定终态，旋转不停则补轴心／圈数／结束方向，动作多无舞句则删不服务主动力的手势，摄影拖后则检查是否误选滞后模式或时点漏绑。未运行H3只输出计划审校；生成后才填实际完成帧、声画误差和成功情况。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **R1**：先片型分流和版本锁定，再按稳定ID读取所需链；Rev.1.4的A—K及拼舞模板是同一知识库，不是已实现的自动模块，也不需要每次全文注入。
- **R2**：单条真实字段优先于概括；库并非所有链都有完整出入态或2–8拍。标题、分解、H3和结束状态冲突先记录并裁决，补齐内容标工程设计；不静默修成来源事实。
- **R3**：时间窗先于动作数量；每窗必须从支撑与动力进入，达到唯一主要结果，制动并产生可接的出态。容量表是启发估计，不能宣称某时长对所有人／BPM／动作绝对可行或绝对不可行。
- **R4**：连续链满足前OUT=后IN，或显式安排桥接；持续层／动链层／微表情层按支撑与hold兼容，不把不断膝弹、完全锁姿和单脚平衡无条件叠加。
- **R5**：共享时间轴不等于所有摄影零相位差；sync_follow、anticipate_hit、delayed_observer和static_observe单窗择一并写时间。提前画框到位、同时到位、迟半拍不能一起当全库铁律。
- **R6**：剪辑语法单独选：动作完成处切、旋转相位匹配切、姿态跳切各自保留条件；首帧锚定、身份参考、单张姿势推测也分开，不跨模式机械粘贴。
- **R7**：旋转记录episode数与每段周数／方向／轴心／停止点；Hero要完整预载和回收。源≤2次及2–4处Hero是局部经验，计数单位须声明，G实现度和稳定星级不构成官方或本次实测保证。
- **R8**：按目标参考映射身体、服装、道具和场景；K章源档案与H3句中的外观世界不可覆盖当前图像权限。单图时间顺序、遮挡内动作与未入镜回收保持inferred标签，不升级成已观测。
- **R9**：拍数、BPM、onset和声场分清measured／source-reported／planned／inferred／missing。自由散板可按秒设计；响度不证明固定BPM，原声波形需在装配阶段回贴。源片长不等于官方单次生成参数。
- **R10**：多人固定的是当前任务的身份与角色数量，动静、接触及槽位逐人声明；示例四人／2×2／不镜像／solo位置不全局化。每段最终给可判定验收项，未生成不报告完成率或成功视频。

## 输出与检查

- **任务模式与参考合同**：片型、官方生成模式、首帧／身份参考权限、素材missing状态、人数与资产、摄影响应和剪辑语法、旋转计数单位。
- **选中链工程卡**：source_id／version／lines、原拍数与实际分解、目标拍数／秒数、入态／出态、支撑／动力／峰值／制动／道具／材料、证据等级、字段冲突及裁决。
- **逐窗编舞与摄影表**：全局和局部时间、BPM或onset依据、主动作完成点、IN/OUT桥接、持续与微表情层适用范围、摄影物理几何和启动／峰值／恢复／延迟；独立生成段自包含。
- **H3正文与编辑装配清单**：按实际模式编译选中链，清除源外观覆盖，音频方式及生成／剪辑时长分列；必要时记录长片分段、短片裁窗、原声回贴和跨切状态。
- **逐窗审校与生成后验收**：十项检查结论、未通过窗口的修复、来源与工程变更表；实际成片未生成则结果栏pending，不填虚构onset、帧数成功率或模型稳定性。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
