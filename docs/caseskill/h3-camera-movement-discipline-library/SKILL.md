# H3 运镜纪律选择与冲突裁决

把历史 E1–E10 经验与后续修订法则拆成可选择的条件规则，先裁决响应时相和剪辑策略，再据人物空间变化决定相机是否需要移动。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **人物动作时间轴**：提供动作起始、空间/高度变化、强调峰值、收势和段末状态；区分实测时间、用户指定时间和暂定时间。
- **当前机位与目标观看关系**：给出高度、距离、左右前后、光轴目标、可用路径及应保留的身体范围；不清楚的几何留待确认。
- **响应与剪辑意图**：明确偏向稳定观看、提前到位、同动跟随或刻意延迟；另行选择连续单镜、收势切或动作相位匹配切，两个选择轴不可混为一条同步铁律。
- **音频/片段限制**：提供片长及已测节拍表；未见音频时不生成测量结论。人数、低机位、步数与快闪密度按当前任务填写，不继承历史实验的全部数字。

## 执行流程

1. **分离历史经验与当前任务**：先定位 E1–E10 中匹配的情境，记录其适用对象：团舞、长镜头、快切、延迟观察等。再读取修订法则，保留物理路径和主要观看行为，不能把历史经验每一条都提升为当前任务必需。
2. **选择相机响应模式**：camera_response 设为 stable_observe、anticipate_hit、sync_follow 或 delayed_observer。稳定观察允许全段静机；提前到位在收势/准备阶段启动并在大定点前到位；同步跟随与实际空间/高度变化同启；延迟观察记录明确的正延迟与修正，人物始终稳定。
3. **独立选择剪辑策略**：edit_policy 设为 continuous、release_cut 或 phase_match_cut。收势切避免动作中途截断；相位匹配切可以在旋转中切，但跨镜方向、肩部相位、转速与发裙惯性需承接；单镜头不生成隐含硬切。
4. **用重大空间变化决定是否移动**：先让动作在已建立构图内完成，只有高度变化、真实位移、穿空间转向或新身体关系出现时，采用一个主要运镜行为及必要的小幅调整。向镜头踢腿可选 Plant；队形横移可选平行 Truck；静止为合法结果。
5. **展开五字段与时间偏移**：填写 CAMERA POSITION、CAMERA GEOMETRY、CAMERA MOVEMENT、MOVEMENT TRIGGER、END CAMERA POSITION。为移动记录触发、启动、到位、停止和 delta_t；delta_t 可以提前、零或延迟，但必须和所选模式一致并处于同一时间域。静机显式写 MOVEMENT:none、TRIGGER:none permitted。
6. **条件化排除项**：默认排除无原因摇晃、逐拍重构图、未写路径的换侧和重复推拉；若用户明确要求受控失衡或特殊转场，仅启用对应允许项并保留回收。禁止同时出现 delayed_observer 与全段零延迟要求，也禁止收势切与旋转中禁止切的无条件拼接。
7. **审查并交付观看轨**：核对每个移动是否服务具体观看关系、阶段起终点是否连续、到位后是否稳定、人物动作是否完整。输出选用/排除规则及原因，随后给可直接拼入完整 H3 提示词的摄影机块；来源和冲突审计另列，不塞进生成正文。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **CMD01**：每段先建立机位并选一个主要摄影机行为，微小身体重音不自动触发相机改向。
- **CMD02**：共享时间轴不等于零响应延迟；提前到位、同动和延迟观察必须分别选择。
- **CMD03**：相机响应模式与剪辑模式独立；收势切和旋转相位匹配切不能同时作为无条件禁令。
- **CMD04**：每个相机块具备位置、几何、运动、触发、终点五字段；零移动显式写 none。
- **CMD05**：物理变化写真实路径、光轴和到达关系；特殊机位才需要强化位置物件与透视，普通机位不强塞极端描述。
- **CMD06**：延迟观察只影响摄影机，人物保持控制；每次过冲最终修正并重新找到主体。
- **CMD07**：低机位、无俯拍、1.5秒驻留、提前1.5–2秒、固定快闪密度等均保留来源情境，不作为所有镜头硬限制。
- **CMD08**：实测字样只能归为作者原文自述，未有模型参数和可重放证据时不宣称所有规则已证明稳定。

## 输出与检查

- **规则选择表**：当前任务、camera_response、edit_policy、适用历史条目、未选条目及其冲突理由。
- **五字段摄影机块**：位置、几何、路径、人物触发和终点；静机字段完整，单位与身体坐标一致。
- **动作—相机时相表**：同一时间域下的人物起峰收、相机起到停、delta_t、测量/计划状态和可见性检查。
- **可拼接提示词与审计**：将摄影机块和真实动作链合成段落；另外列规则例外、输入缺口、未做推理验证的范围。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
