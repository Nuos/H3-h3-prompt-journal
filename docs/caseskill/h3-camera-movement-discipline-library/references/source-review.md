## 2. 多维简评

**方法论与输入输出。**输入可推导为人物动作、空间变化、节拍及当前机位；输出是五字段运镜块。零运镜也要求显式声明，体现较好的接口意识。实际文件没有完整任务输入表、路由步骤或成套样例验收，仍以规则集合为主。[S1：77–89；S2：191–201]

**动作—音乐—镜头关系。**“一个主要运镜行为、重大空间变化才移动”的主张清晰，但同步定义存在关键冲突：E1 要求收势才起步、构图提前于重拍到位；E8 要求人先动、镜头延迟追随；后续 TIME-CODE SYNC 又要求同启、同峰、同恢复。共同时间轴并不必然要求零相位差，封装时须保留不同模式的响应延迟。[S2：8–19、88–125、145–167]

**剪辑与泛化。**E3 的“从不切在动作半途”来自特定双人舞；E6 又明确允许旋转中同相位切镜。两者可分别服务收势剪辑和动作匹配剪辑，但原文尚未把适用条件编码。低机位、时长、快闪密度等也只能保留为源案例参数，不宜升级为所有 H3 视频的硬要求。[S2：36–48、64–86]

**验证与维护。**“实测”是来源文本的自述；本目录没有模型版本、生成参数、对照结果或可重放验收记录。README 的“十法则”未列 TIME-CODE SYNC，而正文修订块已经加入；README 的十三词表又附加该项，显示摘要与主文存在维护差异。[S1：26–58；S2：135–167]

## 3. skill 化判断与最小落地步骤

**可先做运镜规则检索与冲突审查模块，再发展为运镜块生成子技能。**以下是建议，不是现有实现：

1. 给规则增加适用模式：稳定观察、提前到位、同步跟随、延迟观察、匹配剪辑；记录来源及版本。
2. 以人物动作时间轴为输入，明确相机触发时刻、峰值时刻、延迟量和结束位置；“静止”成为合法结果。
3. 输出五字段块及规则选择理由，检查路径连续性、唯一主要行为、静止段和禁用项。
4. 对同一动作做静机、同步跟随、延迟跟随的对照回归，再判断生成稳定性。

## 4. 主要缺口与优先级

- **P0：裁决同步冲突。**共享时间轴、动作同步和延迟追随须分开定义；不可全部作为绝对要求同时注入。[S2]
- **P0：条件化剪辑纪律。**明确收势切、动作中匹配切、单镜头各自适用条件。[S2：36–41、77]
- **P1：整理版本及回归依据。**统一 README 与正文条目，给“实测”增加可复核记录；“物理化就无法被平均掉”等绝对表述尚不能据文本证明。[S1][S2]
