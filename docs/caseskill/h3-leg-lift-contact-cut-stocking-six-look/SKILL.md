# H3 触地事件驱动的服饰硬切

把时间戳和物理事件同时写入可核对的服饰状态转换表，让旧外观在空中和下降段持续、新外观在接触时切入且有稳定展示时间。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **固定视觉锚与可变属性**：给出人物/场景参考和允许变化的服饰属性清单；身份、鞋、背景、机位等固定字段与袜饰例外必须分开。只声明可见/已提供信息，不重复虚构外貌。
- **状态序列**：提供初态LOOK0及后续有序look表，明确转换次数N与状态总数N+1；缺新look参考时列missing或经任务允许按文字设计。
- **接触动作与参考**：给出永久支撑脚、活动脚、足部接触表面和每轮起抬/触地/保持需求。Video1可选，但无视频时必须以动作表和明确时间代替，不引用不存在的Video1。
- **时间和声音**：提供片长、输出fps、接触/音频事件来源、最小展示保持帧数及允许偏差；音频全量保留与新增音效两种策略明确选择，避免叠加重复触地声。

## 执行流程

1. **限定变化范围并计数**：建立固定属性表与可变服饰表；LOOK0为初态，N次接触产生N次转换和N+1个状态。复现原例时应称六次换袜/七状态，不能把LOOK0–6称为只有六个外观。
2. **建立身体与观察锚**：在pose-in完成后固定远/后支撑脚和主要承重，近/前脚仅小幅抬落不成为主要支撑。固定全身机位、脚下接触面及两脚可辨性；源例姿态不是所有事件触发剪辑的通用身体要求。
3. **逐轮定义事件状态机**：对每一轮写lift_start、descending、contact、cut、hold_end、next_lift。旧look贯穿起抬、空中和下降；首次清晰触地帧切至新look，接触后的保持是展示新状态，不是允许渐变生成新状态。下一次抬脚必须在稳定保持结束后。
4. **配置时间预算与帧映射**：将计划接触时刻按实际fps映射到明确索引约定的帧号，记录量化误差与最小保持帧数。先检查相邻接触之间能否容纳抬落和保持，再调整切换数或总时长，不机械压缩全部间隔。
5. **消除原稿时长和剪辑歧义**：复现5.17秒时补上原4.690秒以后到片尾的LOOK6稳定尾段，并在帧率量化后报告实际总长。把原Shot1–6解释为同一固定机位中的状态区间和指定外观硬切；一次生成不等于画面没有编辑事件。
6. **安排音频而不改变职责**：若原音轨包含接触声且要求1:1保留，不再生成重复鞋声/环境声；若要新接触声或环境声，显式采用混音策略并说明原波形不再是唯一声音。声音、可见接触与外观切换以同一事件ID对应。
7. **输出并做前后两层验收**：提交前检查时间链有序、状态切换单一、足部可见、全时段覆盖；生成后逐个核对实际首接触帧、切换帧、保持帧、支持脚位置及允许变化范围。误差超过预算时定位提前换装、滞后换装或保持不足，不仅追加否定词。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **LCC01**：触地为服饰切换的物理触发；旧look在空中和下降全程保持，切点不等于起抬点。
- **LCC02**：CONTACT→CUT→PLANTED HOLD→STABLE→NEXT LIFT有序；硬切立即成为新look，保持用于确认展示，不写成逐渐溶解。
- **LCC03**：支撑脚保持位置和主要承重，活动脚只做紧凑抬落；换装前后身体/脚位/机位不发生附带跳变。
- **LCC04**：N次转换有N+1个状态；六次变化LOOK0→6实际是七状态。
- **LCC05**：切点毫秒必须结合实际fps成为可核验帧号，不把“同帧”文本要求当成已获得的控制能力。
- **LCC06**：全片时间必须覆盖；复现源5.17秒需补4.690–5.170尾段或明确改短总长。
- **LCC07**：固定相机、同视角外观硬切、单次生成是三个不同概念，必须分别声明。
- **LCC08**：Video1缺失时用明确动作/事件表替代；原视频渐变属于被改写的形式，不能按外观或morph全量继承。
- **LCC09**：原音轨全量保留与新增环境/接触声不能含混并用；声音策略必须明确并避免重复事件声。

## 输出与检查

- **固定属性与状态序列表**：固定身份/环境/鞋/机位，可变服饰字段，LOOK0初态和N个后续状态。
- **接触—切换帧表**：每轮lift_start、contact_time、contact_frame、cut_frame、hold_end、next_lift、旧/新look、音频事件和量化误差。
- **完整H3展示提示词**：视觉锚、支撑关系、固定镜头、逐轮动作与外观状态、尾段和音频策略完整定义。
- **生成后事件验收表**：逐轮实际接触帧/切换帧/稳定保持帧、支持脚偏移、非许可属性变化和失败修订。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
