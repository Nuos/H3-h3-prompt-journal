# H3 音频事件驱动的快照与硬锁

将案例5.30秒固定事件表转为带帧边界、相机状态、构图和绝对取向的编排方法，同时保留源文翻译分歧、帧预算不足与旋转累积歧义。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **视觉参考与范围**：提供图像参考及身份/服装/环境职责，不凭空描写图中外貌。给出允许的景别、是否允许面部近景和所需揭示顺序，服从当前任务的裁切范围。
- **音频事件**：提供实际音频、窗口和已核验onset/主重音/末事件；无测量时标missing或使用用户指定计划点，不沿用源2.050/5.100冒充新曲测量。
- **时间与帧率**：提供总时长、fps、每次burst与lock最少可读帧预算、冲击数和误差范围；未给fps不得报告同帧控制。
- **旋转与执行版本**：定义原图为绝对roll零点，明确顺时针的观察坐标、每段绝对角度及最后是相对旋转还是目标朝向。执行以英文离散两态规则为基线，中文文件按教学改写读取。

## 执行流程

1. **判别并固定编辑机制**：若有源片，检查疑似burst附近原始帧和音频事件，寻找运动—静止台阶；稀疏抽帧可能漏掉短事件。相似生成结果不能唯一证明源片机位机制。无媒体时只按案例文字建立离散编辑方案并说明证据范围。
2. **建立两态时间表**：每个非零时长区间只标HARD_LOCK或BURST。LOCK固定相机位置、构图与取向，允许约定的人物微动；BURST只在指定窗口内完成重构图，到末端相机立即进入稳定状态。眼睛闭合/睁开属于人物事件，可与LOCK并存。
3. **选择构图和当前版本规则**：选择脚部、膝部、上身、面部等所需主视觉，不机械强制源极端推脸。采用英文原稿的短促无拖尾执行策略；中文“每次Snap先加速、Lock前减速”等是不同教学改写，不无条件并入原事件稿。
4. **规划绝对roll而非累加口号**：以同一坐标表记录每段start_roll/end_roll与delta_roll，主体躯干保持独立。源中段相对原图+90、结尾再顺时针+90会得到+180，和最终横置+90不兼容；必须确定保留的创作目标并标明改动，禁止静默回正或扭转人物解决冲突。
5. **分配burst与冲击帧预算**：把所有时间映射为帧区间，确保相邻区间相接且LOCK不被运动占用。将三次冲击逐个分为位移、尺度、旋转及回稳节点；0.08秒在24/30fps不足以自然保证三次可数冲击。预算不足时提出减冲击数、延长窗口或改fps，未获合适方案前标blocked而非宣称可读。
6. **绑定音频并保持动静对比**：只把已有音频事件关联到对应snap、主burst、眼部动作与终段roll；前置等待属于LOCK，不提前偷跑。运动模糊仅属于burst，回到lock后恢复清晰；相机冲击不能表现为脸部形变或人物受击。
7. **组装并逐事件验收**：输出参考职责、两态定义、构图/roll/帧表、完整段落正文和验收表。核验时间覆盖、状态互斥、人物与相机主语、冲击是否可数及静段是否漂移；生成前只检查计划，生成后再检查视频的真实帧和音画关系。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **SLR01**：HARD LOCK和INSTANT BURST互斥；所有相机运动必须完全落在burst窗口，不能拖入静态区。
- **SLR02**：相机硬锁不等于后期freeze-frame；人物可以保留已允许的呼吸、眼动和发丝微动。
- **SLR03**：图像拥有所声明视觉职责，音频拥有事件时间；更换音频后重新建立时间表，不能套源毫秒点。
- **SLR04**：相机绕光轴的roll与身体转向分开，必须记录绝对取向及累计关系。
- **SLR05**：三次冲击要逐个占用可检查帧并回稳；极短区间的可读性要经实际帧率和视频确认。
- **SLR06**：英文执行稿与中文教学改写不等价，不混合即刻启停与另加预备加减速的规则。
- **SLR07**：编辑式快照是分立构图逻辑，不自动等同一条真实摄影机连续扫过身体的路径。
- **SLR08**：8fps以上密采样只是源作者建议，原帧核对和音频标注才是具体事件证据；成片相似不唯一证明源结构。

## 输出与检查

- **两态帧表**：start/end帧、对应时间、HARD_LOCK/BURST、构图、绝对roll、delta_roll、运动类型和人物微动权限。
- **音频事件映射**：事件ID、来源/测量状态、触发的视觉事件、原始时点与量化时点/误差。
- **冲击与旋转决策记录**：冲击数和最少帧预算、绝对朝向轨迹、源文冲突的取舍及blocked项。
- **完整H3快照提示词**：视觉参考、相机两态与时间边界、人物动作、画面清晰恢复和最终锁定，避免夹带教学改写冲突。
- **逐事件验收**：实际运动/静止帧、可数冲击、roll与人物姿态、音画事件差和未生成状态。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
