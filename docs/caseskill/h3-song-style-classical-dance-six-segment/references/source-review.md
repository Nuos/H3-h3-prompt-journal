## 2. 多维简评

**方法与输入输出。** 六段均可独立提交，重复参考职责，明确图2不得提供背景、机位或姿态；全局区间与段内时钟分离，具备复用价值。所谓Hero名称是作者编排标签，并非H3内置参数或统一舞蹈术语。[S1：24—69、115—123行；S4：196—200行]

**动作、镜头与状态。** 以蓄力、发力、落地、恢复串联高光，避免只罗列姿势；相机跟随、短促重构图和锁定为动作服务。交接仍常用“一只脚”“略斜向”等描述，独立生成时没有实际上一段状态的结构化输入，文字要求不能证明首尾帧一致。[S2：166—173、1821—1835、2323—2331行]

**验证与泛化。** 时间总表和段04乱序修正提供文本层面的检查机制；README的连续性与身份稳定属于作者自述。中文翻译和词汇扩展帮助理解及揭示残留问题，不构成额外实验。本例适用于固定节拍、单人、同一视觉世界的舞蹈；水袖、圆裙和特定高光并非通用必选项。[S1：93—109、125—138行；S3][S4]

## 3. Skill 化判断与最小落地步骤

建议以素材职责、音频切片清单、节拍事件、段落能量曲线和交接状态表为输入，生成六段或可变段数提示词。先验证全局／局部时间映射，再分配高光机制；明确支撑脚、运动方向、袖手位置及镜头状态的交接字段，最后检查身份、节拍和边界连续性。以上是拟议封装，现有案例未提供可执行编排器及回归包。
