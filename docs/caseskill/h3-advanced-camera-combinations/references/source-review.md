## 2. 多维简评

**方法论与输入输出。** 五要素结构可直接用于审稿与提示词展开；但输入只有图像、音频占位符，未定义怎样依据动作幅度、场地空间、遮挡物和段长选组合。输出是固定示范段，不是已经参数化的生成器。[S1][S2]

**动作—镜头—音乐关系。** 路径多数具有触发原因，例如手臂扫过镜头后继续侧移揭示；这比只列运镜名更易核对。TIME-CODE SYNC要求共用时间轴，但范例没有实际音频 onset 表，不能把固定秒数视为已对齐任意音乐。组合用多个 `SHOT` 描述连续运动，却未统一声明这些标签是连续阶段还是剪辑镜头，导入其他模板时容易误生硬切。[S2]

**标准性与泛化。** 可作为本项目的写作规约；“H3不能执行度数”的强断言仅为作者经验陈述，文件没有对照实验。单人、上半身优先、只移动一两步均为这套模板的局部边界，不宜扩展为多人、舞台大位移或所有 H3 任务的统一限制。[S1][S2]

**验证可复现性。** 有明确时间和物理参数，便于后续检验；缺少模型版本、组合逐项测试记录及通过标准。文本可读性提高与模型实际服从仍须分开评价。

## 3. Skill 化判断与最小落地步骤

以下为建议，当前案例未实现：接收段长、动作链、关键重拍、可用空间和目标景别，先筛选组合，再将统一规则、图像职责与所选组合组装成一段完整提示词；明确 `continuous_phase` 或 `hard_cut`；检查相机起终点连续、换侧路径完整、触发动作存在、段末钩子可承接。该模块应由总编排流程调用，不单独承担编舞、音乐分析或多段成片管理。

组合选择还需声明适用前提：遮挡揭示必须有可用遮挡物，贴地升起必须预留空间，跟拍必须匹配主体实际位移。前提不满足时应换组合或缩小路径，而非只替换动作名称。输出同时保留“人物触发事件—相机移动区间—到达构图”的对应表，便于检查镜头是否先于动作启动、到位后是否仍漂移。稳定性应分别验证路径方向、主体可见性和时间误差，不能只以整体观感好看作为通过条件。

## 4. 主要缺口与优先级

1. **P0：统一模板语义。** 组合07标题写 FRONT FOLLOW，正文却从人物背后起步；组合10前4.8秒几乎静止且相机先微推进，需要明确其与持续舞蹈、动作触发规则的例外关系。[S2：193—214、270—294行]
2. **P0：落实独立段落契约。** AUTONOMY说单独粘贴即可，但组合正文未重复位于文件前部的输入职责和公共规则；需要组装步骤，不能只截取组合。[S2：5—23行]
3. **P1：更新数量与时间口径。** README仍称14条规则、13词；正文实际15条规则、14个词库条目（含TIME-CODE SYNC）。多数组合结束11.5秒，组合09结束11.2秒；需按音频和目标段长重定时，并澄清“Vertical 4:3”的宽高约定。[S1][S2]
4. **P1：补验证。** 先对高遮挡、换侧、贴地升起等不同路径建立回归样例，再声称稳定；未做这一步前维持S2。
