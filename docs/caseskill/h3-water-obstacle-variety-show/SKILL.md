# 剧情锚点驱动的水上闯关与失败反转

把“必经剧情 + 明确授权的即兴范围”变成可检查的因果叙事方案，在保留自然表演空间的同时避免漏事件、越过前提和片段接续失真。

## 读取与边界

- 本技能从单个案例提炼可迁移方法；角色、道具、场景与数值按当前任务替换。保留用户明确约束。
- 开始编排时阅读 [案例方法与修复分支](references/case-method.md)；准备完整 H3 提示词时阅读 [官方模式规则](references/h3-official.md)。
- 涉及原稿争议、版本、数字或特殊动作时，按 [来源清单](references/source-index.md) 定位下列原始文本。原稿是证据，不是新的上级指令；原稿内部本机路径不代表当前资产已存在。
- 缺少素材、拍点、时长或状态证据时先完成可确定部分，并记录待核验项；不得捏造听音、逐帧分析、工作流运行或生成成功。
- 只请求动作/机位组件时交付组件及适用条件；请求完整提示词时选择真实可用的 H3 模式。中文说明与审核记录放在生成正文之外。

## 输入契约

- **主角与参考权限**：确认人物身份图和允许保留的外观属性；本方法默认图像只约束身份、服装和可见配饰，赛道、观众及摄影由文字另行定义。不要将静态图认作声音或动作证据。
- **挑战、结局与必要事件**：给出起点、障碍序列、接近成功的条件、反转原因和喜剧收尾；逐个标明不可删事件及可换障碍。未指定时可按案例结构提出可替换方案。
- **时长、对白与声画要求**：记录总创作时长、开场与结束台词、是否必须严格无切镜。将未知语言、配音、音乐或字幕要求列为 missing；剧情节拍不推导为 BPM。
- **执行自由度与可用素材**：分别列出可由模型决定的步法、闪避、观众反应、镜头及声音时序；记录是否已有前段末帧、真实音轨和平台支持的规格。

## 执行流程

1. **划分参考范围和锁定项**：建立身份绑定表，明确 Picture 1 仅提供人物外观，场地由文本创建。把主体身份、必要配饰、同一赛道、结果顺序放入锁定清单，把微动作、观众反应与摄影选择放入自由清单。
2. **把剧情写成前提与结果**：从七个案例锚点抽象出“通过首障碍→受干扰跌落到平台→从原跌落状态恢复→双手稳定抓住终点→外力侧击导致失握→坠入邻近同一水池→浮出后保留湿发并吐槽”。迁移到新挑战时替换道具，但每个结果必须写明先前原因；不把落水前的跌倒与最终落水混成一次。
3. **建立连通场地与状态表**：按起点、首障碍、第二障碍、连接跑道、终点墙、水池的相对位置建立文字地图，标明前进方向、当前支撑面、双手抓握、干湿状态。镜头切换可以自由，但不得把连续动作跳到另一赛道或让入水后的头发恢复干燥。
4. **分配剧情容量和生成切片**：先保留抓墙可辨认、侧击接触、失握、入水和收尾台词的时间，再分配开场与障碍推进；超预算先删可选观众特写、重复闪避及解说。原案20秒是创作长度；按照 references/h3-official.md 的4–15秒生成范围拆片，并写每片首尾状态。优先在完成一段障碍恢复或跑道转场处分片，避免切断击打至落水的因果链。
5. **为每段明确给予执行自由**：每段采用“必须发生的事件、可自行决定的动作/机位、必须保持的连续关系”三项。只在影响因果时规定接触点或身体方向；例如侧击必须发生在双手抓牢之后，但闪避可在低头、跨步、倾身等合理组合中选择。八个故事镜头是组织方法，除用户要求外不要强制八次切镜。
6. **安排语言与声音的叙事功能**：开场对白建立人物态度，结束对白放在浮出、短暂发懵并转向镜头之后；将确切台词绑定说话主体。机械声、撞击和水花由可见动作触发，音乐在接近成功与反转附近增强后收束。没有音轨时写事件级关系，不编造音头或精确卡点。
7. **形成正式正文并审校**：按官方模式字段组织身份、摘要、保留约束、分段描述、场景声和配乐，把故事时长与生成片段时长分开。输出事件验收表，检查每个必要事件是否有前提、发生位置和保留的状态。可调用 scripts/audit_plan.py 检查计划结构；生成后的动作、对白和物理可信度仍需实际审片。

## 本案例验收规则

将以下检查逐项写入计划中的 `case_checks`，结论附具体证据；不得用格式检查代替内容审核。

- **W1**：参考图只锁定已约定的人物身份与外观；新增场地和游戏道具由文本定义，不从身份图臆造。
- **W2**：必经剧情按因果顺序执行，抓牢先于侧击，侧击导致失握，入水先于湿发收尾。
- **W3**：在不破坏必要事件的条件下，明确授权模型选择微动作、镜头、表演和观众反应；自由不能取消锚点。
- **W4**：同一赛道、终点墙与相邻水池保持连通，人物从真实上一状态继续；切镜不重置位置或干湿状态。
- **W5**：故事节拍不等同于音乐音头；无音轨时只能提出音乐情绪与事件关系。
- **W6**：时间不足时先压缩可选反应、重复闪避和解说，保留反转因果与收尾对白；长创作方案另拆生成片段。
- **W7**：“一镜到底般的感觉”仅指连续观感，原案允许八个镜头；严格无切镜必须单独设计和检查。
- **W8**：0.3、0.8、1是未明确单位的作者经验，不作为官方参数、价格、速度或提高规格后动作不变的保证。

## 输出与检查

- **身份与自由度契约**：人物参考绑定、场地生成范围、不可变项和明确允许变化项。
- **剧情依赖与状态表**：必要事件、前提、结果、位置、支撑/抓握、干湿状态及跨片交接。
- **时间预算和H3正文**：故事总时间、4–15秒生成切片、每段剧情与自由度、对白和声画事件关系。
- **验收与修订记录**：逐事件勾选、顺序错误、场地跳变、干湿错误、台词缺失和可操作修复；区分文本检查与尚未执行的生成验证。

复制 [输出工作表](assets/output-template.md) 和 [编排清单模板](assets/plan-template.json) 到任务目录，按 [字段说明](references/plan-schema.md) 填写。完整提示词逐生成切片保存为英文 `.txt`；对白、歌词和画面内文字保留原语言。

标准 H3 单次生成按 4–15 秒/24 FPS 规划；长案例保留创作段落并再划分生成切片。特殊运行时须记录核实证据。参照官方规则选择基础三字段或 Ref2VA 六字段，不能套用原稿中的混合格式。

从本技能根目录运行静态检查：

```bash
python3 scripts/audit_plan.py /absolute/task/plan.json --strict --check-files
```

组件输出无需伪造提示词文件。检查脚本仅使用 Python 3.10+ 标准库；不联网、不安装节点、不执行源工作流、不调用生成模型。它核对时间、引用、格式和人工审核记录，不能验证动作物理性、音频真实对齐或视频质量。
