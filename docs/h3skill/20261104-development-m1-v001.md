## 2. 冻结设计的落实

### 2.1 核心职责保持原义

冻结框架将 M1 定义为“作品意图与段落功能”，输出 `WorkBrief`；冻结递归规范提出三个子模块。实现沿用这三个职责，不增加未经说明的第四个业务模块。

M1.1 写 `intent`、`constraints`、`must_keep_events`；M1.2 写 `paragraphs`；M1.3 写 `emotion_energy`、`motifs`。父模块只通过明确接受路径形成 WorkBrief，不与子模块维护两套竞争决定。脚本内部函数是结构/版本处理细节，不伪装成新的导演职责。

### 2.2 四项原则怎样成为实际行为

| 原则 | 本轮设计与行为 | 对应验证 |
|---|---|---|
| 高内聚 | 三个子模块分别围绕意图、段落、情绪母题；脚本不创作剧情、摄影、音乐 | 分区所有权、禁止跨专业写入、实际文字使用 |
| 低耦合 | 最小输入投影，接受外部来源，资源随单目录提供，不要求先跑所有模块 | 四节点独立输入、目录复制运行、外部兼容来源 |
| 模块化 | 每节点有 ID、父节点、版本、输入、输出、边界、资源、审计与返回 | 模块登记与程序实现一致性、子提案组合与顺序接受 |
| 路由信息 | 显式目标、资源、返回点、缺项、冲突、修复与影响范围 | 正向路由、失败返回、陈旧版本、责任方修复与精准失效 |

子模块独立不等于另装三个 Skill。请求可以由用户、既有方案或其他兼容实现提供；数据依赖不自动转为调用依赖。父路由发现后续节点，不表示那些节点的输入已经具备或已经执行。

### 2.3 与开发阶段的关系

本轮完成的是 M1 范围内的 P0 来源/范围登记、P1 合同细化、P2 规则和夹具，以及 M1 独立文字实现与局部试用。冻结路线中 P5 的完整集成仍依赖 P4 等其他模块；P7 的全量案例迁移和 P9 的真实媒体试验没有被提前标记完成。

合同 `1.0.0` 是本包的独立接口版本，不宣称已冻结/实现全部共享 ProjectPlan 对象。未来接入其他模块时按公开语义适配，不通过改写原冻结文档掩盖范围变化。

## 3. 案例事实与规则提炼

### 3.1 范围与读取记录

登记 29 案、15 个 10 月案例；来源清单覆盖 98 个文本文件。案例证据索引所登记的提炼阶段包括 17 个文件全文阅读、6 个文件定位阅读，其余按入口或元数据登记；后续独立试用的实际阅读另存于 `validation/`，不与此阶段的统计混算。没有把哈希清单说成逐字全审。源图片、视频、音频未用于本轮效果证明，动作迁移工作流 JSON 未执行。

十个主要案例覆盖古典武侠舞、海滩剑舞、白凤蒙尘、夏日水线、四人队形、下山、台灯 A/B、双段人物揭示、水上综艺和贴纸喜剧。四个补充案例用于变更边界和事件/反应方法；其余十五案定位到其他专业模块。

### 3.2 提炼结果

12 条 CASE-R 规则将原文方法转为 M1 的任务步骤，分别带适用条件、检查问题、正例、反例和证据界限。38 个证据定位保留固定源文件、行号、短摘录、F 类原文事实和 D 类实现推论。

主要方法包括：先确定作品与每段的观看任务；保留剧情锚点同时声明自由执行范围；组织观众信息和因果顺序；保持可识别母题并允许变奏/回收；允许能量回落、留白与克制结尾；区分歌词/情绪参考与画面实体授权。

### 3.3 保留来源差异

连续舞蹈与独立蒙太奇、禁止交叉与实际交叉、固定场景与允许替景、持续运动与有意停顿等，不合并成一套全局限制。下山案例导语的 141.845 秒与工作流清单末值 181.956 也保留为来源冲突，交时间责任方核对，不取任意值作为新任务默认。

F/D/I/U 沿用冻结含义：F 原文事实，D 架构/开发设计，I 已有实现与已执行检查，U 未验证。I 不改成“推断”；作者的成功报告也不升级为本轮实测。

## 4. H3 官方输入对应

官方基础指南规定 T2VA/I2VA/FL2VA/L2VA 使用 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。关键帧模式另有首帧、首尾帧或尾帧对齐指令。

Ref2VA 官方结构为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。本包保留两份官方文本原字节和固定来源记录；映射表逐项区分字段、引用 Label、镜头/说话者/对白标记。

M1 提供语义目标和约束，不夺取 M2 的素材绑定、M6 的声音事件、M7 的排时、M9 的镜头/任务划分或 M11 的模式与正文序列化。该映射满足本次“对应哪些模式/Label、如何编排与审计”的要求，同时保持冻结架构的低耦合边界。

## 5. 目录与执行机制

`SKILL.md` 只保留触发、路由、步骤、最小合同、工具和输出边界；领域细节在三个业务参考文件，公共审计在 `audit-and-handoff.md`。大案例索引按规则/证据 ID 读取；资源不因位于 references 就全部常驻上下文。

`contracts.json` 提供 Draft 2020-12 结构契约；`module-registry.json` 登记四节点路由和权限；Python 标准库实现结构与跨字段检查，运行不依赖通用 Schema 解释器。四个 CLI 操作是 route、check、accept、impact。输出统一为 M1ToolResult；新简报从 `work_brief` 取出。

八个资产模板分别提供父/子请求、空简报和三子提案。以水上综艺为受控例，七个剧情锚点被整理成三个语义段落，明确不是三个实际镜头。MV 程序夹具只取古典武侠舞的前两个片段，未提供的音频能量保持 unknown。

程序不执行网络、模型推理或外部写入，不原地改输入；实际保存由调用者显式选择新文件。测试、运行记录和规范快照在技能外，复制技能目录即可使用其声明的运行能力。

## 6. 真实验证及修正

### 6.1 官方与补充格式检查

实际执行 Anthropic 原版 quick_validate，返回 `Skill is valid!`。另外检查目录名与 name 相同、非空 description、字符限制、主入口长度、相对引用、包内资源、JSON/Python语法和来源完整性。两者的结论均限定为格式/结构。

官方 quick_validate 依赖 PyYAML，仅用于开发验收；技能运行脚本使用标准库。正式 skills-ref 和通用 JSON Schema 验证器未在本轮执行，不在通过声明中冒列。公开 Schema 的 50 个本地引用均可解析；行为由显式合同测试另行验证。

### 6.2 程序行为测试

本轮实际运行 **52 项行为测试，零失败、零错误、零跳过**；另执行 **9 次正常 CLI 调用**，覆盖四节点 route、两类 accept/check 和一次 impact。实际环境 Python 3.12.14；声明最低 3.10+，没有声称在全部受支持版本上都实测。

验收覆盖最小独立输入、缺项/unknown、跨模块越权、兄弟分区保持、组合与顺序接受、基版本冲突、重复 ID、来源保真、必保事件登记覆盖、信息依赖环、显式冲突、责任方修复、内部/外部消费者的精准失效，以及单目录复制运行。JSON 解析拒绝重复键和非有限数值，错误输出有明确状态与退出码。

### 6.3 定向修正的事实依据

首轮 44 项测试之后，代码复核发现来源与依赖两处实际缺口，并增加相关正反例：

| 发现 | 修正 | 实际回归 |
|---|---|---|
| 消费者只登记 M2—M12，无法表达 M1 子模块真实依赖 | 允许 M1 及 M1.1—M1.3 作为明确登记的消费者；仍不自动调用它们 | 内部子节点依赖失效与未影响项分别验证 |
| `check --request` 未比较请求与产物重用来源 ID 的内容 | 对相同 ID 的 locator/version/excerpt/kind 差异返回冲突；允许合法省略未用来源与新增设计来源 | 来源篡改拒绝、合法新增/省略接受 |
| 已知体裁可能在产物里被切换或降为 unknown | 对请求已有的 work_type 做确定性对照 | 切换与信息丢失被准确诊断 |

这些修改针对可观察的合同缺口，不从案例作者报告推导“生成效果提升”。测试数代表断言执行数量，不是视频成功率。

### 6.4 独立文字使用

两类前向使用任务及实际产物登记在 `validation/`：四人 MV SEG10 的完整 M1 编排（含三个子模块），以及仅使用 M1.2 的贴纸短喜剧段落整理。试用执行者未参与本包编写；根代理提供范围收敛指导并对照原文复核，未执行盲测或无技能对照实验。

贴纸试用的 route/check 均实际退出 0，并保留六条正式事件分区缺失的非阻塞提示。四人 MV 试用保留“不越中心线”与实际交叉编舞的来源冲突，父接受返回 rejected，当前 WorkBrief 保持空 version 0。文字复核还发现“禁止对口型”曾弱化成“不要求对口型”；保存前版本并修正后，重跑受影响检查，来源冲突仍正确阻塞接受。

各试用保存任务输入、产物、实际命令、所读资源和语义复核范围；具体结论见 `validation/validation-results.json` 与 `validation/semantic-review.md`。程序结构通过不替代上述文字审阅，拒绝冲突输入也不意味着案例的物理可行性已经被判定。
