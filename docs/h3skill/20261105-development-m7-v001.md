## 核心摘要

按已锁定的十二模块方案开发第七核心模块 M7「统一时间轴与动作—镜头—声音协同」。本轮实现三个可独立调用的职责：M7.1 时间依据与单位归一、M7.2 事件排时与同步约束、M7.3 时间域映射与帧量化。统一结果为版本化 `TimingMap`，由父 M7 对照原始请求、证据、只读上下文和基版本接受。

本轮解决的核心问题是：一个事件在源音视频、作品、某次生成任务和成片中的时刻并不天然相同；动作发生、相机到位、声音出现与切点可以提前、重合或滞后，但需要各自身份、依据和允许误差。BPM 推算不能替代真实拍点；帧号需要其所属时钟的实际或明确计划帧率。

领域创作依据限定为 `case-studies/` 文本，重点为 10 月案例。时钟合同、数学换算、版本路由和设计夹具是本轮工程实现，单独标记。Anthropic／Agent Skills 用于技能结构，MiniMax 官方原文用于模式、字段和 Label。未把合同、数值检查或作者报告当作 H3 真实生成效果。

## 关键结论

1. 三个子模块分别拥有时间依据、排时和映射分区；父模块唯一提交权威 TimingMap。独立使用不要求先执行 M1—M6。
2. M4 的动作语义、M5 的摄影行为、M6 的声音内容和 M9 的编辑选择保持原责任；M7 不能擅自删动作、改台词、增加运镜或选择变速。
3. 五种 H3 输入模式均有明确交接；基础四模式进入 `integrated_multimodal_description`，Ref2VA 的逐镜时序进入 `detailed_description`，不新增原生字段。
4. BPM、首拍偏移、理论网格、标注拍点和真实观测分别记录；缺帧率、源窗口或零点时保留未知。
5. 数值结果保留时钟、来源、映射方向、帧量化策略、误差和容差。计划正确仍需真实媒体验证。
6. 冻结开发原文、控制文件、原案例和 M1—M6 运行包保持原字节；只新增 M7 实现、测试、记录和发布工具，并更新目录索引。

**关键词：** M7、TimingMap、时间依据、事件排时、源素材时间、生成局部时间、成片时间、帧率、帧量化、H3 Label、独立合同。

## 3. H3 五模式、字段与 Label

| 模式 | 主要正文与辅助字段 | 时间编排 | 审计重点 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description`，两个声音字段 | 从局部零点组织完整声画事件 | 有效片长、事件因果、真实切点与声音持续 |
| I2VA | 同上，加官方首帧指令 | Picture 1 对齐生成局部 0.00 秒 | 首态之后的动作路径；图片不能推导 FPS |
| FL2VA | 同上，加官方首尾帧指令 | 首图到尾图的连续发展与终点 | 尾图对齐有效片长和实际最终 Shot；不机械新增切镜 |
| L2VA | 同上，加官方尾帧指令 | 从合理前态逐步收敛到尾图 | 尾图不天然属于 Shot 1；收敛过程有容量 |
| Ref2VA | 六字段；主要时序位于 `detailed_description` | 显式区分源参考时间与目标局部时间 | Video／Audio 窗口、参考用途、保留范围与每镜事件一致 |

Ref2VA 的 `subject_definitions` 说明参考对象和用途，`summary` 说明编辑／续接／音频复用等任务，`retention_analysis` 说明保留或参考关系。M7 提供可计算的时间条件，M11 负责最终字段编译和 Label 编号。[S03]

| Label／语法 | M7 关心的职责 | 避免的混淆 |
| --- | --- | --- |
| `<Subject N>` | 被事件引用的可见主体 | 不把主体号当时钟或事件号 |
| `<Picture N>` | 指定目标画面／关键帧的对齐时刻 | 静态图不提供时长或 FPS |
| `<Video N>` | 源视频选窗、时序结构或续接起点 | 源时码不直接当生成局部切点 |
| `<Audio N>` | 已启用音频信号与源窗口、目标时间对应 | 有音轨文件不等于已经启用或已测拍点 |
| `[Shot N]`、`At MM:SS.mmm` | 真实切镜与局部递增切点 | 时间块、动作阶段或生成边界不自动增加 Shot |
| `<scenetrans>`、`<cutoff>` | 已有声音语义的跨切延续或片尾截断 | 不通过截断标签掩盖预算冲突 |

第一镜不写切点时间戳。尾帧指令使用有效片长的两位小数，不能与零基末帧采样时间机械互换。两个声音汇总字段不另建权威时间线。TimingMap、容差和审计信息保留在制作记录。[S03]

## 4. 案例方法与证据边界

案例证据文件登记方法、适用条件和具体行范围；逐文件索引同时区分全库清点、关键词命中、局部阅读和全文阅读。本轮机械清点29个案例目录的98份文本，对8个10月案例选取直接相关文本开展语义阅读：4份全文、6份局部，另外88份仅关键词索引；4个案例各有至少一份全文读取，不代表这4个案例的全部文件均已读完。原视频、音频和图片的本轮观察数量为0。[S04]

主要方法来源包括：

- 多段剑舞与独舞的源窗口、分段局部时间、BPM、首拍和乐句说明。
- 摄影纪律中的提前到位策略，与其他案例的同步方案并列为可选择策略。
- 触地切换的接触、切换、保持、稳定和再次抬腿顺序。
- 单镜两段生成中的动作接力，证明生成边界与镜头边界需分别表示。
- 动作迁移中动作机制与音频节奏的分权，以及数字冲突应保留而非泛化为模型上限。

例如动作迁移 README 同时出现 9 秒和 124 帧 @24 FPS 的描述，其通常帧数换算不能直接一致。本轮保留原文本，把它作为来源冲突审计的依据；没有擅自改写案例或将“8—9 秒”升格为官方通用上限。

D 类工程实现包括四时间域的类型化合同、有理数换算、半开区间、明确量化策略、版本／幂等机制与额外设计试用。它们服务于冻结架构，不冒充案例已经实现的工具或实测效果。

## 5. 时间工程设计与审计

### 5.1 时间依据与候选拍点

候选恒速网格使用 T=60/BPM，明确拍序起点和首拍偏移 t0 后才可给出 t(k)=t0+kT。未知 t0 只能支持相对间隔，不能默认补零。真实音频重音、歌词边界和乐句需要各自证据；不能从一个 BPM 推出全部声音事件。

源、生成和编辑 FPS 分别登记。有理数帧率保留原精度；可变帧率缺帧 PTS 时不输出精确帧结论。文字、案例报告和实际观测的证据等级分别保留。

### 5.2 事件排时

动作、摄影、声音和编辑事件有独立 ID。同步关系说明参照锚点、响应锚点、偏移方向和容差。检查“相机到位早于动作峰值”与“相机运动和动作同时开始”是不同检查。

容量冲突应提供原预算、可用区间及责任回传。对白没有录音时只能给带假设的候选预算，不能把字数估计标成实测语速。固定观察仍然允许人物运动；音乐存在也不要求所有镜头逐拍移动。

### 5.3 映射与帧量化

常速换算明确速度定义。若每目标秒推进 v 个源秒，则目标时刻 d=d0+(s−s0)/v。M9 决定 v 和选窗，M7 计算。定格映射非一一对应；不能当作普通零速度除法。未实现或资料不足的换算保留明确诊断。

量化同时保留原时刻、目标帧、取整策略、实际帧时间、带符号误差、绝对误差与容差。接触后才允许的边界需要检查量化方向；只检查秒级计划不够。

这些规则中，脚本可以检查明确的数值关系与合同；动作是否自然、镜头是否看清、音频标注是否真实和生成是否执行仍属另外的审阅或媒体验证范围。

## 6. 高内聚、低耦合、模块化与路由

| 原则 | 本轮落实 |
| --- | --- |
| 高内聚 | 时间依据、排时约束、映射／量化按不同专业目的拆成三职责 |
| 低耦合 | 接收带来源和版本的公开输入；不导入兄弟技能脚本，不依赖私有会话 |
| 模块化 | 父、子入口均有可调用合同、最小输入、明确输出、未知和失败形式 |
| 信息路由 | 登记触发、目标、输入、版本、返回点、修复责任和实际依赖读取路径 |

父级接受时对照真实原请求，防止提案替换输入事实。基版本、稳定身份、来源保真、提案 ID 和幂等重试共同保护权威时间表。子模块需要改其他领域时提出修改请求，由相应责任方处理。[S02]

变更复验根据消费者实际读取字段，不因时间对象的标题改变而使全部下游失效；未登记的依赖无法由程序自动推断。M8—M12 的交接是公开职责说明，不是本轮已执行这些模块的记录。

## 9. 完成边界与后续交接

本轮完成的是 M7 文字工作流、公开合同、已实现确定性时间检查、独立调用、组合接受和发布证据。五种 H3 模式与相关 Label 的编排／审计要求明确落盘。

本版的诊断可能重复列出未知，部分路径指向合并检查的分区视图；合同指南已说明对照原输入定位的方法，尚未实现去重。非线性速度坡度、反放和未给PTS的VFR精确定位不属于当前运行器支持范围。

M1—M6 运行包和历史报告保留原义；M8—M12 继续按冻结方案开发。M7 的交接可以被兼容实现消费，但不会因此把未实现模块标为完成。
