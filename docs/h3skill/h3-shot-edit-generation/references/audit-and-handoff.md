## 与现有 M7／M8 合同的适配边界

M9 的三分区不能直接作为其他模块原生输入整包传入。调用者需要显式适配，保存源对象、版本、字段指针和实际值，并按目标合同校验；本轮单包验证不等于已经完成跨模块执行。

| 目标接口 | 已有严格合同 | M9 交接要求 |
| --- | --- | --- |
| M7 `Mapping.edit_binding` | `ReadonlyRecord` 使用 `owner / source_id / source_version / path / value`，此处 `source_version` 为非空字符串 | 对已接受的选窗或编辑意图建立准确只读绑定；不能直接代入版本为整数的通用 Projection，换算仍由 M7 完成 |
| M8 `EditValues.boundaries` | 按 ID 索引的 `EditBoundary`，必需 `boundary_id / boundary_type / from_shot / to_shot / invariants / match_attributes / approved_changes / cue`，不允许未声明字段 | 适配镜头边界与策略；M9 自己的字段名或任务 ID 不能直接代替。持续项和批准变化需要真实授权／政策依据，缺失时返回待补，不能为过 schema 捏造 |

以上目标形状核对输入基线中 M7 `references/contracts.json` 的 `ReadonlyRecord`／`Mapping` 定义及 M8 `references/contracts.json` 的 `EditBoundary`／`EditValues` 定义。消费方升级后重新核对版本和字段含义，不能把相同键名视为永久兼容保证。

## 失败、修复与失效

缺项回输入责任方；版本过期回调用方更新投影；写入越权回提案作者；专业冲突回字段所有者；真实媒体不满足边界时请 M9 调整选窗／任务，必要时请对应责任方修订或重生成。

每次修订保留原问题、引用、工作与计划版本，并指定影响范围与停止条件。技术重放只重用相同操作身份；专业内容改变使用新请求／提案及当前基版本。不要用默认策略、自动截断时间或改写原请求制造通过。

`impact` 只覆盖已经登记的读取路径，不能证明不存在隐藏语义依赖。变更源版本、选窗、边界或能力后，应显式登记相关 M7 映射、M8 接缝、M11 编译与 M12 观察的复验需求。

## H3 交付检查

1. 基础四模式仍为三字段，Ref2VA 仍为六字段；最终正文由 M11 编译。
2. `[Shot N]` 按本目标中的真实切镜组织，首镜无切点时码，后续局部切点单调且位于有效时长内。
3. Picture 的画格映射、Video 的结构／编辑／续接角色、Audio 的复制／参考策略和 Subject 的内容绑定一致。
4. 独立任务正文具备所需初态、过程和结束条件；没有隐藏的“同上一段”依赖。
5. 创作规范、内部审计、路由信息和后期未执行指令保留在制作记录中，不混入生成正文。
6. 未运行 H3 或未观察媒体时，明确交付为计划与编排／审计交接；不要把本地测试称为 G3／G4 通过。
