# M9.1 镜头、分镜格与事件归属

## 职责与最小输入

读取本段目的、必须保留的事件、动作阶段和已有摄影方案，输出镜头与分镜格归属。来源可以是用户明确提供的资料、兼容外部计划或公开上游合同；不要为了获得一个镜头表强制执行全部上游。

M4 决定发生什么，M5 决定如何观察，M9.1 决定这些事件与观察段属于哪个镜头。改变动作机制或机位需返回相应责任方。时间锚点引用 M7，未提供时保持未定，不能凭文字长度制造精确时码。

## 五种单位分别登记

| 单位 | 含义 | 需要保存 | 不可直接推出 |
| --- | --- | --- | --- |
| 动作阶段 | 一个事件中的起动、进行、接触、恢复等阶段 | 原事件 ID、阶段 ID、来源及归属 | 每个阶段都是一次切镜 |
| 分镜格 | 某个时点或状态的视觉计划 | 画格 ID、关联镜头／阶段、用途与锚点 | 画格数量就是镜头或生成次数 |
| 镜头 | 计划中从一个真实切点到下一个切点的连续观察 | 稳定镜头 ID、内容、观看目的 | 固定机位就没有视觉剪辑 |
| 生成任务 | 一次独立模型请求所需的完整输入 | 任务 ID、所覆盖内容、能力依据 | 一次生成只能一个镜头 |
| 编辑实例 | 在装配中采用某份源素材的某个区间的一次使用 | 实例 ID、源 ID／版本、源窗、顺序 | 源片长度等于成片使用时长 |

同一源片可被多次选用，编辑实例 ID 应不同。一个镜头可跨候选生成任务，任务也可覆盖多个镜头；正式编译时按每个目标任务重新建立局部 Shot 序列，同时保留稳定镜头 ID 的对照。重复出现同一姿态值不自动等于重复播放同一编辑实例。

## 实施步骤

1. 列出必须表达的事件与信息，保留原始顺序、因果与禁改项。
2. 从正文中的实际观看变化识别镜头：明确 cuts／switches／切至属于候选切点；连续横移转为后退跟拍、摄影机抬起或缩近仍可能在同一镜内。
3. 对原文 `[Shot]`、SEG、章节和时间块建立历史标记对照。若原文说 Shot 是动作章节，同时另写插入特写与切回，分别登记动作章节及真实镜头，不按标签数量统计。
4. 将阶段与画格映射到镜头；多个阶段或画格允许属于同一镜头。遗漏、重复或重放必保事件需给出明确依据，不用“节奏优化”静默删改。
5. 每个画格说明用于构图计划、动作关键态、真实首帧、真实尾帧还是其他参考；最后由 M2 核对权限，M11 选择模式。普通画格不自动升级为模型端点约束。
6. 核对一个镜头是否在叙事上提供新信息。切镜理由与摄影方式分开；将需改观察位置的问题回给 M5。

## 两种常见误判

**误判一：六个动作章节等于六个镜头。** 某些案例把 Shot 当动作章节；段内仍出现插片、硬切和切回。记录真实编辑事件及两侧观察段后，镜头数可能与章节数不同。只有在一个线性序列、无额外分支且每条边都是实际切镜时，N 次切镜对应 N+1 个连续观察段；不要把这个条件公式推广到所有事件表。

**误判二：固定机位加一次生成等于无切镜。** 触地切换案例的概要与逐项 hard cut 指令存在这种冲突。保留固定摄影机这一 M5 条件，同时将服装切换的编辑事件交 M9.2；不能通过改变计数名称让矛盾消失。

## 输出与审计

输出 `ShotMap` 及对应的缺项、歧义和修订请求，至少能回答：每个镜头承载哪些事件／阶段，画格支撑什么，哪里有真实切点，原标签如何映射，哪些只是候选设计。机器只核验已声明的 ID、覆盖和引用；动作语义、镜头价值与文本矛盾需要 Agent 审阅。

领域依据及准确行段见本包 `case-evidence.md` 的白凤、夏日水线、触地切换证据。五单位合同及 ID 形式属于冻结方案的实现细化，不声称是案例作者已实现的软件接口。
