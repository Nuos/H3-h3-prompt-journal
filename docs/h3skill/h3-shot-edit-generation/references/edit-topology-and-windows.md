## 1. 分别描述边界位置与接续策略

先确定边界发生在本次生成视频内部、后期装配处，还是一个镜头中的动作／任务分界而无可见切镜。再决定连接两侧必须保持什么。环节与连续性是两个维度：模型内硬切可以采用动作匹配，后期硬切也可以采用独立蒙太奇。

| 策略 | 本次编辑决定 | 需要的条件 | 不应附加的条件 |
| --- | --- | --- | --- |
| 连续镜头或同镜续接 | 连续观察，必要时由多个源片候选拼接 | 内容、相位、空间和摄影关系足以支持同镜意图；实际拼接需媒体核验 | 不因生成分段让人物站直或音乐归零 |
| 动作完成后切 | 在一个可识别的动作结果后切换观察 | 完成依据、后继事件、切镜理由 | 不宣称这是所有动作唯一允许的切法 |
| 动作中相位匹配 | 在动作进行中换观察点 | 被选中的方向、相位、动量、支撑／接触与关键构图关系 | 不要求任意两帧逐像素相同 |
| 遮挡与揭示 | 用明确遮挡物及其运动组织转换 | 遮挡区间、方向、揭示内容，必要的变化许可 | 不用“遮挡”授权任意主体替换 |
| 稳定姿态跳切 | 在指定姿态或构图处切换状态 | 需要匹配的姿态／构图、允许变化的服装或背景 | 不把获准服装变化误判成必然失败 |
| 独立蒙太奇 | 用主题、节奏、视觉或段落关系连接 | 联系依据、保留项、批准变化及声音延续策略 | 不强求每段首尾姿态完全一致 |
| 时空转换／省略 | 明确改变故事时间或地点 | 变化理由、观众线索及必要因果不变项 | 不把未知期间发生的事自动写成已观察事实 |

上述是专业描述，脚本只接受机读合同列出的策略枚举；额外类型须先做兼容映射或返回明确未支持。时空省略与部分边界类型来自冻结方案，不能声称本轮案例已经完整证明它们的影视效果。

M9 声明编辑类型、所需匹配关系和变化请求；M8 决定持续项与变化许可。没有许可时保留阻断或未决，不能为了让计划通过而自行把连续接续改为蒙太奇。

## 2. 建立装配关系与源窗

为每个编辑实例列明源素材的稳定 ID、版本、使用区间及其来源、包含的内容、装配位置和邻接边界。先在声明的源坐标中选择区间，再由 M7 映射到目标时间。源视频、生成候选、已经批准的源片各自记录状态；未生成素材可以有计划窗口，但不能被写成实际可用素材。

选窗应说明：

- **使用哪一版源片。** 同名视频重生成后是新版本，旧选窗不能自动继承通过。
- **区间使用什么单位。** 秒、源帧或事件锚点必须带坐标域；帧号不能与毫秒混用。
- **区间两端如何解释。** 机器合同中的区间为左闭右开；真实解码帧如何落点由 M7 的时基与量化合同决定。
- **为何选这段。** 必保事件、动作相位、构图、接触及声音约束分别列明；“挑最好看的一段”不足以成为可复核条件。
- **选窗是否已核实。** 候选值只是计划；实际选择需要 M12 的媒体 ID／版本、观察范围与定位依据。
- **超出范围或缺少时基时怎么办。** 不自动 clamp、不猜帧率、不用最后一帧补齐成片；返回 M7 或素材／任务责任方。

同一源片可以重复使用不同窗口，也可以有意重复播放；每一次使用单独登记编辑实例并给出理由。装配顺序中的相邻实例必须有相应边界解释；不能把一个悬空边当作完整装配。

一次生成可以比最终使用段长，前后余量用于实际选相位。白凤案例给出了这种计划，但其特定秒数及余量属于该案例，不能写成全模块固定补时规则。

## 3. 将时间换算交给 M7

| M9 的决定 | M7 的结果 | M9 后续读取 |
| --- | --- | --- |
| 选用源片某个区间 | 源坐标到作品／生成／成片坐标的映射 | 带版本的有效映射和排时 |
| 在某事件或相位切入／切出 | 事件锚点、时间与帧落点 | 可引用的切点，不重新手算一套权威时码 |
| 采用加速、减速或定格 | 变速映射、定格区间、目标时长与同步影响 | 映射是否支持当前装配与声音条件 |
| 重叠、转场或选窗改变 | 重排后的区间与同步关系 | 相关边界和后继任务的复验范围 |

变速／定格需要任务授权和设计依据；不要为了适配后端而暗中压缩动作、删台词或改变歌曲。数值映射不可用时可交付候选结构，不能宣称任务已符合真实后端容量。

区分歌曲源时间、作品时间、生成局部时间和最终成片时间。段落起点偏移、裁剪、变速或定格都可能让这些时间不同。源时间“33.916 秒”不是独立目标任务的局部“33.916 秒”。

时间交接显式列出给 **M7** 的请求：源选择和坐标域、期望装配位置、编辑意图、尚缺的时基／帧率与需要返回的映射。可为沟通展示未经确认的候选关系，但应标为设计草案、等待 M7 接受；不得把 M9 自行写出的公式当作权威映射结果。

区分演员保持姿态、后期冻结画格与较长生成后裁切。演员的 hold 可以伴随呼吸、目光和衣料残余运动，属于 M4；不能见到 hold 就自动创建 freeze-frame。

## 4. 核对正文、概要与交接表

先读取前段末镜、后段开场和对应交接说明。记录相互一致与矛盾之处；概要、标题和交接表都不天然高于实际正文。

案例中存在以下需要显式处理的情况：

- 标题称单镜，但正文另写硬切；需要分清固定机位、单次运行和真实编辑事件。
- 同一库同时有动作完成切和旋转中匹配切；需要为当前任务选择有条件的策略。
- 交接表要求承接某特写，但前段正文未明确到达它；需要补充或修订计划，不能假设镜头已经出现。
- 概要称连续衔接，而正文在新镜重新从画外入场；需要保留矛盾，不能自动登记为动作相位匹配。

脚本对 ID、区间、装配关系的检查不能发现所有自然语言矛盾；使用者应记录所读段落及结论。未观测视频时，结论限于文本计划。

## 5. 修订和交付

源窗、边界、装配顺序或编辑意图变化后形成新版本，按实际依赖请 M7 重映射、M8 重检、M6 核对声音、M11 重编译受影响任务，M12 保存并复验实际源片或成片。没有依赖的镜头不自动重做；依赖未登记也不能被解释为安全。

交付 `EditGraph`、逐边界理由、候选／已观察源窗标识、变化请求与具体未知项。后期溶解、遮挡桥或硬切的执行位置必须明确，不把装配指令夹进每个生成任务的画面正文。
