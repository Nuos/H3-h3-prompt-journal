# H3 分镜组织、转场、剪辑与生成分段

先明确**观众看见哪些镜头、镜头如何连接、每次模型运行承载什么内容、成片采用源片的哪一段**。分别登记五种单位，保留它们之间的多对多关系，不从时间块、姿态变化或生成次数直接推断镜头数。

实现 M9 及三个可独立调用的子模块。接受用户或外部工具提供的兼容输入，无需先运行 M1—M8。子模块只提交自己的分区；父 M9 对照实际原请求、来源和有效基版本接受，形成版本化 `ShotEditGenerationPlan`。

## 2. 取得本职责的最小输入

确认任务范围、工作及计划版本、段落目的、必须保留的事件、动作阶段、已有摄影意图、时间依据、连续性许可和后端能力。只带入所需的只读投影，保留其来源、版本和未知项。已有兼容资料可以替代重新调用上游；独立使用不等于无输入依赖。

分别标记用户要求、案例原文、作者报告、设计候选、已批准计划和实际媒体观察。原文中的秒数、镜数、参考角色及独立段落只在原案条件下成立。没有实际媒体时，将选窗记为计划或候选，不宣称已找到可用帧或已实现无缝接续。

## 3. 完成三个专业职责

1. **M9.1 整理镜头归属。** 先区分动作阶段、分镜格、镜头、生成任务和编辑实例的稳定 ID；本子模块只提交镜头／分镜格／事件归属，任务和编辑实例由另外两个子模块负责。识别连续观察及真实切点，再将 M4 的事件／阶段和分镜格映射到镜头，不重新设计动作。一个镜头可以包含多个阶段或画格，同一动作阶段也可跨切镜；生成与镜头不预设一对一。保留历史标签与规范镜头之间的显式对照。
2. **M9.2 决定编辑结构。** 分别声明边界在哪个环节发生，以及边界采用什么连续性策略。逐条写清出镜／入镜内容、切镜理由、保留与获准变化的关系、选窗来源和装配顺序。动作完成后切、动作中相位匹配、遮挡揭示、姿态跳切和独立蒙太奇按各自条件审阅，不能合并成一条全局“禁止动作中切镜”。变速和定格只提出编辑意图，时间映射交 M7。
3. **M9.3 分配生成任务。** 用带版本的实际能力资料确定候选任务，列出本任务的镜头及阶段、必要主体和参考权限、初终态、声音策略、边界条件和待编译内容。把生成范围、候选可用窗口和成片区间分开；能力未知时标为待核实。为每个独立请求补齐必要上下文，不能只写“接上一段”。
4. **父 M9 接受。** 对照原请求、只读资料、基版本、子模块所有权和组合关系，接受或返回提案。需要改动作、摄影、声音、时间或连续性许可时发出责任明确的修订请求。保留旧版本及失败原因，不靠改写其他模块字段消除冲突。

后期桥接只进入装配计划；只有明确决定由本次模型生成的可见转换才进入该生成任务正文。一个后期匹配剪辑建议，不自动要求前后两段各生成一次闪白或溶解。

## 4. 处理时间、状态和实际媒体

M9 选择源窗、切点所依附的事件、装配顺序及变速／定格意图；M7 负责源时间、作品时间、生成局部时间、成片时间和帧率之间的换算与排时。记录源 ID、版本、单位与坐标域；不把歌曲全局时码复制成每个生成任务的局部时码。

向 M8 提供边界类型、需要匹配的属性和变化请求；从 M8 读取持续项、获准变化及交接条件。镜头结构不能授权修改人物身份、持物手、道具数量或声音来源。重新使用参考图不自动重置初态。

取得源媒体后，由 M12 或兼容外部观察者记录媒体版本、观察范围、实际可用区间与接缝证据。用观察修订选窗或请求重生成，并请 M7 重映射、M8 重检相关接缝。计划中“取最稳的一帧”不等于已选出那一帧；没有合适相位时保留失败，不伪造无缝通过。

## 5. 向 H3 五模式与 Label 交接

| 模式 | 主要落点 | M9 提供与核对 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 实际镜头顺序、镜内事件、需要生成的真实切镜 |
| I2VA | 基础主正文＋首帧指令 | 首帧属于本任务第一镜；从首帧向后发展，不把普通分镜格自动当强制首帧 |
| FL2VA | 基础主正文＋首尾帧指令 | 首尾锚点与实际末镜一致；通常单镜，仅明确指定时多镜 |
| L2VA | 基础主正文＋尾帧指令 | 尾图属于本任务实际末镜，到达尾态的过程明确 |
| Ref2VA | `detailed_description` 及定义、摘要、保留分析 | 逐镜全画面动态、参考作用位置、视频结构与关键帧的具体关系 |

Ref2VA 的 `<Subject N>` 表示可重用的可见内容；`<Picture N>` 可承担具体帧或分镜规划锚点；`<Video N>` 表示编辑源、续接源或整段时间结构；`<Audio N>` 表示复制或参考的声音信号。图片只提供身份外观时，在 Subject 定义内注明来源，不机械建立独立 Picture 条目。Label 编号和序列化交 M11，内部 ID 不直接充当 Label。

先确定参考角色，再判断该角色内的保留程度；“仅身份”或“仅节奏”不自动等于 `weak_reference`。角色保留程度不明时标待定并交 M2／M11 核对。

每个目标视频从 `[Shot 1]` 开始；第一镜没有切点时间戳，后续真实切点使用 `[Shot N] At MM:SS.mmm, ...`。由 M7 提供有效局部时间，M11 完成表达；一个动作阶段、运镜速度变化或生成任务边界本身不构成新 Shot。

跨切对白、歌词和声音保持 M6 的语义与 M7 的时间关系；需要时交 M11 使用 `<scenetrans>` 或 `<cutoff>`。两类全片声音字段分别为 `overall_soundscape` 和 `non_diegetic_music`。基础模式三字段与 Ref2VA 六字段分别保留；不把 `ShotEditGenerationPlan`、编辑清单、检查规则和修订说明写成 H3 新字段。

## 6. 核验并交付

先读取合同，再从本包目录运行 Python 3.10+ 标准库命令：

```bash
python scripts/m9_contract.py --help
python scripts/m9_contract.py route assets/request-standalone-m9-1.json
python scripts/m9_contract.py check assets/proposal-standalone-m9-2.json --request assets/request-standalone-m9-2.json
python scripts/m9_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

交付镜头／分镜格／阶段对照、编辑及源窗计划、生成任务清单、各任务 H3 语义交接、未决项和责任回传。标明哪些只完成合同检查，哪些经过 Agent 文字审阅，哪些取得真实媒体证据。

`route` 输出路由信息；`check` 核验已实现的确定性关系；`accept` 输出新计划草稿；`impact` 按登记读取依赖确定复验范围。脚本通过不代表完整 G1／G2 通过，更不代替 G3 源片与 G4 成片验收。
