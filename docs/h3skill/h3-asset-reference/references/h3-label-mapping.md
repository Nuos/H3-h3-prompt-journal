本文解释 M2 如何提供可追溯的素材、实体、用途与权限条件。M2 维护 `AssetRegistry`、`EntityRegistry`、`ReferenceMap`；M2.1、M2.2、M2.3 提交 `M2Proposal`，由 M2 汇总。它们均不直接生成最终 H3 请求。

区分三层：① M2 内部稳定 ID、观察与权限；② 官方提示词字段、资源 Label 和正文记号；③ 实际后端的模式、条件文件与数量限制。案例工作流中的“先解析素材”“开启原声”等控件只能转成有出处的条件，不据此创造官方字段。

M2 的资产 ID、实体 ID 和引用 ID **不是** `<Subject N>`；也不能用 `[S]`、`[V]`、`[A]`、`[R]` 充当正式资源标签。所固定的官方提示词资料使用以下四类：`<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`。`[Shot N]` 和 `(S1)` 属于其他记号，见下文。[R24–37；B84–92、127–142]

## 五种输入模式

| 模式 | 官方字段与条件 | M2 提供的编排依据 | 必须审计的边界 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；无参考图片 | 记录纯文本任务及素材是否实际参与；可将经确认的观察交给上游内容模块 | 不能因案例存在图片就擅自宣称上传图片；不加图片对齐首行 |
| I2VA | 同上三字段；一张首帧图 | 确认文件、首帧角色及可见内容；保留后续动作需要继承的起始状态 | 身份参考图不自动成为首帧；真正的首帧要求画面从该图向后发展 |
| FL2VA | 同上三字段；首帧与尾帧图 | 确认两个端点及其素材绑定；把端点差异交给动作、时间和镜头模块 | 不交换首尾，不补造缺失端点；连续桥接默认单镜头，明确要求多镜头时另行编排 |
| L2VA | 同上三字段；一张尾帧图 | 确认结尾状态与文件；把如何抵达终点交给下游 | 不能把尾帧解释为开场；终点时刻和末镜编号未定时保持待定 |
| Ref2VA | 下节六字段；按用途组织多模态参考 | 资产来源、实体绑定、参考角色、属性权限、作用范围及音视频关系 | `integrated_multimodal_description` 不在本版 Ref2VA 六字段中；应使用 `detailed_description` |

基础四模式的三字段和端点规则见 B5–34、36–70；Ref2VA 六字段见 R13–22。M2 给出模式相关条件与冲突；最终模式、后端支持范围及序列化归 M11。不要从“存在多种素材”直接推出 Ref2VA，也不要把三字段模板套到 Ref2VA。

官方 README 的执行条件还限制：FL 检查点可接收 0／1／2 张图片，分别对应文本、首帧或尾帧、首尾帧；Ref 条件最多 9 张图片、3 段视频、3 段音频，合计最多 12 个文件。视频与音频分别要求单段 2–15 秒、各自总时长不超过 15 秒。[G80–85]

M2 只登记实际可核实的数量、时长与缺项；M11 按目标后端检查完整条件。视频内音轨的语义关联不自动等于另上传一个文件。官方执行示例允许 HTTP(S) 或 `file://` 条件 URI，不应自行增加“只能 HTTPS”的规则。[G270–280]

## Ref2VA 六字段

| 官方字段 | M2 贡献 | 编排与审计要求 | 协作边界 |
| --- | --- | --- | --- |
| `subject_definitions` | 实体身份、特征、角色、素材来源与绑定 | 逐项定义实际需要的参考单元；区分主体、关键帧、结构视频与声音来源；定义和后文指代一致 | M2 提供语义；M11 分配正式 Label 并输出定义 |
| `summary` | 哪些参考确实参与、以何种方式参与 | 根据任务关系选择类别；文件存在不等于已采用；编辑、续接、关键帧、声音复用不可混同 | M1 给任务意图，M9 给编辑或续接关系，M11 写正式摘要 |
| `retention_analysis` | 可用／禁用／未知属性、范围及保留意图 | 保留判定限定在已声明角色内；权限不等于实际保留结果；音频必须知道最终混音关系 | M2 给约束，M6 给声音方案，M11 归入官方枚举 |
| `detailed_description` | 首次出现实体的身份依据、位置相关观察、关键帧与音源关联 | 先定义后引用；来源和目标作用范围可追溯；没有证据时不补写观察 | M3–M9 组织空间、动作、摄影、声音、时间、连续性及镜头；M11 汇编 |
| `overall_soundscape` | 环境声／实体声音源及引用范围 | 区分现场声音与配乐；不重复收录对白；未启用原声不得默认复用视频声音 | M6 负责声音层次、事件和混音；M11 序列化 |
| `non_diegetic_music` | 面向观众的配乐来源、参考方式及范围 | 区分复制音频与只借音乐风格；有来源时准确关联；不收录角色对白 | M6 负责配乐设计和混音；M11 序列化 |

`summary` 的官方任务类别为 `reference generation`、`video editing`、`video continuation`、`keyframe completion`、`audio reuse`、`audio reference`；使用方括号类别前缀，多个类别去重并以 ` + ` 连接。分类依据任务关系，不是扩展名。[R125–152]

静态图的修改不自动构成 `video editing`；编辑已有视频时摘要明确其为对应 `<Video N>` 的编辑版本。`audio reuse` 指复用实际信号，`audio reference` 指以音色、节奏、风格、表达等作为生成参考。完整复制与部分复制仍需在保留分析中细分。

## 四类参考 Label

| 正式 Label | 官方语义与合理使用 | M2 的要求与常见误判 |
| --- | --- | --- |
| `<Subject N>` | 需要保持、修改或转移属性的内容单元；可指人、动物、物体、场景／环境、服装、道具、界面／效果及风格、动作、表情、姿态等参考单元 | 主体不限人物；按角色、身份和来源明确绑定；一个文件可含多个实体，一个实体也可有多个来源，不把文件序号直接当主体序号 |
| `<Picture N>` | 实际作为首帧、关键帧、尾帧、被编辑画面、构图锚点或分镜的图片 | 只有身份、服装、背景或风格参考作用的图片，应在主体定义中说明来源，不因它是图片就另立独立 Picture；资产登记仍保留原文件 |
| `<Video N>` | 被编辑或续接的源视频，或提供运镜、切镜、节奏、时序等结构的参考视频 | 可见实体另归主体；区分“借节奏”和“编辑原视频”；登记时间范围，不把视频来源等同身份锁定 |
| `<Audio N>` | 单独音频，或已启用的同步视频音轨；可复用全部／部分信号，或仅参考音色、节奏、配乐风格、表达、对白、歌词及音效 | 音轨存在不代表获准启用；登记来源、启用状态、使用方式、范围以及是否复制信号；不可默认继承台词 |

上述 Label 是提示词资源语义；是否及如何携带媒体文件仍须由最终请求明确。来源、内容单元和正式标签不是一一对应关系。[R37–121]

视频和音频独立编号。例如 `<Video 1>` 的同步音轨可以是 `<Audio 2>`；必须明确二者关系，不按相同数字猜测。M2 先登记来源绑定，M11 再分配并核对这些序号。[R90–121]

`(S1)`、`(S2)` 是按目标视频中实际发声事件顺序分配的说话／演唱者 ID；它们与 `<Subject N>`、`<Audio N>`、`<Video N>` 的序号互相独立。`<Subject 2>` 可以对应 `(S1)`，一个音频文件也不必只有一个说话者。[B127–142；R260–278]

`[Shot N]` 标记镜头；`<d>...</d>` 承载实际对白／歌词；`[unclear]` 表示无法辨清的内容。这些记号不替代素材 ID。未作为独立声源实体辨识的背景音乐人声，不应仅因有人声就额外创建说话者 ID。[B86–92；R217–221、260–278]

## 关键帧与自然语言形式

### 基础四模式的固定对齐首行

以下是官方格式模板，由 M11 结合 M7、M9 确定的时刻和镜头编号填入。M2 只确认文件及端点角色；后续正文与对齐首行之间留一个空行。[B14–34]

**T2VA**：没有图片对齐首行。

**I2VA**：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

**FL2VA**：

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

**L2VA**：

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

`N` 为实际末镜编号；`S.SS` 为目标结尾秒数，保留两位小数。FL2VA 模板的 `Picture`、`Shot` 没有尖括号和方括号，属于官方格式差异，不应为追求统一而修改。L2VA 不能总填 `Shot 1`，也不能用素材文件时长替代目标结束时刻。

### Ref2VA 的自然语言画面绑定

Ref2VA 在 `detailed_description` 中使用自然语言绑定画面，例如 `the shot begins from <Picture 1>`、`the shot's keyframe corresponds to <Picture 2>`、`the shot ends on <Picture 3>`。不得机械搬入基础模式的固定首行。[R225–309]

主体首次出场需要可识别特征、画面位置／景别与当前动作；这些信息分别取自已确认的实体依据和下游编排。身份参考本身不锁定起始姿态、背景、构图、镜头位置或首帧，除非任务另有明确要求。

Ref2VA 的整体风格概述在 `[Shot 1]` 之前；基础四模式放在 `[Shot 1]` 之后。第一镜不写切镜时间戳，后续镜头以时间戳标示切入且保持递增。M7 提供时间，M9 提供镜头结构，M11 检查最终格式。[B78–92；R217–232]

本版官方后端规格的单次输出为 4–15 秒，由 M11 按版本核验；这不是全片时长或 M2 合同的通用上限。[G73；S37] 最终提示词主体使用英语，对白、歌词和可见文字保留原语言。M2 的中文登记、提案和审计记录不受正文语言要求替代。[S33；R5、217]

## 保留关系与声音边界

### 视觉保留

| 官方枚举 | 含义 | M2 需给出的判定条件 |
| --- | --- | --- |
| `fully_preserved` | 在声明角色内，相关属性全部保留 | 明确角色及属性范围；身份参考换背景或新增动作，不必因此降为部分保留 |
| `partially_preserved` | 声明角色内部分属性保持、部分改变 | 列出允许改变与必须保持的属性，注明对应来源和目标范围 |
| `attribute_transfer` | 将某项属性转移给另一个可识别目标 | 明确来源属性、目标实体及转移范围，不能只写“参考一下” |
| `weak_reference` | 仅借用宽泛类别、风格等概括特征 | 明确不承担具体身份／结构保持约束；避免反向写入硬锁定 |

适用于 `<Subject N>`、`<Picture N>`、`<Video N>`。M2 的“可用／禁用／未知”是授权与约束状态，不能直接当作上述枚举。保留分析使用参考 Label，不使用 `(S1)` 等说话者 ID。[R155–207]

### 音频保留

| 官方枚举 | 判定条件 | 需要阻止的错误 |
| --- | --- | --- |
| `fully_copy` | 完整原始音频构成整个最终目标声轨 | 不能把“整段背景音乐保留”自动等同整个最终声轨完全复制 |
| `partially_copy` | 复制部分片段／声层，或在复制基础上增加、移除、替换声音 | 完整复制音乐后新增对白或音效，也归此类 |
| `reference` | 不复制原始信号，借用音色、韵律、风格、表达等特征 | 不把音色参考改写成原台词、原配乐或全片音轨继承 |
| `weak_reference` | 仅借用宽泛氛围／类型 | 不宣称具体声音或逐字内容得到保留 |

M2 必须保留“信号是否复制”“范围”“启用状态”“允许借用属性”；M6 决定声音层、混音和可辨识声源；M11 据完整方案选择枚举。混音未知时保持待确认，不提前判 `fully_copy`。[R155–207]

要求复制或重新表演的对白／歌词，在 `<d>` 中保留源词句与原语言；Ref2VA 按官方要求规范基本标点并去掉装饰性符号。基础模式另有保留原标点的要求，M2 始终保存原始证据，由 M11 按模式格式化。无法听清的部分标记 `[unclear]`，只参考音色时不得继承源台词；未读取或解析的媒体不得伪装成已听清。对白／歌词不在两个声音概览字段重复铺写。[B129；R274–278、303]

## 编排、审计与移交

1. **登记事实**：确认资产存在、来源、媒体类型、可访问性和实际检查状态；未验证解析候选与直接观察分开。资产登记本身不授予使用任何属性的权限。
2. **绑定实体**：判断需要保持的是人物、动物、物体、场景、服装、界面、效果或其他单元；明确一对多、多对一关系及不确定身份，不把文件名当作观察证据。
3. **限定用途**：每条 ReferenceMap 记录引用角色、允许／禁止／未知属性、适用镜头或时间范围、来源与依据；只有身份用途时不外推画面端点和背景。
4. **核验声音**：确认视频音轨是否启用、复制信号或参考特征、同步关系及是否新增混音；将未定项交 M6，不猜测具体音色、内容或节奏。
5. **交接结构**：关键帧时刻交 M7，源视频编辑／续接及切镜关系交 M9；M2 提供对应来源、范围、权限与冲突，不替它们设计时间或镜头。
6. **交接编译**：将三个结构对象及未决问题交 M11；由 M11 最终选模式、分配资源 Label、说话者 ID、填写六／三字段、序列化并检查后端容量。
7. **审计结果**：报告可定位的问题、依据、受影响引用和建议修复；修复建议仍是提案，不静默覆盖禁用属性，也不证明模型生成结果已经符合要求。

本映射给出协议条件，不把官方示例故事引入项目创作案例边界；领域证据仍仅来自用户要求及项目固定 `case-studies` 集合。来源与完整许可记录见 [h3-protocol-source.json](h3-protocol-source.json)；案例溯源另见 [provenance-and-license.md](provenance-and-license.md)。
