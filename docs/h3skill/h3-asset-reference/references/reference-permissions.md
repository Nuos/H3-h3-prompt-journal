# M2.3 属性权限与引用范围

## 目录导航

1. 职责；2. 权限与范围；3. 属性分权；4. 冲突裁决；5. 编排与审计；6. 模型交接。

## 1. 职责

读取 `asset_context`、`entity_context`、`permission_brief`，提出 `reference_map` 中的 `permissions` 与 `decisions`。兼容外部输入即可独立使用；不重跑上游。决定目标作品的属性继承，不裁定法律授权，不分配 H3 上传标签。

## 2. 权限与范围

每条 permission 经 `binding_id` 指向来源资产、目标实体和通道，明确 `attribute`、`decision`、`use`、`scope`、来源及授权依据。decision 为 allow/forbid/unknown；use 为 reference/copy/anchor。具体枚举和范围形状见合同指南。一条“参考此图”不足以代替属性分权。

区分素材有什么、用户允许继承什么、后端能怎样输入。直接观察不自动授权；用户要求不证明素材内容；协议支持不证明生成一定遵从。未声明属性不默认继承。

明确何处/何时生效。全作品权限须显式声明；镜头范围用稳定镜头 ID；区间声明时间域和秒数，遵从合同端点约定。未知范围不扩成全片。源视频、生成片和成片时间不能混用，换算交 M7。

关键帧要区分首帧、尾帧、构图或故事板锚点，说明帧角色。身份外观参考不自动成为帧约束；若用户确实提供实际首帧，就必须处理它与“禁止继承姿态”等要求的冲突。

## 3. 属性分权

| 属性组 | 分开决定 | 常见越权 |
|---|---|---|
| 身份 | 面部、身体特征、发型等 | 参考面孔便继承姿势和背景 |
| 外观 | 服装、配饰、背面结构、材质 | 多来源同时排他控制服装而无裁决 |
| 状态 | 表情、姿态、起手、关键帧 | 身份图当首帧；或否定真实首帧约束 |
| 场景 | 几何、固定陈设、背景、氛围 | 布局参考便锁相机和灯光 |
| 运动 | 动作机制、轨迹、节奏 | 动作迁移带入源演员和场景 |
| 摄影/编辑 | 相机运动、构图、剪辑节奏 | 相机样式当身体姿态；节奏参考称直接编辑 |
| 声音 | 音色、表达、词句、原信号复制 | 音色参考携带原词句；有声视频自动启用音轨 |

上表是语义检查维度，不是后端参数字典。合同采用受控属性集合；尚不支持的组合保留领域说明和缺口，不注入未知字段绕过校验。

典型策略：身份保留而姿态重编时明确身份来源与新动作计划；运动保留而目标替换时逐项决定身份/服装/场景是否排除；声音引用时明确原信号复制、局部复制或特征参考。排除哪些属性仍须本次依据，不把案例否定句机械加入所有任务。

只参考节奏的记录使用 `audio_timing/reference`，不能另授予 `audio_content/reference`。后者用于明确获准采用的词句等声音内容；仅音色参考则使用 `voice/reference`。字段本身与说明必须同义，不能用说明中的“仅节奏”纠正字段已经扩大了的权限。

## 4. 冲突裁决

先确认同实体、同属性、同用途和相交范围，再判断竞争。不同实体、不同属性、不同用途、不相交区间不能仅因同文件而误报。实际帧锚定还须检查它与同源姿态、场景等排除要求的跨属性矛盾。

例如，同一音频可以对 `audio_content` 设置 `reference: allow`（参考原词句并重新演绎）和 `copy: forbid`（禁止复制原信号），两者共同限定目标。不得把前者扩大为复制许可，也不得要求删除后者才能通过。若两条记录都是 `copy`，却在同范围分别允许与禁止复制，则必须处理冲突。

| 情况 | 处理 |
|---|---|
| 同来源/实体/属性/用途/范围同时允许与禁止 | 记录冲突，暂停该项接受 |
| 多来源争同属性、同用途的排他控制 | 明确选择、分区、混合或例外决定，不按文件顺序取胜 |
| 后来用户要求改变旧权限 | 保存旧依据，提出新版本与失效范围，不重复索要同一授权 |
| 有描述、无使用授权 | 保持未知/未授权，不从内容猜用户意图 |
| README 与 prompt 不同 | 保存两份来源和差异；历史复现明确选择依据，通用规则不抹平 |
| 后端不能实现精细权限 | M11 返回能力差距，回目标与规划责任方，不删要求制造兼容 |

决定记录必须有涉及项、理由、授权、范围与选定结果；不能随意填文字绕过检查。脚本能核对引用和实现的组合规则，无法证明决定符合自然语言原意。

## 5. 编排与审计

使用完整限定句，明确对象、来源和范围。例如：“目标角色在指定镜头沿用身份素材的面部特征；开场姿态由动作计划重新确定，参考图中的手势不作为起态依据。”这是依据案例抽象的语义模板，不是已绑定真实资产的最终 H3 正文。

运动句应说明“约定区间提供哪个目标的运动过程”，并按授权说明源演员外貌/服装的处理。声音句应区分“仅参考节奏”与“复制整个录音”；不能同时无解释地写 No signal copy 和 fully_copy。

检查授权来源、正文是否扩大范围、多图属性竞争、关键帧误用、歌词是否被当视觉实体、音轨是否启用、完整音轨复制是否与新增声层相冲突、变更是否使旧消费者过期。不要以长串全局否定掩盖绑定缺失。

## 6. 模型交接

交给 M11 稳定素材/实体/权限、源区间、帧角色、音频策略与未知项。Ref2VA `retention_analysis` 的官方关系值由 M11 按语义映射；内部 allow 不能直接翻译为 fully_preserved，因为允许一个属性不等于全部定义范围均保持。

M6 决定声音内容/发声者，M7 决定时间转换，M9 决定镜头和每任务素材，M8 决定状态。M2 提供权限，不代写这些计划。准确 Label 与枚举见 `h3-label-mapping.md`；案例证据见 `case-evidence.md`。
