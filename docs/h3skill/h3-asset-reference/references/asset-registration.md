# M2.1 资产登记与来源状态

## 目录导航

1. 职责与输入；2. 登记步骤；3. 证据层次；4. 解析与派生素材；5. 局部检查与返回。

## 1. 职责与输入

将当前可能使用的素材及证据登记为 AssetRegistry 提案。读取 `material_brief` 与来源；用户清单、已有项目或解析器结果均可输入，不要求先运行 M1。具体字段和状态见 `contract-guide.md` 与 `contracts.json`。

回答“有什么、来自哪里、能否访问、观察了什么、哪些未知”。主体对应归 M2.2，继承属性归 M2.3；媒体存在不构成这两项决定。

## 2. 登记步骤

1. 为实际资产和待提供素材设稳定 ID。展示名称或上传排序改变不换 ID；内容替换时建立新版本或新 ID，保留旧来源。
2. 保存来源定位、版本、陈述及证据类别。文件路径、URL、案例文字和解析记录分别记录；案例中的 Picture1 不是本次已上传文件。
3. 识别媒体与通道：图片、视频视觉、视频声音、独立音频、派生帧或仅有文本。是否可上传由 M11 的带版本能力资料判断。
4. 分别记录 `availability`、`access_state`、`observation_state`；文件可读取不代表已看画面或听声音。只登记本次实际执行的观察。
5. 观察时记录来源/工具、对象或时间区间及结论边界。未观察片段仍未知，单帧不能证明完整动作连续。
6. 记录用途候选与缺项；目标绑定交 M2.2，继承授权交 M2.3。继续完成无依赖的登记。

## 3. 证据层次

| 依据 | 可以说什么 | 不能推出什么 |
|---|---|---|
| 用户描述、素材未提供 | 用户想要某角色或用途 | 已确认外观、动作、音色 |
| 有定位、无法访问 | 来源已登记、待取得 | 内容已读取 |
| 文件可访问、未观察 | 可以开展观察 | 身份、动作、音轨已核验 |
| 作者/案例说明 | 原文这样描述或报告 | 本轮复现成功 |
| 外部解析候选 | 某工具给出候选切点或动作 | 候选正确、目标必须继承 |
| 指定范围直接观察 | 该范围内可见可听的事实 | 范围外情况、目标授权或生成稳定性 |
| 推测补全 | 规划候选解释 | 原素材既成事实 |

在本模块，“参考权限”是用户让素材控制目标作品哪些属性；本合同不裁定法律许可。

## 4. 解析与派生素材

完整源片逆向系统是可选上游。本包不实现切镜检测、视觉识别、音轨分离或语音转录。接收解析结果时保留源版本、范围、方法、可信度和未决项；置信度不自动成为创作授权。

源视频、抽帧图、线稿、编辑图分别登记，实际产生派生文件后才标为可访问；未创建时只登记计划。派生关系不证明准确保留了原身份、道具或布局。

视频视觉与同步声轨分别说明用途、使能状态及实际输入。未实际提取或启用时，不把视频默默增加成独立音频输入。`channels` 描述素材通道，不能代替用户授权或后端连线验证。

时长、帧数、帧率取自明确证据。README 数字可登记为作者陈述；与连接关系或计算不同则保留冲突。孤立控件值不能冒充已执行参数。源时间、生成时间和成片时间的换算交 M7。

## 5. 局部检查与返回

M2.1 只写 `asset_registry`。每个被引用资产实际存在或明确待提供，并带来源。可登记未知素材，但相关外观判断和生成准备不得通过。

检查 ID 重复、同 ID 内容静默替换、来源缺失、访问冒充观察、作者报告冒充实测、未生成派生素材、未启用声音却承诺复制、无依据的时间参数。结构工具只检查记录间关系，Agent/人工还须回查证据。

缺素材回用户/提供方，来源错误回 M2.1，绑定不明回 M2.2，权限争议回 M2.3，后端能力回 M11；不修改其他节点结果。

案例方法依据：动作迁移的多通道输入、下山的总时长差异、动作链库的单帧推测标记。原文位置、适用条件及冲突见 `case-evidence.md`、`case-index.json`，不据此宣称本包已实现逆向解析。
