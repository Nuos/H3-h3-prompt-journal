# H3 持续审计、问题归因与反馈修复

先回答：**本次检查哪一版产物的哪些要求，实际取得了什么证据，结论能支持到哪里，问题由谁修订、怎样复验？** 将计划、模型正文、实际执行、生成片和成片分开登记。检查结论始终绑定原要求、对象版本、方法和覆盖范围。

实现 M12 和四个可独立调用的子模块。只读取本职责所需投影；用户资料、外部工具结果和已有模块输出满足公开合同即可使用。子模块提交提案，父 M12 核对真实原请求、版本和权限后接受，不直接修改 M1—M11 的专业对象。

## 1. 选择入口与按需读取

| 确定审什么、凭什么判定 | M12.1 | 审计范围、要求和检查计划 | 审计范围 |

Agent 负责读取实际材料、选择适用规则、开展语义比较与观察、说明推断边界。脚本只核验显式记录、版本、证据关系、范围和依赖；不能验证任意外部证据的真实性，也不会读取一份提示词便自动看见视频。

## 2. 固定原始范围与版本

取得用户本次目标、必保要求、已有产物和允许变化，记录工作 ID、审计范围及输入版本。已有提示词可逆向整理为带来源的候选计划，但不能冒充用户原始意图。没有上游对象时建立兼容最小投影，不虚构已运行的模块。

把来源原文、作者报告、用户陈述、工具结果、实际观察、推断和合成示例分别标记。保留每项证据的定位、版本和作用范围。文件存在、字段合法、工具成功退出、人工说“已看过”，分别只能支持它们实际证明的条件。

要求仍适用而证据缺失时登记 `unverified`。只有任务确实不存在该条件、且没有相关依赖时才使用 `not_applicable`。局部审计可以单独交付；不能省略原任务的必需检查后继续宣称原任务全部完成。

## 3. 执行四个子职责

1. **M12.1 建立检查计划。** 为每条有效要求列出检查对象、Gate、适用性、期望、方法、所需证据和覆盖。把结构、语义、工作流执行、视频和音频条件拆开；指出哪些检查可以先完成。范围变化保留原要求和授权依据。
2. **M12.2 汇总有范围的结果。** 对照实际证据核对同一版本的要求、计划、正文和配置。保留局部自检的原始结论与局限；缺少必需证据、版本不符或覆盖不足不升级为通过。关卡汇总只覆盖计划中已登记且实际检查的条件。
3. **M12.3 独立登记媒体观察。** 绑定实际媒体、对应计划、观察者／工具、时间域、观察窗口、方法、通道和限制。记录看见或测得的事实，再单独比较期望。抽样不冒充全片观察；合成记录不进入真实媒体验收依据；不覆盖 M8 的计划状态。
4. **M12.4 归因和安排复验。** 先定位期望与实际差异，再根据证据判断是源资料、计划、编译、运行还是媒体输出问题。原因不明时保留候选和调查项。向唯一字段责任方提交版本化修改请求，沿实际依赖计算受影响对象与检查，登记复验条件及停止边界。
5. **父 M12 接受。** 用真实原请求核对提案、工作 ID、基版本、独占责任和来源关系；成组接受或完整退回。保留旧检查和观察，当前失效状态另记。技术重试复用原操作身份；新语义修订使用新请求，不靠重复运行同一检查制造新证据。

## 4. 五关卡的实际含义

| 关卡 | 检查对象 | 可支持的结论 |
| --- | --- | --- |
| G0 输入与证据 | 目标、来源、素材、用途、访问情况和能力资料 | 当前范围的输入依据及明确缺项 |
| G1 设计一致性 | 空间、动作、摄影、声音、时间、状态、剪辑与风格 | 已检查的同版本计划条件是否自洽 |
| G2 编译与运行契约 | 模式、字段、绑定、正文保真、参数与后端证据 | 当前检查范围的模型输入及运行契约条件 |
| G3 生成片验收 | 实际生成片、配置、计划、观察或测量 | 该片已观察／测量条件是否实现 |
| G4 全片验收 | 实际装配版本、整片、接缝、声画和作品目标 | 该成片已检查条件是否实现 |

分别使用 `pass`、`fail`、`unverified`、`not_applicable`。依赖变化时将原结论在当前版本的有效性标为 `stale`，保留原检查结果。没有生成片不填写 G3 通过；片段通过不推导 G4 通过；文本检查不代替实际工作流运行。

## 5. 对应 H3 官方模式与 Label

T2VA、I2VA、FL2VA、L2VA 的逐镜正文为 `integrated_multimodal_description`，另有 `overall_soundscape`、`non_diegetic_music`。I2VA／FL2VA／L2VA 另外核对官方对齐首行与实际首／尾帧；对齐首行不增加第四个顶层字段。

Ref2VA 使用 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` 六字段。核对获准保留或改变什么、作用于谁、何处和何时，逐镜比较正文与原计划。

逐一审计 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 的实际来源、序列化与角色；将它们与 `[Shot N]`、声音源 `(Sx)`、台词 `<d>` 及跨镜／截断标记分开。`fully_copy`、源窗口、实际音轨和新增声音层必须一致。

M12 产物是伴随审计记录，不新增 H3 的 Audit、Gate、Evidence 或修复字段。修复后的可生成正文由 M11 根据责任模块已接受的新计划编译；不把审计表、内部开发说明或推演过程塞入模型输入。

## 6. 交付与停止

交付本次范围的检查计划、AuditLedger、必要的 MediaObservationLedger、ChangeSet、当前缺项和下一责任方。说明哪些检查实际执行、哪些只作路由、哪些依赖外部证据，以及哪些旧结果已经失效。

达到所要求的有证据交付范围即可结束。资源或资料不足时交付已完成部分和具体缺项；修复后的字段看起来正确仍须按原要求复验。不能为了关闭问题删去失败检查、重命名要求、覆盖原观察，或把模拟任务改称真实运行。

运行前阅读公共合同；Python 3.10+ 标准库脚本只读取显式 JSON、输出结果，不调用其他模块、不联网、不执行生成或外部写入。`assets/` 的夹具和模板有明确用途，复制后填写真实资料才能用于实际任务。自然语言记录可复制[审计报告模板](assets/audit-report-template.md)。
