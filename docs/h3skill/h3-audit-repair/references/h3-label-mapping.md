# M12 与 H3 五模式、字段及 Label 的映射

**核心摘要：** M12 对五种 H3 模式执行有范围、有版本、有证据的持续审计，记录实际媒体观察，分派修复并安排复检；协议选择、绑定和正文编译仍由 M11 负责。

**关键结论：** 基础四模式使用三字段，Ref2VA 使用六字段。审计计划、检查结论、观察记录、修复单及 G0–G4 均属于项目工作流，不是 H3 原生字段。

**关键词：** T2VA、I2VA、FL2VA、L2VA、Ref2VA、Label、证据、审计、失效、修复、复检。

**目录导航：** 1. 来源与责任；2. 子模块映射；3. 五模式；4. 字段；5. Label；6. 保留关系；7. 镜头与声音；8. 门禁与修复。

## 1. 来源与责任

官方协议固定于 MiniMax-AI/MiniMax-H3 提交 `199b7d0e1fd95e7b3eafa8c15eca692534142427`。B 表示包内 `h3-base-official.txt`，R 表示 `h3-ref-official.txt`；行号沿用原始文件。来源、原始字节哈希和核对范围见 [official-sources.md](official-sources.md) 与 [h3-protocol-source.json](h3-protocol-source.json)。

下表的字段、Label、保留枚举与语法来自官方协议；M12 的证据门槛、检查对象、分工和失效规则来自冻结开发方案及本项目合同，不把项目治理包装成 H3 能力。`AuditPlan`、`AuditLedger`、`MediaObservationLedger`、`ChangeSet` 和面向人的审计报告留在工作流侧，禁止加入模型提示词顶层。

审计先固定目标／计划、模式、正文、素材绑定、运行配置和媒体的适用版本，再对具体义务查找证据。不能以“格式正确”推导生成成功，也不能以计划状态替代已观察状态。

## 2. 四个子模块如何作用于官方协议

| 子模块／输出 | 对应模式与位置 | 提示词编排要求 | 审计要求 |
| --- | --- | --- | --- |
| M12.1 范围与门禁／`AuditPlan` | 五模式、全部适用字段和 Label；无新增模型字段 | 引用当前目标和 M11 模式／绑定／编译版本；列出需保留、可改和需观察的义务 | 明确请求范围、适用性、证据需求、检查方法、覆盖和责任方；不能通过缩小范围使失败消失 |
| M12.2 检查与证据／`AuditLedger` | 基础三字段、Ref2VA 六字段、四类 Label、镜头与声音标记 | 对正文与上游设计逐项追溯，标注位置和最小修复建议 | 区分规则检查、Agent 语义审阅、作者报告和实际运行／观察；缺失请求内证据不能写通过 |
| M12.3 实际媒体观察／`MediaObservationLedger` | 输出中对应的画面、动作、状态、切点、参考相似性及声音 | 以该版本提示词和预期状态为对照，不改写原预期以迎合输出 | 只有实际可访问且已检查的媒体才写观察；记录版本、时间窗口、方法和覆盖；M8 计划账本不能冒充观察账本 |
| M12.4 归因与复检／`ChangeSet` | 缺陷涉及的字段／Label／资产／设计／配置及其依赖 | 将修复交给相应责任模块；M11 重编译变更后的提示词 | 使受影响的旧结论在当前版本失效；原证据／观察和旧结论保留历史；修改后按新版本复检，禁止沿用旧媒体通过结论 |

四个子模块可接收兼容公开合同单独运行。G0–G4 是检查阶段和范围，不是五个新子模块；M12 不以调用其他模块私有脚本作为前置条件。

## 3. 五种模式及其编排／审计要求

| 模式 | 官方顶层字段（依序） | 编排约束 | M12 重点审计 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music` | 无图像对齐首行；风格和初始构图在 `[Shot 1]` 内 | 文本目标到完整音画时间线的追溯；没有把身份参考／工作流元数据混入格式 |
| I2VA | 同上三字段 | 固定首行后空一行；实际首帧在 0.00 秒、第一镜 | 输入图确为首帧；外观、位置、构图、场景锚与动作起始一致 |
| FL2VA | 同上三字段 | 首尾帧首行；一般单镜，多镜须有明确要求；正文写连续可见桥接 | 真正末镜／有效时长与尾图一致；中间动作可到达尾帧；两张图不是仅作静态罗列 |
| L2VA | 同上三字段 | 尾帧首行；由合理前态向最后镜头／时点收敛 | 不把尾图当首图；结束时间和末镜编号正确；到达目标的过程有依据 |
| Ref2VA | `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` | 按用途定义参考；整体风格在 `[Shot 1]` 之前；不混入基础模式首行或主字段 | 四类 Label 的角色、来源、使用点和保留关系贯穿六字段一致 |

依据：B:5–70、78–92；R:13–37、215–239。不得添加 `other_descriptions`，不得把基础三字段与 Ref2VA 六字段拼接成自创模式。

### 3.1 必须逐字保持的基础模式首行

I2VA：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

FL2VA：

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.
```

L2VA：

```text
How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

N 替换为实际末镜编号，S.SS 替换为有效时长、恰好两位小数。首行后空一行。FL2VA 的 Picture／Shot 在这一首行中不带尖／方括号；不要为“统一格式”擅自改写。身份参考图不自动成为 I2VA 首帧；L2VA 的 N 仅在单镜时为 1。[B:16–34]

## 4. 逐字段的编排和审计

| 官方字段 | 内容编排 | 审计证据与问题归属 |
| --- | --- | --- |
| `integrated_multimodal_description` | 基础四模式的完整逐镜音画：空间、外观、动作／反应、摄影、发声、同步画内声音 | 与上游计划逐项比对；动作因果、主体状态和声音缺失交专业责任方；格式序列化交 M11 |
| `subject_definitions` | Ref2VA 中需要独立追踪的 Subject／Picture／Video／Audio 及其用途和必要来源 | 定义与绑定版本一致；多源到同一主体、同源到不同主体合法；仅作 Subject 来源的 Picture／Video 不强制另立独立定义 |
| `summary` | 一个简短英文段，开头以 `[task type + ...]` 写实际用途并去重 | 任务类型不能由文件数量推断；`video editing` 时使用官方句式 `The target video is an edited version of <Video 1>.`；引用必须可解析 |
| `retention_analysis` | 每个独立参考在目标中的作用、保留／迁移／复制等级与理由 | 视觉与声音枚举分开；按声明用途判断；禁止 Sx；保留强度与详细正文和实际绑定一致 |
| `detailed_description` | 完整英文逐镜时间线；参考的实际生效位置、动作链、状态、运镜、对白及声音 | 不降为摘要或关系表；保留台词／歌词／可见文字的原语言；检查语义义务，不能仅依赖字符串匹配 |
| `overall_soundscape` | 全片环境、物理动作及非语言人声，通常一个英文段、1–4 句 | 不复述对白／歌词；仅在明确完全静音时使用 `N/A`；不要把“没有音乐”推成完全静音 |
| `non_diegetic_music` | 仅观众可听的配乐：乐器、速度、节奏、动态或无配乐时 `N/A` | 画内收音机、演奏等归主正文；参考音轨的复制／叠加策略与 Audio 保留关系一致 |

依据：B:36–48、76–171；R:24–306。Ref2VA 的 350–500 词是写作建议，不是已验证的模型硬容量；不能为了达到计数而删掉必保原词或时间义务。[R:242]

## 5. 四类 Label 的编排和审计

| Label | 官方含义 | 编排要求 | M12 审计要求 |
| --- | --- | --- | --- |
| `<Subject N>` | 可复用的可见内容单位：人、动物、物、场景、环境、服装、道具、界面、效果、风格、动作、表情、姿态等 | 独立于源文件编号；可多图共同定义一主体，也可一图提供多个主体；首次出现写特征、位置和当下动作 | 比较许可保留／改变的属性；不能按图片槽位替换身份，也不能把新的动作或场景自动视为身份失败 |
| `<Picture N>` | 具体首／关键／尾帧、编辑后的帧，或构图、分镜规划锚；也可仅作 Subject 来源 | 明确帧／分镜角色及与真实 Shot、时点的对应；外观或风格来源嵌入 Subject 时不强造独立帧 | 图片用途来自绑定证据；身份图不能悄然变为首帧；分镜格不自动等于切镜 |
| `<Video N>` | 编辑源片、续接端点或整段时间结构，包括运镜／切镜／节奏 | 区分整段结构与提取的角色、动作、效果；后者可由 Subject 承担 | 运镜参考不自动构成 `video editing`；实际续接必须有源末态和目标起态依据；窗口／版本可追溯 |
| `<Audio N>` | 独立音频或明确启用的视频同步音轨，按整体信号／层／音色／节奏／原词／效果引用 | 明确是否启用、是否实际拷贝以及拷贝范围；必要时连接真实 Sx | 文件含音轨不等于启用音轨；不能根据 Video 的编号猜配对；信号复制与特征参考不得混淆 |

四类 Label 独立编号。同源视频与音轨可以是 `<Video 1>` 和 `<Audio 2>`；同源关系由明确来源说明，不由编号推测。多用途尽量以一个自然句写清，存在歧义时明确分配关系。[R:41–118]

### 5.1 Ref2VA 任务前缀

| 前缀 | 使用条件与审计要点 |
| --- | --- |
| `keyframe completion` | 具体帧锚，含编辑后目标帧；不能把外观来源自动提升为目标帧 |
| `reference generation` | 主体、场景、风格、动作、运镜或分镜指导，且没有要求把同一用途当作关键帧补全／视频编辑／续接 |
| `video editing` | 修改源视频素材；单张帧编辑／首尾插值本身不足以成立 |
| `video continuation` | 从源视频继续、恢复或过渡；必须有可追溯续接关系 |
| `audio reuse` | 实际拷贝全部或部分源音频信号 |
| `audio reference` | 仅参考声音特征、节奏、原词等，没有实际复制音频信号 |

以实际任务组合并去重。视频编辑且保留原声可以同时含编辑与音频复用；仅继承声音特征的续接不应误报 `audio reuse`。[R:120–155]

## 6. 保留与音频复制的审计

| 对象 | 官方值 | 按声明用途判断的要求 |
| --- | --- | --- |
| 视觉 | `fully_preserved` | 完整保留该角色要求的内容；不意味着源场景、动作和故事也必须全部不变 |
| 视觉 | `partially_preserved` | 部分属性或部分内容保留，明确变化边界 |
| 视觉 | `attribute_transfer` | 将属性用于不同身份／内容，不冒充原主体完整保留 |
| 视觉 | `weak_reference` | 宽泛风格、构图等弱引导，不承诺精确匹配 |
| 音频 | `fully_copy` | 完整原始信号作为完整最终音轨，一比一复制 |
| 音频 | `partially_copy` | 片段或声音层复用，或最终轨增加／移除其他层 |
| 音频 | `reference` | 借用特征／节奏／内容，不复制信号 |
| 音频 | `weak_reference` | 仅大类声音或氛围启发 |

完整源音频上再叠加新 BGM，最终音轨已不再是一比一的 `fully_copy`，应按 `partially_copy` 审阅。上述等级是预期引用关系；是否真的复制、音色是否相似、画面是否保真，必须由相应实际媒体证据支持。Sx 不是参考素材，不进入 `retention_analysis`。[R:160–211]

## 7. Shot、Sx、对白及跨镜标记

| 标记／规则 | 编排要求 | M12 检查与责任方 |
| --- | --- | --- |
| `[Shot N]` | 真实镜头连续编号；第一镜不加时间戳 | 动作阶段、分镜格和后台生成分段不等于切镜；M9 定义镜头，M11 序列化 |
| `At MM:SS.mmm` | 后续镜头切点严格递增且位于有效时长内 | 区分源素材时间、作品时间、生成局部时间；M7 负责时间，M9 负责剪辑 |
| 运镜 | 自然语言描述类型；有意义时写幅度和速度 | 变焦与机位移动不可混淆；不能靠增加切镜掩盖原运镜要求 |
| `(Sx)` | 实际说话／唱歌／画外人声按首次发声顺序编号，跨镜稳定；合说可用 `(S1,S2)` | 与 Subject 和 Audio 编号独立；不为从未发声者强加 ID；声音策略由 M6 负责 |
| 首次声源描述 | 在 `<d>` 外建立视觉身份、在／离画、音高、音色、语速、口音等足够信息 | 不把声音描述塞进可读台词；复制的纯音乐不必造一个说话者 |
| `<d>[Language] ...</d>` | 只包含语言标记与实际台词／歌词；动作、身份和语气在外 | 基础模式保留原词原标点；Ref 源音频的基础标点规范化不允许改词、翻译或猜测不清楚片段 |
| 画外旁白 | 按官方 `says in an off-screen voiceover` 写，并明确可见人物嘴部闭合 | 区分旁白与画内对白；未观察口型不能宣称实际无口型冲突 |
| `<scenetrans>` | 同一句话跨切的接合点，两镜明确声音连续 | 核查两侧台词与时间、声源连续；不是通用转场标签 |
| `<cutoff>` | 发声被视频结束截断 | 必须符合真实要求；不能用它掩盖未经允许的台词超时 |
| 英文双引号 | 包住画面中的真实可见文字，保留原语言 | 不擅自翻译标牌；文字计划存在不等于输出中已可读 |

依据：B:86–151；R:215–278。格式检查可发现编号、引用和切点问题；实际嘴部、声画同步、可读性和物理连续性仍需媒体观察。

## 8. G0–G4 与修复回路

| 阶段 | 可形成的结论 | 不足证据与修复路径 |
| --- | --- | --- |
| G0 输入／依据 | 目标、素材用途、来源、可访问性和能力依据在请求范围内是否齐备 | 缺失保留为未核验；目标找 M1，资产找 M2，能力找 M11 |
| G1 同版本设计 | 事件、空间、摄影、声音、时间、状态、剪辑和风格间是否冲突 | 返回内容责任方；不要覆盖 M8 计划来消灭差异；变更后重新冻结并重审受影响项 |
| G2 输入／编译 | 模式、字段、Label、绑定、参数和正文是否符合输入合同且忠实表达计划 | 模式／绑定／序列化找 M11，时间与分段找 M7／M9，素材找 M2；通过不表示已推理或视频合格 |
| G3 实际片段 | 已检查媒体版本、窗口、方法和覆盖内的真实符合／偏差 | 没有媒体或未检查的方面不能通过；再生成／重选产生新版本与新观察，保留旧失败 |
| G4 实际整片 | 整片目标、跨段连续、声音和剪辑的实际覆盖结果 | 片段通过不能替代整片检查；剪辑找 M9，时间找 M7，声音找 M6，内容返相应责任方 |

最小修复链为：定位证据与义务 → 区分输入／设计／编译／运行／观察问题 → 分派责任方 → 记录新版本和依赖影响 → 使受影响旧结果失效 → 重新检查原请求范围。规则检查或人工审阅未覆盖的语义、媒体、物理和审美问题保持明确的未核验状态。详细合同和状态见 [contract-guide.md](contract-guide.md)、[evidence-and-gates.md](evidence-and-gates.md)、[repair-and-retest.md](repair-and-retest.md)。
