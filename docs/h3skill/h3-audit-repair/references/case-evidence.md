# M12 案例证据、适用条件与反例

**核心摘要：** 四个十月案例支撑 M12 的检查范围、观察登记、问题归因和局部复验：水岸独舞、右入三镜换装、触地换袜、人物优先动作迁移。案例提供检查方法与反例；本轮未查看、解码或生成任何案例媒体。

**关键结论：** 提示词要求、作者报告、静态配置与本轮观察是不同证据。必须先固定被审对象、版本、时间域和覆盖，再给出该范围的结论；检测候选、作者自检和修订文字均不能直接关闭媒体问题。

**关键词：** 审计范围、观察覆盖、候选切点、动作因果、参考权限、证据层级、配置冲突、归因、修复复验。

**目录导航：** 1. 来源与读取范围；2. 证据层级；3. 案例证据；4. 冲突与未决事项；5. 对 M12 的使用规则。

## 3. 案例证据

### M12-E01 — 场景检测只产生候选，既可能漏检也可能误报

**来源：** C12-WATER `README.md` 第 12–22 行；C12-SOCK `README.md` 第 11–15 行、第 40–50 行。

- **A：** 水岸案报告，阈值 `0.27` 未检出切点，降低到 `0.06` 后出现 `14.5s`／`18.13s` 两个候选；作者检查候选附近 `±0.2s` 的帧，判断为逆光光晕和大侧弧快速动作。右入案报告，同景同机位硬切在 `0.27` 下漏检，`0.08` 得到 `2.267`／`4.233`／`4.4s` 三个候选，但最终装配只使用前两个切点。
- **D／适用条件：** 对“是否切镜”等要求，记录检测工具、阈值、输入版本、候选位置及复核覆盖。候选和人工确认结果分开；低阈值复测仅是一种补查方法。将工具扫描范围与逐帧确认范围分别登记。
- **反例：** 零候选不能直接证明全片无切镜；三个候选不能直接变成三个确认切点；动作或光源变化不自动等于剪辑。案例阈值和 `±0.2s` 不作为所有视频的统一参数。
- **M12 应用：** M12.1 定义要求及证据覆盖，M12.3 保存候选和复核，M12.2 按实际覆盖判断。真实任务没有相应媒体与观察时，该媒体要求为 `unverified`。

### M12-E02 — 保留被推翻的假设，修复必须回应证据

**来源：** C12-SOCK `README.md` 第 3、13–16、20–26 行；`prompt.md` 第 3–5、25–27、52–54、79–81 行。C12-WATER `README.md` 第 15 行。

- **A：** 右入案作者先把 `0.1–0.2s` 抽帧中的变化解释为迈步中的画内换装，后逐帧撤回；为避免两人同框而发明“左出右进＋空帧停留”也与作者所述源片不符。水岸案报告，按 `1s` 间隔初看排出的中段块序经局部复核后调整。
- **F：** 右入最终提示词要求第一帧已在画右跨入途中、已穿本镜袜饰，末帧保持 pose，人物不退出；它不要求空框过场。
- **D／适用条件：** 审计记录区分假设、采样证据、反证和当前结论；`ChangeSet` 回传具体错项与来源。修复目标是满足冻结要求，不能未经授权新增退出、空框或其他叙事机制。
- **反例：** 增加提示词篇幅、重复“单人”或改写出入画流程，不能证明实际重影已消失；局部抽帧不支持未经检查区间的连续性结论。
- **M12 应用：** 原假设和旧观察保留，M12.4 回传 M9 的边界／任务规划、M8 的入出态或 M4 的动作顺序；具体责任须依据问题字段确认。没有实际输出的纠正只能关闭文字问题，不能关闭 G3／G4 媒体问题。

### M12-E03 — 生成段、镜头、服装状态不能互相代替

**来源：** C12-SOCK `README.md` 第 24–26、40–44 行；`prompt.md` 第 9–98 行。C12-WATER `README.md` 第 3、36–40 行；`prompt.md` 第 11–54、59–102 行。C12-CONTACT `README.md` 第 46–50 行；`prompt.md` 第 239–569 行。

- **F：** 右入案设计三个独立生成任务，局部时长为 `2.267`／`1.966`／`1.667s`，装配硬切点为 `2.267`／`4.233s`。水岸案设计一个连续锁定镜头的两个生成段。触地案说明一次生成完成，正文仍有 `[Shot 1]` 至 `[Shot 6]` 等标签与六次袜饰变化。
- **D／适用条件：** 同时固定生成任务、作品镜头、事件／状态段和实际装配对象，各用自己的 ID、版本、时间域和允许变化字段。检查时按当前任务定义解释标签，不由单词 `Shot` 或文件数量猜测实际执行拓扑。
- **反例：** “一镜一状态／一段不承载两状态”是右入案解决该问题的设计，不能覆盖触地案的一次生成多次换装；两个生成段也不自动表示作品需要两个可见硬切镜头。
- **M12 应用：** M12.1 选择 G1 计划、G2 编译、G3 生成片或 G4 装配范围；M12.4 将拓扑问题交 M9、状态策略交 M8。镜头与生成段的数量必须由计划确认，不能由 M12 擅自重写。

### M12-E04 — 跨段连续性检查有明确状态和时间域

**来源：** C12-WATER `README.md` 第 8、16、24–30、38–47 行；`prompt.md` 第 5–7、21、43–47、59–80、107–119 行。

- **F：** 计划总长 `24.474s`，段长 `12.070s`／`12.404s`，全局交界为 `12.070s`；前段末态是螺旋未完、双臂下拖，后段以拖臂上提交叉穿掌继续。第二段正文用从 `0.000` 开始的局部时间。
- **D／适用条件：** 在接缝两侧对齐同一动作部位、朝向、动量阶段和允许变化项；先使用 M7 的时间映射，再比较 M8 的计划入出态与实际观察。计划交接句齐备只证明要求存在。
- **反例：** 将第二段的局部 `0.000s` 当成作品全局 `0.000s`，或用“同一人／同一场景”代替动作相位检查，都可能漏掉中性站姿重启。源视频被作者判断连续，也不能证明本次重新生成并装配后的接缝连续。
- **未决文本：** 第二段 summary 仍写首拍 `0.070s`，其局部块却按 `0.000 / 2.400 / 4.800...` 排列。需要明确这是全局首拍描述还是局部首拍；不能在未确认映射时静默修成任一值。
- **M12 应用：** M12.2 可定位计划歧义，M12.3 另记真实片段／成片接缝；M12.4 回传 M7、M8 及实际受影响的 M9／M11。源片、生成片和装配成片的结论不互相继承。

### M12-E05 — 接触切换要同时检查事件顺序、支撑和可见保持

**来源：** C12-CONTACT `README.md` 第 12–32、38–40、48–58 行；`prompt.md` 第 19–111、129–233、277–331、575–641、681–759 行。

- **A：** 作者报告时间戳触发会提前／延后，接触与下一次抬腿被压缩、支撑腿漂移及源片平滑 morph 均造成问题。
- **F：** 目标机制是活动脚第一次清晰触地时换袜；切后保持触地，等新袜稳定才再次抬脚。后／远腿承担持续支撑，前／近腿只做紧凑点地。第一轮计划 `1.850s` 起抬、`2.070s` 触地并切换、`2.070–2.200s` 保持、`2.260s` 才开始第二次抬腿。
- **D／适用条件：** 将“脚已触地”“袜饰已换”“脚仍触地”“新袜稳定”“开始下一次抬腿”记为可定位的独立条件；检查支撑腿、髋、躯干及接触脚在切点两侧的许可变化。关键时刻必须可见；遮挡或没有足够帧不能写已确认接触。
- **反例：** 正好在计划毫秒换袜但脚仍悬空，不满足该接触要求；触地声出现也不能单独证明脚位；只看换装前后两张图不能证明中间没有抬脚或 morph。六个时间戳是该案的目标，不是已测得结果或通用容差。
- **M12 应用：** M12.1 分解当前要求，M12.3 分别登记视觉／音频证据，M12.4 按证据定位交 M4 动作因果、M3 接触空间、M7 排时、M8 连续性、M6 声音或 M9 切换；不能因同一症状就预先认定模型或某一个模块导致。

### M12-E06 — 音频复用和同步要求仍须独立证据

**来源：** C12-WATER `prompt.md` 第 6、21–25、52–54、69–73、100–102 行；C12-SOCK `prompt.md` 第 3、21–31、92–98 行；C12-CONTACT `prompt.md` 第 643–677 行。

- **F：** 水岸案明确人声内容未核实、不设歌词锚点；其分段音频作为完整音轨原样复用。右入案要求按音频切片生成、最终整条音轨铺底。触地案要求复制音轨，同时写有喷泉、风和点地声以及声画同接触时刻的要求。
- **D／适用条件：** 保留“复制素材”“生成声景”“最终混音”的不同范围。没有听音／音轨比对时，不声称原词、声源、相位或完整复用已确认；声音和视频各有覆盖，不能以画面观察代替声音观察。
- **反例：** `fully_copy` 是提示词意图，不是音频位元一致或同步测量。触地声若本来就在复用音轨中可符合要求；若还要求新增声景，就需要 M6 明确混音政策，不能自动判定相容或自动添加声音。
- **M12 应用：** M12.2 记录音轨政策未决项，M12.3 登记实际音频与声画测量，M12.4 按具体问题交 M6／M7／M11。缺听音证据是 `unverified`，不是“没有人声”。

### M12-E07 — 参考权限是归因依据，输出症状不是因果证明

**来源：** C12-MOTION `README.md` 第 21–38 行；`prompt.md` 第 17–156、189–303、338–444 行。

- **A：** 作者把源视频人物或环境混入结果列为动作迁移常见失败。
- **F：** 该案把 Picture 1 指定为人物／服装／身份／世界的权威，Video 1 首帧只贡献镜头几何和开场身体机制，其余视频贡献动作／镜头行为，Audio 1 提供时间。提示词明确禁止把视频人物、服装、环境或光线继承为最终外观。
- **D／适用条件：** 审计先确认当前任务实际选择的参考职责，再比对计划、编译文本、上传资产顺序、运行参数和媒体。发现身份错误时分别考察 M2 绑定、M11 序列化／后端映射及实际生成偏差，证据不足时保留候选原因。
- **反例：** “画面像 Video 1”不自动证明 M2 错；文本含正确 Picture 标签也不证明实际上传位置正确。其他任务可以合法选择视频外观作为参考，不能把本案职责分配升级为 Ref2VA 的统一禁令。
- **M12 应用：** M12.1 固定本次权限检查，M12.2 比较对象链，M12.4 只向有字段证据的责任方提出变更，不改写其原计划。

### M12-E08 — FINAL VALIDATION 是待执行检查，不是已经观察

**来源：** C12-MOTION `README.md` 第 38 行；`prompt.md` 第 487–538 行。C12-CONTACT `README.md` 第 52–58 行；C12-WATER `README.md` 第 42–48 行；C12-SOCK `README.md` 第 46–52 行。

- **F：** 动作迁移提示词在“生成之前”列出每帧身份、环境、开场、参考剥离、动作、时间和镜头八项验证，并要求否定时重建。其他三案也有提交前 anchor／continuity／timing 等清单。
- **D／适用条件：** 清单可转为要求 ID、检查对象、方法、范围和通过条件。文本审校可以检查这些要求是否存在、一致、可执行；真正的逐帧身份、动作或时序达成仍需生成后的媒体证据。
- **反例：** 提示词写“每帧相同”或 Agent 给出八个“是”，都不是实际逐帧验收。修改提示词并再读一遍，只能复验文字修改；不能自动把旧媒体失败关闭。该案没有提供适用于所有任务的重试次数。

### M12-E09 — 文本、缓存值、连线与实际执行必须分开

**来源：** C12-MOTION `README.md` 第 6、19、40–50 行；`prompt.md` 第 10–12、582–586 行；`h3-motion-transfer-workflow.json` 全文解析，重点节点与连线定位见 `case-index.json`。

- **F：** Duration 节点 132 值为 `9`，连到公式节点 131／188；公式静态代入得到 `226`。ReferenceToVideo 节点 136／191 同时保存 `1344, 768, 124` 的控件缓存，但宽高和 length 有实际输入连线。ResolutionSelector 节点 115 配置为 `16:9 / 0.4 / 32`；CreateVideo 130／174 配置帧率 `24`。这些配置不能直接合并成“实际生成 124 帧且长 9 秒”。
- **F：** 续接说明节点 211 写裁去前 `22` 帧，取尾节点 194 的值为 `[-1, 22]`，输出切片节点 213 却为 `[26, 4096]`，音频裁剪节点 212 起点约 `1s`；相关续接节点记录 `mode=4`。Audio 节点 155 分别连到 136 的 `ref_video_audios.ref_video_audio_0` 和 191 的 `ref_audios.ref_audio_0`，两个入口并不相同。
- **A：** README 报告目标 `9.29s`、结果 `9.42s`／概述 `9.4s`，另写动作迁移上限 `8–9s`、`Duration=9 / 124 帧 @24fps` 与横屏配置到竖屏成片。上述是作者报告，不能当作当前官方能力配置。

## 5. 对 M12 的使用规则

这些证据支持本包以下工程约束；`AuditLedger`、`MediaObservationLedger`、`ChangeSet` 的公开合同来自冻结方案及本包设计，不声称原案例已使用这些对象。

1. **范围先于结论。** 同一案例可支持文字检查、输入检查、候选发现或局部观察；每种结论只覆盖实际对象、版本、通道和时间窗。
2. **观察先于归因。** 先记录期望、可定位事实及差异，再依据字段权责选择修订方；保留未知原因，不把症状自动归结为提示词或模型。
3. **修复不改变证据历史。** 新计划、新编译、新媒体及新方法使用新记录；旧失败、候选、被撤回的假设和来源冲突仍保留。
4. **复验回应原问题。** 文字更正后复查文字；媒体问题需要对应当前媒体与计划的观察。局部关闭不等于所有 Gate 通过，也不等于其他片段或后端版本通过。
5. **案例数值保留条件。** 阈值、采样间隔、时长、帧数、人数、状态数和生成拓扑均绑定案例；没有当前任务依据就不升级为全局规则。

本轮证据开发完成的是来源阅读与工程提炼。任何真实 G3／G4 结论仍需要该任务的真实媒体、观察者、方法、时间域、覆盖和版本。
