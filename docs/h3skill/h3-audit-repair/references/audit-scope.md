# M12.1 审计范围与检查计划

**核心摘要：** 先固定用户要求、对象版本和检查范围，再选择 Gate、方法、证据与覆盖。局部任务可以独立开展，缺证据不会改变原要求的适用性。

**关键结论：** G0—G4 是检查策略；它们不机械等于五个子模块，也不组成一个可以偷换含义的总分。

**关键词：** 范围、要求、适用性、检查方法、覆盖、版本。

**目录导航：** 1. 最小资料；2. 检查项；3. 五关卡；4. 适用性；5. 范围变化；6. 交接。

## 1. 固定最小资料

记录任务目标、用户必保事项、当前交付类型及明确允许变化。为受检计划、提示词、素材、配置或成片提供稳定对象 ID、版本和来源定位；需要内容身份时保留精确内容摘要。无法取得原计划时，明确本次仅审既有提示词的可见内容，不能推断不存在的作者意图。

只读取本次必要的字段投影。单独检查 Ref2VA 的参考绑定，可以接收兼容的来源清单、权限与编译片段，不要求先运行全部创作模块。缺少身份照片时可核对 Label 是否自洽，但真实外观相符仍是缺项。

## 2. 将每条要求转为可检查项

| 必须明确 | 操作 |
| --- | --- |
| 原要求 | 保留原文或稳定引用；区分用户要求、案例条件和工程建议 |
| 对象与版本 | 指明检查哪个计划、正文、配置、媒体或边界；不得只写“最终版” |
| 期望与判定边界 | 指出必须成立的具体关系；无法机械判定的语义仍需审阅 |
| Gate 与专业责任 | 标明阶段和字段责任方；问题原因未定时不要预先判责 |
| 方法 | 区分结构检查、语义对照、实际运行记录、媒体观察和测量 |
| 证据 | 明确需要哪些原文、报告、日志、帧、音频区间、版本资料或观察记录 |
| 覆盖 | 指定对象、镜头、时间窗、通道、抽样方式与允许的未知范围 |
| 适用性与缺项 | 说明必需／不适用的依据；缺材料时保留原检查要求 |

不要把“检查所有问题”“保证人物不畸形”当作已经可执行的完整检查计划。将它们具体化为本任务关注的身份、肢体、接触、可见性、镜头边界和声音条件，同时保留检查方法无法覆盖的部分。

## 3. 按交付范围选择关卡

| Gate | 代表检查 | 常见缺项 |
| --- | --- | --- |
| G0 | 目标一致、来源明确、资产存在及用途、版本化能力依据 | 只有文件名；参考未到达；后端字段未核验 |
| G1 | 事件与空间可协调、动作过程完整、可见条件、时间与状态一致 | 只读标题未读正文；相邻交接仅看一端 |
| G2 | 模式／字段／对齐首行／Label 正确，原词与必保语义保真，参数对应实际版本 | 静态格式通过；实际素材或运行资料仍缺失 |
| G3 | 生成片内的身份、动作、物理关系、声音与局部时间实现情况 | 未查看媒体；仅缩略图；只看画面未听音 |
| G4 | 最终选窗、接缝、叙事／音乐推进、整片声画与交付条件 | 只验独立片段；实际剪辑版本未知 |

纯提示词任务可以交付 G0—G2 中实际适用的文字范围；不能以这种局部完成宣称“整个生成流程通过”。要求生成片或全片时，缺实际媒体意味着相关检查未验证。

## 4. 判定适用性

不适用的例子：明确无对白的作品无需核对说话轮次；不含跨镜接缝的单镜无需核对两个镜头间的动作衔接。

仍然适用的条件：无对白作品仍有声音策略；单镜仍有生成任务和时间范围；固定机位仍需构图与动作可见性；缺音频的卡点任务仍需声音时间依据，不能改记为没有音乐。

规则冲突先查适用条件。案例中的提前到位、同相响应、滞后追随和固定观察属于可选择策略；不得同时提升为全局强制。蒙太奇与连续动作的接缝条件分别登记，不能一律要求所有属性相等。

## 5. 保留范围变化与原要求

新增、删减或改变交付范围时保留前后版本、原因和用户依据；不同问题的修复不要暗中改变其他必保要求。若只有局部资料，返回局部检查与未覆盖清单，原始整体要求仍保持未完成状态。

检查计划变化会影响依赖它的结论。即使被审媒体没有变化，新增或更换方法后也应新建检查记录，保留旧记录；是否需要重新生成，由实际偏差与修复责任方决定。

## 6. 交接

将检查计划交 M12.2 汇总实际结果；需要实际观察时交 M12.3；资料、语义或版本冲突交 M12.4。仅生成检查计划不表示任何专业条件已经通过。公开 JSON 字段、命令和独立调用示例见 `contract-guide.md`。
