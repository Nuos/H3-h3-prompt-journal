# M12.4 问题归因、变更与复验路由

**核心摘要：** 先固定偏差与证据，再确定修订责任、版本变化和实际依赖；保留历史，按受影响范围复验。

**关键结论：** 发现相同表象不等于具有相同原因；修改请求和路由结果不表示其他模块、外部服务或生成任务已经执行。

**关键词：** ChangeSet、归因、唯一写入、依赖、stale、复验、停止。

**目录导航：** 1. 问题；2. 归因；3. 回传；4. 失效；5. 复验；6. 重试与停止。

## 1. 建立问题记录

保留问题 ID、Gate、原要求、对象与版本、具体位置、期望、实际、证据、严重程度及影响。将“已证实违反要求”和“尚缺证据”分开，不用统一的失败分数遮盖区别。

保存未解决的问题及新证据。要修复的对象不同、基版本改变或修订语义改变时生成新操作身份；不在旧请求中原地替换事实。

## 2. 区分定位和因果归属

身份错误可能来自 M2 的资产绑定、M11 的序列化，也可能只出现在实际生成片。先比较源资料、计划、提示词、实际提交参数和媒体；在没有链条证据前保留候选责任与需要补查的材料。

确认责任须有定位到该责任字段的依据。将专业问题交对应模块判断；把执行、模型随机结果或工具限制作为待调查事实，不编造“提示词造成”的确定因果。存在多项独立问题时分别登记，不能把所有问题塞给同一模块。

## 3. 回到唯一字段责任方

| 问题定位 | 首要修订方 | 必要复查 |
| --- | --- | --- |
| 目标、段落功能或必保内容 | M1 | 相关事件、观看信息、声音和编辑 |
| 来源、身份、素材或参考权限 | M2 | 实际使用这些来源的计划和编译 |
| 坐标、路径、接触空间 | M3 | 动作可进入性、可见条件与排时 |
| 动作过程、支撑、发力或因果 | M4 | 状态、时间、镜头和接触声 |
| 机位、构图、焦点或运动 | M5 | 屏幕方向、遮挡、相机时间与接缝 |
| 台词、声源、音乐或音轨策略 | M6 | 原词、轮次、声音窗口与声画关系 |
| 时间域、偏移、拍点、容量 | M7 | 真正依赖该时间依据的事件和编辑 |
| 状态策略、未许可重置或边界条件 | M8 | 相邻入出态、变化许可与实际观察 |
| 镜头、选窗、转场、分段或装配 | M9 | 时间映射、接缝、声音和自足任务 |
| 风格、光色、材质及效果作用域 | M10 | 参考权限、可见性与持续范围 |
| H3 模式、字段、Label、参数映射 | M11 | 原计划保真、实际素材顺序与运行版本 |
| 审计范围、证据、错误通过或版本管理 | M12 | 受影响的检查和当前交付声明 |

M12 发送修改请求：对象、基准版本、目标变化、证据与理由、允许范围和复验条件。责任模块接受后形成新版本；M12 不直接写回其专业内容。

## 4. 沿实际依赖登记失效

记录消费方实际读取了哪个对象／投影的哪一版。变更后向这些消费方及它们的下游扩散；未引用该变化的对象保持其既有有效性。对象级粒度可以用于小型任务；需要更细隔离时显式建立字段投影 ID，不能假装已经分析不存在的细粒度依赖。

例如换音轨只使实际依赖该音轨的声音、时间、剪辑、编译和对应验收失效；不因这一变化自动废弃无关角色身份检查。改展示名称只需核对实际使用它的索引或包装关系。

依赖图不完整时列出已知影响及待调查边界，不能声称已找到所有影响。历史通过记录保留原状态，当前使用标记 `stale` 并关联变更原因；依赖被标 stale 时，下游不能继续无声使用原通过结论。

## 5. 按原要求复验

修复记录包含前后版本、执行动作及新产物、需重检的要求、方法和证据。修订计划仅说明计划发生变化；关闭媒体问题仍需当前媒体与当前计划下的复验依据。

复验应核对原要求及覆盖，不允许换一个较弱检查、删除失败项或只复查修订说明。媒体改变要检查新媒体；计划或方法改变可重新审阅同一媒体，但使用新检查记录。失败历史和第一次观察不改写。

确认修复通过后关闭本问题所涉及的检查，保留其他问题与未验证范围。其他片段或后端版本不能从这次局部通过自动获得相同状态。

## 6. 区分技术重试、修订与停止

只读检查可按同一输入重放；同一已接受操作不得重复写入台账。修改语义不是重试，需新请求与基版本。生成、上传或外部写入超时后，先核对真实任务 ID 和已有结果；不能默认重发、重复花费或产生多个不同输出。

任务自定修复预算、循环边界与停止条件，不设置跨作品统一次数。达到目标或预算后交付当前结果和残留项；重复自评、重复字符串校验或不断改状态不能替代新证据。

本包输出修复计划与路由，不自动执行目标模块或外部操作。需要执行时由已获授权的调用者按实际操作效果推进，并保存新的执行记录。
