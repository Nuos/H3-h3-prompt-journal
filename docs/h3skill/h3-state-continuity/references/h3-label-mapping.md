## 来源与职责

协议固定为 `MiniMax-AI/MiniMax-H3@199b7d0e1fd95e7b3eafa8c15eca692534142427`，本轮重新获取两份文件，与离线快照逐字节一致。B 指 [h3-base-official.txt](h3-base-official.txt)，R 指 [h3-ref-official.txt](h3-ref-official.txt)，行号从文件第一行开始。完整来源、blob SHA、SHA-256、许可及机器可读映射见 [h3-protocol-source.json](h3-protocol-source.json)。以下 P 为官方协议，D 为把 M8 合同落实到协议的编排/审计设计。

M8.1 提出 `ContinuityPolicy`，M8.2 提出计划 `StateLedger`，M8.3 读取二者并输出 `ContinuityHandoffs` 边界结果；只有父 M8 接受对应版本。**这些名称都是内部合同，不是 H3 字段、Label 或独立输入模式。** M11 负责最终 H3 文本编译；M8 提供内容要求与可审计地址。M12 的实际媒体观察不写入计划账本。

## 五种输入模式

| 官方模式及证据 | M8 编排要求（D） | M8 审计要求（D） |
| --- | --- | --- |
| **T2VA**，B L5、L14、L36–48 | 由用户文本建立计划初态、持续属性、获准转换和末态，落入 `integrated_multimodal_description`；声音分入两个声音字段 | 不虚构首帧图片或 Ref2VA 定义段；文本动作必须解释状态变化；未指定状态标未知 |
| **I2VA**，B L6、L16–20、L54–56 | 官方首行把 `<Picture 1>` 绑定 0.00 秒和 `[Shot 1]`。建立实际首帧状态，然后写动作发起、发展与结果 | 实际首帧角色不能被“identity-only”权限偷偷降级；后续变化仍要有路径，不把首帧姿态冻结到全程 |
| **FL2VA**，B L7、L22–26、L60–64 | 两图分别提供首尾锚，正文说明可观察的中间转换并逐步落到尾态 | 验证首尾都满足、转换许可完整；尾图属于真实最后 `[Shot N]`。通常单镜，明确要求时才多镜；不能仅并列两张静图描述 |
| **L2VA**，B L8、L28–34、L68–70 | `<Picture 1>` 是终态；从兼容的前态规划动作与状态变化，最后收敛 | 不误认其为首帧或必属 Shot 1；区分用户给定末态与推导前态，未定路径标待补 |
| **Ref2VA / full-reference**，R L13–37、L132–147 | 先固定引用内容与权限，再声明任务关系和保留方式，按播放顺序将计划写入 `detailed_description` | 只用实际适用的四类 Label 和官方六字段；定义、分析、正文与声音段中的含义一致，不能让原素材的初始姿态覆盖当前计划状态 |

首尾图模式的固定首行必须由 M11 从 B L16–34 原样采用。FL2VA 模板使用 `Picture 1 (from Shot 1)`；I2VA/L2VA 模板使用带角括号的 `<Picture 1>` 与方括号的 `[Shot N]`。不得为“统一样式”改写这项已核验的格式差异。`S.SS` 是两位小数的有效视频时长，不是零起点最后一帧的 PTS（B L34）。

I2VA/FL2VA/L2VA 的基础字段仍为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。存在图片并不自动选 Ref2VA；实际帧锚、内容参考和视频续接是不同关系，应由任务说明和素材角色决定模式。

## 四类 Label

| 官方 Label 与含义（P） | 如何承载 M8 状态（D） | 编排与审计要求（D） |
| --- | --- | --- |
| `<Subject N>`：可重用的可见内容，包括人物、物体、环境、衣服、道具、风格、动作、表情或姿态；R L41–58 | 引用稳定主体键以及身份、外观、道具、环境或动作权限；同一内容可由多源分别授权 | 把“是谁/是什么”与“当前处于何状态”分开。一个源可提供多个 Subject，一个 Subject 可有多个源；握持、出鞘等当前状态仍须由计划说明。禁止把 Subject 当成源文件或把素材中的全部属性都当成已获许可 |
| `<Picture N>`：具体帧或镜头规划锚；R L62–73 | 将实际首帧、关键帧、末帧、编辑帧或构图锚绑定到相应计划时点和镜头 | **只提供身份、服装、环境或风格的图，不单列 Picture 定义**；在对应 Subject 定义内部标明其来源。真正独立使用的帧/分镜锚才单列 Picture，并给出作用范围。身份稳定不能冒充首帧完全对齐 |
| `<Video N>`：原片编辑、续接起点或全片镜头/节奏/时序结构；R L78–88 | 提供续接的源末端、被编辑区间或结构参考；M8 对源末态与目标初态检查接收条件 | 借用视频中可见的人物、场景、动作或效果仍用 Subject；Video 只标素材或结构来源。不得把只借动作升级为“直接续接原片”，也不能由未观察的视频推定末态 |
| `<Audio N>`：复制或参考的音频信号；R L92–118 | 给音频继续/中断/重启、复制范围、节奏参考和发声者稳定身份提供来源 | 必须有启用的音频角色。视频文件含声不自动产生 Audio；Video/Audio 独立编号，相同数字不代表配对。音色参考与直接复制是不同权限；发声者用已有全局 `(Sx)`，不按 Audio 序号另编 |

官方 R L35–37 要求 Label 在各字段中保持同一含义；只作为另一项来源的 Picture/Video 不必另立定义。M8 不新造 `<State N>`、`<Continuity N>`、`<ShotState N>`，也不把内部对象 ID 当成 H3 Label。

## 逐字段编排与审计

| 模式/官方字段（P） | M8 要交给 M11 的要求（D） | 审计问题（D） |
| --- | --- | --- |
| 基础模式：`integrated_multimodal_description`，B L46、L76–92 | 将初态、动作、接触/受力、获准变化、末态和跨镜接收关系写成可见或可听的播放序列 | 主体与道具数量是否一致？每个变化有事件/编辑许可吗？正文是否实际给出了交接所声称的末镜？ |
| Ref2VA：`subject_definitions`，R L35–58 | 固定实体身份和每项素材的角色/权限，必要时将身份、环境或机制分成独立内容单元 | 是否把身份参考当姿态锚？是否出现未授权的服装、背景、动作复制？同一 Label 是否前后换义？ |
| Ref2VA：`summary`，R L132–153 | 说明实际任务关系及连续/编辑目标；可组合官方任务类型 | `reference generation`、`video editing`、`video continuation`、`audio reuse`、`audio reference`、`keyframe completion` 是否由真实关系支持？有视频不等于续接，有音频不等于复制；不能引入新 Label |
| Ref2VA：`retention_analysis`，R L157–207 | 在已定义角色内声明保留或改变范围；如只保脸部身份，身体运动不自动降低保留等级 | 视觉标记只能为 `fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`；音频标记只能为 `fully_copy`、`partially_copy`、`reference`、`weak_reference`。不得以所有状态必须静止来解释 fully_preserved |
| Ref2VA：`detailed_description`，R L215–232 | 在正文前用一两句建立整体风格；在 `[Shot 1]` 与后续真实切点按顺序写状态、事件和接续，适用处引用 Label | 是否仍误用 integrated 字段？定义的权限、保留方式与实际动作是否一致？边界表的出/入状态有没有正文支撑？ |
| 所有模式：`overall_soundscape`，B L152–158；R L21 | 总结环境声、物理声、非言语人声的范围、持续或中断条件；与各镜接触/动作音事件相容 | 音轨声明完整复制为最终全部音轨时，有无另加脚步、风声等矛盾？未写声音不是静音；`N/A` 仅用于用户要求全片完全静音（B L154） |
| 所有模式：`non_diegetic_music`，B L160–166；R L22 | 说明仅观众可听的配乐以及跨边界持续、变化、收尾，Ref2VA 需与 Audio 复制/参考关系一致 | 是否误把角色可听的音乐放在这里？是否把复制信号与新作同风格音乐混为一谈？无非叙事配乐时用 `N/A` |

`fully_copy` 表示源音频完整成为目标最终全部音轨；若只复制一部分、部分声层，或另加/删/替换声音，则应按实际关系审查 `partially_copy`（R L194–207）。M8 记录矛盾并转给声音/编译责任方，不擅自更改素材权限。

官方 R L242 对生成任务通常建议 detailed_description 为 350–500 英文词，并明确对白密集任务优先容纳完整对白、视频编辑按复杂度调整；这不是 M8 的硬字数上限。不能为满足本地上限而删去必要边界条件，也不能以词数通过宣称计划成立。

## 边界、声音与序列化

| M8 边界语义（D） | 提示词中要表达的事实 | 协议落点与限制 |
| --- | --- | --- |
| 同镜 | 稳定分量、动作过程、接触先后、允许的外观变化 | 当前 `[Shot N]` 内的可观察动作；相机运动本身不自动产生新 Shot |
| 连续接续 | 来自上一计划/已授权源端的末态、接收状态、共同动作阶段 | 对真实源视频续接使用正确 Video/summary 关系；没有末态证据就标待补 |
| 动作匹配 | 同一主体、阶段、动量、运动方向和接触/承重的接收方式 | 在真实切点描述出/入镜动作；只写“继续”或只写末尾特写表不够 |
| 蒙太奇 | 哪些身份、服装、道具、环境要保持，哪些姿态、机位、时间关系可改变 | 在逐镜正文或编辑要求中明确；不要求所有属性或帧完全一致 |
| 时空省略 | 新时空地址、被许可变化的分量及解释 | 合同扩展必须带任务授权与来源；本轮已读案例没有完整的倒叙/时空跳跃实证 |
| 声音跨切 | 同一声音是否继续、何时中断，哪些主体实际发声 | 同一句对白/歌词跨切用 `<scenetrans>` 连接两部分并明确声音连续；视频结尾截断用 `<cutoff>`（B L127–142、R L218–223） |

`[Shot 1]` 不加切点时间戳；真实后续切点使用递增的 `[Shot N] At MM:SS.mmm, ...`，时间在视频时长内（B L86–92、R L218）。不要把每次状态更新、动作节拍、相机轻微变化都变成一个 Shot。实际发声者保持全局 `(Sx)`；静默角色不因跨镜身份稳定而获得 speaker ID。

M8 审计是对**计划及文字之间的关系**作检查。它可以发现状态来源缺失、规则冲突或三方描述不一致，但不能仅凭提示词判定模型已经做到物体守恒、承重正确、帧级匹配或声画同步。实际结果由 M12 观察记录。

## 案例旧语法迁移

案例可能出现大写裸 `PICTURE 1`、`[Shot 5 | 9.208–11.875s | ...]`、基础首行与自定义六字段混用等历史写法。这些文本是领域方法证据，不能作为当前官方协议的替代。M11 应保留可迁移含义，并按上面的固定官方版本重编译。

例如身份-only 案例中的图片，在当前 Ref2VA 下通常作为 Subject 定义内部的来源；不能机械保留为单列 Picture 角色。剑舞原图中的收刀姿态不能压过“本段开始刀已在手”的状态安排；若任务同时要求该图为真实首帧，需报告首帧与计划初态冲突并修改任务或计划，不能静默降级该图权限。白凤交接表缺口应在编译前暴露，不能通过替换字段名掩盖。
