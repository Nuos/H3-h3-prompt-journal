# M8.2 计划状态与转换登记

## 1. 记录计划，不伪造观察

StateLedger 表示某一计划版本要求发生的状态。实际媒体观察由 M12 保存；“脚本接受了起终态”“提示词写了末态”“视频实际达到末态”是三种不同结论。

记录任务／计划版本、稳定实体、时刻或区间、状态维度、值及其来源。必要维度包括身份／外观、道具存在和数量、持有者及解剖学左右手、支撑和接触、位置、朝向、运动方向与相位、环境及声音持续。任务无关维度可以不展开；任务必需而未知的维度必须具体标注未知。

没有观察到手中道具，不等于道具不存在；表情不可见，不等于角色没有情绪；缺少音轨，不等于声音应为静音。

## 2. 让每次变化有来源

状态转换至少能够回答：

1. 从哪个已登记的前态出发？
2. 哪个 M4 动作、M6 声音事件或 M9 编辑边界解释变化？
3. 该变化符合哪一条 M8.1 策略和上游权限？
4. 哪个实体的哪些属性改变，哪些继续保持？
5. 结果发生在 M7 提供的哪个时钟和锚点，后继动作依赖什么？

登记本域结果，不重新编写动作机制或空间路线。动作缺少抓握、接触、释放或恢复过程时，向 M4 提出修订；站位／手与物件关系有冲突时向 M3 回传；时刻和动作阶段对不上时交 M7。

## 3. 区分道具外观与当前状态

案例中的剑可以依靠同一图片保持外观，但后续段必须明确已经出鞘还是仍在鞘内、剑鞘的位置、持剑者与握持手。如果前段拔刀且未发生收刀，后段不能只因再次载入参考图而又从未拔刀开始。

转交道具需要前后持有关系和交接事件；换手需要解释手间过渡；物件增减需要对应事件或获准编辑变化。只写“保持道具一致”无法覆盖这些关系。具体左右手约束属于当前作品，不成为所有作品的统一规定。

## 4. 区分状态区间、状态值与转换

在一次连续、完整覆盖的状态链中，初态加 N 次转换形成 N+1 个有序状态区间。**不同区间允许返回相同值。** 例如 A→B→A 是三个区间、两次转换、两个不同值；不能因为第三个区间又是 A 而删去它。

该计数只适用于已声明覆盖范围的完整链，不适用于任意抽样快照集合。检查前明确账本是完整区间序列还是离散锚点；未知区间、空档和跨时钟记录不能自动补成完整连续链。实际脚本所支持的记录与判据以合同为准。

换装案例中的造型数、转换次数和初态不能混用；触地作为变更触发时，应保留接触发生和允许变化之间的关系，不能把换装提前到尚未触地。

## 5. 时间、空间和版本保持单一来源

M7 拥有权威排时；M8 引用其时钟、时刻和版本，不能为让状态对齐改动音乐窗口或编辑切点。M3 拥有空间方案；M8 可以记录由该方案推导的状态，但保留来源和坐标约定。画面左右不能直接替代人体左右，反打时屏幕位置变化不能被误判为身份互换。

首次状态未知时，可以交付部分账本和待核对项。不得把后续结果倒填成初态，也不能让所有状态默认继承参考图。身份、道具、动作、空间或时间的来源升级后，生成新状态版本并使真正依赖旧值的交接重新检查。

## 6. 观察偏差进入修订流程

若 M12 报告前段实际由左手持物，而计划要求右手持物，应保留两条不同记录及其依据。M8 可以建议修复生成片、改变装配或提出新计划，不能修改原观察或原计划历史让二者看似一直一致。

接受新状态前，明确变更目标和授权，列出受影响的后继动作、空间／可见性要求、相邻边界和 H3 任务。新计划不能让旧媒体失败记录自动变为通过；需要按新目标进行新的、有范围的审阅。

合同、原请求保真及父接受见 [合同指南](contract-guide.md)，道具与接续方法出处见 [案例证据](case-evidence.md)。
