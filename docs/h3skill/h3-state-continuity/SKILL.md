# H3 主体、道具、场景与跨镜状态连续性

先确认**什么必须持续、什么获准改变、变化由哪一个事件或编辑边界解释**。分别管理参考外观、计划状态和真实媒体观察；按边界类型检查连续性。

实现 M8 及三个公开子模块。用户直接提供或其他工具形成的兼容计划可以满足输入，无需先运行 M1—M7。子模块提交自身职责的提案，父 M8 对照实际原请求和有效基版本唯一接受；M8.3 只读计划状态，状态修订回到 M8.2。

Agent 读取证据、理解状态和审阅文字；脚本执行明确实现的结构、引用、状态关系与版本检查；`assets/` 是可复制的设计输入与提案。工具不会读取视频来判断动作，也不会自动调用其他模块。

## 2. 收集最小输入，划定证据边界

取得任务及计划版本、稳定主体／道具 ID、M2 权限、相关 M3 空间和 M4 事件、M6 声音持续条件、M7 时间锚点与 M9 边界类型。只读取本次对象与范围；缺少必需输入时明确缺项，并完成证据支持的局部工作。

分别标记用户要求、案例原文、候选设计、已批准计划、作者效果报告、M12 观察引用和未知。看不见或尚未观察的属性保持未知；不能自动写成“不存在”“保持不变”或“已完成”。解剖学左右、屏幕左右和世界方向分别说明，跨机位不直接比较未换算的屏幕坐标。

参考图片可能只定义身份或服装，不能自动提供本段的姿态、持物手和道具状态。I2VA／FL2VA 的真实首帧约束另行遵守；若实际首帧与指定起态冲突，将冲突交 M2／M11 及相关状态责任方，不能只靠一句“忽略图片姿势”宣布解决。

## 3. 完成三个连续性职责

1. **M8.1 制定策略。** 按全片、场景、段落、镜头或具体边界限定持续范围；分别列出不变项和允许变化。每项许可保留来源、条件和关联事件／编辑决定。M9 声明的同镜、连续接续、动作匹配、蒙太奇和时空省略决定检查范围；不能为了让错误通过而自行换边界类型。
2. **M8.2 登记计划。** 为必要时刻或区间记录主体身份、外观、道具数量与持有关系、支撑接触、位置、朝向、运动相位及相关环境／声音状态。引用 M3／M4／M6／M7 的有效决定，记录转换的前态、过程依据、后态和许可。不同状态区间可以有相同值；一次收刀后再次拔刀必须有相应事件，不能由参考图静默重置。
3. **M8.3 核对交接。** 对照前镜正文的实际计划末态、交接表、后镜正文的计划初态，逐属性形成结论和证据。连续接续检查支撑、持物、方向和相位；动作匹配只检查所选的匹配关系及持续项；蒙太奇／省略核对保留项、变化许可和必要线索。无法从文字证明的接缝保持待审，不把表格中的愿望当成正文事实。
4. **父 M8 接受。** 核对来源、原请求、只读上下文、分区权限、基版本和组合一致性后形成新草稿。保留旧计划与原问题；发现竞争修改、未知依据或无解释变化时返回责任方。接受通过只表明本次合同及明确关系检查成立。

局部特写提供观看线索，不自动产生身体状态变化；构图缺口回 M5，动作缺口回 M4，空间冲突回 M3，时间冲突回 M7，边界选择回 M9。M8 不创作替代动作，也不重写台词或音轨。

## 4. 处理真实观察与版本变化

尚无生成媒体时，只能交付计划连续性。取得媒体后，由 M12 或符合其职责的外部观察者保存媒体 ID／版本、被对照计划、时间范围、方法、覆盖属性和结果；M8 只引用这些记录。

观察显示前段未达到计划末态时，停止把旧末态当作已实现前提。明确选择：请求重生成、由 M9 调整选窗／装配，或提出新计划版本并由对应专业模块修订。保留原计划、失败证据和后续影响；不能改写观察或倒改旧计划制造一致。

根据实际读取路径失效相关交接、后继动作前提和编译任务。没有依赖的镜头不自动重做；未登记的依赖不能被脚本证明安全。技术重放和语义修订分开，改变专业内容使用新的请求／提案与当前基版本。

## 5. 交接 H3 模式与 Label

| 模式 | 主要正文去向 | 本模块提供的状态要求 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 明确文字初态、变化过程和所需终态 |
| I2VA | 基础主正文＋官方首帧对齐指令 | 从实际首帧可支持的状态出发，补充未见属性的依据或未知 |
| FL2VA | 基础主正文＋官方首尾帧对齐指令 | 两端状态与身份／道具关系相容，中间转换可解释 |
| L2VA | 基础主正文＋官方尾帧对齐指令 | 以尾态为目标，前序状态和到达过程具备依据 |
| Ref2VA | `detailed_description`；定义、摘要与保留分析承接对应信息 | 区分参考外观和当前状态，每个独立生成段明确本段必要起态与变化 |

以下四类参考 Label 用于 Ref2VA；基础四模式不照搬全参考标签体系，首尾帧使用相应官方指令。

`<Subject N>` 绑定需要追踪的可见内容，包括人物、物件、场景或动作；`<Picture N>` 单独定义时承担具体帧或镜头规划锚点，仅用于外观的图在相应 Subject 定义内引用；`<Video N>` 承担编辑、续接或全片时间结构，重用的可见动作仍归 Subject；`<Audio N>` 按 M6 策略提供声音信号。标签不等于内部实体 ID，序列化和编号归 M11。

声音持续信息交 `overall_soundscape`／`non_diegetic_music`，保持 M6 的复制、参考或生成策略和 M7 的时间来源；跨切发声按官方规则交 M11。保持 Ref2VA 六字段与基础模式三字段的差别。`ContinuityPolicy`、`StateLedger`、交接诊断、工程规则和审计说明留在制作记录，不新增 H3 顶层字段。

最终正文按真实镜头写完整可见、可听事件，直接说明获准的起态、动作过程和接续结果。每个独立生成任务包含自身必需的状态条件；不能让模型依赖前一段未提供的对话或未观察媒体。

## 6. 检查并交付

读取合同后，从本包目录运行 Python 3.10+ 标准库工具：

```bash
python scripts/m8_contract.py --help
python scripts/m8_contract.py route assets/request-standalone-m8-3.json
python scripts/m8_contract.py check assets/proposal-standalone-m8-3.json --request assets/request-standalone-m8-3.json
python scripts/m8_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

交付本域策略、计划账本、逐边界检查、具体未决项、责任回传和 H3 表达交接。说明当前结果属于合同检查、已实现的确定性关系检查、Agent 文字审阅还是实际媒体观察；明确每一层的输入与范围。

`route` 是路由信息，`check` 是本域核验，`accept` 返回新草稿，`impact` 依据已登记依赖给出复验范围。它们不自动完成 G1 全局审阅或 G2 完整编译；G3／G4 需要实际生成片与成片。
