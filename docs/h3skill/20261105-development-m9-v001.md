# M9 分镜组织、转场、剪辑与生成分段：开发与验收记录

**日期：** 2026-11-05（America/Los_Angeles）。

**模块／技能：** M9／`h3-shot-edit-generation`，包版本 `0.1.0`。

**公开合同：** `1.0.0`，本域输出 `ShotEditGenerationPlan`。

**输入仓库基线：** `36987c56ade886aacfb166a21d6560925c97c330`。

**冻结开发基线：** `skillplan-v0.1.2-608813b`，固定内容提交 `608813b6e51531ac47f860bc384a454a504fe9ff`。

## 核心摘要

依据冻结方案新增第九核心模块，实现镜头／分镜格／事件归属、剪辑拓扑／选窗／转场、生成任务划分三个公开子模块。运行包位于 `docs/h3skill/h3-shot-edit-generation/`；开发、测试、发布与审阅记录置于包外。

M9 将动作阶段、故事板画格、真实镜头、一次生成任务和成片使用片段分别登记。它负责编辑与任务选择，读取 M7 时间、M8 状态许可和 M11 能力资料，向相应责任方提出修订请求。领域方法来自用户指定 `case-studies/` 文本；Anthropic 规范决定技能包装，MiniMax 官方文档决定模式、字段与 Label。

## 关键结论

1. 三个子模块通过公开、带版本的最小输入独立使用；兼容外部资料可代替先运行上游，父 M9 负责唯一接受。
2. 旧稿 Shot 标签、时间块、固定机位和一次生成都不足以单独推断真实镜头数量；一个阶段也可以跨切镜。
3. 边界的执行环节、连续性策略与编辑操作分别解释，后期桥接不会自动变为每段生成必须执行的额外表演。
4. 源窗、生成内容范围和成片使用区间分开；M9 不自建覆盖 M7 的权威时间表，也不把候选源窗冒充已观看的可用区间。
5. 编排与审计必须处理正文、标题和交接摘要之间的冲突；案例专属规则不自动推广为模型硬限制。
6. 原案例、冻结方案、标准快照及 M1—M8 运行包的 367 个文本／代码文件受到精确字节保护；本轮只更新共享索引并新增 M9 交付。

**关键词：** M9、ShotEditGenerationPlan、ShotMap、EditGraph、GenerationPlan、分镜、源窗、剪辑边界、独立生成、H3 Label、模块化。

## 2. 三个子模块及职责边界

| 子模块 | 权威分区 | 专业结果 | 关键边界 |
| --- | --- | --- | --- |
| M9.1 镜头、分镜格与事件归属 | ShotMap | 事件／阶段和分镜格的镜头归属，稳定 ID 及原标签对照 | 不重写 M4 动作或 M5 摄影决定 |
| M9.2 剪辑拓扑、选窗与转场 | EditGraph | 源素材使用区间、装配关系、边界执行位置和连接策略 | 不重算 M7 权威时间，不自授 M8 状态变化许可 |
| M9.3 生成任务划分 | GenerationPlan | 一次次请求的内容分配、必需上下文和边界条件 | 不冒充 M11 编译器，不假定固定时长或未经核实的模式能力 |
| 父 M9 | ShotEditGenerationPlan | 对照原请求、来源、基版本接受三分区提案 | 接受不是重新创作，不能静默覆盖其他模块字段 |

高内聚通过明确专业职责实现；低耦合通过公开只读输入、来源和版本实现；模块化通过独立子入口及组合接受实现；路由信息包含进入条件、必需字段、资源、返回点、错误责任与复验范围。注册路由和实际执行分别记录。

M9 选择源窗、剪辑拓扑及变速／定格意图；M7 负责源素材、作品、生成局部与成片四时间域的实际换算。M8 负责状态许可与账本，M12 保存实际媒体观察；M9 不能把计划中要求的匹配帧当成已经观察到的帧。

## 3. H3 输入模式、字段与 Label

### 3.1 五模式

| 模式 | 主正文与约束 | M9 编排要求 | M9 审计要求 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 镜头顺序、镜内事件、真实切点和声音关系 | 时间块／阶段不误成 Shot，切镜有信息作用 |
| I2VA | 基础主正文＋官方首帧指令 | 从实际首帧发展，首帧属于本任务第一镜 | 不把普通构图画格自动变成强制首帧，也不忽略真实首帧 |
| FL2VA | 基础主正文＋官方首尾帧指令 | 明确两端与中间路径，末图属于实际末镜 | 通常单镜；仅在明确指定时安排多镜，不能自动给每格一次切镜 |
| L2VA | 基础主正文＋官方尾帧指令 | 从合理前序发展至末镜尾态 | 尾帧不是开场；前段事件不能仅由尾图证明 |
| Ref2VA | `detailed_description` 与三类分析字段 | 逐镜描述全画面动态、参考在谁／何处／何时生效 | 定义、摘要、保留分析与实际逐镜正文一致 |

基础四模式保留三字段：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。Ref2VA 保留六字段：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。

### 3.2 Label 与镜头语法

| Label／语法 | M9 的作用 | 必须区分 |
| --- | --- | --- |
| `<Subject N>` | 被重用的人物、物件、场景、动作等可见内容 | 内容单元与源文件、内部镜头 ID |
| `<Picture N>` | 真实帧、关键帧或分镜规划锚点 | 身份图来源与具体画格作用；一张分镜参考可关联多个镜头 |
| `<Video N>` | 编辑源、续接源或整段镜头／节奏结构 | 只参考结构通常不是直接编辑／续接 |
| `<Audio N>` | 当前目标中复制或参考的声音信号 | 音频源与视觉源独立编号；仅后期铺底不自动变成生成输入 |
| `[Shot N]` | 当前目标中的真实镜头序列 | 动作阶段、画格、全片稳定镜头 ID、生成任务数 |
| `<scenetrans>`／`<cutoff>` | 跨切连续发声及视频结尾截断 | 声音语义由 M6、时间由 M7、语法由 M11 负责 |

每个独立目标从 `[Shot 1]` 开始且首镜无切点时间戳；之后在真实切镜处使用局部 `At MM:SS.mmm`。内部镜头／编辑／任务合同不新增 H3 顶层字段，也不把工程审计或后期选片指令混入生成画面描述。完整字段级编排与审计记录在 M9 映射文档。

## 4. 案例依据及实际解决的冲突

本轮全文读取 8 个十月案例的 11 份文件，其他 87 份只做文件清点；不把一案中读过一份文件称为整案所有文件已读。媒体检查数和 H3 运行数均为 0。

| 依据 | 本轮纳入的规则／冲突 | 适用限制 |
| --- | --- | --- |
| 十三段古风舞与十八段剑舞 | 先选连续或蒙太奇策略；每任务自包含；后期视觉桥梁不反向强迫模型多演一个动作 | 原案段数、镜数、左右与余量不作为统一默认 |
| 动态运镜纪律库与身份半身舞 | 动作完成切和动作中相位匹配分别成立 | 不能全局禁止动作半途切；相位匹配需明确保留维度 |
| 白凤六段 | 旧稿 Shot 可是动作章节；一个导演段落采用双生成后选窗；正文和交接表有缺口 | 候选窗口及表格末态不等于实际源帧；双生成说明不授权改写原导演原文 |
| 夏日水线 | Part 3 仅在 3 秒硬切，8 秒为同镜运镜变化；Part 4 的 5／10 秒是同镜阶段 | 时间节点、运镜和动作阶段不自动产生镜头 |
| 触地换装 | 一次生成、固定机位、六次硬切与七个状态区间分别登记 | 概要“单镜头”与正文硬切冲突需显式保留 |
| 右入三造型 | 各状态独立生成，成片短窗与生成时长分开，整轨后期铺底 | 概要“两侧迈步”与正文 pose→重新右入冲突；不自动登记为同动作匹配 |

对白凤正文、S14 与 S15 关键冲突进行了根侧复核，确认其属于文本计划内部问题。未对媒体内容作独立推断；作者关于抽帧、成功率或故障的说法仍标为作者报告。

表演保持姿态和后期冻结画格分别处理。案例中的 hold 可伴随呼吸、眼神、衣料和发丝余动，不能直接替换为 freeze-frame；本轮案例不足以支持通用最优变速率或补帧算法。

### 6.2 文字试用与协议／接口复核

独立 Agent 在只获得 M9 包与一项舞蹈任务的情况下进行文字试用，原始产物、实际读取日志与主执行者审阅均保留在 [首次试用目录](validation/m9/forward-use/)。该任务包含 6 秒同镜运镜变化、9 秒真实切近景、跨切继续转体、三张规划画格、两次独立生成、身份图、仅供节奏参考的视频和仅后期铺底的音轨。

首次产物正确区分了镜头、任务、画格和后期音轨，但把“只参考节奏”与 `weak_reference` 有混淆风险，且候选时间映射的 M7 责任不够显式。根据原文复核，入口和 H3 映射补充了“先确定参考角色，再判断角色内保留程度”；编辑指南补充 M7 时间交接及候选／权威映射区别。保留原始不足和修订原因，不把首轮试用记成无条件通过，也不以一次任务推断宿主触发率或一般成功率。

修订后由另一名未继承首次结果的 Agent 使用同一任务，原始计划、阅读日志和主执行者逐项复核见 [修订后试用目录](validation/m9/forward-use-final/)。此次输出明确保留 6 秒同镜变化、9 秒跨任务切镜接续、参考角色与保留程度区别、M7 候选时间交接和仅后期音轨。具体素材内容、后端能力及实际媒体仍待提供；两次试用不计作两个不同任务覆盖。

另一次独立文字审阅在实际完成的七份文件全文及三份文件部分范围内报告零项已确认实质问题；阅读范围和未完成部分如实保存于 [独立文字审阅记录](validation/m9/independent-doc-review.md)。没有将该有限审阅扩大为全部协议或整个案例库已复核。

另对官方原文和已交付 M7/M8 合同进行了直接复核，记录见 [协议与接口审阅](validation/m9/protocol-interface-review.md)。逐项核对了五模式、三／六字段、四类 Label、目标局部镜头编号、参考生成与编辑／续接、角色内保留关系、全轨／部分音频复制，以及实际只读记录形状。没有把本轮提供的版本化适配说明称为跨包原生集成已实测。
