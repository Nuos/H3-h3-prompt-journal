# H3 模型协议编译与运行参数适配

将**已经确认的创作语义**转换为当前 H3 协议、实际素材绑定和有证据的运行参数。先固定计划、素材和后端版本，再编译；发现能力不匹配时返回具体诊断与责任方，保留原计划。

实现 M11 及四个可独立调用的子模块。兼容用户资料或外部投影可以直接满足输入；无需为了使用某一子模块先执行全部上游。子模块只产生自己的分区，父模块核对原请求、版本、来源和组合关系后接受。

| 了解某版本究竟支持什么 | M11.1 | CapabilityProfile | 能力与版本 |
| 决定输入模式、素材顺序和标签 | M11.2 | 模式与序列化绑定 | 模式与素材绑定 |
| 生成纯模型字段和可追溯正文 | M11.3 | 提示词编译结果 | 字段编译、官方映射 |

Agent 负责理解语义、落实上游计划、写出完整英文画面与声音描述，并核查模型正文保真性。脚本负责公开合同内可确定的结构、编号、引用、时间、字段、参数映射和接受规则。`assets/` 是可复制的工程模板；它们不证明真实部署能力。

## 2. 固定最小输入与证据

取得任务 ID、当前计划版本、目标生成段、实际可用素材及用途、必要创作约束、目标后端／模型／工作流版本。按本次职责只读取必要投影。区分实际已提供、用户声明、待提供、文字来源、作者报告和媒体观察；不能把文件名或案例叙述当作已查看的媒体。

将上游原生对象适配为本包公开输入时，保留来源定位、版本、稳定 ID 和字段关系。这个显式投影不等于 M1—M10 的所有原生 JSON 可以不经适配直接拼接。不要改写它们的领域权威对象。

能力资料可以先于完整创作计划提供。运行参数未知不妨碍有充分输入的协议文字工作；它会阻止声称任务包已适用于某个实际工作流。对时长、分辨率、帧率、参考数量、上下文和 token 限制，只有对应版本的证据才能确立数值边界。

## 3. 执行四个子职责

1. **M11.1 固定能力。** 记录模型、后端、工作流和协议版本，以及每项能力的来源。把支持、不支持、未知分开。保留官方协议说明与实际部署字段的区别；案例参数不升级为官方硬限制，合成 profile 不升级为真实运行证据。
2. **M11.2 选择模式与绑定。** 先判定素材承担身份／动作等参考、真实首帧／尾帧、视频编辑／续接／时间结构、音频复制／参考的哪一种角色，再选择模式。保留 M2 的实体和资产 ID；生成的类别编号只是本次请求的序列化结果。音频轨只有被明确启用才产生 Audio 绑定。
3. **M11.3 编译字段。** 读取已协调计划，组织真实镜头、动作过程、画面状态、摄影、声音和参考生效点。按所选模式输出精确字段集合，展开独立任务需要的公共上下文，解析稳定 ID，生成局部 Shot 和实际发声顺序的 S 编号。逐项保留必保信息、台词和可见文字，附独立追溯记录。
4. **M11.4 映射参数。** 将已确定的时长、尺寸、帧率、模式、素材和正文映射到本工作流有证据的输入位置。核对文本、素材顺序、计划时间与参数一致。资料不足就输出明确缺项；不猜控件名、不靠提示词代替真实参数、不自行截短、裁剪、变速或增减镜头。
5. **父 M11 接受。** 对照真实原请求、基版本、来源和独占分区原子接受本次提案。局部调用只接受局部；不把没有运行的其他子模块标为完成。已接受内容的相同重试应幂等，创作修订使用新请求和当前版本。

## 4. 对应 H3 官方输入

| 模式 | 主正文 | 必须处理的输入关系 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 无图像对齐首行，文字构成完整音画时间线 |
| I2VA | 同上 | 官方首行；Picture 1 是 0 秒、Shot 1 的实际首帧 |
| FL2VA | 同上 | 官方首尾帧首行；Picture 2 落在实际末镜和有效时长 |
| L2VA | 同上 | 官方尾帧首行；Picture 1 落在实际末镜，不默认是开头 |
| Ref2VA | `detailed_description` | 六字段；定义、摘要、保留分析与正文使用一致参考关系 |

基础四模式另有 `overall_soundscape`、`non_diegetic_music`。Ref2VA 按序输出 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。内部 profile、编译诊断、运行参数、合同和追溯表不加入这些字段。

四类官方 Label 分别为 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`。Subject 是可复用内容单元，不是图片编号；Picture 是帧／构图／分镜锚或来源；Video 是整段编辑、续接或时间结构来源；Audio 是实际复制或参考的声音信号。四类标签与 `(Sx)`、`[Shot N]` 各有独立语义，不能相互推导身份。

第一镜不加切点时间戳，后续真实镜头使用递增的 `At MM:SS.mmm`。基础模式风格写在 Shot 1 内，Ref2VA 整体风格写在 Shot 1 之前。完整原词写在 `<d>` 内；编排说明和声音身份写在外部。参考音频原词的标点规范化必须保留变换依据，不把身份／音色参考的源台词偷带到目标作品。

## 5. 审计与回传

先检查结构，再检查语义，最后说明执行边界：

- **结构与绑定：** 模式、字段集合、首尾帧首行、实际素材顺序、标签定义、作用域、镜头切点、说话者及必保信息追溯一致；未解析引用或占位符阻止正式输出。
- **语义与权限：** 对照原计划逐镜确认谁在何处完成什么事件、动作怎样起始和结束、观众看见／听见什么；确认没有因格式或长度要求删除动作、换角色、改原词或增加未授权内容。脚本不能代替这一步。
- **声音分层：** `overall_soundscape` 概述环境与物理声，`non_diegetic_music` 概述观众配乐；对白／演唱及其同步、音色和发声执行要求写在对应逐镜正文。完整原词只写在该正文的 `<d>` 中，交付前逐字段复查。
- **运行参数：** 使用明确的版本与字段证据，检查正文时长、图像锚点、任务参数与素材清单相符。`fully_copy` 的完整最终音轨不能同时再增删替换音层。
- **产物分离：** 模型正文只包含本模式要求的内容；诊断、证据、追溯、缺项、Gate 状态和制作备注留在伴随记录。官方要求的 `retention_analysis` 属于 Ref2VA 格式，不等于可以输出内部推演过程。

纯协议问题回 M11；资产与权限回 M2；场景／动作／摄影／声音／视觉问题分别回 M3／M4／M5／M6／M10；排时回 M7；跨镜状态回 M8；分段、裁剪和装配回 M9；意图变更回 M1。M12 接收核对对象、计划版本、编译结果及待验证范围；一次路由记录不代表被路由模块已经执行。

## 6. 核验与交付

先读公共合同，再运行包内脚本的 `--help`。按需使用 `route`、`propose`、`check`、`accept` 和 `impact`；精确参数及五模式可运行样例见合同指南。运行依赖仅为 Python 3.10+ 标准库；脚本只输出 JSON，不启动推理、不修改输入文件。

交付当前职责对应的版本化能力资料、模式与引用映射、纯 H3 提示词、独立参数任务包、诊断和语义追溯。对于局部工作，明确已经核对什么及仍缺什么。

分别报告机器合同／结构检查、Agent 语义审阅、实际后端执行和生成媒体检查。文字编译成功不能升级为完整 G2 通过；没有执行证据时，不宣称工作流已经运行、人物一致性已达成或 G3／G4 已通过。
