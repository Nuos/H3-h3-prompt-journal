# M11.4 运行参数与任务包导出

**核心摘要：** 把计划值映射到有版本证据的实际输入位置，并将纯提示词、素材绑定、运行参数和诊断分别交付。导出不执行工作流。

**关键结论：** “提示词写了 8 秒”不等于后端收到 8 秒；未知字段不能猜；模拟任务包不能标为真实运行就绪。

**关键词：** 参数映射、工作流版本、素材顺序、时长、任务包、未执行。

**目录导航：** 1. 输入与产物；2. 一致性检查；3. 导出状态；4. 交接。

## 1. 输入与产物

读取本次任务、选定模式、素材序列、已编译字段／正文、有效生成时长、目标宽高和帧率，以及与目标后端／模型／工作流版本相符的能力和参数映射。兼容外部结果可独立提供这些输入，不要求先运行其他三个子模块；必须保留它们的版本与来源。

任务包至少区分以下内容：

| 内容 | 作用 | 写入位置 |
| --- | --- | --- |
| 纯提示词／模式字段 | 供模型解释音画内容 | profile 明确指定的提示词输入 |
| 模式、时长、尺寸、帧率等 | 实际生成参数 | 有证据的工作流参数位置 |
| 素材清单及顺序 | 供执行方加载真实输入 | 有证据的媒体输入位置及伴随绑定表 |
| 追溯与诊断 | 核对版本、缺项、检查范围 | 伴随记录，不进入模型字段 |

参数名、路径、类型、枚举或范围均属于部署适配资料。不要把本包示例中的键名写成“MiniMax H3 统一 API”；不同 ComfyUI 节点、推理脚本或包装服务可具有不同输入契约。

## 2. 一致性检查

1. 核对正文的目标任务、profile、模式及素材绑定与导出输入一致。换了 profile、素材顺序或模型版本后，旧编译结果不能被直接当作新结果。
2. 核对运行时长与 M7 生成局部时长、首尾帧首行和最终切点一致。不能通过四舍五入悄悄改变时刻；若表达精度不兼容，向 M7 请求明确量化方案。
3. 核对尺寸、帧率与 profile 中有依据的取值条件。无法证明支持不等于证明不支持，返回未确认状态及所缺资料。
4. 核对资产 ID、版本、通道、顺序与实际传入的绑定表一致；Subject 内容标签不能被误当成文件槽位。
5. 核对参数映射目标唯一且无相互覆盖。来源未定义的参数不自动补 seed、采样步数、CFG、音频时长或裁剪策略。
6. 对 ComfyUI 一类图工作流，检查参数输入是否由连线覆盖保存的 widget 值，追踪实际数据源及分支启用状态。静态表达式的算术结果只说明配置关系，不证明某次推理使用了该路径；注释与保存配置有冲突时保留两者并请求核验。
7. 保留来源音轨窗口与目标音轨策略。新增、删除、替换任何声音层时，不再宣称完整 `fully_copy`。

这些检查面向显式数据。任意自然语言中的额外数值、真正媒体长度、实际控件类型和推理实现效果，仍需相应的语义或运行核验。

## 3. 导出状态

官方提示词快照本身不提供本地部署字段证据，因此协议资料充分时可完成文字编译，实际参数映射仍可能阻塞。不要用空字典或“默认配置”掩盖这种缺项。

合成 profile 和工程夹具只证明本包的映射逻辑可运行，任务包应保留模拟状态。实际部署资料明确时，可以产生供执行方审阅和加载的任务包；成功导出依然不表示 H3 已执行、素材已成功加载或视频已通过验收。

## 4. 交接与修订

向执行方交付实际正文与参数包，并提供计划、profile、素材和编译结果的版本引用。向 M12 提交纯文本保真、模式绑定、参数一致性已检查的范围，以及媒体／运行尚未验证的范围。

运行能力冲突回 M9／M7；角色、声音、摄影或剧情变动分别请求领域责任方。修订后按真实依赖重编相关部分，不靠修改日志把旧任务包重新标为有效。

**依据：** 冻结框架 M11 与工作流路由的正式编译／G2 要求；具体案例中参数和模型文本分离的证据见 `case-evidence.md`。机读字段以本包合同为准。
