# M11 审计、失败回传与失效传播

**核心摘要：** 审计结论绑定具体输入、计划版本和检查范围。格式、语义、工作流执行、媒体效果分别记录；问题返回拥有相应决定的模块。

**关键结论：** 编译成功只说明已经完成的检查；失败不修改原计划；变更按实际依赖重验。

**关键词：** G2、原子接受、保真、未验证、责任路由、版本失效。

**目录导航：** 1. 检查矩阵；2. 回传责任；3. 版本与重试；4. 交付清单。

## 1. 检查矩阵

| 层次 | 核对内容 | 证据与结论边界 |
| --- | --- | --- |
| 合同结构 | 请求目标、字段所有权、来源、基版本、真实请求与提案一致 | 对当前 JSON 数据有效，不证明来源陈述真实 |
| 协议编译 | 五模式字段、对齐首行、编号、引用、镜头切点、可解析标记 | 只覆盖已实现的显式规则，不能取代语义理解 |
| 内容保真 | 原计划的角色、动作、声音、状态、视觉与必保信息 | Agent 对照具体计划与正文审阅；追溯 ID 本身不是语义证据 |
| 参数适配 | profile 版本、目标字段、值域、素材与时长一致 | 对资料声明的映射有效；没有实际调用不写“运行通过” |
| 媒体与成片 | 身份、动作、声音、节奏、连续性和最终装配 | 需要 M12 的媒体观察与测量，本轮文本工具不执行 |

G0 关注输入与证据；G1 关注协调计划；M11 的文字和参数产物进入 G2。G3／G4 需要真实媒体与成片。仅凭 `route`、`check` 或 `accept` 不得升级全部 Gate 状态。

保留五种审计状态的语义：`pass` 只覆盖确实检查并满足的要求；`fail` 表示已发现违反要求；`unverified` 表示相关证据或执行不足；`not_applicable` 需要依据证明本项确实不适用于当前任务，不能用来代替缺字段；`stale` 表示依赖变化后旧结论已失效。命令的技术执行状态与这些专业审计状态分别记录。

## 2. 失败回传责任

| 问题 | 首要责任方 | M11 应附内容 |
| --- | --- | --- |
| 选错模式、字段混用、标签序列化错误 | M11.2／M11.3 | 模式、字段／绑定位置、期望协议及原文依据 |
| profile 或参数映射缺证据 | M11.1／M11.4 与资料提供方 | 后端／模型／工作流版本、具体缺项 |
| 缺素材、身份或参考属性越权 | M2 | 资产／实体 ID、属性、作用范围、冲突来源 |
| 无法保持必保意图 | M1 | 被影响的意图和无法实现的条件，不自行降级 |
| 位置／空间矛盾 | M3 | 相关主体、空间状态及引用 |
| 动作丢失、因果跳跃、不可达结果 | M4 | 必保事件、起点过程终点及冲突片段 |
| 镜头不能看清必保动作 | M5 | 当前构图、遮挡和观看条件 |
| 台词、实际声源或音轨策略矛盾 | M6 | 原词、说话者、Audio 角色和声音层 |
| 生成局部时间、时长或帧量化不一致 | M7 | 所有时间域的值、映射版本及允许误差 |
| 首尾态／跨镜持续不相容 | M8 | 前态／后态、许可及边界类型 |
| 需要拆段、改切点、裁剪或装配 | M9，时间协同 M7 | 能力冲突、受影响任务及必要规划选择 |
| 风格、光源、调色、材质错写 | M10 | 有效范围、上游决定及编译差异 |
| 实际视频是否实现要求 | M12 | 精确计划版本、编译产物和待核对范围 |

每个问题保留可定位路径、原因、责任方和下一步。路由只输出调用信息，不自动运行其他技能，也不改写其他模块字段。

## 3. 版本、重试和失效

检查提案时必须提供真实原请求。父模块只接受请求授权的子分区；拒绝越权字段、同批竞争写入、过期基版本和同一来源版本的内容漂移。批次失败保持输入状态，不输出半接受版本。

相同已接受 ID 与完整内容的技术重试应返回同一状态；改内容须新请求、新提案及当前基版本。不能复用旧 ID 替换人物或参数后仍声称幂等。

能力变化影响实际消费它的模式／导出；绑定变化影响引用它的正文／任务包；正文变化影响任务包。输入有显式依赖才传播失效，不因某模块存在就宣称已经调用它。已经失效的依赖不能被下游重新引用为 current。

显示标题变动如果不改变被读取的计划值，不应导致整部作品重编。反之，删除依赖记录不能使已经失效的产物恢复有效。摘要只帮助发现内容变化，不是来源真实性签名。

## 4. 交付清单

交付所完成职责的产物，并记录：目标和基版本、资料来源、检查命令与退出状态、已验证关系、未解决问题、责任模块、语义审阅范围、运行／媒体未验证项。模型正文与这些记录分开。

对于合法协议但当前机读合同未覆盖的表达，报告“当前实现需扩展／需人工处理”，不要误报“MiniMax H3 不支持”。对于完整工作流尚缺少参数资料，交付可核对的文字编译成果并具体列出导出缺项。

**依据：** 冻结框架 M11／M12、五关卡、唯一写入责任、公共合同和路由原则。与脚本实际检查范围一致的例子见本包合同指南与仓库 M11 验证记录。
