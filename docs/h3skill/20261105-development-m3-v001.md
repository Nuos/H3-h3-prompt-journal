**技能：** `h3-scene-blocking` v0.1.0；模块公开合同 `1.0.0`。

## 核心摘要

本次交付第三核心模块 M3。运行包位于 `docs/h3skill/h3-scene-blocking/`，包含技能入口、三个子模块的专业工作流、公开合同、离线工具、可复制样例、案例证据和 H3 官方输入映射。核心输出是 `SpatialPlan`：在明确坐标和空间关系的条件下，描述实体站位、移动路径、交互区域与遮挡要求。

本次同时落实两个层面的“可用”：Agent 可以按技能完成职责内的空间编排／审计；确定性工具可以对请求、提案和组合草稿执行其已实现的结构、引用、版本及空间关系检查。真实几何避碰、摄影投影、H3 生成和成片质量仍需要相应数据与实际执行证据。

## 关键结论

1. 第三模块按冻结框架原义实现，三个子模块 ID、名称及责任不变；M3.3 发现站位问题时向 M3.2 提案，父 M3 保持唯一接受路径。
2. M3.1、M3.2、M3.3 可接受各自最小兼容输入独立工作；独立子模块能力不要求复制三套安装包，也不强制执行全部上游。
3. 稳定角色不等于固定画面槽位；世界方向、身体左右和屏幕方向分别解释。路线可达、时间可行、身体无碰撞和镜头可见是不同检查结论。
4. H3 映射覆盖五种模式、基础三字段、Ref2VA 六字段及四类参考 Label。M3 供给空间语义，M11 负责最终模式、标签与正文编译。
5. 领域依据限于用户指定案例集合及当前任务，官方资料只用于协议与技能格式。局部“禁跨中线”等规则保留冲突和适用范围，不设统一人物数量限制。
6. 已有 M1、M2 运行包、原案例、旧验收记录及冻结方案保持原内容；本次只增加 M3 交付并更新 `docs/h3skill/README.md`。

## 3. 高内聚、低耦合、模块化与路由

| 原则 | 本次落实 | 需要实际检查的条件 |
|---|---|---|
| 高内聚 | 三个子模块按空间基础、实体路径、互动关系划界 | 提案只含自己拥有的分区；跨域需求通过修改请求交接 |
| 低耦合 | 公开最小投影、来源和版本；外部兼容输入可替代上游生产者 | 无兄弟目录运行依赖；独立复制包仍能调用 |
| 模块化 | 父／子节点分别登记输入、输出、依赖、权限、检查和未验证范围 | 独立、组合、缺输入、冲突和不兼容任务均有运行证据 |
| 路由 | 显式目标、进入条件、资源、返回点、失败与修复目标 | 不把 `route` 当作自然语言自动调度器，不以记录代替真实执行 |

`route`、`check`、`accept`、`impact` 围绕本模块的合同工作。子提案能够独立检查，不意味着任何父状态都可以直接接受；父接受还要核对实际组合候选、依赖投影、来源、基版本和相互引用。

对同一分区的竞争候选、过期版本、越权内容和无法解释的引用应返回诊断。对尚缺摄影、尺寸或时序的数据，应标明具体未验证范围，不能把缺数据悄悄变成“没有冲突”。

## 4. H3 模式、字段与 Label

### 4.1 五种输入模式

| 模式 | M3 编排任务 | 空间审计重点 |
|---|---|---|
| T2VA | 从文字目标建立场景、站位、路线和互动 | 不虚构参考资产；明确方向参照 |
| I2VA | 从真实首帧的空间关系向后发展 | 身份参考与真实首帧的用途不能混淆 |
| FL2VA | 连接首尾帧空间端点 | 有可观察中间路线，不只复述两张图 |
| L2VA | 从相容前态收敛到尾帧 | 尾帧不能倒填成开场状态 |
| Ref2VA | 按属性授权组织空间参考及逐镜变化 | 明确谁、在哪里、何时、参考什么及哪些属性不继承 |

### 4.2 字段与标签

基础四模式为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。空间内容主要进入第一个字段；两个声音字段由 M6 处理已知声源和声层，M3 不据“自己没有声音数据”填成静音。

Ref2VA 六字段依次为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。M3 的逐镜空间内容进入 `detailed_description`，不混用基础模式主字段。

| 官方 Label | M3 相关用途 | 必须区分 |
|---|---|---|
| `<Subject N>` | 人物、道具、场景等实际复用内容 | 内容身份与源文件／站位槽位 |
| `<Picture N>` | 实际首尾帧、关键帧、构图或分镜锚点 | 具体画面用途与纯外观来源 |
| `<Video N>` | 编辑／续接源或整体摄影、剪辑、时间结构 | 全局视频关系与其中具体可见内容 |
| `<Audio N>` | 明确复制或参考的音频信号 | 声源位置与声音用途、视频内存在音轨与启用音轨 |

空间 ID 不成为新增官方 Label。M3 的内部图连接也不是 H3 官方提供的三维空间求解器。逐字段、逐 Label 的编排要求、审计问题及精确官方原文定位见专门映射文档。

## 5. 案例提炼与冲突保留

本轮可用清单为 29 案、98 个文本文件，重点仍为 10 月文本。索引区分完整读取、相关段落读取和仅清点，不能把全体文件哈希清单当作全部文件已经语义审阅。实际使用范围、摘录和来源固定在 `case-index.json` 与 `case-evidence.md`。

领域提炼索引中 12 个文件读取了相关段落、86 个文件仅作清点；共登记 11 组规则和 10 项冲突／歧义，额外的独立试用读取另行记录。主要提炼关系包括：四人队形的稳定身份与动态站位分离、逐人路线和层次变化；物理机位库对实体位置与观察方向的区分；三镜右入画的空间区域与出入画连续；触地切换的接触位置及可见结果；水上闯关的可达平台、支撑与接触关系。

四人队形案例中，README 的“各守区域／不跨中线”与具体 SEG 10 的中心交叉、前后层交换不能同时作为无条件规则。保留差异，依据当前明确任务确定范围；没有依据时提交冲突，不静默选择一个版本。固定人数、固定景别和动作幅度同样不推广为全局限制。

从案例到合同的 ID、分区、JSON、版本和脚本是本次 D 类工程细化。原文中的提示词要求、作者报告和本次实际执行分开记录。本轮未读取案例图片／视频，不以原作者的成功表述代替本次媒体验收。

## 6. 技能标准与文件组织

运行包遵循 Anthropic 仓库采用的 Agent Skills 结构：`SKILL.md` 必需；`scripts/`、`references/`、`assets/` 按本包实际需要提供。不能把三个可选目录说成所有 Skill 均必须存在。

`SKILL.md` 仅使用 `name` 与 `description` 前置字段，名称与目录匹配；description 同时说明任务和触发情境。主体保留核心流程和资源路由，详细领域规则、合同与原文按需读取。每个运行参考文件在入口有直接路径和读取条件；不靠多层隐含跳转寻找规则。

运行包不塞入开发 README、测试报告或安装说明。测试、文字试用、来源核验和发布工具位于外层 `tests/m3/`、`validation/m3/`、`tools/`。官方原文快照保持原字节，来源、许可和归属在独立记录中保存。

本次是用户指定 GitHub 仓库中的技能开发与提交；没有进行用户个人技能目录安装。宿主是否自动触发此技能也需要独立验证，不能从目录规范检查推断触发率。

最终执行数据由以下记录给出，不使用旧模块历史报告冒充本次结果：

- `tests/m3/`：M3 合同、版本、引用、权限和组合行为测试。
- `validation/m3/delivery-checks.json` 与 `logs/`：实际命令、返回码、M3 测试、M1／M2 回归、官方基础格式检查和隔离目录运行。
- `validation/m3/forward-use/`：基于原始案例的 Agent 文字试用、实际读取的输入／技能资源及来源哈希。
- `validation/m3/source-check.json`：冻结文件及控制记录、H3 两份原文与 GitHub blob 的字节核对。
- `validation/m3/release-check.json`：本轮文件清单、来源完整性和变更范围的发布核验。

从仓库根执行：

```bash
python docs/h3skill/validation/m3/run_delivery_checks.py
python docs/h3skill/tools/verify_m3_release.py
```

第一条会重新运行检查并写入本轮验证日志；重跑后时间、运行环境或日志文本可能变化，因此固定发布清单仍用于核验原发布快照，不应为了掩盖差异自动重算。第二条默认只读，`--write-manifest` 仅用于维护新的、有记录的发布快照。

### 实际案例试用

两次试用分别覆盖完整空间文字审计与独立子模块构造：四人队形试用输出四人阶段路线、交互／遮挡要求及 11 项差异审计；水上闯关试用独立构造 M3.1 的五区域拓扑，并实际执行 route 与两个 check，三次均通过局部合同，整体保持未验证。

试用过程中的资源暂缺、继续交付指令和一次错误路径读取均如实记录，不能称为无干预盲测。四人试用未运行合同脚本；水上试用的最终资源及输入摘要已核对。详细结论及限制见 [发布前审阅记录](validation/m3/review.md)。

### 分层判定

| 层级 | 可证明内容 | 尚不能证明 |
|---|---|---|
| 官方基础格式 | 元数据与命名满足验证器已检查条件 | 专业方法正确或自动触发可靠 |
| 合同／关系检查 | 已实现形状、版本、引用、分区和空间关系通过相应测试 | 实际几何无碰撞、输入陈述真实 |
| 隔离运行 | 包不依赖兄弟目录即可执行已测试命令 | 所有未来输入或所有宿主兼容 |
| Agent 文字试用 | 所记录任务上实际使用技能完成的空间编排／审计 | 通用成功率、实片效果或未做的盲测比较 |
| 来源与基线 | 固定文件和本轮范围可复核 | 媒体生成、观察或商业授权已经完成 |

## 8. 能力边界、发布与来源

该版本是有工作流、合同和可执行局部检查的 M3 首版。没有构建完整视频逆向系统、通用碰撞引擎、相机投影求解器、M7 排时器或 M11 编译器；没有调用 H3 或观察生成媒体。未知与未验证内容在交接中保留，后续模块不能把它们当作既定事实。

M3 运行脚本使用 Python 3.10+ 标准库；官方开发验证器的依赖与可选测试依赖以实际执行记录为准。包内外部文档保留各自许可，不由仓库 MIT 许可重新覆盖。

本轮发布清单只覆盖 M3 新增产物及总 README；它不重写 M1／M2 的历史清单。冻结方案、原案例与既有运行包的完整性由新核验器独立检查。
