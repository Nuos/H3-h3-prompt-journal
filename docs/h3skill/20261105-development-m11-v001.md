## 核心摘要

本轮完成第十一个核心模块 **M11「模型协议编译与运行参数适配」**，目录为 `docs/h3skill/h3-model-protocol/`。它将已协调的创作计划编译为五种 H3 输入模式的字段、参考绑定和纯模型正文，再按明确版本的运行资料映射参数及素材。四个子模块均有公开最小输入、独占输出分区和独立调用方式。

实现同时提供 Agent 的编排／语义审阅要求，以及 Python 标准库的确定性合同、编译、参数映射与父接受工具。程序不会凭任意散文自动完成导演工作；它消费已确认英文片段、原台词和显式参考关系。能力不足或语义冲突返回对应责任方，不能靠改剧情、缩动作或删台词使格式检查通过。

官方提示词语法与实际工作流能力分别记录。只取得官方提示词资料时，能力登记、素材绑定及正文编译可以完成；运行版本、字段、单位或素材槽位未知时，不制造可执行的任务包。模拟参数仅验证接口，实际后端、媒体和生成效果仍须另行验证。

## 关键结论

1. M11.1—M11.4 均可通过兼容输入独立调用，不要求先执行 M1—M10 或所有兄弟子模块。
2. 官方对齐首行放在完整提示词最前方，独立于基础三字段；Ref2VA 保持精确六字段。运行文本映射使用完整 `rendered_prompt`，不会丢失首行。
3. Subject、素材类别、真实 Shot 和实际发声顺序分别编号；身份图片不自动变为首帧，视频不自动启用同步音轨。
4. 复制完整最终音轨与“复制完整配乐再增加对白／效果”分别处理；直接复用音轨中的原词，与本片新生成的发声也分别声明。
5. 父接受核对真实原请求、来源和基版本，保留不可变接受记录；依赖变化后旧编译或旧任务包不能无声恢复有效。
6. 本轮保护除共享索引外的 **1694 个既有文本／代码文件**；M1—M10、历史案例、冻结方案及历史验收记录保持原字节。M12 仍待实现。

**关键词：** M11、CapabilityProfile、CompilationResult、五模式、Label、语义保真、素材顺序、运行映射、版本、来源、独立调用。

| --- | --- | --- |

## 4. 官方模式、字段与 Label

### 4.1 五种模式的编排与审计

| 模式 | 正文结构 | 核心编排／审计要求 |
| --- | --- | --- |
| T2VA | 基础三字段 | 无图像对齐首行；从文字形成完整音画时间线 |
| I2VA | 对齐首行＋基础三字段 | Picture 1 是零时刻 Shot 1 的实际首帧；身份图不能替代这一事实 |
| FL2VA | 对齐首行＋基础三字段 | 输入按真实首帧／尾帧排序；尾帧落在实际末镜和有效时长；采用官方无尖括号／方括号句式 |
| L2VA | 对齐首行＋基础三字段 | Picture 1 是有效时长处的尾帧；末镜不默认为 Shot 1 |
| Ref2VA | 六字段 | 定义、任务摘要、保留分析、逐镜正文与音频关系使用一致标签；摘要以实际任务类型组合起始 |

基础三字段依次为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。Ref2VA 六字段依次为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。

`alignment_instruction` 是本地结果的伴随属性；有需要时，它位于完整 `rendered_prompt` 的第一行，后接空行与正式字段。它不是第四个 H3 字段，也不塞入 `integrated_multimodal_description`。

第一镜无切点时间戳；后续实际镜头使用生成局部时间 `At MM:SS.mmm`。基础模式的整体风格写在 Shot 1 内，Ref2VA 写在 Shot 1 之前。工作参数、内部 ID、追溯、测试结论及 Gate 状态不进入模型正文。

### 4.2 Label 与实际声源

| 标记 | 编排对象 | 必须避免的错误 |
| --- | --- | --- |
| `<Subject N>` | 可复用的可见内容，包括人物、环境、道具、风格或动作 | 不等同图片或文件编号；同一主体可有多个来源，同一来源可贡献多个主体 |
| `<Picture N>` | 具体目标帧、构图／分镜锚；或 Subject 的图片来源 | 只提供身份／服装的图片在 Subject 内注明来源，不另设无用的独立保留条目 |
| `<Video N>` | 编辑源、续接起点或整段摄影／剪辑／时间结构 | 从视频抽取的人物、物体和动作仍属于 Subject，不因此继承所有源内容 |
| `<Audio N>` | 实际复制或参考的声音信号 | 视频有声音不等于启用音轨；与 Video 独立编号，需明确通道 |
| `(Sx)` | 按实际发声先后编号的独立声音源 | Subject 2 可以是 S1；直接复用 BGM 中的语词提示不自动新增人物声音源 |
| `[Shot N]` | 当前生成任务内的实际镜头 | 动作阶段、编辑片段或素材数量不直接变成切镜数量 |

台词、歌词及可见文字保持原语言。基础模式保留原词与标点；Ref2VA 源音频的标点规范化须记录原文和变换，不能改词或猜听不清内容。完整听见的词语进入逐镜 `<d>`，不塞进参考定义或声音汇总。画外音、跨切同句和视频末尾截断分别按官方短语、`<scenetrans>` 和 `<cutoff>` 处理。

`fully_copy` 表示完整原信号就是完整最终音轨；完整配乐上再加本片对白或声音效果时属于 `partially_copy`。原音轨已经包含的对白／歌词不是新增声音层，须保留其来源。`overall_soundscape: N/A` 仅用于全片完全静音；配乐不存在只影响 `non_diegetic_music`，不能删除环境或人物声音。

官方 Ref2VA 的通常字数建议不实现为硬截断、token 限制或删减语义的依据。逐项规则与固定官方行号见 [h3-label-mapping.md](h3-model-protocol/references/h3-label-mapping.md)。

## 6. 合同、来源、状态与运行边界

### 6.1 架构要求的落地

| 原则 | 实现 |
| --- | --- |
| 高内聚 HC | 能力、绑定、正文和导出分开；每个子模块只写一个专业分区 |
| 低耦合 LC | 最小公开输入、自足外部投影、显式来源与依赖；单目录隔离运行 |
| 模块化 MD | 父／子身份、合同、版本、权限、资源、消费者和兼容策略统一登记 |
| 路由信息 RT | 显式 target、输入映射、前置条件、返回对象、失败责任和重试语义；路由不冒充调用 |

### 6.2 可追溯与可重放

请求、结果和状态保留版本。`check` 依真实原请求重算；JSON 的数值和布尔值按规范化内容区分，不能利用 Python 中 `False == 0` 冒充同一提案。专业产物的 `evidence_snapshot` 绑定实际消费来源的版本与内容摘要，防止独立下游换来源却复用旧绑定。

相同请求和提案重试保持幂等；新的修订必须有新 request_id 和当前 base_version。父接受核对所有候选后一次生效；错误不返回部分接受状态，不修改任何输入文件。来源的同 ID／同版本不能换内容。

原始请求与提案进入不可变收据。状态中的内容、上下文、来源、版本与收据互相闭合；不能删除分区、改写来源、修改 stale 标志或假造 partial 状态来绕过原始记录。依赖失效按实际来源读取与 profile／binding／compilation 指纹传播。

来源摘要证明声明之间是否变化，不验证外部文档、媒体或生产能力的真实性。`consumers` 在本版本地状态中不激活外部系统；M12 和执行方通过显式交付取得结果。`impact` 的 JSON 差异与 `accept` 的已接受分区失效检查是两项不同能力。

### 6.3 实际参数适配范围

当前协议语法固定于 MiniMax 官方提交 `199b7d0e1fd95e7b3eafa8c15eca692534142427`。其他语法版本不得只换版本号后继续使用旧编译器。运行资料按模型／后端／工作流版本另行登记；案例中的时长和分辨率不是通用硬上限。

导出器支持显式对象 JSON Pointer 或单个字面字段名；数值的类型、单位、枚举与范围来自 profile。时长必须等于已编译计划；毫秒／秒换算保持可表示的精度，字段路径不允许重叠覆盖。素材映射必须完整对应实际已绑定的资产版本。

本版要求 `runtime.prompt.format: text`，映射完整 `rendered_prompt`；`runtime.media.format: ordered_channel_objects`，映射含值、通道、标签和序号的有序对象列表。它不是任意 ComfyUI 图解释器，也未实现所有后端专用封装、数组路径、加载和上传操作。遇到未实现但合法的 H3 表达或后端布局，应保留语义并明确适配缺口，不能误报成 H3 本身不支持。

模拟映射保持 `simulation_only`；生产声明须引用部署／工作流来源，仍输出 `exported_unexecuted`。字段齐全不代表已运行。运行未知返回 `runtime_unknown`，同时保留已经完成的正文与原始目标参数。

### 7.2 审阅中修正的问题

1. **首行位置及导出遗漏。** 将 I2VA／FL2VA／L2VA 对齐语句移至字段之前，用完整 `rendered_prompt` 导出，防止分字段映射丢失必需首行。
2. **引用含义与编号。** 补齐摘要官方任务类型前缀、独立类别编号、显式音频通道、逐镜作用域和真实发声时间；拒绝把身份来源当作独立帧参考。
3. **来源和历史状态闭合。** 把实际消费证据纳入结果指纹；收据与来源、上下文和内容互相核验；拒绝复用历史请求 ID、清除 stale 伪装重验以及布尔值冒充整数版本。
4. **完整音轨中的已有原词。** 新增复制来源声明，允许完整原音轨本身已包含的对白；新增／重演声音仍与 `fully_copy` 冲突。
5. **纯配乐语词提示。** 移除把歌词放入参考定义的旧入口，实际语词进入详细正文的 `<d>`；Audio-only 提示与真实人物／旁白声音源分别表示。
6. **语义与字符串检查的界限。** 删除以全文子串匹配判定“台词重复”的规则。短词或标牌恰好与对白同词可以合法存在；脚本限制明确的结构位置，自然语言语义由 Agent 审阅。

上述修订后保留最初 63 项行为用例，增加 11 项音频来源与结构位置正反例，形成最终 74 项。独立只读审计另复验声音来源的目标情形；没有把这次复核与正式测试数累加成另一个“总通过数”。

没有执行 H3 推理、实际工作流、媒体解码、宿主自动触发率测量或完整 G0—G4 认证。没有将声明中的使用许可或运行来源当作本轮独立认证过的外部事实。

### 7.3 新上下文独立使用与监督修订

另以一个全新文字任务检验公开技能的实际可用性：8 秒茶铺双人互动，两张仅提供身份／衣服的图片声明，一段完整配乐叠加新对白和物理声，实际部署字段未知。提供独立技能目录与原任务，没有预先提供模式、编号答案或程序断言。

使用代理构造了真实四路请求并运行公开命令。任务正确选用 Ref2VA；叶青为 Subject 1／S2，罗成为 Subject 2／S1；配乐使用 `partially_copy`，保留完整音乐信号同时承认新增声音层。中文台词、可见标牌、3.5 秒切点、8 秒目标和 1080×1920／24 fps 均保留。17 项必保内容提供正文位置和语义审阅证据。

首轮三个 `check` 已通过，但父审阅发现 `overall_soundscape` 混入对白同步与清晰度要求。使用代理将这两项要求移回相应逐镜正文，以新请求 ID 和已接受 version 1 重跑，并接受为 **version 2／partial**。同时在 `SKILL.md` 审计入口增强声音分层提示，脚本保持不变。这个真实修订说明普通文字的领域位置仍需语义审阅，不能用机器通过代替。

两轮各 **13 次实际 CLI 调用**：每轮 12 次退出 0、1 次 M11.4 `propose` 以 `runtime_unknown` 退出 2。共 26 次调用，2 次预期拒绝不计为成功导出。最终状态只有能力、绑定、编译三个分区，保存两轮 6 条接受收据。父审阅再用最终公开 API 核对三提案、幂等重试、状态历史、实际纯正文和原目标。

发布整理仅清除编译器两处行末空格，保留同一 Python AST；历史执行摘要不被改写。随后父代理针对最终发布脚本另实际运行 5 次公开 CLI，核对三个提案、重放已接受状态并复验 `runtime_unknown`，结果均符合预期。这 5 次复核与上述 26 次任务调用分别记录。

全部首轮字节、最终产物、命令、原始 stdout/stderr、作者安排和修订意见保留在 [独立使用记录](validation/m11/forward-use/README.md)。结论限于这一个文字任务；未测量宿主自动触发率或实际视频完成率。纯文字中暂定的发声起点明确列为作者安排，时长内能否自然完成全部语音和动作仍需实际媒体验证。
