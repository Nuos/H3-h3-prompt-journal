**交付版本：** `h3-visual-look` v0.1.0；模块合同 `1.0.0`。

**日期：** 2026-11-05（America/Los_Angeles）。

**读取仓库基线：** `c8ec1a4e5162ec5179ed9bec99d2f46a437ae67c`。

**冻结开发基线：** `skillplan-v0.1.2-608813b`，固定提交 `608813b6e51531ac47f860bc384a454a504fe9ff`。

## 核心摘要

完成第十个核心模块 **M10「视觉风格、光线、色彩与材质」**，落盘于 `docs/h3skill/h3-visual-look/`。技能依据已锁定方案，提供四个可独立调用的子模块、版本化 `LookPlan`、五种 H3 输入模式及四类参考 Label 的编排／审计映射、案例证据、最小示例、确定性检查和父接受流程。

核心决定是把四类问题分开：全片／场景／镜头继承哪些视觉要求，场景中实际有哪些光源，最终画面采用什么色彩关系，具体对象如何呈现材质及效果。由此避免暖光与冷调被机械互斥、湿发被当成换发色、风格统一被当成重设计角色、独立生成段落丢失公共视觉规则。

本轮交付的可执行能力限于文字工作流、结构化合同、版本／权限／引用／继承关系检查及相关路由信息。真实光照模拟、像素调色、材质仿真、视频生成和实际成片质量不在已验证范围内。

## 关键结论

1. M10.1—M10.4 按冻结职责分别实现，接受兼容外部最小输入，无需顺序运行 M1—M9。
2. 风格层级、照明、调色和材质效果分别拥有独占分区，父 M10 只负责核对原请求、来源、版本及组合关系后接受。
3. 身份／参考权限由 M2 决定；动作可读性与 M5 协调；视觉状态持续交 M8；模型字段和 Label 序列化交 M11；实际媒体观察交 M12。
4. H3 基础四模式主字段为 `integrated_multimodal_description`，Ref2VA 主字段为 `detailed_description`。本模块不新增 Style、Lighting、Material Label 或模型顶层字段。
5. 案例原文事实、作者报告、设计推论和未验证事项分别记录；工程示例不冒充历史案例或视频实测。
6. 397 个既有文本／代码文件纳入保护基线，覆盖 M1—M9 运行包、原案例文本、冻结方案及控制记录、标准快照。历史发布清单与验证记录保留原义。

**关键词：** M10、LookPlan、风格继承、照明、调色、材质效果、独立调用、H3 Label、父接受、来源、版本。

## 3. 案例方法如何进入实现

完整逐案证据及实际阅读范围由 `case-evidence.md` 与 `case-index.json` 记录。本记录只列与 M10 决策直接相关的方法及边界。

本轮盘点 29 个案例目录（其中 15 个为 2026 年 10 月案例），索引 98 个文本文件：案例目录内 97 个，加根层词汇文件 1 个。来源分析选取 6 案例、9 文件，2 个全文、7 个部分阅读，所记范围共 809 行；其余 89 文件只作身份盘点。没有继承前九模块的阅读或验证完成声明。

| 案例／证据主题 | 可提取的方法 | 本轮转化 | 不做的外推 |
| --- | --- | --- | --- |
| 古典武侠十三段、海滩剑舞十八段的公共规则与独立段落 | 作品层维护共同要求，每次生成仍需足够上下文 | 全片／场景／镜头继承、当前任务有效风格展开 | 不把某案冷调或写实偏好变成通用默认 |
| 身份参考与风格参考分离 | 图中身份、衣物、姿态、环境、光色不自动共享授权 | 每次视觉引用核对属性、对象、范围和版本 | 不以“统一风格”为由放宽 M2 权限 |
| 夏日泳池海滩水线案例中的冷暖表述 | 暖光源与冷中性基调需分层；“禁暖”文本需检查具体作用域 | LightingPlan 与 ColorPlan 分开，跨分区语义审阅 | 不把冷暖两个词同时出现当作必然冲突或必然正确 |
| 湿发、湿衣、水面及衣物／道具质感 | 表面状态应绑定对象、条件、持续和可见结果 | MaterialEffectPlan、M8 条件许可与交接 | 不把湿润视为换发色、换发型、换衣物的许可 |
| 白凤、下山及多段案例中的视觉连续与局部要求 | 摘要、局部正文、交接条件需要相互对照 | 风格例外、持续范围、有效上下文和未知项检查 | 不从段落表格存在就宣称所有提示词或成片已落实 |
| 剑舞等案例的观看重点 | 需要先明确当前必须看清什么 | 光效、雾气、反光与 M5 的观看要求协调 | 不要求每个镜头所有对象和部位同时清楚 |

案例文本中的作者效果报告与本轮实际运行证据分开。对本文新增的剧情场景、对象 ID、JSON 合同和反例，均标记为 D 类设计；它们用于验证规则与接口，不冒充已发生的案例实验。

源文矛盾也进入审计：下山面纱独舞的 README 将图 1 限于正面服装／身体，提示词第 34 行却将环境视觉语言归因于该图。M10 记录两处来源、冲突属性及范围，回传 M2／用户确定权威版本；不能借案例之名放宽权限。历史案例中的自定义顶层字段和混用正文名称，同样不能代替固定官方协议。

## 4. H3 模式、字段与 Label

### 4.1 五种输入模式

| 模式 | 本模块主要落点 | 编排要求 | 审计要点 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 第一镜内建立风格；逐镜表达具体光色与材质变化 | 风格词是否掩盖动作／对象信息，是否无中生有引用素材 |
| I2VA | 首帧指令＋基础主正文 | 从实际首帧视觉状态出发，明确后续变化 | 不用身份参考声明撤销真实首帧约束 |
| FL2VA | 首尾帧指令＋基础主正文 | 两端光色／材质状态可衔接，必要变化有过程 | 首尾冲突是否有解释，例外是否得到授权 |
| L2VA | 尾帧指令＋基础主正文 | 前序过程能到达实际尾帧视觉状态 | 不把尾帧放到开场，不凭尾图假定前序事件 |
| Ref2VA | 六字段，主正文为 `detailed_description` | 首镜前建立整体风格；逐镜说明参考作用对象与位置 | 定义、摘要、保留分析和正文是否保持同一角色／权限 |

基础模式三字段依次为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。Ref2VA 六字段依次为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。声音语义属于 M6，M10 不因视觉“安静”自行设为静音。

### 4.2 四类官方参考 Label

| Label | 与 M10 的关系 | 编排／审计边界 |
| --- | --- | --- |
| `<Subject N>` | 可重用的可见内容，可涉及人物、场景、衣物、物件、风格、动作或可见效果 | 先定义所借用内容与属性；不把整份素材所有属性都当成已授权 |
| `<Picture N>` | 具体帧、修改后的帧、构图或分镜规划锚点 | 首尾帧／规划锚点与只提供外观来源的图片分开 |
| `<Video N>` | 直接编辑源、续接源或整体时间结构 | 不因风格来自视频就自动授权编辑／续接或继承所有主体外观 |
| `<Audio N>` | 真实被复制或参考的音频信号 | 由 M6 决定；色彩与氛围词不自动生成音频角色 |

M2 确定参考角色与权限；M11 决定最终序号和序列化。在既定角色内根据实际保留程度选择关系，不能因“只用少数属性”就机械选择 `weak_reference`。不新增 `<Style N>`、`<Lighting N>`、`<Material N>` 或 `LookPlan` 顶层模型字段。

映射使用随包提供的 MiniMax 官方固定版本与行号；历史案例协议与当前固定协议的差别保留记录，不直接把旧案例提示词当作最终协议模板。

## 6. 四项架构原则的落地

| 原则 | 具体实现 | 可复查证据 |
| --- | --- | --- |
| 高内聚 HC | 四个子模块围绕独立视觉结果；父接受不兼任专业重写 | 独占分区、专业规则、越权负例 |

## 7. 实际检查、修订与证据

本轮采用官方格式检查、针对实际风险的行为检查、独立目录运行、Agent 前向使用、普通功能复核和发布完整性检查。精确命令、时间、退出码、脚本哈希及实际结果见 `validation/m10/validation-results.json`，可复现测试入口见第八节。

独立功能复核发现并要求修正以下问题；具体修订结果与定向复验记入 `validation/m10/implementation-review.md`：

| 问题 | 必须保持的行为 |
| --- | --- |
| 空目标集合可能放宽主体限定参考 | 明确空目标是作用域使用；仅授权特定主体的参考不能被扩展到整镜 |
| 只读风格投影可能绕过已有参考限制 | 投影中实际使用的参考仍需最小授权资料，不能将“只读”视为可信且免校验 |
| 新提案依赖 stale 照明／调色后恢复 current | 沿实际依赖传播过期状态；未重新确认的依赖不能令下游有效 |
| 只读照明内可见性记录存在未知作用域 | 同样核对内部关系，不能只检查直接输入而遗漏 sibling 投影 |

这些问题是实现正确性问题，不是从案例推断的模型缺陷。只有完成修复及定向复验后，才能报告对应检查通过。脚本输出始终保留自然语言、真实可见性／连续性、物理照明与 H3 推理未执行的边界。

### 7.2 独立 Agent 文字使用与真实 CLI

使用一个不继承开发历史的 Agent，只提供完整技能包、原始夏日案例 README／提示词和两项任务，没有给出先前审阅结论或标准答案。原始任务、输入、42 文件快照、实际产物及执行记录保存在 `validation/m10/forward-use/`。因长输出截断和落盘延迟，过程中有状态提醒及暂停／继续；随后提示其使用包内最小夹具作为结构参考。这是受监督的独立上下文使用记录，不是无人干预的性能基准。

第一项任务按四个 M10 子职责整理既有 55 秒四段 MV，保留角色、动作、八镜头、四切点与音轨窗口；识别局部暖光／整体冷调的分工、湿发／身份的界限，以及前后段服装授权冲突，并交回 M2。它还把局部音效措辞差异交回 M6，没有越权改写音轨。原作者计划没有被写成本轮观察到的视频结果。

第二项任务是标为 D 类设计的雨夜书店单镜。Agent 拒绝从身份专用图复制调色和为冷调重染发色，提出保留局部暖灯及棕木颜色的 M10.3 候选，保留真实图像和身份色值未知。它只用 `brief` 与 `scope_context` 形成最小请求，实际执行 `route`、`check --request`、`accept --requests`，三条命令退出码均为 0。接受结果是 version 1、仅含 `ColorPlan` 的 `draft`，没有补造其他三个分区。

## 8. 使用、交接与完成边界

在仓库根可以执行发布核验与行为／便携检查：

```bash
python -B -m unittest discover -s docs/h3skill/tests -p test_m10_contract.py -v
python -B docs/h3skill/tests/m10_portability.py
python -B docs/h3skill/_standards/anthropics-quick-validate.py docs/h3skill/h3-visual-look
python -B docs/h3skill/tools/verify_m10_release.py
```

在技能目录内可以执行：

```bash
python scripts/m10_contract.py route assets/request-minimal-m10-2.json
python scripts/m10_contract.py check assets/proposal-minimal-m10-4.json --request assets/request-minimal-m10-4.json
python scripts/m10_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
python scripts/m10_contract.py impact --before assets/impact-before.json --after assets/impact-after.json
```

运行依赖为 Python 3.10+ 标准库；发布时采用的官方格式验证器另外依赖 PyYAML，它是开发验证工具，不是 M10 运行依赖。无付费 API、模型下载或媒体生成是这些合同命令的前置条件。

M10 交付当前分区或 LookPlan、作用域和明确例外、必要 H3 语义、未决项与责任回传。自然语言审阅仍由 Agent 完成；自动脚本不判断审美、不读像素。M11、M12 尚未因本轮增加 M10 而实现；对它们的映射及路由是明确的接口交接，不是端到端执行记录。

没有真实生成片段时，G3 未验证；没有完整成片和装配证据时，G4 未验证。格式或合同通过也不单独等于全部 G0—G2 通过。本轮不宣称视频稳定性提升比例、无闪烁、无风格漂移或宿主自动触发率。
