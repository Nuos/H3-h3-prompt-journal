# M3.3 交互区域与遮挡约束

## 职责与最小输入

明确谁与谁在哪个区域接触、交叉、避让、形成视线关系或允许暂时遮挡。读取对应实体、拓扑、站位路线与当前互动目的；已具备这些兼容输入时可以直接调用本节点。

本节点提案 `interactions` 分区。需要改站位和路线时向 M3.2 发修改请求，不直接修改其分区。动作如何发生归 M4，摄影怎样呈现归 M5，占用时间归 M7。

## 一、把互动对象写成可定位关系

对于每个关键互动，说明参与者及具体角色、发生区域、相关站位／路线、触发条件、接触或避让对象，以及必须可见的结果。例如，道具交接需要说明交付者、接收者、道具和交接区，不能只写“两人配合”。

接触区是空间约束，不是动作已经发生的证明。手触道具、脚触地、人物视线指向等关系应保留动作事件引用，供 M4 补全起态、过程和结果。没有动作信息时只提交空间条件。

## 二、交叉与避让

1. 指明两条或多条相关路线及交会区域，分清几何上可能相交与实际同时占用。
2. 允许的交叉写明通过侧、层次、通行条件或先后请求；不允许的交叉写明局部范围和原因。
3. 避让要求回写为 M3.2 的修订请求；涉及速度、先后或重叠时同时向 M4/M7 交接。
4. 路线不足、宽度未知或时间缺失时保留具体未验证项；不以“保持安全距离”替代尚未确定的空间条件。
5. 写实任务中，人物、道具和摄影机不得通过无解释的穿墙、穿台面或彼此穿透完成计划。若任务明确需要非写实变化，保留该依据及发生范围，不把所有变化都判作错误。

不设置“禁止一切交叉”“禁止一切遮挡”或统一人物数量限制。约束应来自本次任务与案例中可迁移的机制。

## 三、关键可见性与允许遮挡

分别登记遮挡者、被遮挡对象／部位、需要保持可读的接触点、作用视图、适用阶段，以及允许或禁止的具体关系。短暂遮挡可以服务剪辑或动作，但必须能说明何时显露关键结果。

屏幕遮挡是投影关系，不等同世界接触。前景手臂经过人物轮廓并不自动意味着身体发生碰撞；世界空间互不接触也不保证手部或表情在镜头中清晰。

缺少机位、光轴、视场、角色尺寸或实际图像时，只提交 `visibility requirement` 的语义条件。没有摄影证据不能给出已通过的像素级可见性、无畸形或无遮挡结论。具体摄影计划与复核交 M5，真实视频观察交 M12。

若反射、屏幕或其他可见再现参与本次叙事／识别任务，记录其实际对象与关系；是否存在这些对象应由输入决定，不在每个案例中凭空增加。

## 四、声源与视线边界

剧情任务可能需要谁看见谁、谁被谁挡住、画外声源位于何处等条件。M3 提供位置、视线与遮挡要求，M4 决定反应动作，M6 决定说话者和声音事件。画外不等于不存在，人物 ID 也不自动等于 `(S1)` 等说话者编号。

此处不强制关闭口型、不自动复制视频音轨，也不以角色站位决定音频标签。

## 五、局部检查与交接

| 检查层 | 本节点处理 | 保留给下游／观察 |
|---|---|---|
| 结构 | 参与实体、路线、站位、区域和来源引用 | 身份识别是否真实正确 |
| 空间关系 | 互动区与所声明路径／站位的关联；局部禁止关系是否冲突 | 几何碰撞、人体与道具体积 |
| 调度 | 记录明确的交叉、避让、接触和先后需求 | M7 的实际时间占用与同步 |
| 可见性 | 指定必须被看见的部位、结果和作用视图 | M5 的摄影验证及 M12 的实际媒体观察 |

缺项用问题记录返回相关责任方，包含对象、原因、证据、建议修订与复验范围。避免通过删除一条问题、自动改成“不适用”或反复运行同一检查制造通过。

来源包括 `2026-10-four-subject-formation-choreography` 的保护弧、中心相遇和前后层次交换，`2026-10-leg-lift-contact-cut-stocking-six-look` 的接触与切点关系，`2026-10-sock-showcase-right-entry-three-shot` 的画面区域，以及 `2026-08-water-obstacle-variety-show` 的障碍平台、弧墙边缘与身体接触关系。必要证据见 `case-evidence.md`。
