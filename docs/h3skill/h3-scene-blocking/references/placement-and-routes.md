# M3.2 站位与移动路线

## 职责与独立调用

把稳定实体放入已有空间，说明起位、朝向、移动路线、到达位置和队形层次。读取所需实体、拓扑和调度任务的最小投影；输入可来自用户或外部兼容数据，不强制先执行 M3.1。

一个角色的稳定 ID 与画面槽位分开管理。源图左侧人物只是源内定位，不意味着该角色永远站在目标画面左侧。人物身份和参考授权归 M2；此节点只提案 `blocking` 分区。

## 一、登记站位

每个相关阶段写清：

- **谁：**稳定实体；人、道具等按本次需求记录，不从参考文件数推导人数。
- **在哪里：**具体区域与空间锚点，必要时补充有单位且有依据的坐标。
- **朝哪里：**世界参照或人物相对朝向，明确哪个身体部位；不要混写屏幕左右。
- **在哪个阶段有效：**当前镜头、动作阶段或交接条件。阶段名称与稳定事件引用不等于已经确定秒数。
- **与谁有关：**前后层次、相对间隔、对应交互区，以及需交 M5 核对的观看关系。

只处理静止站位时无需凭空添加移动；没有朝向依据时保留未知。用文字设定目标站位时，标为设计提案，不伪装为源素材原态。

## 二、把队形名称展开为路线

“浅 V”“错列 2×2”“前后交换”等名称不足以解释转换过程。为每个参与实体建立起位 → 经由区域／转折 → 终位的路径，明确同行者、交叉对象、绕行侧和到达条件。让下游能够看出人物是否真的移动过来。

舞蹈任务中的小步、支撑脚转动和身体后续动作交 M4 具体组织；M3 提供空间路径和所需容量。不要把舞蹈案例中的“不得走到新位置”推广为影视剧禁止行走，也不要只修改终点而省略中间路线。

对于同一区域的竞争使用，建立需交 M3.3 处理的交叉／避让关系。确切先后、占用时间、速度和同步由 M7/M4 决定。暂缺排时时，明确“路线候选可交接；同时占用与避碰尚未确认”，不得自称调度已全部通过。

## 三、处理出入画与换视图

出画不等于从场景消失。分别记录世界中的去向和在指定视图中的出入画要求。反打、绕拍或人物转向后，重新核对投影关系；单凭“人物仍在右侧区域”不能证明人物仍位于画面右侧。

读取 M5 已提供的视图与可见性要求，记录对应版本。未经 M5 确认，输出“需在该视图可读”的条件，不将其写成“已经无遮挡”。摄影路径阻碍人物路线时，返回两条路径与冲突位置，交责任方协调。

## 四、跨阶段和跨镜交接

用稳定站位／路线 ID 提供入态和出态空间条件，供 M8 记录派生状态；M8 保留 `SpatialPlan` 的版本与来源。后一个片段的目标位置不能倒填成前一个片段原本已处于的位置。

若跨镜采用省略、蒙太奇或相位匹配，空间不连续是否允许由任务及 M9/M8 的边界决定。M3 不强制所有镜头连续，也不能自行发明切镜以解释无法完成的路线。

## 五、局部审计与修复

| 问题 | 修复责任 |
|---|---|
| 稳定身份与槽位混淆、实体未登记 | 回 M2／调用者取得实体投影 |
| 路线起终点和站位不一致、路线跨过不存在的连接 | M3.2 修订路线，必要时向 M3.1 请求修订拓扑 |
| 同时交叉但没有空间或时间条件 | M3.3 明确交互约束；M7 排时 |
| 动作幅度／道具尺寸超出可用空间 | M4 与 M3 协调，不静默缩小关键动作 |
| 画面左右或身体朝向与指定视图矛盾 | M3.2 修订本分区，摄影决定交 M5 |
| 入出位变化没有跨镜依据 | 回 M8/M9 处理交接，保留旧状态证据 |

只允许改变自己拥有的站位与路线。收到 M3.3 或 M5 的修改建议时，记录原值、建议、原因及影响，再形成新提案；不直接覆盖拓扑、身份、时间或镜头。

## 依据与适用边界

主要文本依据为 `2026-10-four-subject-formation-choreography` 的 formation map、各角色路径和段落交接，`2026-10-sock-showcase-right-entry-three-shot` 的出入画顺序，以及 `2026-08-three-person-orbital-long-take` 的人物与摄影机相对关系。精确出处见 `case-evidence.md` 与 `case-index.json`。

四人队形案例的局部禁跨中线条款与后文中心交叉／层次交换存在作用域冲突，不能合并成全局禁令。保留原差异，由当前任务明确本次路径。人数、队形、景别与旋转幅度均不设置统一上限。
