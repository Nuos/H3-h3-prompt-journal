# M3.1 空间坐标与场景拓扑

## 职责与输入

建立一个可供站位、动作和摄影共同引用的空间底图。读取当前任务的场景描述、稳定实体、空间参考权限、必要动作空间和已知观看条件。输入可以由用户或其他兼容实现直接提供；不要求先执行 M1、M2 或摄影模块。

把用户陈述、已批准计划、媒体观察、案例文字和本次设计分别记为来源。参考图中可见的布局只有在获得空间用途许可后，才可约束目标布局。只有文件路径或案例文章时，保持“文字描述”层级，不声称量过场地或看过图片。

## 一、先确定三个方向系统

| 系统 | 参照物与用途 | 必须保留的条件 |
|---|---|---|
| 世界／场景坐标 | 门、墙、地面、台面、通道等稳定锚点 | 原点、各方向含义、单位或明确的关系描述；不随镜头反打自动翻转 |
| 人物自身方向 | 某个稳定实体的左手、右脚、面向、背向 | 对应实体与身体朝向；人物转身后重新解释其身体方向 |
| 屏幕方向 | 某个明确视图中的左／右、前景／后景、出入画 | 对应摄影视图和作用范围；换机位后不能无条件沿用 |

先用自然语言说清“谁的左边”。未取得 M5 的观看方向或投影关系时，可记录世界关系和身体关系，把画面左右保留为待核对。不得把数字坐标看起来完整当成已经完成三维重建。

只有当具体任务提供或允许设计数值时才使用数值。标清米、相对尺度等单位；本次假定的尺度列为设计条件，不能伪装为从图片测量的事实。不同坐标框架不凭同名轴或相同数字直接拼接。

## 二、建立锚点、区域与连通关系

1. 登记场景中的稳定锚点，以及它们的相对关系。用可以被读者定位的名称，例如“门内通道”“柜台外侧”“台面右端”。
2. 区分可达区域、不可穿越实体和状态未明区域。门、台阶、水面、平台等状态必须有依据；缺数据时保留缺项。
3. 明确区域之间是否连通、可经何处通行、单向或双向、是否附加条件。只连接已有依据的通路，不为了满足动作自动制造开口。
4. 指定站位、移动路线和交互区要引用的稳定区域 ID。删除或改变区域时，列出受影响的站位、路线、互动和摄影检查。
5. 检查人物及摄影机候选路线是否要求穿越实体。人物路线由 M3.2 修订，摄影机路径由 M5 修订；M3.1 不移动摄影机替代解决。

这里的拓扑表示“区域及其连接关系”。声明两区连通，只支持图上的可达性；它不证明人物体宽、道具尺寸、动作幅度、速度或摄影机体积可以通过。清距不足或未测量时，保留几何核对项。

## 三、输出与编排

提交 `topology` 分区提案，附来源、适用范围、未定项和必要的修复请求。与其他子模块组合前核对同一作品、同一基版本和相同空间框架。

供后续提示词编排的空间描述至少说清：场景锚点在哪里、哪些区域相通、人物可在哪些区域移动、哪些实体不能穿越。不要只写“空间合理”“保持布局”或“与前一段相同”。

不在此节点决定动作过程、时间、机位、景别、切点、布光或服装。空间变化会影响这些决定时，提供影响对象与约束，交回相应责任方。

## 四、局部审计

| 检查 | 可以得出的结论 | 不得推出的结论 |
|---|---|---|
| 区域／连接／框架 ID 可解析 | 已登记关系没有悬空引用 | 实际场地确实如此 |
| 路径上的相邻区域有合法连接 | 声明拓扑内存在通行关系 | 人物和道具无几何碰撞 |
| 世界、身体、屏幕方向分开 | 描述有明确参照 | 实际摄影投影正确 |
| 空间参考有范围和来源 | 计划依据可以追溯 | 媒体已经被观察或测量 |

发现视图不足，回 M5；空间参考许可不足，回 M2；目标要求相互矛盾，回 M1 或当前调用者。只暂停受影响结论，保留仍可用的空间候选。

## 依据与适用边界

领域依据为案例集合中的 `2026-10-physical-camera-position-library`、`2026-10-camera-movement-discipline-library`、`2026-10-four-subject-formation-choreography`，以及 `2026-08-water-obstacle-variety-show` 的场地与接触链文字。必要摘录、精确版本和行号见包内 `case-evidence.md` / `case-index.json`。

世界／身体／屏幕方向区分、M3 字段责任与相邻模块边界来自冻结方案 `01-core-framework.md` 的 M3 合同；可执行的 ID、图连接和版本表示属于本包的工程细化，不冒充原案例已实现的算法。
