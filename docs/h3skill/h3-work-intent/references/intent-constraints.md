# M1.1 意图与约束整理

## 职责与最小输入

把当前任务的创作要求整理为可追溯的作品目标、必保事项、允许变化和约束优先级。可以直接使用用户需求、既有项目快照或外部兼容记录；不要求先运行其他核心模块。机读字段、类型、版本和路由以 `contracts.json`、`module-registry.json` 为准。

只输出本子模块的意图提案，交 M1 接受；不直接改其他子模块的段落、情绪提案，也不改变角色身份、素材权限、对白、机位、拍点或生成参数。子模块提案和父模块权威 `WorkBrief` 要分开保存。

## 编排步骤

1. **分开原始要求与整理结果。** 给原始要求稳定 ID，保存原文、来源与版本。区分用户明确给出、案例原文描述、当前创作建议和未知事项；“案例作者报告有效”只能记为报告。
2. **用结果表述目标。** 写清观众最终应理解或感受到什么，以及内容用于什么交付。不要只留下“电影感”“高级”“有情绪”。可以将“喜剧感”解释为既有情节中的恶作剧、反馈和反转；不要擅自增加新的剧情。
3. **登记必须保留的事项。** 分开角色/道具/场景要求、关键事件、信息顺序、对白原文、媒体用途和交付约束。保持原始措辞可回查，不以摘要替换必须逐字保留的台词。
4. **登记可调整项与作用范围。** 案例中“关键情节固定、动作执行与观察方式可调整”的方法允许受约束创作；它不允许删除锚点。对未说明能否修改的关键内容保留待确认状态，继续完成不受其影响的整理。
5. **区分约束来源与优先级。** 用户要求、已核验协议约束、制作选择、案例经验分别登记。案例经验默认只在相应案例/体裁下适用。来源类别不等于机械覆盖顺序；两项必须条件冲突时保存两项并返回诊断。
6. **检查目标与要求的兼容性。** 例如“结尾保持平面贴纸形态”与“结尾变成三维真人”若同时是必须项，不能悄悄选一项。列出冲突原文、影响范围、可继续部分和需要裁决的责任方。
7. **返回最小提案。** 输出目标、必保项、可调整项、来源与未决项。保留用户给出的成片时长意图，但不把它当作单次生成时长；真实能力校验交 M11，任务划分交 M9，统一排时交 M7。

## 局部审计

| 规则 | 检查内容 | 不通过时返回 |
|---|---|---|
| M1-I01 原文保真 | 所有必保事项有来源且未被摘要删掉；要求逐字保留的对白和文字可逐字比较 | 缺项位置与源要求 ID；回 M1.1 |
| M1-I02 可调边界 | 允许改变的属性、范围和依据明确 | 未知项；涉及资产属性时向 M2 提修改请求 |
| M1-I03 约束冲突 | 互斥必须项没有被优先级排序掩盖 | `conflict` 诊断；由 M1/用户裁决相关语义 |
| M1-I04 案例作用域 | 原案例人数、时长、比例、BPM、段数和特定角色没有进入通用默认 | 删除无依据默认，保留为来源案例参数 |
| M1-I05 事实层次 | 目标、推断、实测、未知相互区分 | 撤销无证据的“实测/已验证”声明 |

以上包含语义检查。脚本只能核对结构、原文 ID、状态、显式冲突等确定性条件；不能根据文本填满就证明目标合理或全部需求已被理解。

## 与 H3 的交接

- T2VA/I2VA/FL2VA/L2VA：向 `integrated_multimodal_description` 提供内容目标和必保事件，先由相关专业模块展开可见/可听过程，再由 M11 编译。
- Ref2VA：为 `summary` 提供目标及主要事件；必保/允许变化的意图交 M2 核对，作为 `retention_analysis` 的上游约束，不由 M1 自行选保留标记。
- `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 的最终绑定和编号由 M2 的稳定实体/素材合同经 M11 产生。M1 不把“有一张图”直接判为 I2VA，也不把“有视频”直接判为视频编辑。
- 具体模式和 Label 审计使用 `h3-label-mapping.md`；内部要求 ID、证据分类和冲突记录不进入模型正文。

## 来源与适用边界

本流程属于冻结框架的 **D 类实现设计**。领域依据见 `case-evidence.md` 与 `case-index.json`：水上闯关的必保情节/自由执行合同；海滩剑舞的作品定位与参考作用域；贴纸喜剧的形态、道具及无对白要求。原案效果描述属于 F 类作者报告，不升级为本模块的视频实测证据。F/D/I/U 的完整含义见 `audit-and-handoff.md`。
