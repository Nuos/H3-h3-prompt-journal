## 1. 证据分类与状态

沿用冻结方案的分类，不能改变字母含义：

| 分类 | 含义 | 当前模块中的例子 |
|---|---|---|
| F | 原文可确认的事实 | 案例确实写有某项方法或作者报告；不等于该效果被本次实测 |
| D | 架构推论与开发提案 | WorkBrief 字段、M1 子模块合同、路由和确定性检查设计 |
| I | 已有实现与已执行检查 | 实际脚本运行、输入/产物与结果记录；I 不表示“推断” |
| U | 未验证 | 未观察素材、未执行 H3 推理、未审阅的媒体效果 |

区分技术执行状态与专业结论。命令退出 0、JSON 可解析、文件存在，只说明相应执行或结构条件；语义、跨模块、媒体和全片结论各自需要证据。

专业检查使用 `pass`、`fail`、`unverified`、`not_applicable`、`stale` 的本义。`not_applicable` 要给出任务不适用的理由；缺少必须证据时用 `unverified` 或阻塞诊断。输入版本变更后原通过结论保留历史，相关依赖标 `stale`。

## 2. 审计顺序

1. 核对当前任务、模块 ID、合同版本、作用范围和源输入。
2. 核对必保要求覆盖、原文保真与显式冲突。发现互斥要求时保留双方。
3. 对每个本次涉及的子模块执行其局部规则，并写出具体证据位置。父模块通过不能代替三个子模块各自通过。
4. 对 M1 聚合结果核对目标、段落、情绪、母题是否指向同一版本；相关缺项不能在聚合时消失。
5. 对照 H3 映射表检查交接方向、模式字段和 Label 责任边界；未实施完整编译时不宣称 G2 已通过。
6. 输出确定性检查结果、Agent/人工语义判断、待补证据和最小修复请求；不要把四种不同证据压成一个“全部通过”。

可用文字检查表：

| 检查 | 通过所需证据 | 必须保留的限制 |
|---|---|---|
| 来源与需求 | 本次需求、原文位置、版本、已知/未知说明 | 未读取媒体仍是未观察 |
| 必保覆盖 | 适用要求均映射到作品目标/段落或明确交接项 | 文本覆盖不保证模型执行 |
| 段落功能 | 逐段有目的、进入/离开信息与相关事件 | 需语义审阅，不是关键词计数 |
| 情绪与母题 | 有依据的变化、可观察目标、识别与变奏关系 | 未测音频不允许编造拍点 |
| 父子一致性 | 子提案来源与基版本一致，唯一接受路径 | 接受程序不擅自改写语义 |
| H3 交接保真 | 精确字段名、标签职责、必保事项去向 | 不是完整 M11 编译器 |

## 3. 冲突与失败回传

| 问题 | 责任方 | 本模块应返回什么 |
|---|---|---|
| 创作目标、必保事项互斥 | M1.1 / M1；必要时请求用户裁决 | 冲突原文、影响段落、可继续范围 |
| 段落无功能、事件遗漏、信息提前 | M1.2 | 具体段落与要求 ID；最小修订目标 |
| 能量与段落意图不符、母题无依据 | M1.3 | 关联段落、源信息、需改变的语义 |
| 素材缺失、身份或参考权限不清 | M2 | 需要的资产角色/属性权限；不伪造已观察 |
| 动作过程、摄影可见性、声音事件未完成 | M4 / M5 / M6，空间问题交 M3 | 目标和必保约束；不代写其权威对象 |
| 拍点、容量、时间域不明 | M7，必要时 M6/M9 | 时间意图与真实依据缺口 |
| 状态接续或编辑组织冲突 | M8 / M9 | 段落目的与允许变化；不替其决定最终方案 |
| 风格/光色与作品意图不一致 | M10 | 受影响意图与观看目标 |
| 模式、字段、参数或 Label 错误 | M11 | 正确协议来源与未完成映射 |
| 缺证据却标通过、结果过期 | M12 接口 / 当前调用者 | 原结果、变化范围、需复核项 |

M2—M12 在本交付中是公开交接目标，不是已安装或已运行的实现。没有下游实现时交付可读的交接请求即可；不能记录伪造的调用成功。技术错误不通过反复语义生成掩盖；语义冲突也不靠原样重试变成通过。自动循环不属于本模块默认行为。

## 4. 父子接受与版本

采用“子提案、父接受”。子模块只产生自身负责范围的提案；M1 核对合同、原始需求、基版本及局部结论后形成新的 WorkBrief 版本。拒绝过期基版本、越权字段和不同作品的混入。拒绝时原产物保持不变。

接受过程允许合并相容字段，不允许静默改写子模块语义决定。需要改变内容时返回该子模块修订。只接受已检查的本次范围；某个子模块未完成，不妨碍交付另外的独立结果，但完整 M1 不能因此声称全部就绪。

变更传播依据真实注册的消费者及字段依赖。改某个段落的揭示顺序时，相关 M4/M5/M6/M9/M11/M12 结果可能需要复核；没有真实依赖登记时只报告“需建立影响范围”，不能假定这些下游已执行。纯展示名称变化不自动触发全片重做。

|---|---|---|

## 6. 四项架构原则

- **高内聚 HC：** 三个子模块分别对意图约束、段落信息、情绪母题负责；确定性工具只处理结构与版本，不冒充创作判断。
- **低耦合 LC：** 只读取合同需要的投影与本包资源；允许用户/外部工具提供兼容输入；不依赖会话记忆或兄弟技能目录。
- **模块化 MD：** 父与每个子模块都有独立触发、最小输入、结果和局部审计；安装单元保持一个技能目录，子模块不是三个额外安装包。
- **路由 RT：** 使用稳定目标 ID、输入映射、成功返回、失败归属和版本；调用定义与真实执行记录分开；缺项和冲突保持可追溯。

## 7. 完成与未验证范围

本模块的可交付结果是来源清楚的作品意图与段落语义，以及局部审计和下游交接。确定性工具不调用 LLM、不生成视频，也不自动证明叙事意义、视听表达或观众感受。

M1 输入/语义检查只能贡献 G0/G1 的相关部分。没有完整专业计划、实际编译/运行合同、生成媒体和成片，就分别保留 G1 全局、G2、G3、G4 的未验证状态。不得把本技能可用写成十二模块系统已完成，或把案例作者的成功报告写成本轮成功率。
