# M2 素材解析、资产绑定与参考权限：开发与验收记录

**版本：** `h3-asset-reference` v0.1.0；M2 公开合同 `1.0.0`。

**日期：** 2026-11-05（America/Los_Angeles）。

**读取基线：** `faa8edc311589d68d37e93524c7cb8e553fff857`。

**冻结方案：** `skillplan-v0.1.2-608813b`。

## 核心摘要

本轮完成冻结方案中的第二个核心模块 **M2 素材解析、资产绑定与参考权限**。三个子模块分别处理资产来源与观察状态、稳定实体与资产绑定、属性继承权限与作用范围；形成可独立调用、可组合接受、可追溯的文字工作流和确定性合同工具。

包路径为 `docs/h3skill/h3-asset-reference/`。`SKILL.md` 规定触发与主流程，领域规则、H3 映射、来源证据按需读取；脚本执行路由、合同/引用/版本/冲突检查、父接受和依赖失效分析。当前 Agent/人工完成自然语言理解和语义审阅，脚本不承担这些判断。

## 关键结论

1. M2 与 M2.1/M2.2/M2.3 均有独立公开合同和路由；不强制先调用 M1 或相邻子模块。
2. 素材、实体、属性权限采用唯一责任；子模块提出候选，M2 统一接受，不代写其他专业计划。
3. M2 与五种 H3 模式及所有四类参考 Label 的映射已逐项说明；正式模式、排序、编号与字段编译仍由 M11 负责。
4. 领域证据来自 29 案、98 份文本的登记范围；区分实际阅读深度、作者报告和本轮执行，不把哈希检查变为媒体证明。
5. 冻结方案和 M1 运行包保留原字节；本轮新增实现、测试与记录在 `docs/h3skill/` 内。

**关键词：** M2、AssetRegistry、EntityRegistry、ReferenceMap、属性权限、稳定主体、参考范围、H3 Label、来源保真、独立调用。

## 2. 模块和字段责任

| 节点 | 专业结果 | 最小业务输入 | 唯一分区 |
|---|---|---|---|
| M2 | 接受相容子提案，形成有版本共同快照 | `material_brief`；接受时另需当前状态与提案 | 三对象的权威接受路径 |
| M2.1 | 素材标识、来源、通道、访问、观察及待补项 | `material_brief` | `asset_registry` |
| M2.2 | 稳定实体、源内定位、多对多绑定 | `asset_context`、`binding_brief` | `entity_registry` |
| M2.3 | 按属性/用途/范围分权及显式冲突决定 | `asset_context`、`entity_context`、`permission_brief` | `reference_map` |

三分区对应冻结方案中的 AssetRegistry、EntityRegistry、ReferenceMap，由 `M2State` 组合保存。实体类型不限于人物，包含道具、场景、动作、风格与声音等复用内容。主体 ID 不依赖某个上传列表，也不随换位或镜头编号变动。

资产状态区分提供/待提供、可访问/未查、未观察/仅描述/已观察。绑定 confirmed 只说明目标关系已获明确指定，不说明图像已被目视核验。权限的 source_refs 是依据，authority_refs 则需来自当前用户要求或已批准计划；工具不能认证记录真实性，仍需语义审阅。

## 3. 案例事实与方法提炼

### 3.1 来源覆盖

固定 29 个案例目录，其中 15 个为 10 月案例；目录内 97 份文本，加共享词汇索引 1 份，总计 98 份。逐文件保存源 Git blob、SHA-256、字节数、行数和阅读方式。

本轮证据提炼记录为：33 份全文语义阅读、7 份选段阅读、1 份匹配行阅读、1 份工作流 JSON 静态连接核查、56 份关键词索引。完整读字节计算哈希不等于全部逐字语义审阅。图像、视频、音频未用于本轮质量核验，ComfyUI 工作流未执行。

### 3.2 十二条方法

| 规则 | 提炼内容 | 主要反例风险 |
|---|---|---|
| C01 | 分开存在、访问、观察与用途 | 文件名冒充已看素材 |
| C02 | 文件数量与实体数量独立 | 一图四人被合并，三图同人被拆开 |
| C03 | 逐属性授权与排除 | 一张身份图自动控制全部画面 |
| C04 | 姿态、首帧与摄影分权 | 身份图误当首帧，或一律禁止姿态参考 |
| C05 | 人物与世界分开继承 | 保留身份同时强制继承背景 |
| C06 | 动作视频仅贡献获准运动信息 | 源演员/服装/环境随动作泄漏 |
| C07 | 外观恒定项与状态变化分开 | 已出鞘的剑被参考图复位 |
| C08 | 音频用途逐项决定 | 所有 MV 都写成原曲复制 |
| C09 | 引用按实体、镜头和阶段设范围 | 前段权限未经授权延续到后段 |
| C10 | 解析候选保留不确定性 | 作者报告或采样命中冒充本轮实测 |
| C11 | 来源内容不自动成为目标内容 | 歌词、源演员自动增加目标人物/物件 |
| C12 | 冲突定位到对象、属性、范围与版本 | 用泛化优先级静默抹平来源矛盾 |

这些是 D 类方法提炼，每项有 F 类原文定位与适用界限。没有引入外部创作案例，也没有把作者报告的“近零漂移”或“逐帧核验”写成本次执行结果。

### 3.3 保留的真实冲突

下山 SEG01 同时出现“仅节奏/No signal copy”和完整音轨复制；环境权限表与提示词的 Picture 1 光色来源也存在竞争。四主体案例的摘要禁中心交叉与 SEG10 穿越中心需要按镜头范围解释。动作迁移标题缩写不能抹去正文许可的开场体态，工作流可见 124 控件值不能代替连接计算的 226 帧；同一音频资产在两个分支连接不同输入通道。

这些差异作为原文事实与修复责任保存；226 帧只来自静态连线代入，不声称已运行或符合实际后端。具体位置见案例证据中的 X01—X06。

## 4. H3 模式、字段与 Label

### 4.1 五模式

| 模式 | M2 编排贡献 | 重点审计 |
|---|---|---|
| T2VA | 明确是否无引用，保留文字创作要求 | 不虚构素材、帧锚和标签 |
| I2VA | 实际首帧资产、角色及允许变化 | 身份图与强首帧条件是否混用 |
| FL2VA | 首尾两帧的身份、范围和变化依据 | 起止角色是否冲突、衔接是否有依据 |
| L2VA | 尾帧来源与目标范围 | 不误加首帧条件 |
| Ref2VA | 内容定义、保留/改变/复制关系、时空用途 | 标签闭合、属性越权、音轨使能与编号分离 |

基础四模式以 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music` 三字段组织；Ref2VA 为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` 六字段。错误拼写 `integrated_multimodel_description` 不作为官方字段使用。

### 4.2 四类 Label

`<Subject N>` 对应复用内容，不等于人物数或文件数；`<Picture N>` 对应具体帧/构图/分镜锚点，外观图不自动成为独立 Picture；`<Video N>` 对应编辑、续接或整体时序结构；`<Audio N>` 对应实际启用的独立音频或同步声轨。Video 与 Audio 各自编号，`(Sx)` 是实际发声者的另一个维度。

M2 保留这些关系的语义，M11 再完成最终模式、编号、字段和参数。视觉保持关系与音频复制/参考关系分别映射，内部 allow 不机械翻译为 fully_preserved；完整原音轨加新对白/音效时也不能继续称 fully_copy。M2 不越权完成 M6 的声音内容、M7 的时间映射或 M9 的剪辑任务划分。

## 5. 官方技能结构和读取机制

| 要求类型 | 本包落实 |
|---|---|
| 必需 SKILL.md | 文件名、YAML 与 Markdown 正文完整 |
| 必需 name/description | name 与目录一致；description 同时描述功能、触发语境、子模块和不适用范围 |
| 可选资源按用途设置 | scripts 执行确定性检查；references 提供按需规则；assets 提供可复制样例 |
| 渐进披露 | 主入口单跳定位所有参考；大索引按 ID/案例读取；脚本无需全文进入上下文 |
| 主入口长度建议 | 主入口低于建议的 500 行；不将推荐长度伪装成唯一有效性标准 |
| 自包含与职责收敛 | 运行资源随目录提供；不需要兄弟目录、外网、API 密钥、GPU 或 H3 模型 |
| 说明/测试分离 | 开发报告、规范快照、测试和验证在包外，不混入模型创作正文 |

没有把可选目录误称必需，也没有为形式添加无用途 `agents/` 配置。官方 quick_validate 的通过只说明其实现范围内的格式检查通过，不表示 Anthropic 为语义、媒体或 H3 效果背书。

## 6. 确定性运行与架构原则

`m2_contract.py` 提供 route、check、accept、impact 四个入口。输入只读，结果写标准输出；`accept` 返回新的草稿，state 才是后续输入对象。

| 原则 | 实现措施 | 可观察行为 |
|---|---|---|
| 高内聚 | 三个子模块只写自己分区 | 越权修改被拒绝，专业计划交回相应责任方 |
| 低耦合 | 最小只读投影、外部兼容输入、独立资源 | 单节点直接调用，无隐式上游执行 |
| 模块化 | 节点 ID、版本、输入、输出、依赖、接受与返回合同 | 单子提案检查、批次接受、独立复制运行 |
| 路由信息 | 明确目标、资源、返回点、失败责任、重试与影响 | route 不冒充语义执行，impact 不擅自调度下游 |

时间区间前闭后开，相邻窗不相交；跨时间域或镜头/时间缺映射时保持未知。多源共同参考需有显式 combine 决定，排他来源可 select；决定范围完全相同，部分交叉需要先拆分。真实共同参考是否合理仍须专业判断。

原请求对照和父接受承担不同检查。正式接受前先逐提案执行 `check --request` 并审阅自然语言保真；accept 没有原请求参数，不证明该前置工作已经发生。

## 7. 验证证据与发现修复

### 7.1 已执行的确定性检查

M2 行为结果由 `tests/m2/test-results.json` 保存，含执行时间、测试统计、跳过原因及所测脚本/合同/样例/测试源码哈希。定稿执行 61 项，其中 60 项通过，1 项可选交叉校验跳过，0 失败、0 错误。原 M1 的 52 项合同测试本轮实际全部通过，结果另存 M2 验证目录，原历史报告不改。

M2 的测试范围包括四节点路由、三子模块独立输入、请求对照、组合接受、来源保真、伪观察、同图多人、多图共同参考、权限冲突、锚帧与姿态矛盾、声音通道、时间窗、版本、问题责任、JSON 异常、独立目录运行和真实消费者失效。

可选 jsonschema 独立实现对照因当前运行环境未提供该库而跳过，明确不计为通过。运行脚本使用标准库实现的固定合同检查已经执行；跳过的是开发期的第三方交叉核验，不是声明了却未满足的运行依赖。

### 7.2 本轮发现并修复

独立检查发现：提案可以保留 source_request_id 与来源 ID，却改写原请求来源 excerpt；原检查未拦截。已增加请求来源原值比对：同 ID 变化返回 `request_source_redefinition`，遗漏原请求来源返回 `request_source_omitted`；新增证据需要新来源 ID。对应反例已加入实际测试。

提交前交叉检查还发现音频用途的区分问题：同一 `audio_content` 的“允许参考词句并重新演绎”与“禁止复制原录音”可以共存。冲突与裁决按具体 `use` 区分，保留同一用途下允许/禁止的拒绝，以及真实帧锚定与排除姿态等跨属性检查；没有通过删除禁止条款来制造兼容。

同源时间窗复核发现：原来按窗口完全相等判断来源，会漏掉“所选内容禁止复制，却允许复制其子区间”的矛盾。现分别判断源内选择与窗口交集；未限定源窗口的禁令仍约束其子区间，重叠窗口拒绝，相邻或不相交窗口不误报。源窗口与目标作用范围继续分别保存。

独立审阅提出的完整父请求投影疑点也经主线程实际复现：M2.1 不读取资产 context，却被要求复制父请求提供给其他子节点的资产投影。现只核对子节点声明的只读输入；M2.2/M2.3 真正读取的内容仍须与请求一致，不能借此改写上下文。模块登记同步列出完整 M2 请求的可选字段。

### 7.3 真实独立使用与组合范围

独立 Agent 按技能处理“半身六段双图分权”和“下山 SEG01 来源冲突”，原始任务、产物、命令、错误与修订保存在 `validation/m2/forward-use/`。这些是文字工作流试用，不是生成视频评测；实际结论以目录内记录为准。

双图分权提案的确定性检查通过，同时保留媒体未提供、语义与媒体未验证。下山提案保留 No signal copy 与完整原声复制、服装来源排他等相反要求，拒绝结果没有被改写为通过。主线程语义审阅还指出初稿将“仅节奏”额外登记为 `audio_content/reference`，以及环境来源冲突需要显式列出；修订保留首版与日志，只用 `audio_timing/reference` 表达节奏，并将 README 与 prompt 的环境分歧列为未决问题。相应属性选择规则已补入合同和领域指南。

独立审阅者完整阅读入口、合同、Schema 和运行代码，提出父请求投影及源窗口疑点；主线程随后实际复现并修复。该审阅者没有取得可确认的独立测试汇总，故不将其调用计作额外一次“测试通过”。最后的确定性结果由本目录保存的实际命令和测试报告承担。

M1→M2 合同衔接例实际运行 M1.1 提案接受，取新 WorkBrief 的公开作品目标/约束投影，构造 M2.1 请求并完成路由。M2 返回 `semantic_execution: not_started`，如实表示只验证了显式数据交接，没有虚构自动调用或完整领域集成。

## 8. 完成范围、限制及历史保护

已实现的是 M2 文字编排/审阅工作流与离线确定性工具，不包含完整源片逆向、真实主体识别、媒体提取、H3 编译器、模型推理或成片审计。仅靠用户填入 media_observation 或 approved_plan 也不能让程序认证事实；这些声明需相应实际证据。

M2State 保持 draft；语义与媒体审计在脚本结果中保持 unverified。已知冲突拒绝，未知范围或未提供素材保留未验证和受影响范围；不把部分草稿保存说成 G0/G1 全部通过。

当前合同不以分区漏项删除已接受 ID，正式退休/删除需后续版本与迁移；精确跨域时间由 M7 提供；自然语言自动触发召回率和真实后端效果没有评测。M3—M12 的后续实现状态不因本轮改变。

首模块的 `release-manifest.json` 与旧核验器覆盖其发布时的整个目录，作为固定提交历史保留。本轮新增 `release-manifest-m2.json` 和专用核验器，更新顶层索引，未重写旧审计结果或冻结文档。
