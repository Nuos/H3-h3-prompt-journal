**版本：** v001；技能 `h3-action-performance` v0.1.0；公开合同 `1.0.0`。

## 核心摘要

本轮实现第四核心模块 **M4「人物表演、动作链与物理因果」**，交付于 `docs/h3skill/h3-action-performance/`。该目录是一个可独立复制的技能包，包含 M4.1 表演事件与前提、M4.2 动作机制与交互过程、M4.3 结果与动作接续三个公开子模块，统一形成 `ActionPlan`。

模块将“动作名称”展开为有目标、执行者、对象、起态、前提、过程、接触、结果与后继条件的事件链，并提供 H3 五种输入模式、基础三字段／Ref2VA 六字段及四类参考 Label 的编排与审计映射。Python 工具负责公开合同和已声明关系的确定性检查；语义编排由使用技能的 Agent 完成，实际视频效果另需媒体证据。

**交付边界：** 本轮只新增 M4 及其开发、验证和发布文件，并更新总索引；M1—M3 运行包、冻结计划和原始案例保持不变。M5—M12 的交接接口不代表这些后续模块已实现。没有执行 H3 推理或真实媒体回归。

## 关键结论

1. 第四模块按照冻结编号确定为 M4，不重新解释模块顺序，不修改已锁定开发文档。
2. 三个子模块有各自最小输入、只读上下文、所属分区、返回路径、问题责任、版本与测试；兼容的外部输入可以替代重新运行上游。
3. M4 负责动作语义；绝对排时归 M7，权威计划状态归 M8，空间归 M3，摄影归 M5，声音归 M6，镜头与编辑归 M9，最终 H3 编译归 M11。
4. 案例中的人数、动作预算、速度、转身、步行、口型或固定镜头限制不扩展为所有项目的统一限制；源文冲突与作者报告保留其范围。
5. 技能格式检查、合同／关系检查、Agent 文字试用与真实媒体效果严格分层；通过前几项不能推导生成成功率或完整 G0—G4 通过。

**关键词：** M4、ActionPlan、表演事件、动作机制、支撑、重心、接触、道具、结果接续、H3 Label、高内聚、低耦合、独立调用。

`scripts/`、`references/`、`assets/` 是按实际用途设置的可选资源目录；本包使用它们，不将三个目录都存在误说成所有 Skill 的强制要求。`agents/openai.yaml` 为可选产品展示配置，本包不依赖它。

初始化使用当前环境提供的技能创建助手；创建目标遵从用户明确的 GitHub 仓库位置，不安装到个人技能目录。最终格式以用户指定的 Anthropic 模板、创建指南和官方验证器复核。

### 四项架构原则的落实

| 原则 | 实现方式 | 验收对象 |
| --- | --- | --- |
| 高内聚 | 每个子模块围绕一类专业结果；专项舞蹈／剑舞规则按需加载，不伪增未登记子模块 | 入口、专业规则、模块登记及独立任务 |
| 低耦合 | 显式最小输入与只读上下文；不导入兄弟脚本，不自动运行上游 | 来源保真、上下文对照、外部兼容输入和独立复制 |
| 模块化 | 子提案仅写自己的分区；父模块唯一接受并核对组合版本 | 越权、冲突、过期、重复操作和组合检查 |
| 路由信息 | 稳定节点与合同版本、输入、输出、返回、失败、修复、操作身份和资源登记 | 路由输出、模块注册、调用记录和影响分析 |

ActionPlan 为本项目内部对象，公开信封和 JSON Schema 是 D 类工程设计，不是 MiniMax 官方 API。三个子模块可以在足够的外部投影下独立工作；“独立调用”不等于输入可以任意缺失，也不要求拆成三个独立安装包。

父接受核对实际原请求、作品和基版本、来源及只读上下文，拒绝不相容或越权提案，并保留可追踪的问题与已接受操作身份。新的草稿不把 G0/G1 局部结果自动升级成整个生产流程已通过。

## 4. 领域来源与适用范围

案例目录以基线树 `70a8a2a632d633f5d532db23cad99c772dc23026` 固定，共登记 **29 案、98 个文本文件**。其中 **3 个全文读取、5 个片段读取、90 个仅核对库存和文件身份**。全文证据来自古风武侠舞蹈方法论、海滩剑舞方法论、袜子／风扇动作链喜剧说明；片段来自剑舞提示词、舞蹈动作链库、白凤说明与提示词、抬腿触地换装提示词。每项实际读取范围、文件 SHA-256 和 Git blob 由 `case-index.json` 登记；文件清单不等于全文阅读证明。

多人互动和动作迁移的检查规则属于冻结职责下的接口设计，本轮没有把仅登记库存的对应案例宣称为语义回归证据。身份参考、动作参考、摄影与音轨的分权依据官方协议和已冻结的模块职责；没有观看这些案例的原成片。

| 可迁移内容 | 保留的作用域／限制 |
| --- | --- |
| 起态 → 过程 → 结果 → 下一入口 | 连续动作需要条件衔接；许可蒙太奇或时间省略由 M8/M9 说明，不要求所有镜头逐帧相同 |
| 身体部位、持物手和道具的稳定身份 | 只在相关任务约束中明确持续关系；固定左脚或固定持剑手不推广到全部任务 |
| 支撑、重心、发力、路径、制动与恢复 | 是表演表达与审阅依据，不能当物理仿真或安全性证明 |
| 多人协作和道具接触 | 分开主动事件、被动反应和共同操作；不设统一人物数量 |
| 参考动作与外观分权 | 动作迁移不自动继承源身份、场景、服装或音轨 |
| 明确触地、握持、释放等结果 | 原案例的触发和切换规则不成为任意视频通用规则 |
| 专项动作密度、速度和转身控制 | 保留原音乐、动作种类与案例条件；不统一禁慢动作、禁走路或规定每八拍动作数量 |

作者的成功／失败描述保留为作者报告，本轮没有观看其原成片。戏剧接口遵循冻结方案，但现有案例对长对白、复杂心理表演和长剧的真实效果证据不足；不能据舞蹈／喜剧样例宣称这些方向已经完成媒体回归。

## 5. H3 模式、字段与 Label

### 五种输入模式

| 输入模式 | M4 的编排任务 | 主要审计 |
| --- | --- | --- |
| T2VA | 从文字目标建立动作起态、过程、结果和反应 | 事件与动作过程完整，不虚构参考资产 |
| I2VA | 从实际首帧的身体、道具和接触状态向后发展 | 首帧可进入下一动作；身份参考不误作开场姿态 |
| FL2VA | 连接首尾帧之间可观察的中间变化 | 端点相容，不用两张静态图代替动作过程 |
| L2VA | 由合理前态逐渐收敛到尾帧 | 尾帧不是开场；推定前态明确为设计 |
| Ref2VA | 把授权动作／姿态／表情特征落实到目标实体、镜头和阶段 | 参考角色、保留关系和实际正文一致，动作不带入未授权外观 |

基础四模式主字段为 **`integrated_multimodal_description`**；Ref2VA 主字段为 **`detailed_description`**。基础三字段及 Ref2VA 六字段按官方原文保留，不混为同一格式。

### Ref2VA 六字段的职责落点

| 字段 | M4 提供／审计的内容 |
| --- | --- |
| `subject_definitions` | 明确目标角色以及可跟踪的动作、表情、姿态等参考内容；继承 M2 的实体和授权 |
| `summary` | 概括本段目标、主动作链与参考用途，不替代逐镜动作正文 |
| `retention_analysis` | 说明保留／变化／迁移的动作特征、对象和范围；不把动作迁移混同整体外观复制 |
| `detailed_description` | 逐镜描述起态、过程、接触、结果、反应及参考生效点；结合其他模块形成完整声画正文 |
| `overall_soundscape` | 向 M6 提供动作可能产生的物理声音和触发；M4 不自行决定全片静音或声音事实 |
| `non_diegetic_music` | 接收 M6/M7 的音乐关系，动作可提出强调需求；不直接写入配乐或虚构拍点 |

### 四类参考 Label

| Label | 官方角色 | 对 M4 的意义 |
| --- | --- | --- |
| `<Subject N>` | 可复用的可见内容单元 | 人物、道具、动作、表情或姿态的目标角色；不是源文件编号 |
| `<Picture N>` | 具体帧／构图／分镜锚点 | 首帧、关键帧、尾帧中的动作端点；身份图不自动锁定姿态 |
| `<Video N>` | 整段视频的编辑、续接或时间结构关系 | 源片运动／剪辑／节奏关系；可见动作内容仍需明确 Subject |
| `<Audio N>` | 明确启用、复制或参考的音频信号 | 动作的音乐或声音线索，归 M6/M7 协调；视频带音轨不自动启用 |

`[Shot N]`、`(Sx)` 和 `<d>` 分别表示镜头、实际发声主体和对白／歌词，不是内部动作事件 ID。六段 Ref2VA 正文的语言、具体标签及首尾帧对齐方式依官方原文执行。详表、引用定位和离线原文在技能包内；本节为交付说明，不替代精确协议文档。

## 6. 调用与检查

在技能目录执行：

```bash
python scripts/m4_contract.py --help
python scripts/m4_contract.py route assets/request-m4-1.json
python scripts/m4_contract.py check assets/proposal-m4-2.json --request assets/request-m4-2.json
python scripts/m4_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 返回显式目标与资源，不自动运行语言模型；`check` 验证其实现的结构、引用和声明关系；`accept` 对照原请求与版本后返回新草稿；`impact` 根据登记的实际读取关系识别需复验的消费者。具体字段、缺项表达及退出码见合同指南。

工具只依赖 Python 3.10+ 标准库，不联网、不覆盖输入文件、不读取媒体、不调用 H3。包内 assets 为 D 类合同设计样例，必须替换为实际任务数据。接受结果中的 `state` 才是下一步可用状态，整个工具报告不是状态对象。

## 8. 完成范围和未验证事项

本轮完成范围为技能内容、公开合同、可运行离线工具、样例、字段映射和所记录的文字／静态验证。以下事项仍需单独输入或执行：真实源片观察、实际身体与道具物理、摄影可见性、音乐／对白实测排时、M8 权威状态接受、M11 完整模型编译、H3 推理、生成片／成片验收以及宿主自动触发率。

本包不承诺视频成功率或相对模型稳定性提升。动作语义表达的完善具有可审阅依据，但在没有实际生成对照之前，不能报告媒体收益。开发和审计文字不进入最终模型创作正文。
