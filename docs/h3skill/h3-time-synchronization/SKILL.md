# H3 统一时间轴与动作—镜头—声音协同

先确认**哪一个时钟、哪一个事件、时间依据是什么**，再安排先后、重叠、偏移与映射。共用时间轴允许提前、同步、滞后和固定观察；具体摄影响应策略继承 M5 的决定。

实现 M7 与三个公开子模块，父模块唯一接受 `TimingMap`。用户资料或兼容外部计划可直接满足最小输入，无需先运行 M1—M6。子模块只提出自己分区的候选，不能通过排时改写动作、台词、机位、选窗或转场意图。

## 2. 确认时间依据

取得任务范围、有效片长、事件 ID 与所有者、已选源窗口／生成任务／编辑段、实际帧率资料和用户容差。分别登记源素材、作品、每个生成片段和成片的时钟，保存零点、单位、来源及版本；两段都写“0 秒”不代表同一时刻。

区分用户要求、案例原文、作者效果报告、候选设计、测量记录和未知。BPM 只支持候选间隔；首拍偏移、重音、乐句和真实声响需要各自依据。没有音频和测量记录时，不自动设首拍为零，不宣称逐帧卡点或实测语速。

时间缺项用具体未知原因表示，继续完成可支持的局部工作。帧率未定可以安排秒级草案，但不能给出已验证的精确帧号。源帧率、生成帧率与编辑帧率分别登记，保留 `30000/1001` 等有理数精度。

## 3. 完成三个时间职责

1. **M7.1 建立依据。** 归一秒／毫秒等单位，声明拍序起点和首拍偏移的适用时钟，登记恒定／可变帧率及测量证据。未知的首拍、FPS 和源窗口不由模型猜成事实。把案例数字作为案例条件，不能变成通用 H3 限制。
2. **M7.2 安排事件。** 保持动作、摄影、声音、编辑事件各自独立 ID，以引用关联。为事件记录起止、必要持续、触发、允许偏移与容差；明确比较的是开始、峰值、接触、到位还是结束。摄影提前到位不等于相机与动作同时启动；固定观察不使人物停止活动。
3. **M7.3 换算与量化。** 按 M9 已声明的选窗、速度或定格决定建立域间映射，再按目标域实际帧率量化。分别保留原时刻、目标时刻、帧号、取整策略和误差。定格须按方向处理：源时刻可对应输出区间，不能强制给单值；可变帧率需要帧时间戳。不能把编辑使用时长直接当后端生成时长。
4. **父 M7 接受。** 核对三分区的时钟、事件引用、来源和版本；复查量化后的关键先后与容量。只接受有来源且符合本域权限的提案。语义冲突或未知依据保留具体诊断，不通过缩短动作、改写台词、额外切镜或偷换 FPS 消除问题。

对白不足以容纳时，提供当前预算、必要停顿和证据缺口，回 M6／M9／M1；不能凭字数自行宣布实际语速。动作无法在时段内完成时回 M4／M9；相机到位错过观看任务时回 M5；音轨和边界策略不相容时回 M6／M9。

## 4. 防止时间含义混淆

- **事件身份与时间锚点分开。** 同时出现的落脚、鼓点、镜头到位有不同 ID；靠同步关系连接。
- **模型生成与后期处理分开。** 源运动重定时、生成提示中的动作节奏、剪辑变速分别说明责任和授权。优先保持必需动作的完整因果链。
- **动作阶段与真实镜头分开。** 一个镜头可以包含多个时间块；只有 M9 或用户提供的兼容编辑决定声明真实切镜，才增加 Shot。
- **半开区间与最后一帧分开。** `[start,end)` 的 end 是区间边界；帧数／帧率得到的覆盖时长与末帧时间戳可能相差一帧。关键帧指令的有效片长由实际参数口径确认。
- **计划容差与媒体误差分开。** 数学换算通过只说明所给数字自洽；生成结果是否准确到位需实际媒体和测量记录。

## 5. 交接 H3 模式与 Label

| 模式 | 时间内容的正文去向 | M7 的关键检查 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 从任务零点组织完整声画事件与真实切点 |
| I2VA | 同一基础主正文＋官方首帧指令 | Picture 1 对齐生成局部 0.00 秒，后续动作由首态发展 |
| FL2VA | 同一基础主正文＋官方首尾帧指令 | 起点、有效片长和最后实际 Shot 的终点一致 |
| L2VA | 同一基础主正文＋官方尾帧指令 | 尾图对齐有效片长，前序路径有足够时间收敛 |
| Ref2VA | `detailed_description`；参考用途进入对应分析字段 | Video／Audio 源窗口与目标局部时间分开；Picture 对齐真实目标帧 |

`overall_soundscape` 与 `non_diegetic_music` 接收相应声音的全片持续／渐变信息，不能形成另一套竞争时间轴。Ref2VA 保持官方六字段结构；`TimingMap`、帧表、容差和审计记录是内部制作资料，不新增 H3 顶层字段。

`<Subject N>` 表示可见内容，`<Picture N>` 表示具体画面锚点，`<Video N>` 可承载时序结构，`<Audio N>` 指已启用的声音信号。参考标签不能充当内部时钟或事件 ID；最终绑定与编号交 M11。

第一镜不写切点时间戳；实际后续镜头使用递增且在片长内的 `At MM:SS.mmm`。每个生成任务重新换算局部切点。跨切台词和片尾截断由 M6 的语义决定及 M7 的排时交 M11 表达为 `<scenetrans>`／`<cutoff>`，不能用截断标签掩盖时长冲突。最终英文正文按镜头描述可见、可听事件，保留台词和画内文字原语言。

## 6. 检查并交付

读取合同后，从本包目录运行 Python 3.10+ 标准库工具：

```bash
python scripts/m7_contract.py --help
python scripts/m7_contract.py route assets/request-standalone-m7-2.json
python scripts/m7_contract.py check assets/proposal-standalone-m7-2.json --request assets/request-standalone-m7-2.json
python scripts/m7_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 输出责任与资源；`check` 核对合同和已实现的时间关系；`accept` 对照真实请求和基版本输出新的父级草稿；`impact` 按实际读取路径返回复验消费者。脚本不分析音频、不自动探测视频 FPS、不执行剪辑、不调用 H3，输入文件保持原样。

交付本域提案或 TimingMap、时钟／事件／映射、允许误差、未解决项、责任回传与 H3 时间表达交接。分别报告结构检查、数值关系检查、Agent 文字审阅和实际媒体验证。父接受与局部检查通过不能替代 G1 跨模块审阅、G2 完整编译，更不能证明 G3/G4 视频效果。
