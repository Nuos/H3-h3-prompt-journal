# M7.1 时间依据与单位归一

## 核心任务

建立可以追溯到来源与版本的时间基准，明确“0 秒”和“第 1 拍”分别属于什么对象。输出时间依据候选供 M7 父级接受；不会因登记一个数字而升级其证据等级。

## 1. 收集并区分时钟

| 时间域 | 标识对象 | 零点与常见依据 | 不能自动推导 |
| --- | --- | --- | --- |
| source | 原音轨、源视频或外部时间标注 | 当前资产的开头、媒体 PTS 或已标定零点 | 生成片段的零点、真实首拍 |
| work | 整部作品的统一时间线 | 作品计划起点及已接受版本 | 任一后期重排后的时刻 |
| generation | 某一次生成任务 | 该任务局部 0 秒、后端有效片长 | 源视频 FPS、最终使用时长 |
| edit | 某个成片版本 | 成片起点、编辑帧率与 M9 选择 | 与作品时间始终一一对应 |

为每个资产、生成任务和编辑版本单独标识时钟。资料没有标明域时保留未知，不能根据秒数大小猜测；将源母轨 24 秒和分段局部 0 秒写成两个相关时刻。

帧率资料至少区分恒定帧率（CFR）、可变帧率（VFR）和未知。静态参考图没有可推导的帧率；播放器显示“30”不自动证明精确 30/1。读取实际媒体、后端参数或用户声明时分别保存证据类别。

## 2. 单位与精度

秒是本域比较的统一单位，源单位仍保留用于溯源。毫秒除以 1000；以帧0为零点时，恒定帧率 f 的零基帧索引 n 对应 n/f 秒；若该时钟中帧0的时刻为 o，则对应 o+n/f。保留有理帧率，例如 30000/1001，不将其先四舍五入成 29.97 或 30 再累计。

项目约定的区间采用半开区间 [start,end)，区间长度为 end−start；单一触地、切点或峰值是时间锚点，可以没有持续区间。源资料若按闭区间帧号描述，须先按其口径转换，不能只复制数字。内部比较保留精度，显示时间码时才按目标格式取位。

可选 `Clock.frame_count` 只表示这个时钟覆盖的连续采样帧总数；已知 CFR、FPS 和覆盖时长时，运行器按 `extent = frame_count / fps` 检查一致性。不要把“最后帧索引”直接填成总帧数，也不要把局部选窗的帧数填给整部源资产。C07 的 9 秒与 124 帧 @24 FPS 应作为待核对冲突保存；如果来源使用不同计数口径，先明确口径再建合同，不能为通过检查改写原文。

## 3. 拍点依据

候选恒速网格的数学关系为：

- 拍长 T = 60/BPM。
- 若拍序从 0 开始，第 k 个候选拍点 t(k) = t0 + kT。
- 若源资料从第 1 拍记起，先转换序号，不把公式直接套到未声明的编号。
- t0 是指定时钟的首拍偏移，必须独立登记；未知 t0 只允许给相对拍长，不能输出确定的绝对拍点。
- 小节和乐句还需要明确的拍号、段落划分或测量；BPM 不足以确定所有重音、歌词起点或声音瞬态。

案例中的单拍秒数往往是显示近似值。以有来源的 BPM 推算候选时应避免逐拍累加已截短的小数；实际测得拍点可以偏离恒定网格。测量列表和理论网格出现差异时登记差异，不能把测量强行吸附到理论值后继续称原始测量。

## 4. 证据等级与不确定性

| 输入 | 可支持的结论 | 仍需保留 |
| --- | --- | --- |
| 用户仅给 BPM | 候选拍长、相对拍序 | 首拍、实际拍点、速度变化、乐句未知 |
| 案例给 BPM 和首拍 | 该案例的文本条件与可复算网格 | 本轮没有听音；不是新资产的实测 |
| 可获得的标注文件和测量记录 | 该资产版本下的已报告测量值 | 记录真实性和媒体执行效果仍待相应检查 |
| 实际视频帧 PTS | 对应源资产的帧定位 | 不能替代生成／编辑域 FPS |
| 后端运行参数 | 该任务的参数口径 | 没有输出媒体仍不能证明实际输出时长 |

仅有证据条目类型写为 media_observation，不足以证明真实性；必须能够追到资产、版本、测量者／方法和观测范围。脚本最多核对记录是否具备必要字段及彼此相容，不能自行听音或读取视频。

## 5. 交接与修复

将时间依据、已知／未知、可复算公式和来源交 M7.2、M7.3。资料互相冲突时保留双方原值，发出具体问题；源资产与测量回 M2/M12，声音时间依据回 M6，编辑口径回 M9，后端片长与 FPS 回 M11。继续完成不依赖缺项的秒级安排。
