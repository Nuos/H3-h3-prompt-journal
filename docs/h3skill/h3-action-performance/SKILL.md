# H3 人物表演、动作链与物理因果

把动作名称展开为：**谁为达到什么目标，在什么前提与起态下，通过哪些可观察过程，与什么对象发生什么接触，形成什么结果，怎样持续、结束或进入下一动作。**

实现 M4 及三个公开子模块。子模块提出各自分区的候选，M4 父模块核对并唯一接受；不得另存竞争动作事实。兼容的用户资料、外部输入或既有计划可以直接替代上游执行。当前任务和已经确认的约束优先，案例规则保留适用范围。

## 2. 确立输入与动作范围

确认本次事件、人物、道具、镜头／阶段与模块目标。只读取必要的作品目标、稳定实体与动作参考权限、空间条件、当前计划状态和约束。已有兼容输入足够时，直接工作，不自动重跑 M1—M3 或 M8。

分开用户要求、案例原文、作者报告、设计决定、假设及真实观察。无实际媒体时，不声称已看见动作完成或已测出拍点。缺失的空间、当前持物、接触条件或动作来源应明确保留；不能为填满合同而编造事实。可逆设计选择在授权范围内自行完成并标注；真正阻断当前判断的缺口才回传或询问。

将每个必须保留的动作和结果登记为可追踪事件。使用稳定实体与事件 ID，不把模型 Label、源文件编号、镜头编号和身体左右混作同一标识。修改原要求时保留变更依据，不因动作难编排就悄悄删除、替换或弱化。

## 3. 形成表演事件与因果链

1. **M4.1 确定发生什么。** 写清执行者、作用对象、目标、前置条件、触发及起态；将情绪落到目标相关的目光、呼吸、停顿、表情和身体行为。区分收到信息后的反应、已知信息下的预判与无依据的提前反应。
2. **M4.2 解释怎样发生。** 依次写出支撑与重心变化、发力和传递、身体与道具运动、接触建立／保持／释放、恢复与落点。每个必要中间过程使用完整动作句，明确执行者及对象；不以“完成动作”“自然过渡”“快速切换”掩盖机制。
3. **M4.3 确认发生之后。** 写出可观察结果、出态、持续或终止条件、后继事件进入条件。把持物、接触、位置或朝向变化作为给 M8 的请求；为 M5 指出必须看清的结果，为 M7 提交事件依赖，为 M6 提交潜在声音事件。
4. **M4 核对组合。** 对照实际原请求、来源和只读投影，检查事件引用、过程覆盖、结果承接、冲突与版本。通过父接受路径形成新草稿；需要改变专业语义时回到相应子模块，不在聚合中偷偷重写。

身体支撑、接触、道具不适用于某个纯表情／视线事件时，用有理由的“不适用”；事实尚未知时用“未知”，两者不得互换。保持、等待、静止观察或戏剧走路可以是有目的的表演，不强制每秒产生一个新动作。摄影机移动不能代替人物动作，画面变化不能自动证明物体或人物发生物理变化。

## 4. 选择专项策略并保留边界

舞蹈检查脚下支撑、重心转移、躯干与四肢顺序、动作质地及回收；剑舞检查持剑手、握持、剑与鞘状态、刃尖路径、制动和下一动作入口；普通操作检查抓握、共同接触、放手、实际落点与最终归属。多人互动逐一写清各自事件和相互触发，不能用一人的动作默认代表全体。

实际参考动作需要 M2 的使用许可和明确源范围。只迁移动作时，不同时继承源角色外观、服装、场景或声音。参考图只定义身份时，不把图中姿态锁成目标首帧。已拔剑的连续段落不能无事件地再次拔剑；许可的蒙太奇或时间省略由 M8／M9 声明，不能误判为必须保持所有局部状态。

不把案例固定人数、八拍动作预算、旋转上限、禁慢动作、禁走路、无口型、固定镜头或特定切换机制扩大为通用规则。动作容量冲突提交给 M7 协调；M4 不自造绝对秒数、偷删事件或把动作阶段直接改成剪辑点。

## 5. 映射到 H3 的模式与 Label

| H3 模式 | M4 提供的内容 | 主正文去向 |
| --- | --- | --- |
| T2VA | 从文字目标建立起态、过程、结果和反应 | `integrated_multimodal_description` |
| I2VA | 从实际首帧动作状态向后发展 | 首帧对齐指令及基础主正文 |
| FL2VA | 连接首尾帧之间可观察的动作与状态变化 | 首尾对齐指令及基础主正文 |
| L2VA | 由合理前态逐渐收敛到实际尾帧 | 尾帧对齐指令及基础主正文 |
| Ref2VA | 将授权动作与表演特征绑定到目标实体和生效镜头 | `detailed_description` |

基础四模式共三个字段：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。Ref2VA 依次使用六字段：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。M4 提供动作语义与检查要求，M6 决定声音内容，M11 编译最终格式；内部 ActionPlan 不是 H3 API 请求体。

四类官方参考 Label：`<Subject N>` 可跟踪复用的可见内容，包括动作／表情／姿态；`<Picture N>` 具体帧或分镜锚点；`<Video N>` 整段视频编辑／续接／时间结构关系；`<Audio N>` 明确启用的音频信号。动作取自视频仍应明确目标 Subject，不能仅写“参考 Video”。`[Shot N]` 是镜头记号，`(Sx)` 是实际发声主体编号，`<d>` 承载对白／歌词；它们不等于事件 ID。

逐镜把动作写成当前完整事件：起始条件、过程、结果、正在生效的参考及必要可见／可听信息。Ref2VA 六段正文按官方要求使用英语，保留对白、歌词和画内文字原语言；中文分析与审计另放。最终模型正文不夹带内部合同、开发规范、审计过程或未验证的效果承诺。

## 6. 运行离线检查并交付

仅需 Python 3.10+ 标准库。先读合同指南，再执行：

```bash
python scripts/m4_contract.py --help
python scripts/m4_contract.py route assets/request-m4-1.json
python scripts/m4_contract.py check assets/proposal-m4-2.json --request assets/request-m4-2.json
python scripts/m4_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 定位显式目标与资源；`check` 检查声明的形状和关系；`accept` 核对原请求及基版本后输出新草稿；`impact` 根据已登记读取范围标记需复验的消费者。脚本不自动解释自然语言、执行子 Agent、观察媒体、求解人体物理或调用 H3，也不覆盖输入文件。样例须换成本任务输入后重检。

交付子提案或 ActionPlan 草稿、必要动作链表、依据与未知项、局部问题、责任回传、H3 字段交接和执行记录。分别报告结构、确定性关系、专业语义、实际媒体的结果。文本通过不能提升为真实接触／动力学成立、完整 G2 编译或 G3／G4 通过；没有生成片时保留 `unverified`。
