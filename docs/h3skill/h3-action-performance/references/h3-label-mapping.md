# M4 人物表演与动作因果：H3 模式、字段和 Label 映射

## 核心摘要

M4 将经授权的表演目标、参考、空间和当前状态组织成 `ActionPlan`：事件与前提、机制与交互过程、结果与后继条件。它为 H3 五种输入模式提供动作语义及审计要求，不是 H3 API 请求体，也不负责素材编号、全套正文编译或实际模型调用。[F176–189]

**关键结论：** T2VA／I2VA／FL2VA／L2VA 使用 `integrated_multimodal_description`；Ref2VA 使用 `detailed_description`。两者都要描述具体发生的完整事件，不能用动作名称清单、终态或引用关系代替过程。Ref2VA 可见的动作、表情和姿态属于 Subject 内容角色，来源视频的整体结构才由 Video 角色表达。[B36–48、54–70；R7、13–22、41–58、75–87、209–256]

**关键词：** ActionPlan、事件、前提、动作机制、接触、结果、Subject、Picture、Video、Audio。

## 1. 职责与子模块贡献

| 子模块 | 专业结果 | H3 编排贡献 | 审计与交接边界 |
| --- | --- | --- | --- |
| M4.1 表演事件与前提 | 事件、执行者、对象、目标、前提及触发 | 说明谁从什么起态开始什么行动，为什么此刻可以进入该动作；明确参考动作的目标实体 | 不重定义 M2 身份与许可；不把源文件、人物左右槽位或模型 Label 当事件 ID |
| M4.2 动作机制与交互过程 | 支撑、重心、发力、路径、接触和道具操作 | 在相应镜头写出动作如何展开、关键接触如何建立／保持／解除 | 不用运镜替代人物动作；空间调整交 M3、观看方案交 M5；未知不伪造为实测 |
| M4.3 结果与动作接续 | 可见结果、出态、持续／结束、后继条件及状态请求 | 说明动作造成什么变化，怎样反应、停留或进入后继事件 | 绝对时刻由 M7 提供，权威计划状态由 M8 接受，镜头／编辑边界由 M9 决定 |

M4 父模块仅接受、核对和组合这些提案。以上是项目内部职责细分，不是 MiniMax 新增的三个输入模块或三个 Label。声音语义由 M6 决定，最终标签与提示词结构由 M11 汇编。[F176–218、319–360；D210]

## 2. 五种输入模式

| 输入模式 | 官方结构 | M4 的动作编排 | M4 的审计要求 |
| --- | --- | --- | --- |
| T2VA | 三字段；没有图像对齐首行 | 从文字目标建立起态、触发、过程和结果，明确动作主体及对象 | 不引用不存在的图像或视频；动作从已有条件可进入，关键过程完整 |
| I2VA | 三字段；首帧对齐首行 | 从实际首帧身体姿态、支撑、持物和接触关系向后发展 | 图片确为首帧；仅作身份参考的定妆照不自动固定动作起态；图片未观察时不声称已核对姿态 |
| FL2VA | 三字段；首尾帧对齐首行 | 对照首尾动作端点，补足可观察的身体、道具和接触变化，使差异逐渐收敛 | 不只复述两张图；端点冲突或中间动作缺口明确登记。官方通常偏好连续单镜头，多镜头按用户明确要求处理 |
| L2VA | 三字段；尾帧对齐首行 | 根据任务构造合理前态，让动作渐进收敛到尾帧状态 | 尾帧不是初始姿态；推定前态标为设计，末镜编号和有效时长分别交 M9/M7 |
| Ref2VA | 六字段；四类参考 Label | 将授权动作、表情、姿态及其机制绑定目标 Subject，在实际生效镜头展开 | 正文使用 `detailed_description`；动作特征与身份／场景／音轨权限分开；定义、保留关系与正文一致 |

模式与对齐语法见 B5–34；端点处理见 B50–70；Ref2VA 字段及主正文差异见 R13–22、225–232。本包不能仅按参考文件数量保证某一后端的模式可用性，运行能力与参数由 M11 复核。

## 3. 基础四模式的三个字段

| 官方字段 | M4 提供的内容 | 编排要求 | 审计与责任 |
| --- | --- | --- | --- |
| `integrated_multimodal_description` | 人物事件、起态、前提、动作机制、接触、道具、结果与反应 | 在对应镜头用完整句明确执行者、对象、过程和变化；将关键动作与必要声画事件相连 | 不能只写“旋转、挥剑、落地”；动作过程和结果可对照。由 M11 合并其他模块形成完整正文 |
| `overall_soundscape` | 动作可能产生的脚步、衣料、接触、呼吸等线索及对应事件 | 提交 M6 决定声音内容；全片环境和物理声摘要放在此处，具体镜头同步声仍在主正文 | 不能从文字接触直接认定实际有声；本模块缺声音资料不等于全片静音，不擅填 `N/A` |
| `non_diegetic_music` | 动作与配乐关系的需求或已给定线索 | 由 M6 决定面向观众的配乐，由 M7 定位真实拍点；动作模块不另造音轨或秒数 | 不把人物可听见的画内音乐混入此字段；无配乐的决定不由动作模块代替作出 |

字段语义见 B36–48、152–162。`overall_soundscape` 的 `N/A` 只用于明确要求整片完全静音；`non_diegetic_music` 的 `N/A` 表示没有非画内配乐。声音层为空、未决定与明确不存在是不同情况。

## 4. Ref2VA 的六个字段

| 官方字段 | M4 提供什么 | 编排要求 | 逐项必查 |
| --- | --- | --- | --- |
| `subject_definitions` | 被跟踪的目标角色／道具和动作、表情、姿态等内容角色 | 引用 M2 稳定实体与许可；来源有不同用途时说明谁提供外观、谁提供动作；仅作来源的 Picture/Video 可以在该定义中引用 | 是否把动作内容误当视频文件身份；是否创建没有独立用途的重复标签；角色编号是否前后同义 |
| `summary` | 本段主要行动、结果与参考用途 | 使用一个简短段落概括任务；任务类型按真实参考角色选取 | 借用动作指导不自动成为直接编辑源视频；摘要不能加入正文没有的动作或未定义 Label |
| `retention_analysis` | 保留／改变／迁移的动作特征、对象、范围和阶段 | 按已定义内容角色说明实际关系，明确哪些运动特征转到哪个目标 | 不能把“只继承动作”扩为外观、环境或声音；许可可用不等于生成已实现；关系判断须按角色定义范围 |
| `detailed_description` | 每镜动作起态、过程、支撑、接触、结果、反应和状态变化 | 依播放顺序写完整事件，在内容首次清晰出现和参考真正生效处引用相应 Label；与空间、摄影、时间、当前声音结合 | 不得退化为剧情梗概或引用清单；关键握持、支撑、制动、释放和后继入口是否被跳过；前后状态是否有因果 |
| `overall_soundscape` | 与动作有关的物理声线索及对应事件 | M6 决定全片环境／物理声；参考音频关系写在匹配的声音层 | 视频原带音轨不自动启用；具体镜头同步声在正文；不重复整段台词和歌词 |
| `non_diegetic_music` | 与动作推进相关的音乐要求或既有音乐线索 | M6 处理配乐及复制／参考方式，M7 处理动作响应；M11 序列化 | 不自造拍点或把音乐关键词变成画内物体；直接复用曲中歌词线索不自动产生人物口型或新说话者 |

六字段按表中顺序保留。定义见 R26–118，摘要见 R123–153，保留关系见 R155–207，正文见 R209–256，声音与说话者见 R260–303。M4 对相关内容给语义和诊断，不代填其他专业模块尚未决定的完整字段。

## 5. 四类参考 Label

| 官方 Label | 官方作用 | M4 编排与审计要求 |
| --- | --- | --- |
| `<Subject N>` | 从参考资产中抽取并用于目标视频的可见内容，包含人物、道具、场景、动作、表情和姿态 | 动作参考与目标执行者明确绑定；一个源文件可以给多个 Subject，一个 Subject 可以由多份来源共同定义。不把角色左右位置、事件编号或源文件序号当身份 |
| `<Picture N>` | 首帧、关键帧、尾帧、编辑帧、构图或分镜锚点 | 说明具体镜头、动作端点和锚定作用。仅为人物／道具外观来源时在 Subject 内说明来源，不必另立独立 Picture 定义；不能强加源图的非授权姿态 |
| `<Video N>` | 编辑源、续接起点或整段视频的运镜、切镜、节奏及时间结构 | 区分“这个视频提供结构”和“其中的动作作为可见内容被使用”；动作迁移仍归 Subject 角色。独立跟踪时说明源范围、目标镜头和继承属性 |
| `<Audio N>` | 单独音频或明确启用的视频同步音轨，被复制或参考的音频信号 | 只消费 M2/M6 已明确的音频用途；将听觉触发或节奏线索交 M7 配时。普通视频含声音不自动创建 Audio；Video 与 Audio 独立编号，不按数字猜配对 |

依据 R26–118。四类 Label 在各字段中始终保持同一含义。场景和动作都可能是 Subject，但只有需要独立追踪、在目标中实际使用的内容才单独定义；不为每一个手势机械增加一个 Subject。

## 6. 保留关系、端点与说话者

### 6.1 保留关系按内容角色判断

视觉关系使用 `fully_preserved / partially_preserved / attribute_transfer / weak_reference`；音频关系使用 `fully_copy / partially_copy / reference / weak_reference`。动作特征的迁移不是同一音频信号复制，也不是源人物身份整体替换。[R161–207]

若一个 Subject 只定义目标人物身份，目标增加动作不自动意味着身份没有完整保留；若某个 Subject 的角色明确包含参考步法、表情或姿态，改变这些内容应在该角色的保留分析中反映。M4 给出动作特征的保留／变化事实，M11 结合完整内容角色确定最终表达，M2 负责许可裁决。

### 6.2 关键帧约束的是特定端点

I2VA 固定首帧，FL2VA 固定首尾，L2VA 固定实际末镜尾帧；基础模式首行按原文模板，实际时长精确格式和镜头编号由 M7/M9/M11 提供。M4 检查身体、持物、接触及可观察中间过程，不把尾帧作为开场，不凭缺失图像编造已观察状态。[B14–34、50–70]

Ref2VA 在 `detailed_description` 中自然说明某镜开始、关键帧或结束对应哪个 Picture，不机械粘贴基础模式对齐首行。分镜图需要给出镜头映射及具体规划用途。[R62–73、248–256]

### 6.3 镜头、发声主体和事件编号分开

`[Shot 1]` 为第一镜，不附时间戳；后续切镜使用 `[Shot N] At MM:SS.mmm, ...`。动作阶段不自动形成新镜头，动作“暂停”也不自动生成剪辑定格。切镜与实际时间分别由 M9/M7 提供。[B84–92；R213–223]

`(Sx)` 对应实际发声源，`<d>` 承载对白／歌词。参考人物实际发声时使用 `<Subject N> (Sx)`；相同角色画外发声仍复用同一编号。纯表情、视线或跟随配乐的身体手势不自动成为新说话者。[R260–278]

当直接复用 BGM／完整音轨中的词句仅为动作线索，且没有独立人物或旁白实际发声时，使用 Audio 作为听觉来源，不虚构额外 `(Sx)` 或口型。只借音色、节奏、情绪和发声方式时，不连带复制原台词。对白和歌词原话由 M6 保全，M4 只处理相关表演及反应。

## 7. 编排及审计步骤

1. 取得当前目标实体、动作许可、空间、状态与必保事件；缺失资料保留未知，兼容外部输入可替代上游执行。
2. 由 M4.1 建立起态、前提和触发；由 M4.2 展开机制和关键接触；由 M4.3 明确结果和后继条件。重复动作在事件内部说明循环与结束条件，不以无入口的互相依赖代替动作循环。
3. 对照基础／参考模式的字段表选择语义交接位置；逐镜补全当前动作，而不是仅列 Label。首帧／尾帧任务检查端点相容，Ref2VA 检查来源作用域和保留关系。
4. 将必须看清的支撑、接触和落点交 M5；潜在声音交 M6；依赖和强调条件交 M7；状态变化请求交 M8；必要分段条件交 M9。发现问题回到责任方，不越权覆盖其字段。
5. 交付已接受动作版本、来源映射、逐镜完整事件及未决条件，由 M11 与其他模块一起编译。最终正文不夹带内部合同、开发规范或审计过程。
6. 分别报告结构、关系、语义和媒体结论。文本可读或字段正确不证明模型执行、真实接触、动作可见性或成片质量。

Ref2VA 六段按官方要求使用英语，保留 `<d>` 中对白／歌词及场景可见文字的原语言。官方 350–500 英文词属于通常生成任务的写作指导，含对白的完整时间线和复杂编辑任务有其原文例外；不能将其改成硬 token 上限或本地部署的统一截断条件。动作必需信息不因机械凑长短而丢失。[R5–9、242]
