# M4 审计、修复与下游交接

## 核心摘要

M4 审计“动作能否从声明起态进入，经可观察过程形成声明结果，并向后继事件提供必要条件”。审计对象是当前输入与动作计划；实际身体动力学、接触真实性、H3 输出和成片质量需要各自证据。合同检查不能替代专业判读或媒体观察。

**关键结论：** 子模块只提交本分区；父模块唯一接受。动作依赖交 M7 排时，状态变化请求交 M8，必须看清的过程交 M5。发现冲突时修改责任分区并产生新版本，不通过改写来源、删除原要求或覆盖失败记录制造通过。

**关键词：** 前置条件、支撑、接触、结果、接续、版本、局部检查、状态请求、未验证。

## 1. 审计范围与证据

先记录事件／镜头范围、计划与来源版本、已读取输入及采用的检查方式。结果状态采用 `pass / fail / unverified / not_applicable / stale`；工具的 `completed` 只代表操作完成，不代表专业结论通过。

| 检查层 | 可采用的证据 | 可以确认什么 | 不能由此推出什么 |
| --- | --- | --- | --- |
| 格式与引用 | 当前 JSON、原请求、Schema、稳定 ID | 已实现的字段、引用、版本与所有权条件 | 自然语言意图完整满足 |
| 声明关系 | 事件图、前后条件、过程和结果记录 | 有向依赖、对象绑定、条件对照等实际实现的规则 | 接触或动作符合真实动力学 |
| 专业语义 | 任务文本、案例依据、空间和状态投影 | 在给定证据下，动作链表达及接口是否自洽 | 生成模型一定执行成功 |
| 媒体结果 | 实际视频／音频与明确观察区间 | 被观察或测量的动作、声音、接续是否实现 | 未观察镜头、整片或其他后端也通过 |

本包脚本的确定性检查范围以合同指南和实际工具输出为准。语义审阅必须另列检查对象、具体发现和依据；不把脚本的 `unverified` 改写成媒体 `pass`。已有来源中的效果陈述标为作者报告，不当作本轮实测。

## 2. 子模块专业检查

### M4.1 表演事件与前提

1. 对照用户每项必保事件，确认存在稳定 ID、执行者、作用对象、目标和来源；保留用户强调的动作强度、方向或结果，不用同义词暗降要求。
2. 确认动作从当前身体、道具、接触和信息状态可进入；未知条件单独标出，不把“未知”当“已满足”。
3. 区分行动、接收到信息后的反应、预先知道信息后的预判。听见、看见、接触、事件完成等触发须有明确来源与作用对象。
4. 把情绪转成可观察行为：视线何时转向什么对象、呼吸或停顿有何变化、动作如何与人物目标相连。人物目标与情绪解释仍由 M1 提供或确认。
5. 使用稳定事件编号表达先后、条件依赖和反复；不拿事件编号顺序代替因果，也不把角色身体方向默认为屏幕方向。

### M4.2 动作机制与交互过程

1. 检查动作所需支撑、重心、发力、路径、接触和回收是否明确；身体方向、手脚侧别及道具身份与输入一致。
2. 检查关键过程有没有被终态跳过。抬腿需要进入、抬起、保持或回落；道具交接需要接近、共同接触、握持建立、放手及最终归属的合理过程。
3. 多人互动分别记录执行者、接触部位和被作用对象，不能把主动施力、被动响应和共同操作写成同一无主体动作。
4. 对参考动作，检查保留的是动作机制、节奏、姿态还是其他特征，并落实到目标角色；不因动作迁移同时复制来源外观和环境。
5. 对纯表情、视线、呼吸或无道具动作，必要物理字段可有理由地不适用；不填无意义的“支撑脚切换”以满足模板。未知接触与确实没有接触须区分。
6. 画面中的运动、摄影机运动、慢动作播放及人物实际速度分别解释。M4 不替代 M5 的机位／运镜或 M9 的变速意图。

### M4.3 结果与动作接续

1. 为每个适用事件给出可见结果、出态，以及持续或结束条件。维持姿态也是过程：明确保持什么、何时解除，必要时保留呼吸或局部变化。
2. 对照后继前提检查持物手、道具位置、支撑状态、朝向和接触是否衔接；有意变化须由事件或明确编辑策略解释。
3. 连续剑舞中分开剑、鞘和持握状态。拔剑后仍持剑的后继段不重新拔剑；许可的重新入鞘与拔剑过程、蒙太奇或时间省略另行说明。
4. 把预期结果写成计划结果，向 M8 提交状态变化请求；未经媒体观察，不称为“已经生成的末态”。
5. 保留打断、失败、拒收或未完成动作的实际叙事结果。不得为了整齐把所有动作自动改成成功收束；应说明打断事件和后继入口。

## 3. 组合与接口检查

| 组合边界 | 应核对的关系 | 缺依据时的处理 |
| --- | --- | --- |
| M4.1 → M4.2 | 过程对应同一事件、执行者、对象与前提，必保事件没有消失 | 缺事件／过程退回责任子模块；未知源条件保留未知 |
| M4.2 → M4.3 | 结果由所写过程产生；接触和道具操作没有跨过关键阶段 | 指出缺失阶段或矛盾，不以“自然完成”补洞 |
| 前事件 → 后事件 | 出态与后继所需条件相容；边界类型与变化许可明确 | 向 M4.1／M4.3 或 M8／M9 提修订请求 |
| M3 → M4 | 动作有相容空间、对象可达、身体方向不混用 | 向 M3 请求空间调整或补证据；不私改站位 |
| M4 → M5 | 必须看清的支撑、握持、触地、表情或落点已声明 | 摄影条件未知就保留可见性待验 |
| M4 → M6/M7 | 声音触发和动作依赖有明确事件，时钟来源不由动作文本冒充 | 提供语义关系；真实声音、偏移和秒数由责任方给出 |
| M4 → M8 | 状态请求包含变化原因及相关实体／事件；计划和观察分开 | 状态未接受不能声称已有权威状态更新 |
| M4 → M9 | 动作阶段与镜头／生成任务分开；关键过程是否允许被切掉已说明 | 提交边界需求，不自行增加切镜 |

子模块独立通过，只说明该投影下的局部结果。组合时必须核对同版本依赖：不能删除它借用的前提或机制后，仍把局部通过当完整 ActionPlan 通过。公开合同的完整替换、来源不可变、旧版本拒绝、幂等重放和问题所有权按合同指南执行。

## 4. 问题定位与修复路由

| 问题 | 首要责任方 | 返回内容 | 复验范围 |
| --- | --- | --- | --- |
| 缺执行者、对象、事件目标、前提或触发 | M4.1 | 事件 ID、缺项、已知条件、来源 | 当前事件及依赖它的机制与结果 |
| 支撑不明、动作跳步、接触／握持缺过程 | M4.2 | 缺失阶段、实体与道具、相冲突记录 | 当前机制、结果、可见性与占时 |
| 结果无原因、后继入口不符、持物突变 | M4.3；必要时 M8 | 前后事件及具体不一致条件 | 相邻结果、前提和状态请求 |
| 动作参考权限或角色身份混用 | M2 | 原来源、属性、目标和作用域 | 使用该来源的动作及下游编译 |
| 空间不可达、身体与屏幕方向混用 | M3 | 所需空间／接触区与已知约束 | 受影响过程及 M5 可见性 |
| 动作被遮挡、镜头没有看见关键过程 | M5 | 事件和必须可见的部位／结果 | 摄影、空间与动作呈现 |
| 对白、声源、歌词或动作声关系错误 | M6 | 声音线索与关联事件 | 发声、反应与排时 |
| 动作容量不足、依赖或同步偏移不成立 | M7 | 不可删事件、先后与完成条件 | 排时及相关动作／声音／摄影 |
| 计划状态／连续性或编辑重置许可不足 | M8/M9 | 原入出态、边界类型、待变属性 | 接缝、后继动作与编辑关系 |
| H3 主字段、标签、镜头或说话者格式错误 | M11 | 模式、目标字段、原语义和协议依据 | 编译产物；不改动作解决格式问题 |
| 实际媒体偏离计划 | M12 记录；再交专业责任方 | 媒体区间、观察、计划版本与差异 | 受影响生成片及后继接续 |

每次反馈明确任务、问题 ID、责任方、输入版本、建议变化、受影响项和退出条件。技术重试不替代语义修订；同一冲突重复运行不能自动变成通过。禁止隐式循环调用所有模块。

## 5. H3 编排交接

向 M11 提供已接受的 ActionPlan 版本、实体和事件对应、原要求与来源、每镜动作起态／过程／结果、正在生效的参考角色、来自 M7 的有效排时引用以及仍未解决的限制。M11 结合 M2、M3、M5—M10 的必要输入编译最终正文。

基础四模式动作正文进入 `integrated_multimodal_description`，Ref2VA 动作正文进入 `detailed_description`。只写“使用舞蹈参考”或事件表不足以构成最终正文；必须在参考实际生效的镜头解释谁如何动作。具体字段／Label 的编排和审计表见本包 `h3-label-mapping.md`。

交付的动作语义不是最终全套 H3 请求体。没有声音决定时，不能替 M6 把声音字段设为 `N/A`；没有真实时间依据时，不能给切点或动作虚填精确秒数；没有 M8 接受时，不能称状态已更新。

## 6. 变更影响与复验

动作目标或触发改变时，先核查依赖该事件的机制和后继结果；支撑脚、持物手、接触对象或路径改变时，检查相关空间、摄影、声音、时间与状态；仅修改显示说明不应让没有读取该说明的全部模块失效。

`impact` 只按登记消费者实际读取路径与版本做影响分析。登记外消费者保留未验证；“无已声明交集”不等于真实作品没有任何潜在影响。新的来源内容应使用新来源 ID，不能覆写旧来源让历史结论看起来仍然有效。

## 7. 交付形式与完成判定

优先提供本任务所需的动作链表：事件 ID／执行者／目标与前提／起态／过程／结果与出态／后继条件／来源与未知项。完整任务再附可接受的子提案及组合草稿、问题清单、下游交接与实际执行记录；单一子模块任务无需伪造其他分区。

本地结构与确定性关系完成后，可报告其实际通过范围；语义判读另行记录。存在未知参考、空间、当前状态、实际时间或声音时，给出仍可完成的局部结果和缺口。G0/G1 的局部完成不自动升级为完整 G2、G3、G4 通过。
