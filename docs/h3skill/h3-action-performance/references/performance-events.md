# M4.1 表演事件与前提

按需加载：出现动作名称缺少内容、表情／视线缺少动机、动作的执行者或对象不清、入态不一致、舞蹈或剑舞策略选择，以及戏剧表演请求时读取本文件。M4.1 只写 `ActionPlan.events` 的事件语义与前提；运行时字段以 [contract-guide.md](contract-guide.md) 为准。动作机制由 M4.2 写，结果与接续由 M4.3 写。

## 1. 先建立可辨认的事件

每个事件必须能回答下表。缺项时先保留待核实项，不能用“自然地”“优雅地”“完成动作”代替过程。

| 概念 | 必须说明的内容 | 不应代替它的内容 |
|---|---|---|
| 事件身份 | 稳定事件 ID、执行者、对象或交互对象 | 画面左侧、第一张图片、一个 H3 Label |
| 目标与可见变化 | 为什么执行；观众将看到什么改变 | 单独一个情绪形容词 |
| 起态与前提 | 姿态、已有支撑、朝向、已持道具、可用手、必要空间条件 | 默认重新回到参考图起始姿势 |
| 触发条件 | 上一事件的结果、另一人的动作、音乐节点或用户指定条件 | 未观察音频时假定精确强拍 |
| 事件范围 | 需要保留的动作、人物数、接触范围、开始／结束条件 | 自动增加配角、物件或一个动作系列 |
| 来源与确定性 | 用户指定、案例文本、作者报告、设计推断、待核实 | 把提示词存在当成视频效果已验证 |

先接收 M1 的目标、M2 的参考权限、M3 的空间条件和 M8 的当前状态；它们有效时直接使用，无需为调用 M4.1 重跑全部模块。M4 不改角色身份、参考资产权限、空间布局或权威状态。冻结职责见 [P01、P02](case-evidence.md#plan-boundaries)。

## 2. 让表演目标落到可观察事件

按“目标／收到的信息 → 行为选择 → 可见身体反应 → 期待变化”展开。根据情境选择视线、眼睑、呼吸、停顿、表情、躯干或手部中的必要载体；不要求每个部位同时表现。案例的三层舞蹈结构区分底层呼吸与重心、主动作链、头眼指腕细节，可以用于避免动作只有标签，但“古风舞脚步 → 重心 → 身韵 → 手臂 → 眼神”的次序只属于该舞种策略。[E01](case-evidence.md#e01)

表演事件须区分：

- **主动动作**：角色为达成目标而做什么。
- **回应动作**：被什么刺激改变，并以什么可见反应回应。
- **受阻后的再选择**：动作在哪个身体环节受阻，怎样制动、找回支撑、改变方向，再进入下一行动。白凤案例以身体改向表达受限；原案禁止新增施力者、手、绳或笼，这些限制只适用于该版设定。[E08](case-evidence.md#e08)
- **有意停顿**：仍在等待、观察、压制冲动或蓄势，并有呼吸、视线或身体张力的明确状态。它与意外失去动作内容不同。[E10](case-evidence.md#e10)

动作和反应可分为两个相互依赖的事件。例如道具接触后才出现眼神反应；接触与反应之间的因果关系需要明确，不能仅把两个画面描述并列。喜剧案例 README 提供动作链、道具触镜和眼神反应的文本依据；本轮未观察视频。[E13](case-evidence.md#e13)

## 3. 按领域选策略，保留共用事件结构

| 领域策略 | 编排重点 | 不可外推的限制 |
|---|---|---|
| 舞蹈 | 音乐／情绪目标、动作主题、力感、主链与细节、强拍后的余势和回收 | 案例的动作数量、转圈上限、速度或禁止走位不是所有舞蹈规则 |
| 剑舞／持物表演 | 当前持物状态、持物手、道具数量、身体与道具共同路径；剑舞仍需要完整身体动力链 | 已出鞘、只拔一次、空鞘、单人等是选定版本的约束 |
| 戏剧表演 | 角色目的、已知信息、对手行为、回应对象、表情／视线／停顿如何服务当前目标 | 不把 MV 的持续舞动、禁止对白、禁止走路扩展为戏剧规则 |
| 接触或道具交互 | 谁先做什么、接触是否成立、接触后的对象／身体变化、松开条件 | 接触不必一律引发换装、剪辑或音效 |
| 动作迁移 | 对齐接收角色与动作执行者；逐项检查允许迁移的节奏、姿态、路径、接触和起终态 | 本轮未语义阅读动作迁移案例；本项是权限与动作兼容性接口检查，不是已验证迁移方案 |

舞蹈的主题可以重复、变形或回归；不要求每段都增加动作数量。慢动作可以有完整的入态、展开、停留和回收。[E03](case-evidence.md#e03) 戏剧子策略来自冻结计划，本包提供可执行的事件描述与审计接口，但真实对白、同句异意、听者反应和对白走位尚无本轮生成验证。[P01](case-evidence.md#plan-boundaries)

## 4. 先消解范围矛盾，再交给机制分解

1. **快／慢**：识别形容的是音乐速度、身体动作、局部重音、镜头还是整段风格。允许“慢展开、快制动”，但同一时段同一身体过程同时要求全程极慢与瞬间完成时，登记冲突，保留用户优先级，交 M7 处理容量。
2. **原地／走路**：原地限制和移动动作作用于同一事件时必须修订。抬腿点地案例中非承重脚触地不等于迈步；其他案例可有踏步或位移，不能全局禁止走路。[E11](case-evidence.md#e11)
3. **已出鞘／再次拔刀**：先查权威当前状态和所选版本。已有裸刃时，把“再次拔刀”标为前提冲突；不能悄悄生成第二把刀或把状态重置为参考图。[E04、E05](case-evidence.md#e04)
4. **单人／多人**：保留 M1／M2 确认的演员与实体 ID。单人案例不能支持增加舞伴，也不能推出其他项目一律单人。多人交互需要每个参与者的事件、对象和依赖；本轮多人实例未做语义验证。
5. **动作来源／角色来源**：参考动作可以借用不代表参考中的人物、服装、背景也可借用。M2 决定来源权限；M4 检查允许的动作能否由当前身体、空间和道具状态完成。[E11](case-evidence.md#e11)

存在不可满足的必要前提时输出具体缺口与受影响事件；不得删除用户要求的主动作来制造“通过”。

## 5. 交付与审计

M4.1 输出：事件身份、执行者和对象、目标与触发、可观察动作／反应、必要起态、策略、范围约束、来源及未决项。下游只需进一步展开机制，不应重新猜测演员或目标。

验收问题：目标是否落到可见行为？对象是否明确？触发是否先于反应？起态是否符合已有支撑与道具状态？动作与镜头是否分开？是否错误套用了另一案例的单人、速度、站位或无对白限制？不满足时回到本分区修订；身份／权限冲突转 M2，空间前提不足转 M3，权威状态不明转 M8。

### 设计性演示：目标性停顿

> 听到对手提及关键物件后，角色先把视线移向对手的手，再停住自己原本伸出的右手；右脚维持当前支撑，身体没有继续前倾。短暂停顿后，他将视线移回对手面部，等待回应。

此例用于检查“信息 → 反应 → 身体抑制 → 等待”的事件描述，不是案例抽取，也未运行 H3。停顿时长由 M7 决定；台词文字和声音由 M6 决定；身体制动、支撑和下一动作入口继续由 M4.2／M4.3 展开。H3 输入模式与 Label 落点见 [h3-label-mapping.md](h3-label-mapping.md)。
