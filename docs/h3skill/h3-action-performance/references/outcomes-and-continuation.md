# M4.3 结果与动作接续

按需加载：动作没有结果或回收、段落之间复位、结尾与下一动作冲突、触地后立即离地、道具与持物状态丢失、循环／静止要求不清时读取。本分区只写 `ActionPlan.outcomes` 并提出状态变更请求；M8 是权威状态的提交者。运行时字段以 [contract-guide.md](contract-guide.md) 为准。

## 1. 结果必须可辨认，且能成为下一动作的前提

分别记录三个层次：

1. **已达到的动作结果**：角色／对象出现什么可见改变，是否达到目标；未达到时明确受阻点。
2. **身体退出状态**：支撑、位置／朝向、高度、接触、持物、剩余动势、表情／视线中与下一动作有关的状态。
3. **后续条件**：继续保持、循环、恢复、结束，或进入哪个下一事件；进入前必须满足什么。

仅写“动作结束、自然接下一段”不合格。上一链的出口必须能成为下一链的入口；剑舞不能每段从参考图重新拔刀，地面动作不能在没有支撑转移的情况下直接站起。[E04、E05](case-evidence.md#e04) [E09](case-evidence.md#e09)

## 2. 区分完成、保持、恢复和有意未完成

| 退出类型 | 需要说明 | 审计重点 |
|---|---|---|
| 完成并稳定 | 目标状态、稳定支撑、持物与接触 | 不是只给峰值而跳过制动 |
| 保持 | 保持什么、为何保持、什么条件允许结束 | 不以“短暂停留”掩盖缺少释放条件 |
| 回收后接续 | 余势怎样消散或被利用，下一动作怎样启动 | 不无故方向反转或姿态复位 |
| 有意未完成 | 中断发生在哪个阶段、哪些状态仍未完成、下一事件如何接管 | 与生成缺失或意外停顿分开记录 |
| 循环 | 循环入口、出口、重复条件及停止条件 | 不把每条链都变成无终止循环 |
| 段落结束 | 最后目标状态、是否静止、哪些微动仍持续 | 局部结束规则不能被一般“全程连续运动”覆盖 |

白凤案例明确设计过未完成的回收、动作受阻与有意停顿；动作库也包含明确的短循环。这说明“禁止所有静止”“禁止所有重复”均不能推广为通用规则。[E07、E08、E10](case-evidence.md#e07)

当用户要求全身静止却又要求同一时段持续迈步，需登记矛盾；允许区分身体大动作停止、呼吸继续、衣发余势、视线保持和镜头继续移动。是否保留这些运动由当前事件意图决定，不应自动添加。

## 3. 检查跨动作、跨段和接触切换

### 普通接续

对每个后继事件逐项比较：执行者一致吗？当前位置和朝向能到达下一入口吗？支撑脚／接触点是否可转换？空闲手和持物关系是否足够？上一动作的余势与下一方向是否相容？未解决的冲突交回对应分区或上游字段所有者，不能由 M4.3 偷改原目标。

不同段落的参考图可提供身份，却不能覆盖已有动作状态。剑舞案例的后续段落需要明确“刀已出鞘并被持有、腰侧空鞘”等入口事实；特定版本是否最后归鞘要按该版计划，不能把不同版本拼成一个状态链。[E04](case-evidence.md#e04)

### 接触触发的切换

已读抬腿案例的正确顺序为：下降 → 第一次明确触地 → 保持接触 → 切换／外观稳定 → 解除接触 → 下一次抬腿。身体离地与外观切换不是同一事件。M4 只规定动作依赖和保持条件；外观变化写成给 M8 的请求，切点给 M9，时刻给 M7，必要可见性给 M5。[E12](case-evidence.md#e12)

“首次触地”也不必等于“主要承重建立”：该案仍由后侧脚支撑。若任务要求迈步或换脚承重，须增加实际负载转移并重新检查范围，不能复制该案固定支撑模板。[E11](case-evidence.md#e11)

### 拍点与时间冲突

区分启动、峰值、接触、达到结果和释放；它们可以依赖同一音乐节点，但不能默认发生在同一时刻。已读剑舞提示词对拔刀时刻存在 00:03.500–00:03.850 与 00:03.870 两种写法；应作为来源内部冲突交 M7，不能选择一个并声称它是已测量的音频事实。[E14](case-evidence.md#e14)

窗口不够时，保留用户要求和不可缺少的因果过程，列出容量风险，提出可选的动作精简、拆段或窗口调整，再由相应所有者修订。不要用更快的形容词假定复杂动作已经可容纳。[E03、E07](case-evidence.md#e03)

## 4. 输出给其他模块的最小接口

| 接收者 | M4.3 交付 | 权威边界 |
|---|---|---|
| M5 镜头 | 必须看见的过程、接触、结果及不能被遮挡的关键部位 | 不决定镜头语言或相机路线 |
| M6 声音／对白 | 潜在发声／音效事件、听到后的反应依赖 | 不决定台词文本、声音素材或混音 |
| M7 时间／音乐 | 启动、峰值、到达、保持、释放的先后与容量约束 | 不伪造节拍或绝对时刻 |
| M8 状态 | 事件造成的身体、道具、接触等状态变更请求及依据 | 不直接提交权威状态 |
| M9 剪辑 | 可切换条件、必须保留的因果过程、接续入口 | 不自行确定剪辑方案 |
| M12 审计 | 未决前提、冲突、来源限制、可检验的结果 | 文本通过不等于成片通过 |

职责按冻结计划 [P01、P02](case-evidence.md#plan-boundaries)。详细交接和审计见 [audit-and-handoff.md](audit-and-handoff.md)。

## 5. 设计性演示与验收

**案例规则的设计性重组：点地后进入下一抬腿**（非逐字案例抽取，未运行 H3）：

> 近侧脚从空中下降，脚跟／脚掌首次清晰接触地面后保持原位；后侧脚继续承担主要支撑，身体不向前迈步。待外观切换完成且接触状态仍清晰后，近侧脚才释放接触，膝盖再次屈曲进入下一次小幅抬腿。

本例只适合具有相同固定支撑前提的点地切换任务。没有外观切换的任务无需增加等待外观稳定的步骤。

最终验收：每个事件是否有可见结果或明确未完成原因？峰值后是否制动／回收？接触保持是否有释放条件？结果是否满足后继前提？终点与循环／静止要求是否冲突？状态变更是否只作为请求？台词、相机、剪辑和时刻是否保留各自所有者？H3 模式／Label 落点继续以 [h3-label-mapping.md](h3-label-mapping.md) 为准。
