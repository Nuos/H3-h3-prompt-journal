# M4.2 动作机制与交互过程

按需加载：动作只有名称或结果、身体／道具穿透风险、支撑和重心不清、接触或握持未说明、动作迁移与当前身体条件不兼容时读取。本分区只写 `ActionPlan.mechanics`；读取已确认的事件和起态，不覆盖 M4.1 的目标或 M4.3 的终态。字段以 [contract-guide.md](contract-guide.md) 为准。

## 1. 用完整链说明动作怎样发生

基本检查链为：**入态条件 → 支撑／受力 → 运动路径 → 接触 → 可见结果 → 制动／回收 → 下一入口所需状态**。本分区说明产生结果及回收的机制，结果记录与接续条件由 M4.3 收束。不涉及接触、跳跃或握持的事件可明确“不适用”，不能为了凑字段增加动作。

| 检查点 | 应写清楚的内容 | 常见缺口 |
|---|---|---|
| 入态 | 身体高度、朝向、已有承重部位、空闲肢体与已持物 | 从未知状态直接写“旋转／落地” |
| 发力与支撑 | 哪个部位推动、哪个部位承重，重心向哪里转移 | 脚不动却无条件整体位移 |
| 路径与轴 | 身体或物件经过的方向、轴心、幅度；必要的避让 | 只写动作峰值，不写到达方法 |
| 接触与承重 | 谁与什么接触、接触何时成立、是否承重、是否持续 | 把触碰等同于承重或抓牢 |
| 握持与交接 | 手、握点、持有者、释放与接收的先后关系 | 道具无故换手、增殖或悬浮 |
| 制动与余势 | 怎样减速、重新平衡；衣发或道具的惯性怎样收束 | 峰值后立即无解释切入反向动作 |
| 退出接口 | 给 M4.3 的最终支撑、方向、持物和剩余动势 | “自然衔接下一动作” |

完整身体过程与衣发滞后依据古风舞方法论；剑舞进一步明确蓄势、重心启动、扩张、峰值、制动、恢复和下一动作入口。[E02](case-evidence.md#e02) [E06](case-evidence.md#e06) 这是提示词的可执行描述与一致性审计，不等于生物力学模拟或动作安全认证。

## 2. 区分接触、承重与约束

对接触事件至少检查四种关系：**接触前可达 → 首次接触 → 接触保持／负载变化 → 释放后状态**。可达性不足由 M3 修正空间条件；M4 不能用伸长肢体、物件瞬移或未声明的新人物补足。

- **触碰而不承重**：抬腿点地案例的近侧脚触地用于剪辑触发，后侧脚保持主要支撑；这不是走路中的换脚承重。[E11](case-evidence.md#e11)
- **支撑发生转移**：白凤地面动作有手掌、前臂、肩、骨盆等相继承担支撑的文本，应说明各阶段怎么进入，不能把固定单脚支撑当成所有动作模板。[E09](case-evidence.md#e09)
- **握持与移动分开**：物件随手移动时仍须保持持物关系；有交接时明确谁先提供稳定接收、何时释放。交接规则是由唯一持物状态与接触连续性推出的设计检查，未把未观察的交接视频当作证据。[E04、E05](case-evidence.md#e04)
- **约束来自何处**：被阻挡、失衡或改变方向时写出可见身体机制；案例未允许的牵引者、绳索、额外手不能自行补入。[E08](case-evidence.md#e08)

只有世界观明确允许的非写实动作才使用相应规则，并把该许可记为前提。不要仅靠“超现实”覆盖前后互相矛盾的接触关系。

## 3. 领域展开

### 舞蹈与地面动作

动作主题和力感来自 M4.1；这里展开主动作链。转身至少说明支撑脚、重心／轴、启动、减速和找回平衡；跳跃说明起跳支撑、离地与落地；地面动作说明降低身体、接触地面、负载迁移、回到下一姿态。头眼手指等细节服从主链，不以全身同时微动代替主动作。[E01、E02](case-evidence.md#e01)

案例动作库的时间估计用于暴露容量风险：动作链必须有进入、峰值、制动和接续，不能把有限窗口塞满动作名称。案例中的拍数、秒数、转圈上限均不是模型保证或通用物理常数；M4 描述不可删减的过程，M7 负责音乐／绝对时间分配，容量不足时回传重排、拆段或简化建议。[E07](case-evidence.md#e07)

### 剑舞与持物

先核对身体解剖学左／右手、握点、刀剑数、鞘状态及所选版本。刀剑的路径与肩、肘、腕、躯干和重心一起描述；既有刀剑从已持位置开始，不能反复拔出或在身体内穿行。剑舞案例的海滩踏地、身体外侧刀路、制动和低位持刀收势可提供文本范例；单刀、单鞘、只拔一次是该版约束。[E05、E06](case-evidence.md#e05)

### 表情、视线与戏剧动作

按必要粒度说明视线目标、头部／身体是否跟随、动作被抑制或恢复的过程。普通视线回应无需强塞全身重心链；涉及前倾、转身、坐下、伸手或制动时才展开相应支撑。对白时说话与身体动作的依赖可由 M4 提供，原句、口型要求、语气、声音和声画时间由 M6／M7 管理。戏剧接口来自冻结计划，真实对白表演能力未被本轮案例验证。[P01](case-evidence.md#plan-boundaries)

### 动作迁移与多人交互

迁移前逐项核对：接收角色的起态和支撑、允许借用的动作特征、空间／道具可达性、动作源中的接触对象是否存在、速度是否可容纳，以及退出状态能否接入当前叙事。动作参考的权限由 M2 确认；没有观察参考视频时保留待核实，不声称逐帧复制或测量节奏。[E11](case-evidence.md#e11)

多人时分别追踪执行者、接触对象、承重与相互依赖，实体 ID 不随画面左右或站位互换。单人已读案例不能验证多人复杂交互或遮挡；无法确认空间可达性时请求 M3，无法确认身份对应时请求 M2。本轮没有动作迁移／多人案例的语义回归证据，以上属于通用接口审计设计。

## 4. 接触切换的专门检查

对“抬腿后触地切换外观”一类任务，分别记录：抬起、下降、首次明确触地、保持、切换完成、解除接触、下一次抬起。切换是接触的下游事件，不能与抬腿自动合并。固定后脚支撑、近脚小幅抬落、触地后保持、服装只在触地点切换，是已读案例的范围约束。[E11、E12](case-evidence.md#e11)

M4 写接触与保持／释放条件；M7 写时刻，M5 保证必要接触可见，M9 决定切点，M8 提交外观与状态变化，M6 决定对应声音。不能把“拍到接触”“剪到下一装扮”当成身体已经完成承重转换的证据。

## 5. 设计性演示与验收

**设计性演示：持剑转身的展开**（未运行 H3）：

> 角色已用右手持剑，剑尖在身体外侧低位。左脚承担主要支撑，右脚踏出半步，髋部先转、胸肩随后转入；右臂带剑沿身体外侧上行，剑身避开躯干。到达目标朝向后，双脚重新稳定承重，手腕降低剑尖并吸收余势，右手继续持剑，准备下一次抬剑。

示例中的手别、脚别和幅度是设计值，执行前必须与 M2／M3／M8 的输入对齐。审计需确认：动作可由起态进入；支撑和接触不互相矛盾；必要负载转移有过程；物件数量和持有关系连续；制动／回收有出口；没有把镜头运动写成身体运动。结果状态和下一动作前提由 [M4.3](outcomes-and-continuation.md) 最终收束。
