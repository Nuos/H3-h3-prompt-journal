# H3 声音、音乐、对白与歌词关系

先确认**观众应当听见什么、声音来自谁或何处、使用原信号还是参考特征**，再组织声音与人物动作、镜头及前后段落的关系。

实现 M6 与四个公开子模块。各子模块只提出本分区候选，父模块按真实请求、来源与版本唯一接受。兼容的用户文字、已有计划或外部资料可以直接满足输入；不要求先按编号运行 M1—M5。案例方法保留适用条件，当前明确的用户要求优先。

## 1. 选择职责并按需读资源

## 2. 建立声音任务与证据

确认作品范围、镜头／事件、用户给出的完整台词、语言、声音来源、音频资产版本与启用状态、使用许可、已有动作及跨镜要求。只读取本次所需的 M1/M2/M3/M4/M7/M8/M9 公开投影。

分别登记用户要求、案例文本、作者效果报告、本轮设计、假设与实际观察。取得文本转述不等于听过音频；没有音频或实测标注时不写“已确认音色”“精确拍点”“实测语速”。图片和视频视觉内容不自动证明声音属性，视频文件带声不自动授权启用音轨。

对不足信息保留具体未知理由，完成仍有依据的局部方案。未知不能写成静音、无配乐、不适用或检查通过。台词、音轨使用目的或权限有矛盾时，返回具体对象和修改选项，不静默删改必保内容。

## 3. 完成四项声音决定

1. **M6.1 绑定来源。** 为每个独立声源建立稳定身份，区分画内人物、画外人物、旁白、音轨、环境或动作来源。说明声音身份／音色来自用户要求、参考许可还是待确认设计。关联已有实体，不用 H3 标签编号反推实体。配乐中的歌词cue不自动构成画面人物的发声。
2. **M6.2 组织发声事件。** 以独立声音事件关联声源、话语原文、语言、发声方式、语义顺序、起止或延续条件。保留用户批准文字；仅参考音色不继承原参考台词。明确是否实际演唱、旁白或音轨内提示，是否有口型要求，是否在切镜后继续。精确排时交 M7，切点选择交 M9。
3. **M6.3 选择音轨策略。** 区分完整最终音轨复制、部分时间或声层复制、特征参考、新生成和无配乐。登记源音频、源时间域、窗口、使用属性和目标范围。完整复制不能同时新增其他声音；引用完整配乐但混入动作声属于部分复制关系。没有实测音乐依据时只给候选结构与缺项，不从 BPM 推定真实拍点或首拍偏移。
4. **M6.4 组织环境与动作声。** 说明哪种环境或动作产生声音、是否在原音轨中已有、何种事件触发、怎样持续或停止、跨镜是否保留；明确全片静音指令在本分区登记。区分物理动作声、非语言人声与画外配乐。新增声层必须与 M6.3 策略相容，不因画面有触地动作就覆盖完整音轨复制要求。
5. **M6 父级检查组合。** 核对声源引用、文字保真、音轨策略、原窗口、发声身份、静音范围与声音延续。需要修改专业值时返回分区责任方；不得代替 M2 更改许可、M4 改动作、M7 改时间或 M9 改剪辑。

完整对白、打断、多人重叠或复杂混音的契约支持不等于这些能力已经获得充分案例或媒体验证。将未知和专项验证任务交给相应消费者。

## 4. 处理高风险混淆

- **复制与参考分开。** 原信号的整条／局部复用与音色、节奏、曲风的参考不同。保留整条配乐并新增声音，不符合 `fully_copy` 的完整最终音轨定义。
- **歌词与人物分开。** 背景音轨出现词句，不自动要求人物演唱、开口或把歌词名词变成画面实体；当前任务明确要求时才建立对应表演和声源。
- **声音编号与资产编号分开。** `<Subject N>` 是可见参考内容，`<Audio N>` 是声音信号，`(Sx)` 是实际发声源；M11 统一编译，不由 M6 抢先固定编号。
- **原文与格式转换分开。** 内部保留原文和批准文本。基础模式逐词逐标点保留；Ref2VA 的基本标点规范和 `[unclear]` 规则由 M11 按协议显式处理，不覆盖原始记录。
- **局部静音与全片静音分开。** 无画外配乐不意味着无环境声或对白；未提供声音信息不能当作全片静音。
- **声音语义与排时分开。** 建立声音事件和触发关系即可交 M7；只在有来源时登记源音频窗口，不维护竞争的成片绝对时间表。

## 5. 交接 H3 模式、字段与 Label

| 模式 | M6 的主要正文去向 | 声音汇总 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | `overall_soundscape`、`non_diegetic_music` |
| I2VA | 实际首帧对齐后的基础主正文 | 同上；首帧图片不证明声音 |
| FL2VA | 首尾帧之间事件路径的基础主正文 | 同上；声音延续与终止另行说明 |
| L2VA | 收敛到尾帧的基础主正文 | 同上；尾图不自动确定音频起点 |
| Ref2VA | `subject_definitions`、`summary`、`retention_analysis`、`detailed_description` 中对应声音语义 | 对应可听层的两个声音字段 |

在 Ref2VA 中核对 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 四类参考 Label 的实际职责；Video 与 Audio 独立编号。基础四模式不直接套入完整参考 Label 结构，只保留各自官方 Picture 对齐用法；需要启用音频参考时交 M11 核对模式。Ref2VA 的可见主体实际发声时才与 `(Sx)` 联用，直接复用配乐里的词句提示可以只以 Audio 为源。五模式的台词和歌词均写成 `<d>[Language] ...</d>`；跨切延续及片尾截断分别由 M11 使用 `<scenetrans>` 和 `<cutoff>`。

最终 H3 英文描述保留对白／歌词及画内文字原语言。`overall_soundscape` 不重复完整台词；角色可听见的乐器、电视或手机音乐进入主正文；只有观众可听的配乐进入 `non_diegetic_music`。内部 SoundPlan、来源索引、合同和审计说明留在制作记录，不进入模型正文。

## 6. 检查并交付

读取合同指南后，在本包目录执行 Python 3.10+ 标准库工具：

```bash
python scripts/m6_contract.py --help
python scripts/m6_contract.py route assets/request-m6-3.json
python scripts/m6_contract.py check assets/proposal-m6-3.json --request assets/request-m6-3.json
python scripts/m6_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 返回显式目标、必要输入和资源；`check` 核对公开合同及已实现的声音关系；`accept` 对照实际原请求和基版本输出新草稿；`impact` 根据实际登记的读取路径定位复验消费者。工具不自动听写、分析节拍、合成音频、混音、调用 H3 或改写输入文件。

交付本域提案或 SoundPlan、未解决事项、责任回传与 H3 字段交接。分别说明格式／合同检查、确定性关系检查、Agent 文字审阅和实际媒体结果。草稿接受与 `local_contract: pass` 只证明对应本地检查；没有真实生成媒体时，口型、音色、节拍贴合、混音和 G3/G4 均保留未验证。
