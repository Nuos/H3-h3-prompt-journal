# H3 摄影机、构图与可见性

先确定**观众必须看清什么**，再组织摄影机在哪里、看向哪里、画面包含什么、哪些对象需要清晰，以及摄影机为何在某个事件前后运动。

实现 M5 及四个公开子模块。子模块只提出自己分区的候选，M5 父模块按原请求、来源与版本唯一接受。兼容的用户资料或外部计划可以直接提供输入，不要求按编号运行 M1—M4。当前用户约束优先；案例方法保留适用范围。

## 2. 建立本次观看任务

确认当前镜头／连续阶段、稳定实体、动作事件、场景尺度、关键接触、参考使用权限与必保信息。只读所需的作品、空间、动作、时序、连续性、剪辑和风格投影。区分用户要求、案例文本、设计选择、假设和实际媒体观察。

给每个重要事件写出“哪个主体的什么部位或关系，在动作的哪个阶段需要可见”。如手递道具，应检查递出、共同接触、释放与最终持有的必要可见关系；不能只说“拍得清楚”。未取得动作或场景资料时，继续形成当前可作出的方案，并把依赖该资料的结论标成未知。

M5.2 可以直接使用外部提供的机位与动作。M5.3 可以独立整理清晰范围。必要信息不足时返回具体缺口；不为凑齐参数虚构传感器、焦距、光圈、距离、真实拍点或媒体观察。

## 3. 分开完成四类摄影决定

1. **M5.1 确立观察位置。** 说明摄影机相对主体与场景的位置、高度、距离、朝向、光轴目标及必要的机身姿态。区分世界方向、主体自身左右与画面左右。特殊视角说明造成其视觉结果的空间条件；普通镜头按需要表达，避免机械堆满参数。
2. **M5.2 确立画面信息。** 说明景别、画面边界、主体占画、相互层次和动作展开空间。将关键可见条件绑定到实际动作阶段；允许的遮挡单独说明范围、理由和重获可见条件。明确已知视场／尺度及其缺口。
3. **M5.3 确立清晰范围。** 指定本阶段需要读清的对象和层次，说明保持或改变焦点的目的与触发。多主体是否同时清晰由当前观看任务决定；缺少光学资料时只交付清晰目标及待核对项，不宣称精确景深已经满足。
4. **M5.4 确立运动。** 为摄影事件建立独立于人物动作的 ID，引用起终机位、主路径、沿途光轴目标、触发事件、响应策略和停止／稳定条件。复合运动逐阶段说明转换原因。固定观察明确机位与朝向保持；人物与环境仍按自己的事件运动。
5. **M5 父级核对组合。** 检查相机位置、光轴、构图、焦点、路径与观看任务是否相容。需要改变任何专业值时返回拥有该分区的子模块；父接受不偷偷改写动作、站位或参考权限。

机位高度不等于俯仰角，机身滚转不等于人物倾倒，近距离不等于已经满足指定景别，物理推进不等于变焦或裁剪。需要真实移动的方案应写出路径；数字变换若为当前任务明确许可，标明其性质并交相关职责处理，不能伪装成物理机位改变。

## 4. 选择响应策略并处理边界

从任务中选择**提前到位、同相响应、滞后追随、固定观察**。共享时间线不等于所有事件零延迟：写清对齐的是动作启动、峰值、接触还是恢复，将精确时刻、偏移与容差交 M7。没有镜头运动需求时，不因每次手指、脚步或音乐拍点自动增加运镜。

遮挡可服务构图或揭示，也可能破坏接触可读性。相机在遮挡期间的路径仍须连贯；真实切镜、变景、生成分段及转场决定交 M9，不能将案例内名为 `SHOT` 的连续运镜阶段自动改成切镜。跨镜出入构图与运动方向交 M8 协调。

不将案例的手持、低机位、5–15 cm、1:1 同步、禁角度数字、固定人数、上半身优先、固定锁焦或禁数字变换提升为所有任务的硬规则。保留明确需要的多主体、剧情走路、主观观察、静止镜头与有理由的焦点变化。发现需求冲突时列出最小修改候选，不悄悄删除必保动作。

## 5. 交接 H3 字段与参考 Label

| 输入模式 | M5 摄影工作 | 主要正文去向 |
| --- | --- | --- |
| T2VA | 从文字观看任务建立机位、取景、清晰范围和运动 | `integrated_multimodal_description` |
| I2VA | 对齐实际首帧的观察关系，再描述后续变化 | 首帧对齐指令及基础主正文 |
| FL2VA | 连接首尾帧的取景与空间端点，说明中间路径 | 首尾对齐指令及基础主正文 |
| L2VA | 从合理前态收敛到实际尾帧的观察关系 | 尾帧对齐指令及基础主正文 |
| Ref2VA | 按授权参考用途逐镜组织摄影；分析保留与改变 | `retention_analysis` 与 `detailed_description` 等六段字段的对应职责 |

Ref2VA 的四类官方参考 Label 为 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`。身份图不自动决定首帧和机位；图像／分镜可作为具体视觉锚点；视频层参考须明确复制或改变的范围；音频节奏不会自动触发每拍运镜。`[Shot N]` 是镜头记号，`(Sx)` 是发声主体编号，均不是 CameraEvent ID。

H3 字段中不存在由本包新增的 `camera_movement`、`camera_position` 或 `focus_plan` 顶层键。基础四模式的三个字段与 Ref2VA 的六个字段按官方原文编译；内部 CameraPlan 留在制作记录中。M5 提供摄影语义与审计要求，M11 负责实际素材排序、Label 编号及最终正文。Ref2VA 描述使用英语，保留对白、歌词和画内文字原语言。最终模型正文使用完整、具体的镜头事件描述，排除内部合同和审计说明。

## 6. 检查并交付

先读取合同指南，再从本包根目录执行 Python 3.10+ 标准库脚本：

```bash
python scripts/m5_contract.py --help
python scripts/m5_contract.py route assets/request-m5-2.json
python scripts/m5_contract.py check assets/proposal-m5-2.json --request assets/request-m5-2.json
python scripts/m5_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 定位显式目标、最小输入和资源；`check` 核对合同与已实现的引用关系；`accept` 对照实际原请求和版本输出新草稿；`impact` 根据登记的读取路径定位复验消费者。脚本不自动拍摄、计算完整光学或碰撞、不观察视频、不调用 H3，也不修改输入文件。

交付本域提案或 CameraPlan、关键可见条件、未解决项、责任回传和 H3 字段交接。分别报告结构检查、确定性关系检查、Agent 专业审阅及实际媒体结果。`local_contract: pass` 只表示已实现的本地检查通过；缺少真实媒体时保留 G3／G4 未验证，不把草稿接受写成 H3 生成质量通过。
