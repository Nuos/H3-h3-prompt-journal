# M5.3 焦点与景深策略

## 证据边界

冻结 M5 方案明确要求焦点对象、变化与清晰范围，同时说明现有案例不足以覆盖完整镜头视场和景深问题。当前模块把案例中的观看目标、主体与动作可读要求整理成可检查的清晰范围合同；不增加未经案例支持的通用镜头参数配方。[C01][C04][C05][C06；D]

本分区输出摄影计划中的清晰要求。它不执行光学计算，不从图片猜测实际焦距或光圈，也不把“主体清楚”当作已经获得真实媒体证明。

## 独立调用

从当前镜头的取景与关键事件建立清晰优先级。外部提供兼容构图资料时可以单独完成本职责；未提供镜头、距离或场景尺度不应迫使调用者先运行其他模块。

最小语义问题：哪个目标在什么事件阶段必须可读，哪个对象可被弱化，是否存在有理由的焦点变化，以及当前资料能支持哪一级判断。

## 清晰目标与焦点变化

| 决定 | 要写出的内容 | 审计 |
| --- | --- | --- |
| 清晰对象 | 稳定主体、部位／道具、关键关系 | 是否漏掉本镜头必须辨认的对象？ |
| 清晰范围 | 需要读清的景层或同时发生的关系 | “背景虚化”和“多人同时清晰”是否冲突？ |
| 保持焦点 | 保持对象和持续条件 | 是否把锁焦误写成所有对象、动作都停止？ |
| 改变焦点 | 从谁到谁、为什么改变、由哪个事件触发、何时需重新可读 | 是否造成关键接触发生时目标不可读？ |
| 光学条件 | 已提供的尺度／距离／镜头条件及来源；其余标明未知 | 是否伪造测量值或把设计参数当作照片事实？ |

表中“改变焦点”是 M5.3 的合同设计能力。当前案例只支撑可读性需求与有限的摄影描述，不构成完整调焦样本或稳定效果证明。焦点事件可以与动作关联；权威时间与容差由 M7 安排。[D]

## 处理常见冲突

- **多人同时可读与选择性模糊冲突：** 先确认观看任务需要哪些对象，再提出调整清晰范围、构图或层次的候选。由各责任方决定；不强制使用某个光圈或焦距。
- **主体前后移动但清晰要求未变：** 记录需要保持可读的动作范围和重获目标条件；距离或光学资料不足时保留待核对，不臆造精确跟焦距离。
- **接触点与面部目标竞争：** 按本镜头信息优先级处理，必要时向 M5.2／M9 提出覆盖方案，不删除接触事件。[C05；D]
- **参考图清晰但目标镜头不同：** 参考图的清晰度并不授权复制其机位、取景或焦点策略；先核对 M2 的属性权限。[C07；D]

## 未知与通过范围

区分四种陈述：

1. 用户要求某个对象清晰。
2. 摄影方案提出使该对象可读的条件。
3. 已有计算或实际观察证明某个范围内满足要求。
4. 生成媒体尚未提供，结果未验证。

本包可完整表达前两者，并记录后两者的证据与缺口；本轮实现不自行创造第 3 类证据。缺少精确光学资料时，合同检查可以通过，但光学可行性、真实可读性与 G3／G4 继续未验证。[D]

## 返回与交接

输出焦点目标、保持／变化策略、清晰范围、必要来源和未知项。构图更改交 M5.2；位置和距离更改交 M5.1；运动路径更改交 M5.4；人物层次更改交 M3；时序交 M7；真实清晰度观察交 M12。
