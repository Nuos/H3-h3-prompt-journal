# M5.2 取景、构图与可见性

## 独立入口

接收观看目标、主体／动作与机位的必要投影，形成 `framing` 分区。兼容外部输入足够时直接执行，无需重新运行 M5.1 或 M1—M4。缺少视场或场景尺度时可给出可见目标与条件，实际可见性保留未验证。[D；冻结方案 §7.1]

## 先列信息，再安排取景

将每个关键动作写成“谁、什么部位／道具、在哪个阶段、需要看见什么关系”。取景随后服务这张信息清单。

| 任务 | 需表达的可见条件 | 不能用来替代它的描述 |
| --- | --- | --- |
| 脚步或触地事件 | 接触之前、接触建立、必要保持与离地的关系 | “有一个脚部特写” |
| 道具交接 | 递出者、接受者、道具与关键抓握／释放关系 | “人物自然交接” |
| 多人队形变化 | 稳定实体、必要层次、交叉关系及展开空间 | “所有人排好队” |
| 角色反应 | 应被看见的面部／视线／身体反应与原因 | “镜头有情绪” |
| 遮挡后揭示 | 遮挡对象、被遮目标、路径、再出现的观察位置 | “转场后出现在另一边” |

触地与队形行来自案例方法提炼；道具交接与角色反应为与 M4 合同兼容的设计示例，不是新增实拍证据。[C04][C05][C03；D]

## 编排步骤

1. 说明镜头观看任务、主体与动作事件 ID，列出不可丢失的信息。
2. 选择景别和画面范围，说明哪些部位、接触点和环境关系应入画。
3. 说明主体占画、前后层次、画面方向与运动空间；不把单一裁切结果当作所有阶段的保证。
4. 对比动作全过程：动作展开、遮挡建立、相机位移、焦点变化是否令必要信息在关键时刻不可读。
5. 逐项标记已知条件、设计要求、未取得的数据与待媒体验证的结论。
6. 需要改机位、动作、空间、焦点或时序时向对应责任方提出具体请求。

案例里的“上半身优先”、固定前后顺序、固定人数或接触特写只在相应观看任务内适用。若用户需要全身动作或多人同时可读，重新选择画面范围，不能用案例默认值截断必要信息。[C03][C04][C05][C07]

## 遮挡可被设计，但需声明

区分无意遮挡、任务允许的短暂遮挡，以及为揭示组织的遮挡。允许遮挡不等于任意内容可以消失：列明遮挡对象、遮挡发生的动作阶段、期间仍须可读的内容，以及恢复可见的条件。若遮挡覆盖关键接触，回传 M3／M4／M5.4／M9 协调。[C03][C05；D]

遮挡期间的摄影机连续运动不能直接变成传送；运镜阶段中使用 `SHOT` 字样也不自动授权剪辑。真实镜头边界按 M9 的声明解释。遮挡后的身份、持物和运动方向按 M8 的持续范围检查。[C03；D]

## 多主体与画面关系

稳定主体 ID 用于追踪角色；画面左右属于当前观察关系。机位跨侧、主体交叉或队形变化可以改变槽位，不允许因此交换身份。逐一说明本镜头需要辨认的角色、关键部位和相互关系，不设置人数上限，也不强制主角永远位于相同画面槽位。[C04]

近中远层次与清晰范围需联合 M5.3 核对。要求多人可读时，不能仅因主角清晰便报告完成；反之，任务允许次要角色模糊时，也不自动将全部人同等清晰作为硬约束。[C04；D]

## 检查范围与返回

文字审计检查：观看目标有无遗漏、构图描述是否自洽、是否能指出关键可见条件及其依赖。合同脚本只检查当前实现的字段、引用与规则，既不渲染视锥，也不检测真实画面像素。

视场、尺度、距离或动作范围缺失时，返回对应 `unknown` 与理由；不得用“没有发现错误”推导精确可见性通过。后续有媒体时，交 M12 绑定真实片段、时间窗口和计划版本进行观察。[D]
