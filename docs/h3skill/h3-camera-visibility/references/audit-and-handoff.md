# M5 局部审计、修复与下游交接

## 1. 明确本次检查范围

先记录工作 ID、实际原请求、所用计划与来源版本、目标 M5.x、镜头／事件范围，以及本次是否仅检查文字。将执行状态与审计状态分开：命令已执行可以是 `completed`，专业结果仍可能为 `unverified`。

| 层次 | 可以判断 | 不由此证明 |
| --- | --- | --- |
| 结构检查 | 必需字段、类型、额外属性、ID 和版本 | 摄影表达符合创作目的 |
| 确定性关系 | 当前脚本实现的所有权、引用、固定观察与请求保真等条件 | 光学、空间碰撞、真实画面可见性 |
| Agent 文字审阅 | 观看任务覆盖、几何用语、路径因果、焦点与取景冲突、参考范围 | H3 已经按要求生成 |
| 真实媒体观察 | 有媒体与方法时检查明确片段中的结果 | 未观察镜头或其他模型也同样成功 |

本包前三类的范围分别记录。没有实际视频时不能报告 G3／G4 通过；本地合同通过也不等于完整 G0／G1／G2 已完成。

## 2. 四个子模块的语义检查

| 子模块 | 必查 | 失败或未知时返回 |
| --- | --- | --- |
| M5.1 观察机位 | 坐标含义、高度与俯仰分离、距离对象、光轴、姿态、特殊视角的空间条件 | 不明参照、矛盾机位、缺少必要尺度；需要改主体空间则转 M3 |
| M5.2 构图可见 | 景别／画面边界、关键动作阶段、主体与接触关系、遮挡许可和重获可见条件 | 必保信息出画、遮挡冲突、视场不足以判断；不自动删动作 |
| M5.3 焦点景深 | 本阶段清晰对象、层次、保持／变化原因、光学依据与缺口 | 清晰目标冲突、精确景深证据缺失；不虚构镜头参数 |
| M5.4 运动触发 | 起终机位、主路径、光轴、转换理由、独立相机事件 ID、响应策略与稳定条件 | 路径断裂、事件引用矛盾、固定观察与位姿改变冲突；排时转 M7 |

具体领域规则及来源见各专业文档与 [案例证据](case-evidence.md)。脚本不分析自然语言含义，审阅者不得只依据退出码省略语义检查。

## 3. 组合审计

1. 对照原请求逐条检查观看任务；确认修订没有删掉用户指定动作、关键接触、人物关系或参考权限。
2. 将机位、画面边界、焦点和运动放在同一镜头／阶段核对。进入下一阶段的起始观察条件应能由上一阶段或已声明编辑关系解释。
3. 检查同时提出的要求是否相容：低位与俯仰、贴近与全身取景、多个景层同时可读与选择性模糊、固定观察与移动端点。
4. 判断输入是用户明确要求、实际观察、来源文本还是本次设计；不能用案例作者的效果报告替代目标片段证据。
5. 检查 H3 模式、字段与 Label 使用范围。M5 只交接摄影语义；最终编号、媒体排序、协议和参数由 M11 核对。
6. 按原请求、来源、只读上下文与基版本完成父接受。需要修改专业结果时退回相应子模块，不在聚合阶段改写。

视场／尺度缺失与明确矛盾不同。前者限制通过范围，后者必须阻断其影响范围；均不得以 `not_applicable` 掩盖。

## 4. 责任回传表

| 问题 | 责任位置 | 本模块提交什么 |
| --- | --- | --- |
| 观看目的或必保事件不明确 | M1 | 具体镜头／事件、缺口与候选理解 |
| 身份图被误当首帧或摄影参考权限冲突 | M2 | 资产、属性、作用范围和冲突 |
| 主体／相机空间关系或遮挡冲突 | M3 与 M5 对应子模块 | 当前版本、冲突位置、必要可见条件、调整候选 |
| 动作缺少可被拍摄的过程或接触阶段 | M4 | 需要可读的阶段与缺失关系 |
| 位姿、取景、焦点或路径需要改变 | M5.1／M5.2／M5.3／M5.4 | 对象 ID、基版本、期望变化、理由与影响 |
| 声音动机／视听关注关系 | M6 | 需要声音专业判断的事件；不改台词或声源 |
| 提前、同相、滞后或固定覆盖的排时 | M7 | 相机与人物独立事件 ID、相位、相对关系；精确时间待 M7 |
| 跨镜方向、观察关系或连续状态冲突 | M8 | 出入观察条件与已声明编辑关系 |
| 需要补镜、分镜、切点或生成分段 | M9 | 不可遗漏的信息、覆盖候选及对应事件 |
| 光线／材质令关键内容难辨 | M10 | 受影响对象与可读性要求 |
| 协议字段、Label 或后端能力冲突 | M11 | 原语义、输入版本、模式与具体冲突 |
| 需要真实可见性、清晰度或运镜结果证据 | M12 | 计划版本、镜头／事件、待观察范围与方法要求 |

这些是公开交接职责，不表示其他模块已实现或已被调用。1.0.0 的结构化合同能表达的范围以 [合同指南](contract-guide.md) 为准；表中其余内容可作为独立审计／交接文字，不向未声明 JSON 字段塞入载荷。

## 5. 变更与复验

保留先前记录，按真实消费者引用标记失效。机位改变通常影响画面关系、焦点条件、运动端点与下游编译；仅改变无关展示文字，不自动让全片失效。`impact` 只能处理已登记读取路径；未登记的语义依赖由审阅者补查。

每轮修订明确责任方、新基版本、修改范围、依赖、退出条件与下一检查入口。同一输入的技术重试与改变专业结果的创作修订分开；不能原样多跑几次把未验证改成通过。

## 6. 交付三类内容

- **制作记录：** 当前本域提案或 CameraPlan、来源、必要未知与责任回传。
- **编译交接：** 对目标模式提供最终摄影语义、关键可见条件与引用权限；M11 将其写入正确 H3 字段。
- **审计记录：** 本次检查范围、实际执行、明确问题、已修复项和未验证内容。

交付给模型的正文使用完整事件描述；不要夹入 HC／LC／MD／RT 条款、合同 JSON、内部审计过程或案例研究说明。
