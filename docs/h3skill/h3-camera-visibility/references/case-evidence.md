## C02：运镜纪律与响应策略

精确路径：`case-studies/2026-10-camera-movement-discipline-library/README.md`、同目录 `prompt.md`。

|---|---|---|
| README 16–24；prompt 151–157 | 先建立观察关系，动作产生空间或层次理由，再运动并重新稳定 | 将一次镜头的主路径与次级调整分开；不是规定所有作品只有一种运镜 |
| prompt 8–19 | 九人一镜案例包含释放时移动、关键动作前到位、踢腿落地后接近、队形扩展提前拉开等 | 分别选择提前、事后响应或动作阶段策略；其中秒数、低机位和镜头停留限制均属该任务 |
| prompt 88–125 | “微醺摄影机”先观察、滞后、过冲、修正、重获目标；主体动作仍稳定可读 | 只在选择该表达意图时用滞后和小幅过冲，不扩展为所有手持镜头的默认状态 |
| prompt 159–167；README 75 | 同步策略要求启动、峰值、收束对应同一动作区间 | 仅在用户选择 1:1 响应时约束相位；不能覆盖提前、固定、释放后响应与滞后策略 |
| prompt 174–186 | 推近、退远、侧跟、经过、绕侧、升降、遮挡与揭示、快速转向、短退、停稳分别给出物理含义 | 选择有观看任务的动作；指明方向、目标和终态，不能将词表堆叠当作路径 |
| prompt 191–201 | 动作需说明方向、幅度、触发和结束；无运镜也可明确写零运动 | 固定观察是一种有效策略；摄影机固定不禁止主体和环境变化 |

这里存在需要选择的策略差异：prompt 11–12 的释放时启动／提前到位，与 159–167 的同起同收不是同一时间关系。先确定本镜头响应方式，再交由 M7 处理实际时刻和偏移（D）。不能把所有来源条款同时变成全局硬约束。

prompt 79–86 的 E7 又允许特定变焦冲击等视觉设计，因此这套案例集合并不支持“所有任务一律禁止数字变换”。普通视角可简写、特殊透视才补足物理条件的适用区别，见 prompt 50–62。

## C03：组合路径与可达条件

精确路径：`case-studies/2026-10-advanced-camera-combinations/README.md`、同目录 `prompt.md`。

README 13–14、prompt 324 将组合组织为起始位置、物理路径、主体触发、终止位置、最终构图。prompt 44–294 是十组实例。其 4:3、单人、10–12.5 秒、上半身优先、1–2 步等是 prompt 5、18–23 的局部约束。

| 来源行段 | 文本依据（F） | 审核要求 |
|---|---|---|
| prompt 44–66 | 从前方后退、侧移、经过右肩，再从动作范围外回到前侧 | 保留侧别、光轴目标、经过关系及终态；每阶段起点衔接前阶段终点 |
| prompt 70–89 | 先侧向跟随，再超过主体、转向前方并后退 | “跟随”“超过”“转向”分别表达，核对主体仍在运动时的相对位置 |
| prompt 93–112 | 真正接近后停止前进，沿肩侧空间移动，再停稳 | 推近不自动等于变焦；侧路不能穿过身体 |
| prompt 116–140、144–163、218–241 | 下降读取脚步、脚步结束后升回上身；低起点随动作上升；贴地滑行转连续升高 | 将观察信息和高度变化绑定，不把脚部镜头无限延长，也不把升高缩成原位仰拍 |
| prompt 167–189 | 手臂／衣袖遮挡期间摄影机仍向前并侧移，揭示新位置时主体动作持续 | 遮挡不提供传送许可；若确有剪辑，应由 M9 声明边界（D） |
| prompt 270–294 | 小幅前进、关键动作、响应、重新稳定形成有次序的过程 | 局部动作时间交给 M7；不得把时间数字推广到其他组合 |

**原文歧义必须保留。** prompt 193 的组合七标题写 FRONT FOLLOW，196 的实际起点却是 behind。按具体几何字段审查，并报告标题与正文冲突，不能默默把二者视作一致。该组合 200–214 的停下、人物穿过、摄影机原地转向、重新从后方跟随，需要核对人物方向和空间关系。组合九 245–266 尤其 260 的 opposite side 揭示没有完全解释绕行路径；缺少空间条件时应记录待明确的连接段，不能凭遮挡补造位移。

安全可达检查需要 M3 的场景、边界和障碍，及 M4 的主体运动范围（D）。文本足以提出“从哪一侧通过、是否穿过身体、终点如何到达”等待检条件，不能证明真实设备路径、碰撞距离或生成画面已安全可达（U）。

该文明确是 NO DEGREE VERSION（prompt 1、10–23、298–324）。这是几何叙述策略，不是 H3 禁止角度数字的官方规则；C01、C06 本身包含角度数字。

## C05：固定机位与接触可读

精确路径：`case-studies/2026-10-leg-lift-contact-cut-stocking-six-look/README.md`、同目录 `prompt.md`。

README 23–40 将流程规定为接触触发切换、落地保持、新造型稳定可见、再次抬腿，并区分支撑腿与活动腿。prompt 620–638 明确采用与参考一致的锁定摄影机，头到脚完整入画，双脚和石面清楚可见，接触瞬间可读，支撑腿与活动腿可辨。

这支持 M5.2 将“接触点和支撑关系在关键阶段可见”作为该镜头检查项，及 M5.4 使用固定观察策略。它不要求所有接触场景都采用同一景别或固定机位。固定相机也不冻结人物的抬腿、落脚或服装变化。prompt 600–618 提供触地后保持的可见状态，650–659 提供接触、声音与切换关联；具体事件时间和剪辑执行归 M7／M9，M5 不重写其事实（D）。

该案例不能直接证明完整景深策略。把接触点与面部列为竞争的清晰目标并提出覆盖方案，是任务驱动的设计推论（D），不是本案例已经执行了焦点转换实验。

## C07：参考属性与摄影权限

精确路径：`case-studies/2026-10-identity-only-half-body-dance-six-segment/README.md`、同目录 `prompt.md`。

README 18–25 及 prompt 7–44 将脸部身份、身体外观、环境等授权属性，与姿态、头角、手位、朝向、构图和首帧姿态分开。README 23、prompt 65–84 将“半身肖像感”转换为摄影语言，允许摄影机提前、滞后或短暂固定，而不逐一追赶每个肢体。

M5 可以据此在 M2 权限内规划距离、画面范围和观看关系，不因为参考图清晰就默认复制其构图或焦点安排（D）。角色开始姿态和动作归 M4，场景属性归 M3；这些权限不能由“参考风格”一词整体继承（D）。原文手持、上半身、单人、111 BPM 与段落内短暂低机位都是本任务选择。

README 29–31 对效果原因的解释属于作者论述（A），不是本轮生成对比实验。案例历史提示词使用 Picture 标签表达身份来源；本模块只提取属性分权经验，当前官方身份参考 Label 仍按 [H3 映射](h3-label-mapping.md) 转换，不直接复制旧语法。

## 跨案例适用边界

| 问题 | 可复用原则 | 不可无条件继承 |
