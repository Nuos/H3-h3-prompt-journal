**版本：** v0.1.0；公开合同 `1.0.0`。

**日期：** 2026-11-05（America/Los_Angeles）。

**技能：** `h3-state-continuity`。

**读取基线：** `f1456793d21bfb411d36eea13cee2916c3bd20c5`，目录树 `9daf4d31efb79f3d23c8a4649905b2b0d00054bb`。

**开发依据：** `skillplan-v0.1.2-608813b`，冻结内容提交 `608813b6e51531ac47f860bc384a454a504fe9ff`。

## 核心摘要

本轮按冻结方案实现第八个核心模块 **M8 主体、道具、场景与跨镜状态连续性**，在已有 `docs/h3skill/` 中新增 `h3-state-continuity/`，并更新集合索引。模块维护连续性策略与计划状态，以具体边界为单位检查交接，向 H3 五种输入模式提供状态表达与审计交接。

M8 的核心是明确：哪些属性在什么范围持续，哪些变化已获许可，变化由什么动作或编辑决定解释，下一段可以依赖什么状态。M8.1／M8.2／M8.3 分别拥有策略、计划账本与只读交接检查职责；实际媒体观察继续归 M12。

领域方法来自用户指定的 `case-studies/` 文本，重点为十月案例。Anthropic 官方资料用于技能包装与创作标准，MiniMax 官方资料用于输入协议；工程合同、CLI、结构化示例及测试属于本轮设计。未执行 H3 推理、视频观察或成片验收，不把文本与合同核验解释为生成成功率。

## 关键结论

1. M8 与三个子模块均有明确输入、输出、来源、版本、职责、调用和返回路径；可直接使用兼容外部资料，不要求先完整运行前七个模块。
2. 同镜、连续接续、动作匹配、蒙太奇及换场／时间省略分别审计，合法变化与无解释的重置得到不同处理。
3. 道具外观与当前状态分开；重新加载同一参考图不自动授权重复拔刀、换手、物件增减或姿态复位。
4. 边界检查需要对照前镜正文末态、交接表、后镜正文初态，不能仅凭一张交接表认定镜头存在。
5. 计划状态与真实观察分别保存；新证据导致修订时建立新计划版本，保留旧计划和原失败记录。
6. 保护 339 个既有文件的精确字节，涵盖原案例文本、冻结计划与控制记录、标准快照及 M1—M7 运行包。

**关键词：** M8、ContinuityPolicy、StateLedger、道具状态、变化许可、跨镜交接、计划与观察、模块化、H3 Label。

## 2. 三个子模块与架构边界

| 节点 | 负责结果 | 最小专业输入 | 边界 |
| --- | --- | --- | --- |
| M8.1 连续性策略与变化许可 | ContinuityPolicy | 任务范围、实体／属性、权限、编辑边界与来源 | 不决定 M2 参考权限或 M9 编辑意图 |
| M8.2 计划状态与转换登记 | StateLedger | 策略、必要状态、事件／空间／声音／时间依据 | 不重新创作动作或维护另一份权威时间表 |
| M8.3 边界交接与接续检查 | 交接检查、接缝条件和修订请求 | 兼容策略／状态、边界、两侧文字或结构化声明、相关观察引用 | 只读计划；状态修订回 M8.2，观察归 M12 |
| 父 M8 | 组合后的连续性草稿 | 原请求、同一基版本的子提案、父状态 | 对照原输入唯一接受，不能静默改写子模块专业决定 |

独立调用依赖公开数据合同，不依赖某一上游执行器。已有用户计划、外部工具结果或其他实现可以满足输入，但来源类型、版本和未知项必须保留。合同版本相同也不意味着来源真实性已经认证。

四项强制架构原则落实如下：

| 原则 | 实现方式 | 实际验收关注点 |
| --- | --- | --- |
| 高内聚 | 策略、状态、边界分别有专业结果；编译、观察和调度不混入状态决定 | 子模块只处理自身职责，跨域问题回传责任方 |
| 低耦合 | 必要只读输入、明确来源与版本、兼容外部输入、包内资源 | 独立最小调用、来源替换、无隐含兄弟目录依赖 |
| 模块化 | 父子登记、公开合同、写入分区、版本拒绝和唯一接受 | 独立与组合调用，越权／竞争／过期提案不能提交 |
| 路由信息 | 目标、触发、字段投影、资源、返回、失败、修复、重试和依赖影响 | 定义与实际执行记录分开，未知不转成通过 |

## 3. 五模式、字段与 Label 映射

### 3.1 输入模式

| H3 模式 | 官方主正文 | M8 编排要求 | M8 审计要求 |
| --- | --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 文字建立初态、过程、终态与持续范围 | 属性变化有事件或编辑解释 |
| I2VA | 基础主正文＋首帧对齐指令 | 从实际首帧支持的状态发展 | 不用身份图的“忽略姿态”权限绕过真实首帧约束 |
| FL2VA | 基础主正文＋首尾帧对齐指令 | 连接两端可支持的身份、道具和空间状态 | 两端不相容时明确冲突，中间变化不能省略成任意跳变 |
| L2VA | 基础主正文＋尾帧对齐指令 | 以尾态为目标建立前序状态及到达过程 | 尾图不自动证明前半段已经发生某个事件 |
| Ref2VA | `detailed_description`，配套定义／摘要／保留分析 | 区分身份外观、参考权限和本段状态，逐镜描述实际变化 | 同标签语义稳定；每个独立任务带必要状态；不混用基础模式字段 |

基础模式的完整字段为 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。Ref2VA 的完整字段为 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。

`ContinuityPolicy`、`StateLedger` 和边界结果属于内部制作合同，未被定义为 H3 新字段。动作／状态正文、声音持续和参考关系各归正确字段，最终编号与序列化交 M11。

### 3.2 四类参考 Label

四类参考 Label 属于 Ref2VA。基础四模式使用各自的正文与首尾帧指令，不直接套用完整参考标签体系。

| Label | 与 M8 的关系 | 关键检查 |
| --- | --- | --- |
| `<Subject N>` | 需要独立追踪的可见人物、物件、场景或动作等 | 标签含义跨字段保持，稳定身份与时变状态分开 |
| `<Picture N>` | 具体首帧／关键帧／尾帧或镜头规划锚点 | 仅用于身份／服装的图片在 Subject 定义内引用，不滥用独立 Picture 条目 |
| `<Video N>` | 编辑来源、续接起点或全片时间结构 | 可见动作或对象的复用仍归 Subject，源状态不自动成为新目标状态 |
| `<Audio N>` | 复制或参考的音频信号与持续关系 | 视觉／音频编号独立，声音来源、复制策略和跨切语义保持 |

官方语言、关系标记、首尾帧指令和逐字段审计详见运行包内映射及原文。案例里的历史写法只作为领域方法证据，不能覆盖当前固定的官方协议。

## 4. 案例方法与适用范围

| 案例依据 | 提炼的方法 | 保留的适用边界 |
| --- | --- | --- |
| 十八段海滩剑舞 README 选段 | 外观与状态分开；拔刀、持剑、剑鞘与后继状态按版本登记 | 组间可通过后期视觉桥梁相连，不强制逐帧匹配；具体持剑手和场景属于本案 |
| 白凤六段 README／提示词 | 支撑、方向、相位和音轨关系参与交接；三方核对正文与表格 | 交接表是待核对的设计声明，不证明对应特写存在或视频实现 |
| 身份专用半身舞 | 图片特征权限与起始动作分别确定，未完成运动可跨切接续 | 不把“身份图不继承姿态”推广为可以无视 I2VA 实际首帧 |
| 触地切换与造型展示 | 初态、转换边界和后续状态区间分别登记，事件顺序明确 | 原案六次转换形成七个状态区间；允许返回先前值而保留区间是冻结路线图规定的合同规则，非本案出现袜饰回返 |

一个实际文本缺口是白凤 SEG03→SEG04：SEG03 的 Shot 5 末尾将镜头从支撑手抬向眼睛，Shot 6 保持当前低位及静止机位；SEG04 开场和交接表却要求接续同一手掌特写。因此，本轮规则要求回查正文是否明确安排了所需末镜，不能仅凭交接表确认特写存在。这里识别的是计划文字缺口，不是对未观看视频的效果判定。

逐项来源、精确读取范围与短摘录记录在 `case-evidence.md` 和 `case-index.json`。本轮清点 29 个案例目录中的 98 份文本，语义阅读覆盖 4 个案例的 6 份文件，其中 3 份全文、3 份选段；其余 92 份只有关键词和哈希索引。全文文件数不等于整案全文已读。本表概括规则范围，不表示重新观看了案例图片、视频或音频。

## 6. 运行合同与验证方式

运行依赖为 Python 3.10+ 标准库。官方格式检查单独使用仓库既有的 Anthropic 校验器及其 PyYAML 依赖，不能将开发验证依赖误报为 M8 运行依赖。

```bash
cd docs/h3skill/h3-state-continuity
python scripts/m8_contract.py route assets/request-standalone-m8-3.json
python scripts/m8_contract.py check assets/proposal-standalone-m8-3.json --request assets/request-standalone-m8-3.json
python scripts/m8_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

`route` 返回调用合同和资源；`check` 只执行已实现判据；`accept` 返回新的父级草稿而不覆写输入；`impact` 依据明确登记的读取依赖报告复验影响。自由文字语义、人物识别、身体物理、真实接缝、自动视觉跟踪及媒体真实性不是这些命令的自动判定能力。

所有结果区分执行状态、局部检查范围与整体未验证项。独立调用不等于无输入依赖；缺少当前职责必需证据时保留诊断。每个正式接受使用实际原请求、基版本与来源，不能只检查提案自行携带的上下文就宣布保真。
