# M12 持续审计、问题归因与反馈修复：开发与验收记录 v0.1.0

**核心摘要：** 按冻结方案实现第十二个核心技能 `h3-audit-repair`，包括 M12.1 范围与检查计划、M12.2 检查结果与证据汇总、M12.3 独立媒体观察、M12.4 问题归因与变更复验。交付可独立复制的技能包、四路公共合同、确定性记录工具、H3 五模式／逐 Label 映射、案例证据、行为测试及发布核验记录。

**关键结论：** 本模块保留原要求和失败历史，区分历史结果与当前有效性，按实际依赖计算影响。文档、计划、实际执行和媒体观察分别提供证据；合同通过不认证媒体效果。专业字段修订交给原责任方，M12 不自动运行上游模块或 H3。

**关键词：** M12、G0—G4、AuditPlan、AuditLedger、MediaObservationLedger、ChangeSet、原子接受、版本、失效、复验。

**目录导航：** 1. 范围与基线；2. 模块和合同；3. H3 映射；4. 案例依据；5. 技能目录；6. 关键行为；7. 验证；8. 使用；9. 完成边界；10. 发布与保护。

### 3.2 Label 与相关标记

| Label／标记 | 必须分清的作用 | M12 的具体要求 |
| --- | --- | --- |
| `<Subject N>` | 可复用主体，与素材下标不是同一命名空间 | 主体定义、外观／身份、角色和正文绑定有来源；不靠同号推定对应 |
| `<Picture N>` | 图像参考、帧／分镜锚点或主体来源 | 记录图像角色、实际编号和首尾对齐；不能把网格格数当镜头数 |
| `<Video N>` | 视频编辑／续写／时空结构来源或主体提取来源 | 指明使用范围、保留／变化权限、源窗口及目标对象 |
| `<Audio N>` | 独立获准使用的音频信号来源 | 不能由视频同号自动推断；复制策略、可用窗口和实际音轨分别核对 |
| `[Shot N]` | 真实镜头边界 | 不以动作阶段、服装状态或生成段数量冒充 Shot；局部时间戳按官方格式递增 |
| `(Sx)`、`<d>` 及跨镜／截断标记 | 声源编号、原词对白及发声跨边界关系 | 声源按首次实际发声次序编号；正文保留原词与语言，不把背景音乐自动当新说话人 |

`fully_copy` 需要完整原始信号构成整条最终音轨；新增对白／音效层、局部复用或删改声音时，必须重新核对 `partially_copy` 等适用策略。M12 比较源权限、声音计划、正文与实际音轨；缺听音证据不能宣称声音验收通过。

四个子模块对这些字段的分工是：M12.1 建立检查义务；M12.2 比较文字与证据；M12.3 检查实际媒体中相应表现；M12.4 将偏差路由给对应责任方并安排复验。正文修订由专业模块形成新版本，再由 M11 编译。

## 6. 已实现的关键约束

### 6.1 范围与证据

每项检查绑定原要求、计划、对象版本、方法、证据和覆盖。所有登记要求与 Gate 均需有检查；缺结果或支持证据保留 `unverified`。`not_applicable` 必须有明确规则和适用性证据，不能用“没有提供媒体”替代不适用理由。

四种历史结果是 `pass / fail / unverified / not_applicable`；`stale` 表示当前版本下的有效性，不成为第五种历史结果。具有有效违例证据的失败不会因附加一条无关证据而消失，额外缺口仍保留。Gate 仅汇总当前范围，局部 G2 通过不认证整项任务。

### 6.2 媒体与时间

G3 绑定 `generated_media`，G4 绑定 `assembled_media`，同时核对媒体和计划版本、观察方法、通道、窗口以及每条事实的窗口。抽样或缺少所需音频不能证明完整范围通过；范围外的违例不能用于判定范围内失败。

程序支持 `media_ms` 局部毫秒时间域；源片、作品和剪辑时间需要先通过 M7 或外部有效映射转换并保留来源。本版 G3／G4 的正式通过采用 `full_window`，采样仍可登记事实。`declared_actual` 仅是提供方声称实际观察的标记，程序不能认证其真实性。

### 6.3 问题、影响与复验

问题保留具体对象、位置、期望、实际和证据；因果分析证据独立于症状。原因未确认时保持 `unresolved`，不按模块序号或直觉指定责任。唯一字段责任可为 M1—M12 或显式 `external` 提供方；外部媒体变化仍保留原 owner，不伪造模块拥有权。

影响沿显式有向依赖计算传递闭包，无关对象不强制失效；依赖不全时标记 `partial`。`proposed` 仅提出影响，`reported_applied` 才登记提供方报告的变化和相应失效；程序均不执行修复。

复验保留原检查含义、方法、时间窗、通道与覆盖，要求当前版本及新证据。直接修改对象与受影响的普通派生文档须推进版本；上游计划变化后，可以用新的合格观察复核同一份下游媒体，旧观察仍保留为历史。不能仅把旧证据改名，或修改期望来关闭失败。

同一 scope 允许增加要求和推进引用版本，不允许删减／弱化原检查。范围扩大后，新审计不能回退旧 scope；历史原审计仍可作为修复来源。方法等语义改变需要明确新范围，保留原范围和未解决问题，不自动把新范围结论当作旧任务完成。

### 6.4 状态接受

提案必须等于根据原请求重新计算的结果。父接受校验工作 ID、当前基版本、每个子模块独占记录、同版本摘要、不可变证据／观察、范围历史与当前版本声明。批次任一项失败不产生部分更新；完整重试幂等，历史状态必须能够从 receipts 原样重放。
