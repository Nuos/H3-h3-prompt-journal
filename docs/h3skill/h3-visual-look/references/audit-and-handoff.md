# M10 审计、失败回传与 H3 交接

## 核心摘要

审计 M10 的对象是当前版本的视觉方案及其明确引用。分别记录结构化合同检查、Agent 文字审阅和真实媒体观察；前两者不替代生成片段与成片验收。

本文的检查及路由为 D 类实现设计。判断依据来自冻结职责、案例证据及本包固定 H3 协议；参考权限、身份、空间、动作、时间、连续性和剪辑仍由原模块维护。

**关键词：** LookPlan、局部审计、版本、引用、可见性、修复路由、G0—G4。

## 1. 检查对象与结论层次

| 层次 | 检查什么 | 可以声称什么 | 不能据此声称什么 |
| --- | --- | --- | --- |
| 确定性合同 | 类型、非空字段、来源、引用、版本、权限声明、已实现关系 | 这些结构化检查已执行及其结果 | 已理解所有自然语言；已经打光、调色或识别像素 |
| Agent 文字审阅 | 风格继承、范围、冷暖分工、材质身份边界、动作可读性及协议交接语义 | 具体文本和作用域的已审阅结论与问题 | H3 已生成稳定画面；无闪烁、无偏色 |
| 媒体观察 | 实际图片／片段／成片的对象、时段、边界与对照 | 实际观察到的范围及证据 | 未查看范围、其他种子或其他模型版本也必然通过 |

对所有适用检查保留对象 ID、输入版本、证据、问题、责任方及重检范围。缺证据使用 `unverified`；明确不适用才使用 `not_applicable` 并附理由。旧通过所依赖的输入改变时标 `stale`，不能原样沿用。

## 2. 四子模块审计表

| 对象 | 关键问题 | 脚本与 Agent 的分工 |
| --- | --- | --- |
| M10.1 StyleHierarchy | 父子作用域和继承是否可解析？是否存在循环或竞争值？例外改变什么？独立任务的有效风格是否自足？ | 脚本核对声明关系；Agent 判断例外及当前有效语义是否符合任务 |
| M10.2 LightingPlan | 光源、方向、性质、对象是否明确？坐标依据是否充分？反打下屏幕变化是否被误判？照明是否遮蔽关键动作？ | 脚本核对 ID／上下文；物理与可见性判断需 Agent 及实际证据 |
| M10.3 ColorPlan | 固有颜色、局部光色和整体调色是否分开？是否借调色修改身份？局部差异与全片意图是否相容？ | 脚本核对权限和类型；自然语言冷暖关系及审美判断由 Agent 完成 |
| M10.4 MaterialEffectPlan | 对象／部位是否唯一？状态变化是否有来源？湿润与身份是否混用？效果是否妨碍观看或跨镜持续？ | 脚本核对声明的对象与引用；因果、材质语义及实际效果另行审阅 |
| 父 M10 | 提案是否来自原请求、有效基版本和正确子模块？是否越权？四分区组合是否存在未解决问题？ | 不改写子模块专业决定；返回具体冲突或形成新版本草稿 |

不能把“缺图”“缺光向”“未取得真实片段”都压缩为一个总分。分别说明缺少什么、影响哪个结论、已有部分还能交付什么。

## 3. 冲突的责任回传

| 问题类型 | 应回传的公开责任 | 最小回传信息 | 本轮退出条件 |
| --- | --- | --- | --- |
| 未授权的风格引用、身份／衣物变化 | M2.2／M2.3 | 对象、来源、属性、范围、目标变化与现有权限 | 获得明确许可或修订本候选 |
| 视觉目的或场景例外与必保叙事冲突 | M1；相关 M10 子模块 | 必保事项、冲突表现及候选 | 由作品责任方接受视觉取舍 |
| 光源／效果位置与既定空间矛盾 | M3；M10.2／M10.4 | 场景及对象、坐标依据、矛盾关系 | 返回相容空间依据或修订视觉设计 |
| 效果缺少动作原因 | M4；M10.4 | 效果对象、预期结果、缺失前提 | 取得动作原因或移除未经授权的事件假设 |
| 反光、雾气、暗部遮蔽必保信息 | M5.2；必要时 M5.3 | 镜头、事件／区域、观看要求、视觉候选 | 取得可读性方案；实际可见性仍待媒体核验 |
| 效果时间或变化节奏不明 | M7 | 稳定事件／条件、来源、作用域 | 得到相容排时或继续标时间未验证 |
| 跨镜表面状态／色彩持续冲突 | M8.1—M8.3 | 出入镜、属性、当前／目标状态及许可来源 | 明确持续、变化或合法省略关系 |
| 生成段缺公共风格、镜头归属不明 | M9.1／M9.3；M11 | 任务及镜头、需带入的有效风格版本 | 当前请求具备自足上下文 |
| 模式、Label 或实际后端能力冲突 | M11；涉及权限时 M2 | 模式、字段、素材角色、官方依据和能力缺口 | 模式／序列化相容或保持阻塞 |
| 实际画面漂移、闪烁、遮挡 | M12 登记观察后回相应 M10 子模块 | 媒体及版本、时间范围、对照计划、证据 | 修订形成新版本并重检受影响范围 |

这张表是责任映射，不表示 M11／M12 或全部跨模块自动调度已经实现。`route` 只产生可追溯的路由信息，Agent 或宿主决定是否执行实际交接。

## 4. H3 模式与 Label 审计

逐项核对当前采用的模式和参考角色；只有当前实际存在的输入才能被引用。完整官方行号与编排矩阵见 `h3-label-mapping.md`。

1. 基础四模式使用 `integrated_multimodal_description`；Ref2VA 使用 `detailed_description`，不得混写顶层主字段。
2. T2VA 的整体风格进入第一镜；Ref2VA 在第一镜前建立整体风格，镜内再描述具体光线、材质和变化。
3. I2VA／FL2VA／L2VA 保留真实首／尾帧约束。参考角色声明不能撤销模式输入实际带来的可见约束。
4. Subject 表示可重用可见内容；Picture 表示具体帧或规划锚点；Video 表示编辑、续接或整体时间结构；Audio 表示实际音频信号。不能创造 Style／Lighting／Material 类型。
5. 先固定角色和权限，再判断该角色内的保留关系。“只参考色彩”说明属性范围，不自动说明参考强弱。
6. 旧案例中的自定义风格字段、摘要格式、提示词标题可以作为领域证据，不能覆盖固定官方协议。
7. M10 不为“静谧”“激烈”“唯美”等视觉词自行写声音轨。两类声音字段沿用 M6；风格变化也不自动新增切镜或动作。
8. 最终模型正文只包含需要生成的描述和协议要求；内部合同、规则编号、证据、诊断、修订记录和开发说明留在制作记录。

## 5. 变更、失败与重试

父接受时以实际请求作为授权依据，核对提案内来源快照、范围、子模块身份、基版本与候选数据。不能让提案自行声明一套更宽权限后接受自己；不能把过期版本直接写入当前状态。只读投影继续校验所用参考的属性、对象和作用域；空对象列表只表示作用域使用，不绕过对象限定。依赖的兄弟分区已为 `stale` 时，必须先重验或同批重验，不能仅复制当前内容便把新结果恢复为 `current`。

复验范围根据实际引用确定。例如只改一镜局部照明，至少核对该镜可见性及真正引用该决定的色彩／效果；没有引用的另一场景不自动失效。风格源、参考权限或状态持续关系变化时，沿依赖回查相关分区和消费者。`impact` 的输出是待检查范围，不是已经完成的复验。

技术失败与语义冲突分开：只读校验可以按调用规则安全重复；同一冲突不能靠原样重试变成通过。需要媒体生成或外部写入时，由相应执行方核对请求身份及已有结果，本包不代执行。

保留旧请求、提案和失败诊断。修订另形成新版本；不能删掉反例或重算旧证据来制造一直通过的历史。

## 6. 交付与完成边界

交付当前分区或组合 LookPlan、作用域和明确例外、来源与参考权限、具体 H3 语义交接、未决项、责任回传和版本。独立子模块调用不要求其他分区已经存在，也不将它们标为通过。

局部合同检查可为 G0—G2 的相应文字检查提供证据，但不单独宣称完整 Gate 通过。G3 需要真实生成片段，G4 需要真实成片及装配范围；未执行时写 `not_run`／未验证。没有 H3 推理记录，就不报告生成稳定率、无风格漂移或视觉质量提升比例。
