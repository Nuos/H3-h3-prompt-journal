# M10 与 H3 五种输入模式、字段及 Label 的对应

## 核心摘要

M10 交付视觉语义：风格继承、照明、调色、材质与效果。`LookPlan` 和它的四个分区都是内部制作合同，不是 H3 顶层字段。M2 确定素材角色与属性权限，M5 负责观看条件，M8 负责持续状态，M11 负责最终字段、Label 编号与协议序列化，M12 负责实际媒体观察。

本表固定于 `MiniMax-AI/MiniMax-H3@199b7d0e1fd95e7b3eafa8c15eca692534142427`。**B** 为 [h3-base-official.txt](h3-base-official.txt)，222 行；**R** 为 [h3-ref-official.txt](h3-ref-official.txt)，341 行。行号从原文第 1 行起算，离线快照未加页眉。**P** 表示官方协议事实，**D** 表示本模块的编排／审计设计。

关键词：T2VA、I2VA、FL2VA、L2VA、Ref2VA；Subject、Picture、Video、Audio；风格开场；参考权限；首尾帧；照明与调色。

目录：1. 五模式；2. 四子模块；3. 逐字段交接；4. 参考 Label；5. 编排／审计流程；6. 来源。

## 1. 五种模式（P）及 M10 的工作（D）

| 模式与原文 | 官方结构 | M10 编排要求 | M10 审计问题 |
| --- | --- | --- | --- |
| T2VA；B L5、14、36–48、76–82 | 无图片对齐首行；基础三字段 | 从用户文本建立风格，在 `[Shot 1]` 内开场；逐镜给出可观察的光色、材质、效果与变化 | 是否把空泛风格词当完整事件？是否凭空引用未提供的素材？ |
| I2VA；B L6、16–20、52–56 | 首帧对齐指令＋基础三字段 | 实际图是 0.00 秒的第一帧；从其风格、主体、构图、色彩和空间发展 | 目标基调与实际首帧是否相容？有没有用“仅参考身份”否认真正首帧的可见约束？ |
| FL2VA；B L7、22–26、58–64 | 首尾帧对齐指令＋基础三字段 | 描述两端之间的光照、场景或表面变化过程；通常单镜，多镜须明确指定 | 是否无过程地跳变光色？终态是否确实落在有效时长末端和实际末镜？ |
| L2VA；B L8、28–34、66–70 | 尾帧对齐指令＋基础三字段 | 尾图属于最后一镜；为前序提出可到达尾图视觉状态的路径 | 是否把尾图当开场？是否凭尾图断言此前已发生某种打光或材质事件？ |
| Ref2VA；R L13–37、211–242 | 六字段；主正文为 `detailed_description` | 第一镜前用一两句建立整体风格；参考在对应对象、镜头和视觉阶段生效 | 定义、摘要、保留分析和正文的角色、权限及范围是否一致？是否误用基础正文名？ |

以上五种模式均可消费四个子模块的专业结果，但不是要求每次调用必须生成完整四分区。图片未提供或未查看时，首尾状态、原图光色和身份属性保持未确认；不能凭案例文字编造像素观察。

I2VA／FL2VA／L2VA 的固定首行见 B L16–34，交 M11 原样序列化。FL2VA 原模板中 Picture／Shot 的括号形式与另两者不同，不能为统一格式自行改写。模式选择和真实输入绑定优先于自然语言中的“参考”措辞。

## 2. 四子模块分别对应哪里

| 子模块与内部结果 | 基础四模式的落点 | Ref2VA 字段与 Label | 对应编排／审计要求（D） |
| --- | --- | --- | --- |
| M10.1 `StyleHierarchy` | 第一镜内的整体风格及后续镜头有效例外 | `subject_definitions` 中合法的风格／场景 `<Subject N>`；`summary`、`retention_analysis`；首镜前风格句和逐镜正文 | 区分全片、场景、镜头范围；展开当前独立任务继承值；参考提供的风格与用户设计的风格分别标来源 |
| M10.2 `LightingPlan` | 主正文内实际光源、光向、对象与变化 | 主体／场景定义、必要保留分析及 `detailed_description`；真实帧锚点可用 `<Picture N>` | 具体光源与整体调色分开；首尾帧光态相容；参考照明有授权；强光／逆光与 M5 观看条件协调 |
| M10.3 `ColorPlan` | 主正文的基调、对比、曝光倾向及局部保护 | 风格／主体的授权属性、保留关系和逐镜色彩；不是新 `<Color N>` | 保护身份与服装色彩；局部暖光不必抹除；同范围的调色要求不竞争；不把少量属性借用误认成弱参考 |
| M10.4 `MaterialEffectPlan` | 对象表面表现、效果条件、可见变化及终态 | 可见衣物、道具、材质承载对象或效果可定义为 `<Subject N>`；帧／源视频只按实际角色使用 | 湿润不等于换发色或换装；效果需绑定对象和原因；持续交 M8，可见性交 M5；不新增 Material／Effect 类型 |

四个内部分区均不能作为额外 H3 顶层字段提交。风格来自视频中的可复用内容时仍可作为 `<Subject N>` 的授权内容定义；只有真实存在整体编辑、续接或时间结构关系时才设独立 `<Video N>`。

## 3. 逐字段交接

| 官方字段及依据（P） | M10 提供（D） | 需要检查（D） |
| --- | --- | --- |
| 基础 `integrated_multimodal_description`；B L46、76–82 | 初始风格、光色与具体表面，以及镜内视觉变化；在事件和空间中呈现 | 不写成只有标签的美术清单；不替换角色动作、构图或时间决定 |
| Ref2VA `subject_definitions`；R L25–73 | 获准继承的风格、主体、场景、衣物或效果来源；说明每份素材提供什么 | 只借身份的图片不能扩成环境／调色来源；源图与可重用内容的 Label 不混淆 |
| Ref2VA `summary`；R L121–153 | 当前目标的整体视觉意图、保留／修改范围与真实任务关系 | 风格迁移不自动等于视频编辑或续接；不要虚构已提供的图片视频 |
| Ref2VA `retention_analysis`；R L157–207 | 当前已定义角色内的保留、修改、属性迁移或宽泛借鉴 | 对象、作用域、属性和出现镜头是否吻合；关系强度不能扩大权限 |
| Ref2VA `detailed_description`；R L211–242 | 首镜前整体风格，逐镜环境光线、对象外观、质感、效果及变化 | 参考落点明确；与摘要／保留分析一致；风格只作约束，不能替代完整过程 |
| `overall_soundscape`；B L47、152–158、R L21 | 仅交接视觉事件与已有声音方案的关联需求，由 M6 决定声音 | 雨、水花或视觉静谧不能自动授权添声音、删声音或全部静音 |
| `non_diegetic_music`；B L48、160–166、R L22 | 保持 M6 的配乐语义与 M7 的时序，不把美术情绪当音轨决定 | 色彩转冷不自动改音乐；镜内可听音乐与观众配乐不能混为一项 |

字段顺序保持固定：基础为 `integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`；Ref2VA 为 `subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → 两个声音字段。

Ref2VA 六部分使用英文，实际对白／歌词及画面文字保留原语言（R L5、217）。M10 的中文制作方案可独立保留；内部审计、来源账目和未决事项不直接塞进模型正文。R L242 的通常 350–500 英文词是有例外的写作建议，不是 M10 合同字段或硬性后端能力。

## 4. 四类官方参考 Label

| Label 与依据（P） | M10 中的合法角色（D） | 审计错误示例（D） |
| --- | --- | --- |
| `<Subject N>`；R L41–58 | 可复用的可见内容，包括人物、场景、衣物、道具、效果，以及风格、动作、表情、姿势；可以多个来源定义同一内容单元 | 把 Subject 误当源文件编号；为风格另造 `<Style N>`；仅凭一图给所有视觉属性授权 |
| `<Picture N>`；R L62–73 | 图本身作为具体首帧、关键帧、尾帧、修改后的关键帧、构图或分镜规划锚点 | 只提供身份／服装／风格来源的图，又建立一个没有独立用途的 Picture 定义；把分镜格都当实际尾帧 |
| `<Video N>`；R L78–88 | 原视频编辑、从结尾续接、整体摄影机／切镜／节奏／时间结构关系 | 只借视频里的场景风格却自动复制整条视频；把普通视觉引用误报成编辑或续接 |
| `<Audio N>`；R L92–118 | 实际复制或参考的独立声音资产，或明确启用的视频同步音轨 | 因视频文件有声音就自动启用；用视觉氛围推断声音角色；将 Audio 序号当 Subject 或 speaker 序号 |

如果图片只为角色、场景、服装或风格提供来源，按 R L68 在对应 `<Subject N>` 定义中引用该图，**不建立独立 Picture 定义**。同一图确实另有帧／构图任务时，再据该独立角色使用 Picture。视频中的可见风格、人物、动作或效果同样不能由 Video 标签替代 Subject 内容。

视觉保留关系固定为 `fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`（R L161–168）。先确定标签角色和允许属性，再选择该角色内的实际保留程度。“只用身份”不自动是弱参考；有可识别的新目标承接属性时才审查 `attribute_transfer`。权限缺失或来源矛盾时先回 M2，不靠改关系名称解决。

音频关系固定为 `fully_copy`、`partially_copy`、`reference`、`weak_reference`（R L190–207）；M10 保留 M6／M11 的结果。完整复制、部分声层／时间复制和非信号参考须按真实用途区分。Label 在定义、摘要、保留分析、正文和声音字段中保持同义（R L35–37）。

## 5. 编排、审计与交接流程

1. 确认实际输入模式和已提供素材；先区分真实首尾帧、内容参考、构图锚点、视频结构与声音信号。
2. 取得 M2 或兼容外部输入给出的角色、属性权限和版本；首尾帧对齐事实不能由权限文字偷偷撤销。
3. 按 M10.1—M10.4 的实际职责取得本次有效风格、照明、色彩、材质／效果；未调用的分区保持未提供。
4. 在作用域内检查局部暖光与整体调色、固有色与受光、湿润与身份、参考权限与正文是否相容；把未决项送回责任模块。
5. 交 M11 编译正确字段及 Label。基础模式风格在第一镜内；Ref2VA 风格在第一镜前。真实切镜使用 `[Shot N]`；第一镜不带切点时间，后续切点递增且在有效时长内（B L86–92、R L218）。光色变化本身不自动新增镜头。
6. 标记本轮完成的是语义方案、合同检查还是最终协议编译。未经生成与实际观察，风格漂移、闪烁、真实光照、材质稳定和动作可读性均未验证。

案例中的 `COLOR & ATMOSPHERE`、`final_visual_constraints` 或其他制作段落可以提供写作意图，不能据此增添官方顶层字段。旧稿的基础／Ref2VA 混合字段需保留来源后交 M11 迁移；M10 不改案例原文件，也不声明已执行后续编译。
