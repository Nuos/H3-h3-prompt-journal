# M10.2 光源与照明设计

## 核心摘要

描述场景中实际如何照亮人物、道具和环境，再由 M10.3 决定最终画面的整体色彩关系。M10.2 拥有 `LightingPlan`，不能通过照明方案直接修改空间、机位、动作或身份。

本文为案例与冻结 M10 职责提炼的 D 类工作流。案例中的日光、晚霞、逆光、暖光与冷中性基调按原条件使用，不外推一套通用摄影设备配方。

**关键词：** 光源、方向、性质、坐标依据、局部光色、可见性。

## 1. 最小输入

取得当前作用域、可用场景条件、需要照亮的对象、视觉目的及实际引用的权限。涉及关键动作可读性时，读取 M5 或兼容外部资料给出的观看要求；涉及既定光源位置时，读取 M3 的空间依据。缺少精确空间时可以形成标注未知的定性候选，不能写“物理光位已验证”。

单独处理照明无需完整 `StyleHierarchy` 或 `ColorPlan`；如果引用其中的决定，必须声明所用对象和版本。已知的全片风格是只读条件，不由本子模块重写。

## 2. 把光源描述写完整

| 要素 | 要回答的问题 | 常见错误 |
| --- | --- | --- |
| 来源与对象 | 日光、室内灯或已有可见发光物来自何处，影响谁 | 只写“电影灯光”，无对象和来源 |
| 位置与方向 | 使用场景方向、人物方向还是屏幕左右；依据是什么 | 正反打都写屏幕左光，却声称同一固定场景光源 |
| 光质 | 光边、阴影或过渡需要呈现怎样的可见关系 | 用焦点、景深或滤镜词代替光源性质 |
| 局部光色 | 哪部分是暖光、冷光或中性光 | 暖色轮廓直接变成全片暖黄调色 |
| 可见结果 | 面部、手部接触、衣物／道具细节怎样可读 | 追求逆光而使必保接触过程完全不可见 |
| 变化条件 | 光变化是否来自人物移动、光源变化或场景切换 | 自行补造动作原因或未经批准的切镜 |

可用自然语言表达可见结果。不要从“柔光”虚构灯具型号、瓦数、照度或精确色温；参数必须来自实际输入，且在 M11／具体工作流支持范围内。

## 3. 正反打、移动与跨镜一致

先判断当前镜头是否仍在相同场景和光源条件下，再用其空间坐标核对光向。屏幕左右可能随机位改变；这不自动意味着光源漂移。若只有屏幕描述而没有共同空间依据，记录“待核对”，不要给出强物理一致性结论。

人物进入阴影、水面反射变化或衣物受光不同，可以是获准运动的结果。动作原因由 M4 提供，机位由 M5 提供，发生时间由 M7 提供；跨镜延续及允许重置由 M8 处理。

## 4. 保护关键观看信息

逐项比较照明结果与已有观看要求：脸部身份是否仍可辨、接触区域是否被眩光覆盖、湿亮材质是否吞掉边界、环境效果是否让必须看见的物体完全消失。

发生冲突时提出具体候选，例如减少局部效果覆盖、保留接触区的可读边缘、调整本镜获准光照；不能擅自挪动 M5 的机位、删去 M4 的动作，或把整个场景改成白昼。最终取舍由相应字段责任方接受。

“光效不遮挡关键动作”是需要验证的目标，文本写出该句不证明实际帧已经满足。M12 应在生成片段的对应时段检查并登记观察证据。

## 5. 与色彩、身份和协议协作

- 与 M10.3 对照：局部暖光和全片冷中性基调可同时成立；审阅实际对象和范围，不进行机械的冷暖关键词互斥。
- 与 M2 对照：不从身份图推定可继承原图光线，不以光色变化授权换肤色、发色或衣物。
- 与 M8 对照：持续光源与允许的场景变化分别登记；独立蒙太奇与连续接续使用各自规则。
- 与 M11 对照：将具体照明写入当前模式主正文的画面描述，不新增 H3 `lighting` 顶层字段；Ref2VA 参考作用需与定义及保留分析相符。

交付光源方案、作用对象、空间依据、与调色的分工、观看冲突和待确认项。脚本只检查结构化声明，不计算真实照度或证明摄影布光可实施。
