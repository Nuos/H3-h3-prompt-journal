# M10.1 风格层级与继承

## 核心摘要

以一个可解释的层级回答“本镜究竟执行哪些视觉要求”。M10.1 拥有 `StyleHierarchy`；照明、调色和材质的专业决定仍属于各自分区。全片规则不意味着每镜相同，场景变化和镜头例外也不能静默覆盖角色身份或用户要求。

本文是 D 类实现设计；领域依据为案例中的公共规则重复、连续段落、风格替换与局部例外。精确原文、行号与证据类型见 `case-evidence.md`，不把文字效果描述作为真实媒体通过记录。

**关键词：** 全片基线、场景规则、镜头例外、继承、作用域、独立生成。

## 1. 最小输入与输出

需要当前任务及作用域、视觉目的、用户必须保留的属性，以及实际使用的来源和参考权限。仅整理用户给定的局部风格时，不必先取得全片动作、音轨或全部镜头；若声明继承已有方案，就必须提供所继承对象及其有效版本。

输出列明稳定作用域标识、层级关系、风格意图、继承／覆盖的属性、例外依据和未知项。按照 `contracts.json` 构造 `StyleHierarchy` 提案；不要自行增加其他分区的写入权限。

## 2. 先分层，再形成当前有效值

| 层级 | 负责的决定 | 不可省略的说明 |
| --- | --- | --- |
| 全片 | 可识别的视觉表达与需要持续的共同属性 | 适用作品、来源与版本；不要把所有案例风格并入一条基线 |
| 场景 | 在环境、叙事条件下继承或改变的视觉关系 | 所属全片；保留、改变与不适用的具体属性 |
| 镜头 | 为当前信息揭示或观看任务安排的局部例外 | 所属场景；覆盖原因、范围与恢复关系 |
| 生成任务投影 | 当前独立请求必须携带的实际有效上下文 | 对应镜头与各层版本；由 M9／M11消费，不新建竞争的风格层级 |

先解析父层，再应用本层明确声明的例外。父项不存在、继承形成循环、场景与镜头归属不符、同范围存在竞争决定时，保留诊断并回 M10.1；不要用文件顺序或自然语言最后一句消除歧义。

全片“真实质感”不能自动覆盖局部明确要求；局部“暖灯”也不能自动把全片冷中性调色替换为暖黄。若冲突实际位于光源／调色语义而非继承关系，分别交 M10.2／M10.3处理。

## 3. 记录可以被检查的例外

每个例外至少回答：改什么、作用于谁、在哪里、为何改变、从哪个版本继承、保留哪些相邻约束。不要只写“允许变化”。

例如，全片采用冷中性基调，室内镜头保留窗边的局部暖光，这是照明与调色的分工；若下一场明确转为另一套整体基调，才是需要登记的场景级色彩例外。这个示例说明合同关系，不证明任何案例或模型已输出该效果。

镜头例外不授权新增人物、替换发色、重设计服装或改变关键道具。相关决定需要 M2 的身份／参考权限及 M8 的持续／变化许可。用户只要求“统一质感”时，保留原有合法身份与资产差异。

## 4. 为独立生成任务展开公共上下文

在 M9 已指定的每次生成任务内列出：全片共同表达、当前场景差异、当前镜头例外和需要持续的视觉状态。若下一任务仍需同样约束，重新带入必要内容及正确引用，不能假定模型记得前一个请求。

可在制作记录中按 ID 去重；向每次独立 H3 请求交接时仍需自足。不要把“避免提示词冗余”解释为删掉本请求唯一的主体质感、光色或参考权限依据。也不要在同一镜内重复多套同义形容词，把不同色彩和质感要求混为一团。

## 5. 局部审计

| 检查 | 通过所需证据 | 失败或未知时 |
| --- | --- | --- |
| 继承可解析 | 所有引用、父子关系及版本有效 | 请求补充或修订 M10.1 的关系 |
| 例外范围明确 | 同范围的决定能说明优先关系 | 不接受最后写入覆盖；保留竞争值 |
| 来源可替代 | 用户／外部输入满足公开合同 | 不强制先运行所有上游 |
| 权限未扩大 | 继承属性在允许的参考用途内 | 回 M2，不以风格统一解除限制 |
| 独立请求自足 | 当前任务实际有效风格已展开 | 回 M9／M11补齐投影 |
| 变化与意图相容 | 有具体视觉目的及相邻约束 | Agent 语义复核；脚本不判断审美优劣 |

交接 M5 必需的观看条件，交接 M8 视觉持续范围，交接 M11 可编译的有效风格。只记录本次已执行的检查；注册路由不等于完成这些交接。
