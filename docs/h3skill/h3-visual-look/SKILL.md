# H3 视觉风格、光线、色彩与材质

先回答**哪些视觉属性需要持续、哪些可以变化、变化由什么引起、具体在哪个场景或镜头生效**。将全片表达、实际光源、整体调色和主体表面状态分开，再结合当前任务的主体、空间、动作与观看要求形成版本化 `LookPlan`。

实现 M10 及四个可独立调用的子模块。接受用户、已有计划或外部工具提供的兼容最小输入，无需顺序执行 M1—M9。子模块只提出自己分区的候选值；父 M10 按原请求、版本和组合关系接受，不悄悄修改其他专业决定。

## 2. 取得最小输入，保留事实层次

确认当前职责、目标对象及作用域、作品意图、用户必须保留的视觉属性、可接受变化、实际素材角色和版本。仅传入本职责需要的只读投影；已有兼容资料可替代上游重跑。需要继承已有风格时取得对应版本；仅设计局部照明或材质时，不强制先产生其他三个分区。

区分用户指定、源文写明、作者报告、候选设计和实际媒体观察。案例中“清冷”“低饱和”“柔和暖光”仅在原案条件下有效，不升为所有影视剧或 MV 的默认偏好。没有查看图片时，不写“已确认原图光向／肤色”；没有分析媒体时，不写“无闪烁／无风格漂移”。

先明确每份参考允许继承的属性。身份参考只提供获准身份属性；它不自动提供目标服装、姿态、构图、灯光或整体调色。若当前模式真实绑定首帧／尾帧，其实际可见约束不能靠“仅作身份参考”一句话撤销。只读继承投影中的实际参考同样需要最小权限资料；`target_ids=[]` 表示作用域级使用，不是任意主体通配，主体限定许可不能扩为整镜。

## 3. 组织四个专业结果

1. **M10.1 建立风格层级。** 分开全片基线、场景规则和镜头例外，登记每个父作用域及明确的继承或替代关系。为例外写明改变什么、保留什么、适用范围和依据；遇到同一范围的竞争值，返回冲突，不采用最后出现的句子覆盖。为每个独立生成任务展开其实际生效风格，不能只写“同上”。
2. **M10.2 设计照明。** 指明光源、方向／位置的坐标依据、作用对象、光质及可见结果。实际暖光可与冷中性的整体调色并存；它们属于不同决定。反打镜头先保持场景内光源关系，再检查屏幕左右变化。遇到脸部过暗、反光掩盖接触或雾气遮挡必保动作，形成与 M5 的协调问题，不自行删动作或挪机位。
3. **M10.3 组织色彩。** 写明基调、对比、曝光倾向、需要保护的主体颜色和获准局部差异。区分环境色、材料固有色、局部光色与成片调色。为统一风格而改发色、肤色身份、服装设计或道具标识时，回 M2 判断；跨镜持续由 M8 判断。没有设备与流程证据，不补造色温数值、LUT、色域或曝光参数。
4. **M10.4 规定材质与效果。** 绑定具体主体、部位、道具或环境表面，写明质感、触发条件、可见变化、强度边界和退出条件。湿发、湿衣属于表面状态表达，不能默认为身份、发型或衣物更换许可。水花、雾气、反光、光晕与关键动作可见条件同时检查；动作原因交 M4、时刻交 M7、状态延续交 M8。
5. **父 M10 接受。** 对照真实原请求、只读上下文、基版本、字段所有权和组合一致性，接受四分区中的本次有效提案。局部使用只接受局部，不将未提供分区补写为“通过”。发生冲突时保留原版本、诊断、修改对象、责任方和重检范围。

风格词需要附着到画面中的对象和事件；“电影感、唯美、史诗感”等词不能代替谁在何处完成什么动作，也不能单独证明动作可读、跨镜一致或真实生成有效。

## 4. 守住职责与变化边界

| 遇到的问题 | M10 提供 | 接收责任 |
| --- | --- | --- |
| 参考图是否可继承风格、发色、衣物 | 冲突属性、来源、作用域及目标请求 | M2 资产／身份／参考权限 |
| 光源位置依赖场景结构 | 所需空间条件或疑似矛盾 | M3 场景空间 |
| 湿润、飞散或发光需要动作原因 | 预期视觉结果及所缺原因 | M4 动作与因果 |
| 高反差、逆光、雾气影响关键观看信息 | 风格候选、受影响对象和可读性条件 | M5 构图、焦点、可见性 |
| 效果开始、峰值、结束时刻 | 效果事件或状态条件 | M7 权威排时 |
| 湿度、衣物和视觉属性跨镜持续 | 需持续／获准变化的视觉关系 | M8 连续性 |
| 独立段落缺少公共风格 | 当前任务的有效风格投影 | M9 任务上下文／M11 编译 |
| 实际片段偏色、闪烁或效果遮挡 | 计划版本、待比较属性与范围 | M12 媒体观察，再回相应责任方 |

协调是版本化交接。没有取得修订结果时保留未决项；一次 `route` 输出不代表其他模块已经执行。根据实际引用传播失效，不能因改一镜光色自动重做全部作品。

## 5. 向 H3 五模式及 Label 交接

| 模式 | 主要官方落点 | M10 必须交接与核对 |
| --- | --- | --- |
| T2VA | `integrated_multimodal_description` | 在第一镜内建立风格；逐镜描述实际光色、材质、效果与变化 |
| I2VA | 首帧对齐指令＋基础主正文 | 首帧实际视觉状态与后续风格相容，不将真实首帧降格为松散参考 |
| FL2VA | 首尾帧对齐指令＋基础主正文 | 两端光色与材质差异的变化过程明确；冲突不以风格词遮盖 |
| L2VA | 尾帧对齐指令＋基础主正文 | 前序可到达尾帧的实际视觉状态，尾图不被当作首帧 |
| Ref2VA | 六字段；逐镜正文为 `detailed_description` | 第一镜前建立整体风格；定义、摘要、保留分析和逐镜正文的素材角色及权限一致 |

Ref2VA 可将人物、场景、服装、物件、风格或可见效果定义为 `<Subject N>`；具体画面或分镜锚点按用途使用 `<Picture N>`；`<Video N>` 保持编辑、续接或整体时间结构角色；`<Audio N>` 表示实际声音信号角色。没有独立的官方 `<Style N>`、`<Lighting N>` 或 `<Material N>`。不能为了“参考风格”自动继承整张图片，或虚构未提供的视频和音频。

先由 M2 确定素材角色与属性权限，再在该角色内判断实际保留关系；少量属性引用不自动等于 `weak_reference`。标签编号、字段序列化、首尾帧首行及运行参数交 M11。内部 `LookPlan` 和四个分区都不是 H3 原生顶层字段。

基础四模式保留三字段，Ref2VA 保留六字段；两类全片声音字段仍为 `overall_soundscape` 与 `non_diegetic_music`，声音语义归 M6。视觉“静谧”不等于静音，色彩变化不等于切镜，光效变化不自动产生配乐或声音来源。详细映射与官方行号见上述 H3 资源。

## 6. 核验与交付

读取合同后，从本包目录运行 Python 3.10+ 标准库命令：

```bash
python scripts/m10_contract.py --help
python scripts/m10_contract.py route assets/request-standalone-m10-1.json
python scripts/m10_contract.py check assets/proposal-standalone-m10-2.json --request assets/request-standalone-m10-2.json
python scripts/m10_contract.py accept assets/state-empty.json assets/proposal-batch.json --requests assets/requests.json
```

交付本次职责的风格层级及有效范围、光源方案、色彩方案、材质效果方案、明确例外、H3 语义交接、未决项和修订路由。独立子模块只交付对应分区及所需关系，不伪造完整 LookPlan。

`route` 生成调用信息；`check` 核验结构化提案；`accept` 输出新计划草稿；`impact` 根据实际引用提供失效与复验范围。命令不改写输入，不自动启动后端或其他模块。分别说明合同检查、Agent 文字审阅和实际媒体观察；文本通过不等于完整 G1／G2 通过，G3／G4 没有真实媒体证据时保持未验证。
