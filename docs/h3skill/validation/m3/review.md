# M3 发布前审阅记录

## 核心结论

本轮交付的是 M3 首版的文字工作流、可独立调用合同、确定性检查和案例试用。审核结论分别记录结构／合同、专业文字与实际媒体层级；所有命令通过后，整体视频效果仍为未验证。没有把已有 M1/M2 的历史报告重命名为本次证据。

## 1. 四人队形文字试用

实际产物见 [formation/answer.md](forward-use/formation/answer.md)，实际操作见 [formation/operations.md](forward-use/formation/operations.md)，输入和资源读取哈希见同目录 `read-manifest.sha256`。

父代理审阅确认：输出区分世界方向、身体方向与画面方向；保持 S1–S4 身份而不固定参考横排；分别描述四人阶段路线；保留源文换层时点、保护弧角色、OUT 方向和摄影窗口等未决问题；明确接触、路径交叉与投影遮挡不是同一件事。对 k199 四条手臂线未分配身份、k181 与 k186–k188 换层描述不同等缺口，未伪装成原文已有唯一答案。

这一试用的实际限制也随结果保留：执行时合同指南尚未落盘，未生成 JSON 或运行合同工具；收到过一次继续交付指令；无媒体观察、H3 推理、碰撞求解或投影检查。故它支持“这些文字规则能用于该案例的空间梳理与问题定位”，不支持宿主触发率、全任务成功率或独立无干预基准。

读取记录与最终候选版本的逐项比较见 [formation-read-review.json](formation-read-review.json)。父整合时只将两个输入链接换成固定提交的 GitHub 链接；专业规则文件的一个来源摘要改为更精确的文字，原试用哈希保持不变，不声称试用读取了后来的版本。

## 2. 水上闯关的独立 M3.1 试用

实际产物见 [narrative/answer.md](forward-use/narrative/answer.md)、同目录的 `request.json`、`proposal.json`、`commands.json` 与 `operations.md`。输出将连续赛道映射为单一场景、一个设计坐标框架、五个区域与四条向前连接；终点旁泳池保留为文字关系，没有伪造落水为普通步行通路。原文与自行设定的坐标／图表示分别登记为 case_text 和 design_decision；父代理的开发试用指令标为 external_input。

实际运行 route、check request、check proposal 对照原请求三条命令，均返回 0，局部合同 pass、整体 unverified。没有调用 M1/M2 或其他核心模块，没有接受父状态，没有米制测量、机位、媒体观察或物理效果结论。该试用也收到过继续交付指令；最初哈希准备错误引用不存在脚本，失败及纠正均记录，未把失败隐去。

父代理核对 10 个已读文件／运行依赖快照和三次输出的实际输入、Schema、registry 摘要均与最终候选匹配，结果见 [narrative-final-check.json](narrative-final-check.json)。这里只是归档一致性复核，没有冒称重新执行或对媒体作观察。试用证明该范围的 M3.1 可使用兼容文字输入独立构造和检查提案，不代表其他独立子任务的通用成功率。

## 3. 案例证据的整合修正

- 来源事实 F、作者报告 A、设计细化 D、实际实现 I、未验证 U 分开；不把作者自述的身份稳定当作本轮媒体测量。
- 领域索引清点 29 案、98 个文本文件；规则提炼记录 12 文件相关段落读取、86 文件仅清点。独立 Agent 试用额外的全文读取在各试用记录中另列，未混入这项统计。
- 将“后退跟随”与“以退远揭示队形”分开。两者是否冲突取决于跟随目标与相对距离，不能把原文压缩成无条件禁止摄影机后退。
- 增补赛道区域顺序、三人显露、画面右侧入画、触地剪辑四组可复核依据；保留历史 Ref2VA 混用基础主字段的问题，由 M11 按官方模式编译。

## 4. 合同审阅与修正

以下修改针对具体错接受或误判风险，不代表三维语义已自动求解：

| 发现 | 修正 | 回归范围 |
|---|---|---|
| 同相位第一条站位 unknown 可能掩盖随后两个已知矛盾值 | 比较组内全部相关站位；有尺度差但同向的向量不误判为方向冲突 | 六种输入顺序及正向比例朝向 |
| 仅按参与者、视图和区域比较遮挡，可能混同不同部位或反向关系 | 增加可选 `occlusion_target` 的遮挡者、对象和部位；未知目标保留未验证，仅明确同一目标支持矛盾判断 | 同部位反政策拒绝；不同部位、反向、未知不误拒；悬空对象拒绝 |
| 批次 `check --requests` 可能忽略混入的其他有效公共对象 | 原请求数组只接受 M3Request | 完整请求外混入 M3State 时拒绝 |
| 子提案可先新建问题再在同提案中宣称解决 | resolution 必须指向接受前状态的既有开放问题，仍由原所有者处理 | 同提案新建再关闭拒绝 |
| route 只有机械依赖列表，不便直接定位专业规则 | 每个公开节点登记对应领域资源，返回推荐读取与工具依赖；trace 只列脚本实际读取的合同／登记表 | 四节点路由及资源字段 |

合同说明同时明确：同一 placement phase 表示同时成立的空间状态；移动的起点与终点应分配不同相位。区域不同不自动推出互斥，明确 `exclusive_with` 才支持相应拒绝。自然语言语义、来源真实性、实际时间与相机投影仍须另外核对。

## 5. 独立只读复核的实际范围

另一个无父上下文的 Agent 对脚本、Schema、合同指南和测试做了有限时间的只读审查，检查原请求保真、分区权限、实体投影、批次组合、版本／重放、来源、ID 保留、引用和增量影响；未报告上述已识别问题之外的可复现阻塞项。审查中父代理提示了具体候选问题，因此不称为盲审。

该 Agent 实际运行的是修复前三项扩展回归尚未加入时的 28 项测试：27 通过、1 可选跳过。它没有独立重跑或重新审查后来的三项修复。修复后的 31 项测试及发布检查由父代理实际运行并归档，不能冒称是该审查 Agent 的验证结果。三项修复依据静态查阅与新增负例回归；未另存它们在旧版代码下的失败日志。
