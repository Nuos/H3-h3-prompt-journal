# M5 实际审阅记录

## 范围与方法

本轮主审阅针对 `h3-camera-visibility` v0.1.0／合同 1.0.0。审阅者读取冻结 M5 职责、全部技能入口与专业文档、完整合同脚本、相关 schema 定义、路由登记、测试及样例，并结合案例证据记录检查引用范围。另安排不参与实现的 Agent 完成两项自然语言前向任务和一次独立合同审阅。

这是开发过程中已执行的文字／代码审阅。实际 H3 推理、媒体观察、光学求解、碰撞检测和宿主触发率不在本记录范围内。测试的数值来自执行输出，专业判断来自明确列出的读取与审阅，二者不相互替代。

## 2. 领域审阅要点

**机位与取景分开。** 高度、俯仰、机身滚转与人物倾倒分开表达；距离不自动证明景别或视场。普通镜头允许按任务表达，未把所有特殊机位字段全局强制化。

**关键动作可见。** 取景要求绑定接触建立、保持、释放与结果等阶段，多主体身份不等于当前画面槽位。允许有目的的遮挡，但遮挡期间的路径仍应连续，不能以看不见为依据传送相机或主体。

**焦点证据有边界。** 水线案例支持脸眼清晰、前景泡沫柔化等定性层次，未提供完整焦距、光圈和测量系统。本包因此交付清晰目标与未知项，没有发明通用光学配方。schema 对 `visibility_assessment`／`focus_assessment` 只允许 `unverified`。

**运动关系按任务选择。** 案例中提前、同相、滞后、固定和连续任务运动都有适用范围；未把 1:1 同步、单人、低机位、手持或禁角度数字提升为官方通则。精确时间与镜头边界分别交 M7、M9。

**参考角色与正文分开。** 身份照片不自动变为首帧或摄影约束。Video 摄影参考不自动包含人物、剪辑、焦点和音频；Label 定义不能代替实际镜头过程。内部 CameraPlan 不进入最终 H3 字段。

## 3. 已发现并处理的问题

| 问题 | 修订 | 验证 |
| --- | --- | --- |
| 异常批次为数组或标量时，trace 访问错误类型可能产生未捕获异常 | 操作身份读取增加类型防护，保持结构性拒绝报告 | 数组、数字、null、字符串批次回归返回 `completed`＋本地失败，无状态输出 |
| 父路由的输入映射措辞与子路由混用 | 明确父只返回入口和最少字段；真实子请求独立形成，不把父请求冒充子原请求 | 检查当前 registry、guide 和 CLI 的职责一致性 |
| Consumer 枚举未包含四个 M5 子模块，内部结果无法登记实际依赖 | 允许 M5.1—M5.4 作为消费者，按显式 `read_paths` 传播失效 | 真实接受机位修订：依赖机位的构图／焦点／运动结果失效，未读取变化路径者保持 current，输入未改 |
| 自然语言试用将“仅参考视频运镜”自动解释为 `attribute_transfer` | 补齐四种视觉关系的官方含义，强调另一可辨识目标主体与已定义参考角色 | 首次输出保留；协议复核和局部修订见 [前向试用附录](forward-use.md) |

没有把自然语言端点的字面不等作为固定机位失败条件：`Fact.value` 是已声明的不透明业务载荷，两个表达可以同义。确定性检查使用显式位姿变化枚举；实际端点含义和摄影可行性继续由语义／媒体层检查。

## 4. 前向试用审阅

### 任务一：独立 M5.2 柜台交接

给定柜台侧面机位、高度约 1 米、距双手约 1.2 米、光轴朝向双手；接收者先握住钥匙、递出者再放手，要求同时看清手部交接与接收者脸部反应，背景有人经过，未提供视场或光学资料。

实际输出直接执行 M5.2，没有重跑上游；按动作阶段列可见关系，保留手部／脸部同框需求和第三人的遮挡风险。它没有由两个距离数据推断视场通过，也区分了同框与同时清晰。最小修改先从构图目标和边界检查开始，再以明确交接提出必要机位或空间调整。此任务的指定文字范围得到覆盖。

### 任务二：水线连续显露与 Ref2VA 交接

给定单一连续前进方向、漂动泡沫前景、人物轻转头、水线保留和脸部可读，身份照片只负责身份，视频只负责摄影路径；没有实际媒体。

实际输出将相机路径、人物动作和泡沫遮挡关系分开，没有断言“向前”必然使脸显露，没有补造焦距、时间或真实媒体事实。六字段交接保留声音意图缺口，未将其包装为已绑定素材的可提交成品。首次 `retention_analysis` 的 Video 关系词出现偏差，已据官方原文定位，并以独立附录修订，未覆盖第一次输出制造从未失败的记录。

完整读取日志、两任务首次输出和后续局部复验见 [forward-use.md](forward-use.md)。该试用不证明所有任务的可靠性，也不替代 Claude 宿主自动触发或有／无技能对照实验。

另有一次[独立合同审阅](independent-review.md)，检查主要控制流、原请求保真、写入边界、原子接受与未验证状态。初读时缺少的案例资源已在最终存在性检查中补齐；内部消费者枚举修复也经直接读取确认。独立审阅未发现其已查范围内仍未关闭的阻断问题，但未独立重跑测试、完整审计全部 schema 或核对官方协议，不能把它扩写成全量签核。
