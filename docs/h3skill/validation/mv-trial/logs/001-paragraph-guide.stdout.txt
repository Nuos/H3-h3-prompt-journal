# M1.2 段落功能与信息结构

## 职责与最小输入

接收可追溯的作品意图、必保事件和本次待组织的内容，形成段落功能、信息变化与必要的前后依赖。输入可以由用户或已有项目直接提供；没有必要为取得兼容输入而重新运行 M1.1。精确字段见 `contracts.json`。

这里的“段落”是作品语义单元。它可以对应一个镜头、多个镜头、多个生成任务或某个任务的一部分；M1.2 不直接决定这种数量关系。镜头、分镜格和生成任务归属交 M9，实际机位交 M5，起止时间交 M7。

## 编排步骤

1. **为段落建立稳定 ID。** 指明本次只组织局部段落还是整份作品。新段落 ID 是内部语义标识，不是 H3 的 `[Shot N]`。
2. **写出段落为何存在。** 用“建立什么、推进什么、揭示什么、转折什么、回收什么”等可核对的目的组织已有内容。每段至少回答：观众进入时知道什么；本段主要事件是什么；观众离开时新增或改变了什么；该变化怎样服务作品目标。
3. **安放必保事件。** 建立要求 ID 到段落的覆盖关系。某事件有意发生在画外时保留其存在与观众获知方式，交 M4/M5/M6 细化；不要把“没有直接展示”误写成“事件不存在”。
4. **区分角色信息与观众信息。** 只有源文本或用户要求支持时，才记录角色目标、已知/未知和揭示关系。不能为完成表格臆造人物心理、隐藏动机或背景故事。
5. **建立前后关系。** 反应要能追溯到引发反应的信息或事件；需要保密的信息不能提前泄露。这里只表达语义先后，不虚构具体秒数、拍点或相机提前/延迟量。
6. **选择当前体裁的判断重点。** MV 核查主题、乐段功能、动作重点和观看变化；有限叙事段落核查已有事件的起因、反馈、转折和结果。两者可以组合，不强迫所有舞蹈具有对白，也不强迫所有叙事按音乐拍点展开。
7. **解释重复与省略。** 重复如果承担母题回收或信息重新理解，可以保留；无需为了“每段不同”任意加戏。有意蒙太奇、省略或状态跳跃向 M9 提交目的，交 M8 决定相关连续性检查。
8. **返回段落提案与缺口。** 未覆盖的必保项、缺少因果的反应、没有来源的人物目标分别列出。局部范围未包含的相邻段落保持未知，不能声称已经检查整部作品。

## 局部审计

| 规则 | 可核对问题 | 修复位置 |
|---|---|---|
| M1-S01 功能可说明 | 段落是否只有动作/摄影名词，缺少信息或作品作用？ | M1.2 |
| M1-S02 必保覆盖 | 必保事件是否全部映射到适用段落，或有明确未解决记录？ | M1.2，必要时回 M1.1 |
| M1-S03 因果与信息 | 反应是否有已到达的触发；揭示是否违背保密或顺序要求？ | M1.2；执行可见性交 M4/M5/M6 |
| M1-S04 单元不混同 | 是否把段落数直接写成镜头数、分镜格数或生成次数？ | M9 接受划分请求 |
| M1-S05 目标不丢失 | 切换风格、增加变化或适配后端时，是否删除必保事件？ | 回产生变更的责任模块，M1 裁决目标变化 |

ID/覆盖/依赖环可以做确定性检查；“该段对观众有何意义”需要 Agent 或人工语义审阅。不要用结构检查代替这一判断。

## 与 H3 的交接

- 四种基础模式：段落事件和信息顺序最终进入 `integrated_multimodal_description`；以实际镜头为单位由 M9/M11 映射成 `[Shot N]`。
- Ref2VA：总体关系进入 `summary`；每个事件的完整可见/可听过程进入 `detailed_description`。摘要不能替代详细描述。
- 涉及对白时，M1 保存台词及其信息功能，不分配 `(Sx)`、不重写 `<d>` 内容；M6 负责声音事件，M11 负责标签序列化。
- 首尾帧任务中，开头/结尾信息与真实图片锚点的兼容性需由 M2/M8/M11 核对；M1.2 不凭段落文字宣称图片已经观察或关键帧已经吻合。

## 来源与适用边界

`case-evidence.md` 中的古典武侠舞、海滩剑舞提供段落五问与“观看新信息”的直接文本依据；夏日水线提供分段目标；水上闯关、贴纸喜剧及角色揭示案例提供有限的事件与揭示顺序依据。完整人物弧线、长篇影视剧结构、集级叙事不在本次案例证据已覆盖范围。本子模块能整理用户提供的此类要求，但需标明额外语义评审，不能声称由这些案例证实。
