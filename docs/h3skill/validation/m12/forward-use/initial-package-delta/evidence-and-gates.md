# M12.2 检查结果、证据与关卡汇总

**核心摘要：** 将检查结论绑定具体要求、证据、对象版本和覆盖；保留原始局部结果，独立计算当前范围的关卡结论。

**关键结论：** 程序可以核验记录的关系和完整性，真实证据是否支持语义结论仍须审阅；证据标签或内容摘要本身不是事实认证。

**关键词：** AuditLedger、证据、结果、四状态、stale、覆盖。

**目录导航：** 1. 证据层级；2. 状态；3. 交叉核对；4. Gate 汇总；5. 不足与冲突；6. 交付。

## 1. 保留证据性质

| 材料 | 可以支持 | 不能自动支持 |
| --- | --- | --- |
| 用户要求或明确授权 | 本次目标、范围与允许变化 | 实际生成效果 |
| 案例原文 | 文本中存在的规则、字段或自相矛盾 | 本轮已观看其图片／视频、规则普遍有效 |
| 作者的效果报告 | 作者报告过该结果 | 本轮独立复现或成功率 |
| 静态程序结果 | 其实际实现并执行的结构、数值或引用条件 | 任意语义正确、外部部署已运行 |
| 人工／Agent 语义审阅 | 明确材料和范围内的对照判断 | 未读文件、未观察帧或通道 |
| 媒体观察／测量 | 特定媒体版本、区间、方法的事实 | 全片未观察范围、其他运行或因果来源 |
| 推断或假设 | 候选解释与待验证方向 | 已确认原因 |
| 合成夹具 | 接口和反例行为 | 真实后端、真实媒体效果 |

保存定位、来源版本、原始结果、实际方法、执行者和范围。外部日志未经复核时明确其报告者；不把“来源存在”直接变为“来源可信且结论正确”。

## 2. 使用明确状态

| 状态 | 判定 | 返回内容 |
| --- | --- | --- |
| `pass` | 对当前适用要求已有足够范围和版本一致的检查依据，无未解决相关阻塞 | 检查范围、方法、证据和通过理由 |
| `fail` | 已有具体证据表明违反有效要求 | 期望、实际、位置、严重程度与修复需求 |
| `unverified` | 要求适用，但缺材料、执行、可判定方法或足够覆盖 | 缺项、影响与可先完成部分 |
| `not_applicable` | 要求在本任务确实不存在且无相关依赖 | 适用性依据，不以“没提供”代替 |

`stale` 表示历史结果对当前对象已失效；它不改写原检查的四状态。程序错误、JSON 合同失败或工具未执行属于技术状态，不能装作被审媒体的失败结论。

## 3. 做跨材料对照

至少建立本次相关的对照关系：要求→计划；计划→正文；正文→素材／参数；计划与配置→生成片；片段及编辑计划→最终装配。仅存在一端时标明不可完成的对照。

对跨段接缝同时读前段末镜、交接表和后段开场。对拍数、圈数、镜数与时长同时读标题、分项、正文和有效时间依据。对动作接触同时核对过程、可见条件、声音与状态，不用抽象动作名称代替事件证据。

官方语法检查按 `h3-label-mapping.md` 执行。把合法的正文要求与错误的字段包装分开；发现混用字段时保留语义，由 M11 重编译并复验，不删去无法装入错误格式的内容。

## 4. 汇总 Gate 时保留分项

只对检查计划中的当前适用范围汇总。必需项有失败，不能关卡通过；没有失败但仍缺必需证据，整体保持未验证。全部被判不适用也不产生“已经完成全部检查”的成功证明。

G2 应分别报告协议结构、语义保真、素材与绑定、实际参数和运行条件。只通过协议结构时，说明该子范围通过；不能省略其他本任务必需项后写“G2 全通过”。

G3／G4 的支持依据必须来自对应媒体版本的观察或测量，并关联生成配置／装配版本和计划。片段的观察不能证明尚未取得的装配成片；抽样结果不能悄悄扩大为全时长、多通道或全部镜头。

## 5. 处理不足、冲突与新证据

保留有冲突的证据及来源，不以多数投票、同源材料数量或自动选择较新文件消除矛盾。相同来源被多个案例转引，不构成多份独立实验。

证据版本与目标版本不一致时，停止把它作为当前通过依据；可以保留历史检查，明确需要复核或重新取得哪一项。程序重试不产生新的观察，重新改写一遍结论也不构成新证据。

## 6. 交付

返回范围、分项状态、Gate 汇总、证据引用、未覆盖部分和问题记录。每个问题至少指向具体对象与位置，说明期望、实际和必要修复；原因未确认时将归因留给 M12.4 调查。模型正文与审计台账分别交付。
