# M2 局部审计、父接受与交接

## 目录导航

1. 验收层次；2. 检查项；3. 接受与状态；4. 修复返回；5. 影响传播；6. 下游交接。

## 1. 验收层次

| 层次 | 依据 | 能报告的结论 |
|---|---|---|
| 结构 | 类型、字段、版本、ID | 合同格式有效性 |
| 确定性关系 | 引用、所有权、范围、版本、冲突记录 | 所实现关系的检查结果 |
| 专业语义 | 当前要求、案例规则与实际授权 | 本次范围的 Agent/人工审阅 |
| 媒体观察 | 实际读取指定素材/成片的记录 | 仅所观察对象/区间的事实 |
| 全流程 | 各模块计划、编译、运行、成片 | 相应 G0—G4，不能由 M2 单独代替 |

保存实际输入版本、执行者、范围、证据与结果。路由定义不等于实际调用；结构通过不等于语义通过；权限明确不等于生成遵从。缺证据为 unverified，依赖变化为 stale，真正无关才为 not_applicable。

## 3. 接受与状态

M2.1 提 `asset_registry`，M2.2 提 `entity_registry`，M2.3 提 `reference_map`；M2 为唯一权威接受路径。子输入只读，不能修改兄弟内部数据。

接受核对同作品、合同、基版本、来源请求标识、合法分区、来源不可静默替换、引用和必要冲突。原请求内容先用 `check --request` 对照并做语义审阅，`accept` 不能代替该前置步骤。批次对一个基版本整体核对；逐次接受后，后续提案重读新版本，不只改数字。

接受仍为有范围的草稿。可登记待提供/未观察资产，但不等于生成就绪。关键未知影响目标、身份或权限时暂停相应最终确认。

问题保留对象/字段、证据、责任、阻塞和复验范围。修复由责任方提新版本，不通过删除问题或更改审计状态制造通过。技术重试按任务预算；语义冲突须新决定，本包无自动互调循环。

## 4. 修复返回

| 发现 | 返回 | 可继续 |
|---|---|---|
| 缺素材、无法访问、无观察依据 | 用户/提供方、M2.1 | 已知登记、无依赖规划 |
| 无法唯一辨认目标 | 用户、M2.2 | 来源和其他明确绑定 |
| 权限或来源相互矛盾 | M2.3；目标冲突回用户/M1 | 非冲突属性/范围 |
| 提案已过期 | 提案所有者 | 比较差异、重读投影 |
| 只有后端编号，无稳定对象 | M2.2 / M11 | 保留原话并明确缺项 |
| 后端不支持要求 | M11；必要时 M1/M7/M9 | 能力差距和可保留意图 |
| 生成片身份或声音错误 | M12 先保存观察，再定位 M2/M11 等 | 保留旧结果与失败证据 |

## 5. 影响传播

登记真实消费者所读字段和版本，按引用路径相交判失效。更换身份素材可能影响空间、动作、摄影、状态、视觉与编译；这只是候选影响，实际失效以真实依赖为准。

展示名变化不应让无关内容全部失效；文件内容、绑定、关键帧角色、声音使能或权限范围变化时，相关消费者复验。未登记依赖的覆盖未知，不能宣称找到全部影响。

保留历史来源、版本和审计。`impact` 输出待复验对象，不执行消费者，也不把原本未验证的对象补成通过。
