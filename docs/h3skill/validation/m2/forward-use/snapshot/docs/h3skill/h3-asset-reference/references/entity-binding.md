# M2.2 主体身份与资产绑定

## 目录导航

1. 职责与输入；2. 稳定实体；3. 多对多绑定；4. 替换和冲突；5. 编排与检查。

## 1. 职责与输入

读取 `asset_context` 与 `binding_brief`，输出 `entity_registry` 中的 `entities`、`bindings`。外部兼容清单可直接提供输入，不必先执行 M2.1；资产和证据版本仍须明确。

实体是目标作品的稳定复用内容，不只指人。按合同使用 person、animal、object、scene、motion、style、voice、soundtrack 或 other；不要为每个形容词新增实体。M11 将来可能把相关内容编译成 Subject，但不是同一编号系统。

## 2. 稳定实体

1. 给目标对象稳定 ID 和可区分名称。出现顺序、左右位置、前后层次或镜头编号改变时保留身份。
2. 每条 binding 保存 `entity_id`、`asset_id`、`channel` 与 `source_selector`。同图多人明确选中谁；使用源图方位、可辨特征、提供者标注或已有区域 ID。
3. 方位只定位**源图对象**，不自动成为全片固定站位。目标走位归 M3，动作归 M4，跨镜状态归 M8。
4. “她”“左边那个”“第二张”等指代必须在当前明确素材范围内唯一解析；无法确定时保留候选和缺项，不猜选或静默合并。
5. 可见人物、声音参考和实际发声者分别判断。M6 定义发声事件，M11 分配 `(Sx)`；静默人物不因有照片而自动成为说话者。

## 3. 多对多绑定

| 情况 | 表示方式 | 检查 |
|---|---|---|
| 同人有正面/背面/脸部图 | 同一实体，多份绑定 | 是否为同一目标，哪些属性各自负责 |
| 一张合照多人 | 多实体，同一资产，分别定位 | 不把文件数当人数，不合并身份 |
| 一图提供人物和环境 | 人物与场景分别绑定 | 人物授权不自动授权背景，反之亦然 |
| 视频供动作和相机结构 | 按用途明确引用对象与通道 | 源演员是否只是运动载体 |
| 音频供声音参考 | 明确目标声源/区间及用途 | 不猜说话者，不从资产列表推导目标发声 |

绑定只声明来源与目标的关系。是否继承全部或部分属性仍由 M2.3 决定，未列权限不默认开放。

## 4. 替换和冲突

替换时分别标明源对象、目标对象及素材。保留运动不等于保留源面孔、服装和场景；新身份图也不自动授权改变源节奏和运镜。

多份外观资料不一致时保留候选，M2.3 按属性与范围裁决。如果“是否同一目标人物”本身不明，M2.2 不得以权限优先级代替身份判断；仅询问该项所需问题，继续已知资产登记。

不施加全局人数上限、统一锁焦或每图一人的假设。多人绑定清楚不证明实际画面全部清晰；那需要 M5 可见性计划和 M12 媒体观察。

## 5. 编排与检查

完整描述对象是什么、由哪份资产哪部分识别、哪些未知。原图位置标明“在源图中”，目标状态标明作用范围，避免一句含糊命令混用两者。

检查稳定 ID、存在的资产引用、可区分的源内定位；多图同人不重复造人，同图多人不合并；换位和出入画不改身份；运动源演员不成为额外角色；音色与原词句/人物外观不未经许可继承；未观察来源保持对应状态。

M2.2 只能提出实体/绑定分区。改来源回 M2.1，改权限回 M2.3；站位、动作、声音、状态分别交相关模块。向下游只提供所需投影。

案例依据：四主体队形的一图多人、稳定身份与换层；身份半身舞/下山的多图分权；动作迁移的源演员排除。四主体部分段落允许交叉，不能把局部“不交叉”文字变为全系统禁令。精确来源和冲突见 `case-evidence.md`、`case-index.json`。
