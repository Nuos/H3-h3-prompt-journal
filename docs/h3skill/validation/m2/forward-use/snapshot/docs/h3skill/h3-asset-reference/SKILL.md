# H3 素材解析、资产绑定与参考权限

把每次参考关系说明为：**哪份素材的哪一部分，为哪个稳定对象提供什么属性，在何处、何时生效，哪些属性不得继承，判断依据是什么。**

实现 M2、M2.1、M2.2、M2.3。子模块提交提案，M2 父模块核对版本与组合约束后形成权威记录；不要求先运行 M1 或其他兄弟模块。遵从用户当前明确要求和已确认约束；案例方法只在适用范围内采用。新要求与旧资料冲突时保留差异，不把旧案例置于用户要求之上。

| 登记来源、访问情况、解析观察与待补项 | M2.1 | 资产登记 | AssetRegistry 提案 |

## 2. 建立最小输入与来源边界

由当前 Agent 将自然语言转为 `M2Request`，合同版本 `1.0.0`。提供请求 ID、目标、作品 ID、基版本、来源和所需只读输入。脚本不自动理解自然语言。

| 节点 | 必需的业务输入 |
|---|---|
| M2 / M2.1 | `material_brief` |
| M2.2 | `asset_context`、`binding_brief` |
| M2.3 | `asset_context`、`entity_context`、`permission_brief` |

使用用户资料、已有项目或兼容的解析结果，不强制指定上游生产者。只有口头描述、路径或案例文字时可以登记计划，不能写成已读媒体。

缺项时保留可完成部分和阻塞范围；不猜测脸部、动作、音轨、时长、主体对应或权限。身份、授权或相同范围的排他要求无法确定且影响本次结果时，提出最少的具体问题并暂停该项接受；已有授权及常规可逆实施决定不重复询问。

## 3. 执行三个子模块

1. **M2.1：登记资产。** 保存稳定标识、来源版本、访问状态及观察依据。图片、视频视觉轨、音频轨与文本解释分别识别。解析器只提供带证据的候选观察，不自动决定继承什么。
2. **M2.2：绑定实体。** 人物、道具、场景或其他复用内容采用稳定 ID，用源内定位区分同图不同对象。允许多份素材定义一个对象或一份素材支持多个对象；不把位置、镜头顺序和文件编号当身份。
3. **M2.3：分配权限。** 每条记录来源绑定、属性、允许/禁止/未知、范围和授权依据。身份、服装、姿态、首帧状态、背景、相机、动作、音色及原音复制分别决定。未列明的属性不默认继承。
4. **M2：接受提案。** 先用 `check PROPOSAL.json --request REQUEST.json` 逐提案对照真实源请求并完成语义审阅，再检查引用、范围、版本、字段责任与冲突决定。`accept` 自身没有原请求参数，不能代替该对照。接受相容提案形成新草稿，过期或互斥提案退回责任子模块；不暗改专业决定，不以重复检查代替裁决。

案例中的人数、时长、画幅、固定机位、站位、参考数量和工作流数值保留适用条件。不得施加统一人数上限；“身份参考不继承姿态”不能扩大为对真实首帧约束的全面禁令。

## 4. 运行确定性工具

仅需 Python 3.10+ 标准库；不联网、不读取图片/音视频内容、不调用 H3、不覆盖输入。先查看样例与字段说明：

```bash
python scripts/m2_contract.py --help
python scripts/m2_contract.py accept assets/state-empty.json assets/proposal-batch.json
```

按合同指南执行 `route REQUEST.json`、`check ARTIFACT.json`、`accept CURRENT.json PROPOSAL.json`、`impact PREVIOUS.json CURRENT.json`。`check` 请求对照选项核对目标、作品、来源请求与基版本；父接受不证明自然语言要求已忠实实现。

从 `assets/` 复制请求、初始状态或子提案，替换 ID、来源、版本、资产状态及内容，再检查。将工具报告和真正状态对象分开保存到任务目录；`accept` 结果中的 `state` 才是新的 `M2State`。未知或未验证状态不能通过删除字段变成通过。

## 5. 检查 H3 交接

| 模式或角色 | M2 提供的语义 | 主要审计问题 |
|---|---|---|
| T2VA | 无引用时明确参考集合为空；保留文字要求 | 不伪造素材绑定 |
| I2VA / FL2VA / L2VA | 实际首帧、首尾帧、尾帧的资产身份、角色与变化范围 | 身份图误当关键帧；同帧位互斥要求 |
| Ref2VA Subject | 复用内容、源内定位、多源属性与稳定绑定 | 主体不是文件；同图多人不串线，多图同人不重复造人 |
| Ref2VA Picture | 真实帧位、构图或分镜锚点用途 | 纯外观来源不自动产生独立 Picture 条目 |
| Ref2VA Video | 编辑、续接、整体运镜/节奏/时间结构来源 | 动作参考不自动复制演员、布景或全部剪辑 |
| Ref2VA Audio | 明确启用的声音来源、复制/参考意图和范围 | 有声视频不等于启用；音色参考不等于原录音复制 |

基础四模式主字段为 `integrated_multimodal_description`；Ref2VA 使用 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。准确映射见专用参考，不混用字段集合。

**M2 稳定 ID 不等于 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`、`[Shot N]` 或 `(Sx)`。** M11 分配实际模式、上传顺序、标签与字段。M2 给权限语义，M6 决定声音事件，M7 提供时间映射，M9 决定镜头与生成任务；下游未实现时交付明确交接，不声称已调用或编译。

## 6. 按范围交付与报告

交付三类登记对象或本次子模块提案、参考权限表、来源/缺项/冲突与修复责任、H3 交接及执行记录。单个子模块请求只交付该范围。采用“素材—对象—属性—范围—权限—证据”表便于审阅；正式模型正文不得夹带合同、审计或开发说明。

局部检查分别报告结构、确定性关系、专业语义和媒体。用户陈述、作者报告、推断和直接观察不能互相冒充；权限通过不证明生成已保持身份。M2 只贡献 G0/G1 的相关范围；完整 G2 编译、G3 生成片、G4 成片需要各自执行证据。
