# M7 文字一致性审阅记录

日期：2026-11-05（America/Los_Angeles）。

## 审阅范围

独立审阅者读取新包 SKILL.md、time-bases.md、event-scheduling.md、time-domain-mapping.md、audit-and-handoff.md、provenance-and-license.md，结合已核对的官方模式／Label 映射与冻结 M7 职责，只检查现有文字的一致性。该审阅未执行 H3、未读取媒体，也未把并行尚未落盘的合同视为缺陷。

## 发现与修正

| 问题 | 原表述／风险 | 已作修正 | 验证范围 |
| --- | --- | --- | --- |
| 定格方向表述不准确 | SKILL.md 曾写“定格映射不可唯一反求”，而映射参考已明确输出→输入可唯一得到固定源时刻 | 入口改为按方向处理：源时刻可对应输出区间，不能强制给单值 | 与映射专业文档的方向一致；不是实际剪辑执行 |
| 独立入口可能被错误收紧 | “只有 M9 声明真实切镜”可能被理解为必须先运行 M9 | 允许 M9 或用户提供的兼容编辑决定声明真实切镜 | 与独立接收兼容输入的公开合同原则一致 |

上述两项由 h3_protocol 审阅者报告，根代理在实际文件中修改。审阅未发现其他实质 H3 字段、Label、首尾帧口径或证据强度冲突。该结论仅覆盖所列文字，数学运行器另行测试。

## 运行接口与数学边界复核

根代理读取运行器及合同指南后，另外核对并收口了以下实际问题：

| 问题 | 修正与检查 |
| --- | --- |
| 通用区间检查允许量化结果落在覆盖末端，容易把端边界当作已有帧样本 | 增加 sample／boundary 明确语义，默认 sample 的原时刻和量化结果都必须严格早于覆盖末端；正反例已进入行为测试 |
| 时钟仅登记 FPS 和时长时无法机械检出帧数口径冲突 | 增加可选 frame_count，明确是样本总数；CFR 检查 extent=N/FPS，VFR 检查 PTS 条数；124帧／24FPS／9秒冲突负例已通过 |
| 定格源点可能错误取半开源覆盖末端 | 根代理实际复现源覆盖 [0,10) 却接受定格源点10秒；新增 freeze_source_outside_coverage 和回归负例，保留5秒有效定格正例 |
| boundary 文案可能暗示 VFR 可按 extent 推导结束帧号 | 发布复核者指出并复查修正：CFR 网格可表达覆盖末端边界，VFR 仍限定已有 PTS 范围，结束时刻不冒充结束帧号 |
| 必要持续、总时长预算与并发容量容易互相替代 | 分别检查只读 timing_requirements、duration_budget、capacity；文档明确总量通过不证明串行顺序，仍需 before／meets 等约束 |
| 入口示例一度指向没有分发的 request-m7-2.json | SKILL.md 与目录 README 改用实际 standalone 文件名；发布器额外核对文档中 assets 路径是否存在 |

根代理在上述修正后实际复跑46项行为测试和12次隔离调用，均通过，记录分别见 `behavior-tests.json` 与 `portability.json`。上述结论仍不涵盖真实媒体测量或 H3 生成执行。

第二位发布复核者全文阅读入口、H3映射、合同指南、三个专业参考、审计交接和案例证据，并对照冻结职责、规范和随包官方原文相关条款。其实际检查了11个文档提到的具体 assets 路径，确认三个子入口与官方模式／字段／Label 的映射明确；在确认 VFR 文案修正后，没有报告剩余实质阻断。该复核未重复完整测试，也未验证远端发布。

## 协议核对结果

五种输入模式的三／六字段区分、真实 Shot 切点、首尾帧指令、Video／Audio 源时间与目标局部时间、跨切声音与截断语义已经在 h3-label-mapping.md 给出固定官方原文行号。该文件使用9项目录导航，未把 TimingMap 或量化表扩展为 H3 原生字段。

## 保留边界

语义审阅不是自然语言正确率或自动触发率基准；离线数值检查与实际媒体同步仍各自需要证据。已知的案例矛盾保留在案例证据中，由专业责任模块处理，不修改原案例来消除冲突。
