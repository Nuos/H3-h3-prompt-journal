## 2. 多维简评

**标准化程度。**案例的强项是把“多人始终一致”拆成视觉锚、空间路径和时间状态三类问题，并给出十部分提示词结构。它比泛泛要求“保持队形”更可操作；但仍缺少给任意人数、场地和段数自动编排的输入格式与决策步骤。[S1：33–88、130–141]

**身份及资产职责。**图像负责身份和场景，文本固定四人编号，并用同一锚块避免跨段改写；图像姿势不控制后续起步。此处明确写服装库存，与其他案例“零外貌文本”采用不同策略，不能把任何一种未经条件化地推广为全仓绝对规则。[S1：37–55；S2：6–38]

**动作、队形与镜头关系。**人物性格和逐拍动作有区分，前景主体表演时其余人继续移动，入出状态包含动力信息。但 README 的“只在自己象限内、禁止过中线/从别人身前经过”，与 SEG10 的中心穿越、保护弧和前后层交换直接冲突。需要允许经过的角色、路径与时窗，而非同时保持全局禁止和局部穿越。[S1：70–82；S2：79–86、100–118]

**时序及复现。**SEG10 提供 22 个逐拍节点和原音频全局窗口，适合作为编排样本；正文引用 `cuts_manifest.json`，本案例目录未包含该文件。README 的“身份漂移接近零”属于作者自述，未列样本数、失败数或模型版本；媒体按本次范围未检查。[S1：46–51；S2：24–28、88–134]

## 3. skill 化判断与最小落地步骤

建议封装为“固定主体表→节拍网格→安全路径及队形状态→状态接力→镜头可读性检查”的子流程，而不是直接生成通用 14 段群舞模板。

1. 参数化主体数量、身份锚、可用场地、队形节点、音频网格和禁止区域；本案例四人是任务设置，不是统一人数上限。
2. 为每人记录入态、路径、承重脚、时间区间和出态，并将相邻段状态逐字段比较。
3. 将交叉、遮挡、前后交换标为局部许可；检查同一时刻是否占据同一空间。
4. 输出提示词与独立核对表，先完成至少两段连续生成的身份/队形/接缝回归。

## 4. 主要缺口与优先级

- **P0：修复队形规则冲突。**“不穿越”须给中心交叉和层交换留出明确许可条件。[S1：78–79；S2：79–86]
- **P1：保留相机规则作用域。**SEG10 的 6.40–8.80 秒要求 back-pedal，同时要求基本维持距离并禁止退成大全景；这可以解释为同距跟随，不能据此直接判为运动冲突。封装时应把“跟随退步”与“为了揭示队形而拉远”分成不同条件，避免抽取禁令后误禁前者。[S2：71、75、142]
- **P1：补齐工程证据。**归档实际最终 14 段提示词、节拍 manifest、模型/参数及身份漂移核对记录；当前只能复核 SEG10 的文字设计。[S1：94–120、157–161]
