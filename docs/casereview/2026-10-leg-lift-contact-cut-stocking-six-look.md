# 抬腿触地换袜：案例简评

## 核心结论

本案例已经给出**物理事件触发外观切换的可复用方法**：固定支撑关系，先完成触地，再换外观并保持，最后进入下一次抬腿。适合封装为服装／道具状态切换的专项子技能原型。主要工程缺口是时长与状态数量口径不一致、实际帧率和验收记录缺失；精确到毫秒的文字并不等于已实现同帧控制。[S1][S2]

## 2. 多维简评

**方法论。** 本例把“卡点换装”展开为有前后条件的状态机。触地是切换条件，落地保持是禁止过早进入下个动作的约束，因此能够针对README列举的切换提前、动作黏连和支撑漂移逐项修订。[S1：12—58行]

**输入与输出。** 正文使用 `subject_definitions / summary / retention_analysis / detailed_description / camera / soundscape / music` 等结构，形成整段提交稿。角色、场景和袜饰枚举高度具体；要复用必须分离固定锚定属性与允许变化的属性。README称“零外貌／场景外描写”，正文却详细复述人物和环境，应先选择统一策略。[S2：1—13行]

**时序与剪辑。** 六个接触点、起抬时间和切后保持都写出，因果关系清楚；但没有帧率，2.070秒等时刻不能直接当成帧号。正文的六个 `Shot` 更接近同机位外观状态区间，与README的“单镜头直出”需解释为固定机位内的指定硬切，避免误读成完全无剪辑。[S1][S2]

**验证与泛化。** 作者说明把源片渐变改写为硬切，因此这是机制改编，不是对原转场形式的逐帧忠实复制。接触触发思路可迁移至手碰物体、放下道具等事件；永久单腿支撑、袜饰序列与具体时间只适用于当前示范。现有文本未提供跨服装、跨人物或不同速度的回归结果。

## 3. Skill 化判断与最小落地步骤

建议输入目标属性清单、初态、状态序列、接触事件、音频锚点和帧率，输出状态表及完整提示词。编排器应检查每一轮“旧态持续→触地→新态生效→保持→再抬”的顺序；审核阶段分别核验支撑脚、活动脚、相机、角色身份和允许变化属性。先用不同动作速度与两种服装序列验证，再扩展为通用事件触发模块。

最小状态表可逐轮记录旧外观、新外观、接触时刻、切换时刻、保持终点和下一次起抬。若相邻两轮过密，先判断能否容纳落地确认与保持，再决定调整动作或切换数量；不应将所有时间机械等比例压缩。生成后的检查还需区分提前换装、触地正确但外观滞后、保持期间再次变装等失败类型，这样才能定位时序规则或属性锁定规则，而不是反复加长同一组否定词。

## 4. 主要缺口与优先级

1. **P0：统一总时长。** README写5.17秒、单次直出，正文最后明确区间结束于4.690秒，余下0.480秒没有动作安排；需补尾段或修正目标时长。[S1：3、50行；S2：563—575行]
2. **P0：统一状态及参考口径。** “Six Looks”实际为LOOK0初态加六次转换，即7个状态；README又说视频可选，正文持续依赖Video1机制。独立使用时应明确无视频输入的替代信息。[S1：34—50行；S2：187—219行]
3. **P1：建立帧级验收。** 将毫秒时间映射到实际输出帧，记录可容许偏差、保持帧数和失败修订；不能把“第一接触帧”要求当作已获得的能力。
4. **P1：澄清生成与剪辑语义。** 正文已经明确“仅袜饰变化”的例外，应在封装时保留；另将固定机位、同视角外观硬切和整段生成分别定义，避免把不移动相机误解为没有状态切换。[S2：110—123、604—638行]
