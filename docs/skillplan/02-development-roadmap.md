# 通用 AI 视频提示词编排与审计框架：开发提炼计划

**文档版本：v0.1.2。**

**文档状态：planned。** 本文定义待开发范围、依赖、产物与验收条件；以下工作包尚未因本文建立而视为完成。用户新增的架构原则为已确立的强制要求，实现符合性须经后续验收。

**计划日期：2026-11-04（America/Los_Angeles）。** 案例与既有技能基线：`35658d3615d02c6aa6e4221fb223d73b86aa6875`。本轮交付为设计与开发计划，后续实现需按工作包逐项记录实际结果。

## 核心摘要

开发应先建立**共同数据契约、来源规则与审计边界**，再把案例方法提炼成可组合的职责单元，最后迁移案例配方并完成影视剧、音乐 MV 两类任务的集成回归。直接把 29 个案例提示词拼接成一个大技能，会把参考用途、机位策略、动作时序及剪辑意图的差异混在一起；共同契约应先表达这些差异，再由具体任务选择策略。[S01][S07][S09][S10][S18]

拟采用 **12 个核心职责单元 + 共享项目状态 + 总编排入口 + 体裁配置 + 案例配方**。12 个职责单元不预设为 12 个独立安装的技能。最终安装单元应依据触发边界、上下文需求、维护成本和离线复制要求确定。[S19]

MVP 的验收范围是**文字编排、结构与算术检查、来源可追溯性、明确限定的语义审阅及变更后的局部重检**。实际人物稳定性、动作实现、视线、音画同步、接缝与整片表现，须在获得真实素材并运行相应生成和编辑流程后另行验证。现有静态通过记录不能替代这些证据。[S18]

**关键词：** 高内聚、低耦合、模块化、路由信息设计、共同数据契约、动作事件链、摄影观察计划、参考权限、时序协同、状态交接、局部修复、模型适配、案例迁移、分层验收。

**目录导航：** 1. 基线与缺口；2. 职责与开发约束；3. 共同数据契约；4. 工作分解与依赖；5. MVP 与试点；6. 测试分层；7. 来源冲突裁决；8. 29 案迁移；9. 版本与变更传播；10. 拟开发目录；11. 发布与验收；12. 未决设计项与来源。

创作时这些模块会迭代协作。开发顺序则先解决共同字段、证据和校验能力，再接入跨模块行为，具体依赖见第 4 节。

### 2.2 必须保留的边界

1. **任务参数与通用规则分开。** 人数、镜头数、旋转次数、是否静止、是否全身、是否唱歌、是否允许跳切，均依具体任务与实际后端配置；不从单案提炼统一上限。[S07][S08][S09]
2. **创作意图与可执行能力分开。** 用户希望的时长、参考组合和精度要与指定部署核对；参数只写进正文不等于已经在工作流中设置。[S16][S17]
3. **计划与观察分开。** 文本中的动作落地、同向接续、音轨复制是计划；生成后实测记录才支持相应结果声明。[S18]
4. **原始证据与裁决分开。** 源文保留原样；修正规则记录理由、范围、版本与受影响案例。[S07][S10][S18]
5. **导演记录与生成正文分开。** 制作说明、问题清单、审计意见、证据等级与未决项留在工作记录；M11 只输出对应模式需要的正文与独立参数记录。[S17]
6. **通用能力与体裁策略分开。** 剧情需要动机、信息和反应；MV 可能以音乐段落、重复母题和动作峰值组织内容。它们共享状态、事件、摄影和审计契约，但不使用同一套全部必填表演规则。[S02][S03][S07][S10]

### 2.3 所有模块与子模块的强制架构原则

用户补充要求确立：**M1–M12 以及每一个现有或未来子模块，无论层级、执行者和安装方式，必须遵循高内聚、低耦合、模块化、路由信息设计原则。** 具体规则以 `06-modularity-routing-principles.md` 为准；较早文档的建议不能减弱此要求。

| 原则 | 开发中必须落实的条件 |
|---|---|
| 高内聚（HC） | 每个模块或子模块围绕明确的专业职责、产物和变更原因组织；跨专业取舍由责任模块处理，编排入口只协调调用 |
| 低耦合（LC） | 依赖公开且带版本的合同；只读取本任务需要的只读字段投影，返回限定字段的变更提案；不传递可任意改写的全项目对象或依赖未声明上下文 |
| 模块化（MD） | 递归登记模块树、父子责任、可调用入口、独立产物、资源和局部验收；父模块保留对外语义责任，子模块按提案或明确授权工作，同一字段／范围／版本只有一个有效写入责任 |
| 路由信息设计（RT） | 路由定义与实际执行记录分开；条件、输入输出版本、目标、依赖、汇合、返回、失败、修复与失效信息可追溯；反馈有明确终止条件 |

每个模块与子模块必须能够在满足自身输入合同的条件下完成局部任务并接受独立验收；输入可以由用户、外部工具或既有计划提供，不强制重跑全部上游。独立能力不预设独立进程或独立 Skill 包。所有层级纳入同一清单，不能以十二个顶层已登记代替子模块覆盖。

## 3. 共同数据契约优先

### 3.1 先确定对象，再开发模块

P1 应形成一份可审阅的字段字典、约束说明和示例集。下表是拟采用的逻辑对象，不等同于已存在或已实现的 JSON Schema。

| 对象 | 核心内容 | 必须解决的歧义 |
|---|---|---|
| 项目简报 | 目标、体裁、交付规格、用户固定要求、可调整项 | 生成片长与最终成片片长分别记录 |
| 约束记录 | 来源、适用对象/时间、优先级、适用条件、验收方式 | 用户要求、官方限制、制作选择、案例经验不可混为同级 |
| 素材与权限 | 素材 ID、模态、内容依据、目标主体、继承/排除属性、时间范围 | 身份参考、姿态参考、首尾帧、运动参考、声音复制分别表达 |
| 主体与场景 | 稳定 ID、身份属性、场景坐标、锚点、出入场及可见性 | 在场不等于入画；世界左右、身体左右、屏幕左右分别声明 |
| 动作/表演事件 | 施动者、对象、触发、前提、过程、主要结果、接触/支撑、终态 | 舞蹈链、道具操作、对白反应可用同一事件外壳、不同专业子字段 |
| 摄影计划 | 机位、景别、构图、光轴、距离、焦点、路径、可见对象 | 机位不等于景别；移机、摇镜、变焦、裁切分别记录 |
| 声音事件 | 说话者/声源、原文台词、声音类别、复制/生成/参考、区间 | BGM 人声不自动要求舞者对口型；音色参考不等于整轨复制 |
| 时间关系 | 全片时间、段内时间、源片时间、拍点、帧率、偏移、响应策略 | 同步、提前、延迟、固定等待均可表达；精确数值需标依据 |
| 状态与交接 | 固定属性、可变状态、计划末态、观察末态、继承/变化许可 | 同一人物允许状态发展；只有获准变化才可以跨切重置 |
| 分镜与装配 | 分镜格、实际镜头、生成任务、素材版本、裁切、后期定格/变速 | 一个动作章节不自动等于一个实际镜头或一次生成 |
| 视觉风格 | 色彩、光线、材质、质感、变化范围 | 全片恒定项与有意的场景/情绪变化分开 |
| 后端能力 | 后端/模型/版本、模式、输入与输出能力、已核对参数 | 能力来自当前选用后端，不继承某旧案例工作流的孤立数值 |
| 审计发现 | 规则 ID、对象 ID、证据、期望/实际、严重度、修复、复检范围 | 未观察到、推测、已验证、无法判定不能统一填为通过 |

字段字典应同时给出最小示例、合法省略条件、单位及坐标约定。空值需要区分“未知”“不适用”“尚未测量”，不能用一个空字符串隐去原因。

### 3.2 先落地的跨对象不变量

这些不变量属于拟开发的契约与审计设计，须由对应正反例验证后才能纳入实现：

| 不变量 | 检查对象 | 失败时的最小修复方向 |
|---|---|---|
| 每个被引用对象都能解析到有效 ID 与版本 | 素材、主体、镜头、动作、声音 | 修复引用或补真实定义；不虚构素材 |
| 被声明为连续接力的同一动作链，其前一动作终态满足后一动作前提，或存在明确过渡；并行事件按各自对象与依赖检查 | 动作链与状态 | 修复相邻边界，保留不受影响的动作 |
| 连续性要求与切点类型一致 | 镜头与剪辑关系 | 选择符合意图的边界策略并核对两侧状态 |
| 关键事件需要被相应镜头看见或明确作为画外事件处理 | 动作、声音、摄影 | 调整观察计划或事件表达；不把不可见细节记为已核验 |
| 时间关系可以从声明的时间基准追溯 | 音乐、动作、相机、源片、成片 | 重算受影响窗口；保留原始精度与量化规则 |
| 整轨复制、新生成声音和静音声明相互一致 | 声音与后端输出 | 修正声音用途或装配方案 |
| 每个独立生成任务包含执行所需上下文 | 分段、参考、连续性、风格 | 在该任务内展开必要信息，避免依赖未输入的上一段提示词 |
| 模型正文与导演计划语义相符 | M11 编译结果 | 定位漏写、错绑定、误加规则与未替换占位符 |

### 3.3 原型状态与发布状态

拟分别记录 `planned`、`draft`、`ready_for_generation`、`generated`、`media_reviewed`、`assembly_reviewed` 等状态及其证据。状态命名在 P1 冻结前可以调整，但必须保留不同证据层次。文字/静态检查通过只允许推进到相应文字阶段；缺少真实输入或后端能力证据时，应保留未就绪原因。

### 4.2 可以并行与必须串行的工作

- **必须先行：** P0 → P1 → P2。规则还没有清楚的对象、时间和证据语义时，不进入大范围技能提取。
- **可并行：** P3 内素材、空间、动作、声音、风格可以分别开发，但提交前使用同一版契约。M11 的官方规格映射与 M1 的体裁样本设计可在 P1 后启动设计，不提前宣称完成集成。
- **协同收敛：** P4 负责跨对象关系，避免每个基础模块分别编写互不相容的“连续性”和“同步”规则。
- **先试点后迁移：** P5 → P6 → P7。通过代表任务检验共同机制后，再逐案迁移；不先批量重写29案来证明提炼完成。
- **媒体验证独立登记：** P9 可以在具备条件时与后续迭代并行，但其结果不能由 P6 的静态回归代替。

### 4.3 每个工作包统一交付格式

每个工作包应交付：输入与版本、产物列表、受影响职责、适用规则、正反例与实际结果、未决项、证据位置、下一阶段的开始条件。完成状态由真实产物和验收记录推进，不以文档中写下“通过”“锁定”“稳定”作为完成依据。

模块清单须包含稳定 ID、父模块、职责、公开合同及版本、输入投影、输出／写入范围、必需／可选依赖、资源、路由 ID、直接消费者、局部与组合验收、实际状态。新增或拆分子模块时同步更新清单、路由、依赖与覆盖记录；具体子模块数量由职责边界确定。

## 5. MVP 范围与两类试点

### 5.1 MVP 的完成目标

MVP 应能把一份创作任务转成共同导演记录，生成对应 H3 模式的提示词与独立参数说明，并输出有定位、有依据的审计结果。发现冲突时，系统应保留用户目标，提出或执行已经允许的最小修复；需要新增真实素材或用户取舍时，记录具体未决项。

MVP 包含：

1. 十二职责的最小可调用流程及共享状态接口。
2. H3 基础模式与 Ref2VA 的明确路由、字段和引用检查，实际能力由所选后端配置。[S17]
3. 动作、摄影、声音、状态及剪辑之间的语义核对流程；自动可判定部分与人工/模型审阅部分分别标记。
4. 对变更的影响分析、局部修复、复检与版本记录。
5. 影视剧与 MV 的文字级代表任务及正反例。
6. 既有案例技能的兼容迁移方案与可复核映射。

真实模型调用、音频测量、素材识别、图像身份测量、自动剪辑和整片质量评分不作为本轮文字 MVP 已有能力。后续接入这些能力时，须列出工具、输入、执行记录及实测边界。

### 5.2 MV 试点矩阵

下列任务是拟采用的回归方向，不代表本计划已经执行。

| 试点 | 选用依据 | 主要验证对象 | 必须包含的反例 |
|---|---|---|---|
| 摄影提前到位与动作中切镜 | 摄影纪律、已有摄影组件试用 | M4/M5/M7/M9；响应策略与剪辑策略分别表达 | 把提前到位误改成同时启动；相机到位晚于要展示的峰值[S05][S18] |
| 身份参考不继承姿态 | 半身六段舞 | M2/M4/M5/M8 | 身份图被当成首帧；镜头风格被误当身体姿势[S09] |
| 多段剑舞的道具状态与动作变化 | 18段剑舞 | M4/M7/M8/M9 | 重复拔刀、持物手或剑鞘状态冲突；把许可蒙太奇误判为连续性错误[S03] |

### 5.3 影视剧需要新增的文字样本

影视剧样本应先明确“新设计的验证样本”，不能标成从舞蹈案例中已经验证的方法。样本可在文字阶段建立，媒体阶段再用真实输入执行。

| 新样本方向 | 必须表达的内容 | 可核查的失败条件 |
|---|---|---|
| 询问—回避—追问 | 两个角色各自目标、台词轮次、停顿、听者反应、下一句因果 | 说话者串线；听者反应早于信息到达；台词改变了用户给定事实 |
| 递交并拒收道具 | 谁持有、哪只手、接触/共同抓握/放手、对方拒收、物件最终归属 | 道具无接触或交接依据地改变归属、在两个不相容位置被重复持有或凭空消失；反应没有可见触发 |
| 进入空间并发现异常 | 角色已知/未知信息、视线目标、发现顺序、观察镜头 | 角色先表现已知，后才看见证据；镜头未展示关键对象 |
| 反打与画外声音 | 世界坐标、屏幕方向、视线、声源位置、画外说话者 | 空间关系反转未解释；画外人被误生成入画；声音绑定错误 |
| 有意省略与时间跳跃 | 跳跃前后时间、保留身份、允许变化的状态、观众应理解的信息 | 审计错误要求所有状态逐帧连续；或未标变化许可而重置物件 |
| 表面平静与潜在紧张 | 动机、显性动作、微反应、观察者视点和信息控制 | 只用抽象情绪词；无可观察表现；相机提前泄露任务要求保留的信息 |

这些样本用于补齐 M1、M6 及 M3/M5/M8 的剧情接口。长期人物弧线、复杂故事结构和集级叙事需要额外样本与评审，不能由单场文字试点自动宣称覆盖。

## 6. 分层测试与验收设计

### 6.1 统一审计关卡

开发阶段使用 P0–P9；任务运行中的审计关卡统一使用 G0–G4。关卡作用于实际产物，不能因开发阶段进入下一步而自动标记通过。

| 关卡 | 核查范围 | 允许推进的条件 | 未通过时的处理 |
|---|---|---|---|
| G0 输入与证据 | brief、素材、用途、来源、用户固定要求、后端信息与未知项 | 已知与未知可区分，后续任务所需的输入有依据 | 完成可做的编排，保留具体缺项与草稿状态；不伪造素材观察 |
| G1 设计与跨模块一致性 | 意图、空间、动作、摄影、声音、时序、状态、剪辑与风格 | 所选策略相容，关键因果与交接成立，合法例外有标记 | 定位冲突对象及依赖，执行最小修订并重检 |
| G2 编译与运行契约 | 模型模式、字段、引用、正文/参数、实际能力、生成/编辑预算 | 正文忠实于计划，调用所需条件与选定后端一致 | 修复适配或明确能力缺口；不以文本声明代替参数设置 |
| G3 生成片验收 | 真实生成片的身份、动作、物件、可见性、时序、声音与接缝候选 | 本片所需的媒体观察和测量有记录 | 记录实际差异，局部重生成或修订装配；回写观察状态 |
| G4 全片验收 | 完整装配后的叙事信息、段落功能、节奏、风格、声音与连续性 | 成片满足已定义目标，残留问题与许可变化可查 | 修订受影响段落或编辑决策，重检相邻依赖 |

文字 MVP 主要实现 G0–G2 的流程和检查；G3、G4 先定义接口与验收记录，在 P9 取得真实输入和输出后执行。[S18]

### 6.2 四层验证分别报告

| 层级 | 评估内容 | 执行方式与主要关卡 | 可作出的结论 | 不能推导的结论 |
|---|---|---|---|---|
| 结构与算术 | 字段、ID、引用、单位、时间排序、区间覆盖、转换数、帧率映射、模式要求 | 确定性检查及适用的规范验证器；覆盖 G0/G1/G2 的相应字段 | 声明的结构/算术条件满足 | 动作一定能生成、人物一定稳定 |
| 语义与跨模块关系 | 主体归属、动作因果、接触、支撑、可见性、策略冲突、交接与正文一致 | 规则驱动审阅，必要时独立审阅者核对；主要对应 G1/G2 | 在指定审阅范围内未发现或发现哪些文字问题 | 未观察媒体时的物理/视觉通过 |
| 真实媒体 | 实际帧、动作实现、身份、道具、节拍、声音、相机、切点 | 真实素材与输出、工具测量、人工视觉/听觉核验；对应 G3 | 本次输入/配置/输出的实际结果 | 不同后端或未测试题材的成功率 |
| 整片作品 | 段落功能、观众信息、节奏、情绪、风格、全片声音与连续性 | 完整成片评审、任务标准及必要受众反馈；对应 G4 | 本片是否满足预先定义的创作目标 | 自动证明框架普遍优于其他方法 |

结构与算术中可自动判定的项目应保持确定性；语义层的人工判断须标审阅者、输入版本和理由。真实媒体与整片层没有输入时标为未执行，不以空记录或静态分数补齐。

### 6.3 正反例成对建立

P2 应先为每条关键规则设计“满足条件”和“违反条件”的最小对照。以下是拟开发夹具，不是已经完成的测试：

| 规则类别 | 正例 | 反例 | 期望行为 |
|---|---|---|---|
| 引用权限 | 身份图只绑定脸；动作来自事件链 | 把身份图姿势声明为强制首帧 | 定位到素材用途及冲突字段 |
| 支撑与物件 | 先建立承重/抓握，再移动或放手 | 未接触就转移重量；物件归属无过渡改变 | 要求修复具体事件前提 |
| 摄影响应 | 主体峰值前已形成所需构图，策略为提前 | 同一事件同时被标为提前和不可提前 | 报告策略冲突，不强改为全程同步 |
| 连续性 | 连续切镜维持授权状态；蒙太奇明确允许变化 | 未获许可的姿态/道具重置；或错误阻止许可跳切 | 按边界类型选择检查规则 |
| 状态计数 | 初态与三次转换形成四个可追溯的状态时间区间，允许后一区间返回先前状态值 | 三次转换却遗漏某个状态区间或转换边界 | 报告缺失区间或边界；不要求四个状态值各不相同 |
| 时间映射 | 源片裁切、后期定格与成片区间分别登记 | 用成片时长冒充生成时长；混用两种帧率 | 报告对应时间域及算式问题 |
| 声音 | 指定原轨连续铺底；舞者不口型 | 同时声明完整音轨复制和新增覆盖其内容 | 报告保留策略冲突 |
| 交接 | 末镜正文、交接表、下一镜开场一致 | 表格引用正文未出现的手掌特写 | 定位两侧文本和表格，不接受仅改标题 |
| 未知项 | 缺音频时保留拍点待测与draft | 没有音频却声明已实测卡点 | 拒绝错误的就绪/验证声明 |
| 变化传播 | 改持剑手后重检相关动作、构图、边界 | 仅替换人物描述，后续仍引用旧持物手 | 产生受影响对象清单并复检 |

### 6.4 测试报告必须区分定义、执行与结果

每个测试记录至少包含：测试 ID、输入版本、覆盖模块、规则来源、预期行为、实际执行方式、实际结果、产物路径、执行日期、未执行原因和残留限制。`authored` 不能等同于 `executed`；反例按预期被拒绝属于该断言通过，不能被写成“任务已就绪”。[S18]

回归范围由实际变更决定：修改纯展示名称只检查包装与索引；修改声音复制语义需检查相关声音、同步、适配和装配路径。扩大测试应针对尚未覆盖的具体风险。

### 6.5 架构原则的递归验收

| 原则 | 必须取得的验收证据 | 必须能识别的失败 |
|---|---|---|
| HC | 职责与产物对应；局部变更由相应专业单元完成 | 子模块同时承担无关专业决策，或入口替专业模块改写业务内容 |
| LC | 使用声明输入和资源即可完成代表任务；兼容实现替换后合同仍成立 | 隐式读取兄弟私有文件、依赖整份聊天历史、跨模块写全局状态、无关变更迫使全流程重跑 |
| MD | 每个已声明模块／子模块有局部入口、独立输出、独立验收和至少一个适用的组合场景 | 只能随全流程运行、子模块未登记、独立包遗漏必要规则或脚本 |
| RT | 选择条件、版本、目标、返回、汇合及失败分支有执行记录；受影响复验可追溯 | 隐式循环、错误分支、未就绪被当不适用、过期结果继续使用、重试造成重复生成 |

覆盖分母取自该版本完整模块树，逐项记录定义、执行、结果和未执行原因；不规定无依据的统一子模块数量、耦合度分数或重复测试次数。这是后续实现的验收要求，本次文档检查不等于这些运行检查已经执行。

## 7. 来源冲突裁决与规则升级

### 7.1 规则登记格式

每条候选规则记录：规则 ID、来源 ID、原文位置、适用任务、条件、效果/目的、反例、与其他规则的关系、证据等级、裁决状态和版本。证据等级区分官方规格、案例文本、作者报告、本文推断、新增实验和实际媒体观察。

### 7.2 已知冲突进入回归集

| 来源问题 | 裁决原则 | 涉及模块 |
|---|---|---|
| 同时启动、提前到位、迟反应同时存在 | 抽象为共享时间轴与可选响应策略；不保留互斥的全局命令 | M5/M7/M12 [S05][S07][S09] |
| 动作中匹配切镜与姿态间跳切并存 | 先确定剪辑类型；连续性只检查该类型要求保留的关系 | M8/M9/M12 [S07][S09][S15] |
| 身份图与首帧约束冲突 | 按属性与时点明确权威；首帧绑定须对应实际模式和输入 | M2/M8/M11 [S09][S10][S17] |
| 库内拍数、圈数、镜数标题与正文不一致 | 查原文及可获得的真实证据；无从消解时保留未决项，不把标题自动当真 | M4/M7/M9/M12 [S07] |
| 交接表与实际段落正文不一致 | 联合核对上一段末镜、交接表、下一段开场；修复受影响边界 | M8/M9/M12 [S10] |
| 一条源提示词混用模型模式字段 | 保留导演意图，由 M11 重新映射到选定模式；不复制错误包装 | M11/M12 [S10][S17] |
| 案例片长或源片参数不符合所选后端 | 核对实际后端能力，再决定生成与编辑方案；必要调整不得隐去 | M7/M9/M11 [S07][S16][S17] |
| 某案使用固定人数、固定景别或旋转预算 | 作为案例/体裁参数保留；获得独立证据前不升级为通用限制 | M1/M3/M4/M5/M12 [S07][S08] |

### 7.3 升级为通用规则的门槛

候选规则至少需要清楚说明它解决什么失败、适用于什么输入、有哪些合法例外、如何观察是否满足。多案重复出现可以加强其提炼价值，但来源数量不自动构成效果验证；同一原始资料被多个目录复制时，仍计为同一证据来源。

涉及效果改进的结论应使用实际可对照的任务、相同或可说明差异的条件、完整保留的失败样本与审阅记录。未开展此类验证前，只报告方法与检查覆盖，不报告成功率提升或通用稳定性排名。

## 8. 从 29 个案例配方迁移

### 8.1 迁移策略

1. **登记现状。** 为29案记录现有skill路径、规则ID、来源版本、验证记录与使用方式。[S01][S18]
2. **四类提取。** 将内容分类为共同机制、体裁策略、案例参数和证据/例外；案例完整性不因提炼而丢失。
3. **建立映射。** 每条迁移规则指向新模块、规则ID和原文证据；未迁移的特殊流程说明保留原因。
4. **先做试点。** P6验证共同机制；保留旧配方作为对照，不用同时改写源案例来掩盖差异。
5. **逐案兼容。** 迁移产物可调用共同机制，但各现有案例skill继续满足单目录复制要求。
6. **记录行为变化。** 对格式修复、冲突裁决及输入要求变化分别说明，避免以“重构”隐藏输出差异。

### 8.2 原文件与打包边界

`case-studies/`、`docs/casereview/` 及已经保存的原始来源快照作为证据保留。新的提炼记录和规则不覆盖源文。对现有案例skill的后续兼容调整需有单独diff、版本与回归记录；本开发计划本身不执行这些调整。

共享规则可在维护源中集中管理；发布时有两种待评审方案：

| 方案 | 使用方式 | 优点 | 验收风险 |
|---|---|---|---|
| 发布时展开依赖 | 构建每个案例包时复制对应版本的共同规则/脚本 | 保留当前单目录可复制体验 | 必须校验副本版本、来源和构建可复现性 |
| 完整集合包与独立案例包并行 | 集合包使用共同核心；独立包包含所需依赖 | 支持集中调用，同时兼容单案例使用 | 两种包必须由同一版本映射生成，防止行为分叉 |

不将跨兄弟目录的相对路径作为独立案例包唯一依赖。采用哪种发布方案在 P7 冻结，不能仅因减少重复文件而破坏已有可复制承诺。

### 8.3 迁移验收字段

每案至少登记：旧路径、旧版本、关联源文件、迁移模块、保留的案例参数、冲突裁决、输出变化、兼容方式、正反例、实际回归结果、尚未迁移项。29案覆盖表应能明确指出缺失、重复和例外，不以总数相等代替一对一映射检查。

## 9. 版本、变更传播与局部修复

### 9.1 独立版本轴

| 版本轴 | 记录对象 | 触发更新的事件 |
|---|---|---|
| 来源版本 | 案例、官方文档、真实素材与观察结果 | 上游文本或资产改变、新证据到达 |
| 契约版本 | 字段、枚举、必填条件、时间/坐标语义 | 共同接口发生兼容或不兼容变化 |
| 规则版本 | 检查条件、例外、修复策略 | 冲突裁决、新反例或实际媒体结果 |
| 后端配置版本 | 模型/工作流、输入能力、生成参数 | 选用部署或有效连线配置变化 |
| 配方/技能包版本 | 模块组合、体裁配置、案例映射、发布资源 | 对外行为或打包依赖变化 |
| 任务运行版本 | brief、计划、提示词、生成结果和装配 | 一次具体任务的修改与重跑 |

发布记录应固定这些版本的组合。不会因一个文件日期较新就自动覆盖更高权威或更适用的规则。

模块／子模块的公开合同与路由定义必须声明版本兼容范围；破坏性变化提供迁移或明确拒绝旧输入，并使受影响的检查失效。消费者依赖公开合同，不以私有文件布局、其他模块内部算法或目录日期推断兼容。

### 9.2 变更影响表

| 修改项 | 至少需要重检的关系 | 不应自动改动的内容 |
|---|---|---|
| 音频更换、拍点或片段偏移调整 | M6音源/台词；M7拍点/动作峰值；M9切点与母带位置；相关M5响应 | 人物身份、剧情目标，除非用户同时修改 |
| 动作支撑脚、持物手或结束方向改变 | M3空间；M4动作前提；M5可见性；M8相邻交接；相关M7时间 | 未关联镜头与无关角色 |
| 参考图用途改变 | M2权限；M8首末态；M10风格继承；M11模式与绑定 | 未获授权的外貌、服装或环境设计 |
| 镜头路径/景别改变 | M5几何与可见性；M7到位/恢复；M8切点两侧；M9装配 | 动作目标，除非几何冲突确需调整 |
| 剪辑时长、裁切、定格或变速改变 | M7各时间域；M6声音持续；M8接缝；M9选用区间；M11实际参数 | 原始源片与历史运行记录 |
| 剧情信息顺序或对白改变 | M1动机/信息；M4反应；M6轮次；M5观察目标；M8叙事状态 | 用户指定的角色身份及未关联事实 |
| 后端升级或工作流连线改变 | M11能力；M2输入；M7/M9预算；相关静态与媒体回归 | 以旧结果继续声称新后端已验证 |

### 9.3 局部修复流程

发现问题后，按“规则与证据 → 具体对象 → 受影响依赖 → 最小修订 → 重检 → 版本记录”处理。修复要保留用户固定要求。需要改变剧情、增删动作、调整总时长或换素材才能满足条件时，明确指出冲突及可选调整，不把未授权删改作为自动修复。

同一问题反复失败时，应检查规则是否适用、证据是否充分、输入是否缺失，记录失败原因和未决项。修复次数与资源预算由具体任务配置，不预设没有依据的统一循环次数。

## 11. 发布与验收

### 11.1 MVP 候选发布条件

候选发布应同时满足：

1. **范围明确。** 发布说明列出覆盖职责、可执行操作、依赖与未完成能力；不将媒体层标为静态测试的延伸结果。
2. **契约明确。** 字段、ID、单位、坐标、时间基准、未知项和版本兼容规则可查。
3. **规则可追溯。** 通用规则有来源或明确的设计理由；源冲突有裁决记录，案例限制没有被误升格。
4. **流程可复核。** 影视剧与MV试点保存真实文字输入、实际产物、审计/修复记录及未决项。
5. **正反例生效。** 支持的合法情形通过，明确违规的情形被准确拒绝或标为未就绪；结果对应本次发布版本。
6. **迁移完整。** 29案映射与兼容说明齐备；源文件保留；独立案例包所需依赖完整。
7. **包装合规。** 对实际产出的技能包执行所选 Agent Skills 格式检查、资源链接和必要运行检查。[S19]
8. **声明准确。** 不将规则数量、测试数量、人工自评或一次案例结果当成生成成功率。[S18]
9. **架构符合性完整。** M1–M12 及发布范围内所有层级子模块按清单接受 HC／LC／MD／RT 验收；缺少必需合同、路由、依赖或实际验收的单元保留阻塞，不以顶层数量覆盖子模块缺项。

### 11.2 发布交付物

发布候选应包括：共同契约、模块职责与资源、体裁配置、H3适配、规则/证据登记、29案迁移表、正反例定义、实际回归报告、未决问题、许可归属和升级/兼容说明。提交前核对待发布内容与已审阅内容的版本一致；合并和后续发布按当次用户授权及仓库约束执行。

### 11.3 媒体与整片验收的后续入口

P9启动前应具备真实输入媒体、选定后端与配置、生成/编辑资源、评价任务和观察方法。生成后按事件与镜头核对，再看完整作品是否达到段落功能。记录素材、参数、输出、失败和修复，不只挑选成功片段。

若需要比较新旧方案，应提前定义相同任务和可比条件，再完整保留两套结果。评价可围绕具体动作是否完成、错误状态是否出现、关键内容是否可见、音画关系是否成立、接缝与整片是否达成目标展开；本计划不预设没有样本依据的性能指标、成功率阈值或开发工期。
